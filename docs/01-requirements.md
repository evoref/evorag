## 1. 記法

### 1.1 ID 体系

| 接頭辞 | 範囲 |
|---|---|
| FR-1xx | チャットとセッション |
| FR-2xx | 保存とデータの保護 |
| FR-3xx | メモリ |
| FR-4xx | 検索と文脈の組み立て |
| FR-5xx | llama-server との接続 |
| FR-6xx | 自己学習 |
| FR-7xx | カートリッジ |
| FR-8xx | 更新と配布 |
| FR-9xx | TUI・CLI・設定 |
| NFR-1xx | 性能 |
| NFR-2xx | 資源と依存 |
| NFR-3xx | 信頼性とデータの保全 |
| NFR-4xx | 移植性 |
| NFR-5xx | セキュリティとプライバシー |
| NFR-6xx | 使いやすさと国際化 |
| NFR-7xx | 保守性と開発の基盤 |

### 1.2 優先度 (MoSCoW)

- **Must**: その版の完了条件。欠けたらリリースしない。
- **Should**: 強く望む。間に合わなければ次の版へ送れる (送ったら [08 §6](08-roadmap.md#6-繰り越しの記録) に記録する)。
- **Could**: 余力があれば。
- 1 つの要件を段階的に満たすときは「Must (v0.1: 範囲 A) / Must (v0.3: 範囲 B)」のように書く。

### 1.3 版

版の一覧と目的は [08 §1](08-roadmap.md#1-版の概観)。本書の「版」列は、その要件が初めて Must (または Should) になる版を示す。

### 1.4 受入基準の書き方

- 検証の方法は T (自動の試験) / B (ベンチマーク) / M (手動の確認) / R (レビュー) で示す。区分の定義は [09 §2](09-testing-quality.md#2-検証の区分)。
- Must の要件には、判定できる受入基準 **AC** を §5 に置く。AC は `AC-<要件ID>-<n>` で識別する。リリースゲートは「その版の Must の AC がすべて合格」。

## 4. v0.1 の範囲

### 4.1 v0.1 の定義

> Windows 11 の Windows Terminal で、手元の llama-server に `evorag setup` で接続し、日本語で会話できる。応答は逐次表示され、中断と再生成ができる。会話はセッションとして残り、強制終了しても消えず、翌日に続きから話せる。以前の会話の関連する発言を、出典つきで応答に添える。

### 4.2 v0.1 に含む (Must)

FR-101〜106、110、201〜212 のうち版が v0.1 のもの (FR-201〜209、214〜217)、309 (ターン・ジャーナル・語彙の索引)、311、401、402、406〜409、501、503、506〜510、801、802、807、901〜907、909。NFR は版が v0.1 のもの。

### 4.3 v0.1 で外すもの (後の版)

| 外すもの | 版 |
|---|---|
| sleep-time、埋め込み、ベクトルの検索、ノート、rerank (言い換えは v0.2 でやめた) | v0.2 |

| カートリッジ (`/sources` はメモリの入り切りだけを持つ) | v0.5 |
| `import`、macOS | v0.6 |

### 4.4 v0.1 の既知の制約 (リリースノートと README に書く)

- Windows 11 のみ。Linux は v0.2、macOS は v0.6 (予定)。
- 以前の会話は語彙 (文字の並び) で探すので、言い換えた話題は思い出せないことがある。
- 本体の更新は手作業 (取得 → 署名の検証 → 置き換え)。`evorag update` は v0.3。
- 事実を覚える機能と「忘れる」操作は v0.3。v0.1 で消せる単位はセッション。
- コード署名をしていないので、初回の起動で SmartScreen の警告が出る。
- 保存の形式は v0.5 まで変わることがある。移行は直前の版のデータから行うので、版を飛ばさずに更新する。
- プロンプトの言語は、初回の起動時に決めたものから変えられない (変えるには新しいデータ根を使う)。
