## 1. 何を最適化するか

### 1.1 性能の指標と目標

目標は段階 0 の計測 (S-17) で見直す。数値は今の実測から見積もったもの (【推測】を含む、§15)。

| 軸 | 指標 | 今 (v0.3.0) | 目標 |
|---|---|---|---|
| **速度: 応答** | 発話を送ってから最初のトークンまで (TTFT)。基準機・Qwen3.5-9B・履歴 2k トークン。**添えたトークン数ごと** に測る | 想起なし 0.43 秒。想起あり (1 往復) 約 1.7〜2.4 秒 | (a) 下書きと同じ本文を送った (先読みが当たった): p50 0.6 秒以下。(b) 本文は違うが想起は同じ: p50 1.2 秒以下。(c) 想起が違う: 引用 300 トークンで p50 2.2 秒以下 |
| 速度: 起動 | TUI を開いてから最初の応答 | 先頭の処理し直しで 7〜14 秒 | 開いてから「先頭のトークン数 ÷ 読みの速さ」秒の後の発話で、2 ターン目と同じ (履歴 2k なら約 10 秒) |
| 速度: 裏の処理 | 1 日分の見本の会話を覚え終えるまでの、裏の生成トークン数と時間。止められて捨てた呼び出しの率 | 3 つの別の呼び出し | 生成トークン 1/2 以下。時間は、chat のモデルで 1/2 以下、速いモデル (`memory` の役割) で 1/3 以下。捨てた率 10% 以下 |
| **信頼性: 記憶の正しさ** | LongMemEval oracle の **保留の問い** (100 問以上、§10.1) の正解率と内容語の再現率。EVAL-facts。誤った事実の率 | 開発の 50 問で 29/50 (0.58) | 保留の問いで、対の検定 (McNemar) で有意に上回る。開発の 50 問の中央の見込みは 35 前後 (判定の照合の上限は約 44〜45 問、§10.1) |
| 信頼性: 答えない判断 | 関係の無い問いに誤って添える率 (abstention 30 問 + 関係の無い問い) | abstention 1/3 | 今以下 |
| 信頼性: 守り | 強制終了・電源断でのデータの失い、忘れた・private の値の残り (置き場所の一覧 §7.4 のすべて)、指示の混入 (同梱の攻撃の事例) | 失い 0 (S-01) | すべて 0 件 |
| **自己学習の効果** | 学習の前と後の差 (縦断の台と保留の事例、対の検定、§10.1)、縮退の構成でも誤って添える率が上がらないこと、誤った採用の率 (§9.4 の定義) | (未実装) | 採用は有意な改善のときだけ。誤った採用の率 5% 以下 |

### 1.2 物理的な制約 (実測。変えられない)

| 項目 | 実測 | 設計への意味 |
|---|---|---|
| 読み (プロンプトの処理) | Qwen3.5-9B で毎秒 216〜320 トークン (LFM2.5-8B-A1B は 761) | **文脈に足すトークンが、そのまま待ち時間になる** (300 トークンで約 1〜1.4 秒) |
| 生成 | Qwen3.5-9B で毎秒 10〜12 トークン (LFM2.5-8B-A1B は 33.5) | 裏の処理は、LLM に書かせる量が律速 |
| 先頭の一致 | 先頭を変えると 14 秒、変えなければ 1〜2 秒、先に処理しておけば 0.43 秒 (S-13 §3) | 先頭を変えない作りと、先に処理しておく作りが、最大の速度の手段 |
| 候補の収集 | 平均 188 ms・p95 227 ms (v0.3.0、埋め込みは qwen3-embedding-8b、`docs/perf/0.3.0/EVAL-retrieval.json`) | 当たりの経路に入れない |
| リランク | 往復で 5 件 141 ms、10 件 250 ms、30 件 約 900 ms。CPU だけでは 10 件 951 ms (S-13 §5)。時間は本文の長さに比例 | 応答の経路のリランクは 10 件前後まで。入力中に済ませる |
| リランクの単位 | ターンより **往復** が良かった。しきい値の余裕は狭い (関係の無い問いの最大 −3.47、正解の低い値 −3.0) | **関係の判定は往復の単位のまま** にする (今の較正を使える) |
| 型縛りの補助の呼び出し | 1 回 2.3〜6.5 秒 | 応答の経路に LLM の呼び出しを足せない |
| 裏と応答の取り合い | 裏で埋め込みを作る間、応答のプロンプトの処理が 28〜42% 遅くなる | 裏の処理は、利用者が入力・待機していない時間に寄せる |
| ルーターのモデルの入れ替え | 使っていないモデルを降ろし、読み込み直しは chat で 3.6 秒 (S-15) | `memory` の役割に別のモデルを置くと、主記憶の少ない機械で chat の KV が追い出されうる |
| redb の耐久性 | 1,000 回の強制終了・電源断で失い 0。コミット 1〜2 ms | 保存の土台はそのまま使える |

## 2. 性能を上げる 6 つの手段

### 2.1 起点の弱さの原因 (確かめたもの)

| 弱さ | 原因 | 根拠 |
|---|---|---|
| single-session-assistant 3/6 | 添える引用を 1 ターン 400 文字で切っている。外した 3 問は、どれも正解が応答の 431・477・544 文字目にある | `crates/evorag-core/src/recall.rs:34`、oracle のデータと問いごとの結果 |
| multi-session 3/13 | Fire のときに最上位の 1 往復しか添えない。外した 10 問のうち 6 問は数量の合計・差、3 問は件数 | `recall.rs:980-990` |
| abstention 1/3 | 前提が誤った問いに、近い数値を持つ往復が添わって答えた | 問いごとの結果 |
| 引用 1 件で TTFT +1.3 秒 | 往復の全体 (数百トークン) を引用にしている | S-13 §3 |

### 2.2 手段

| # | 手段 | 効く軸 | 中身 |
|---|---|---|---|
| **P1** | **往復で選び、文の窓で詰める** | 速度・正しさ | 関係の判定は今の往復の単位のリランク (較正済み) のまま。添えるのは、上位の往復の中で問いに当たった **文の窓** (問いのときに作る。記録を持たない)。同じトークンで多くの往復を添えられ、応答の後ろのほうにある答えにも届く |
| **P2** | **投機的な先読み** | 速度 | 入力が止まったら、下書きで想起と引用の枠を作り、**履歴 + 引用の枠までを llama-server に先に処理させておく**。TUI を開いたら、すぐに先頭を処理しておく |
| **P3** | **LLM の出力の台帳と、決定論の導出** | 信頼性・学習・速度 | 裏の LLM の生の出力を、区切りごとに台帳に持つ。単位・状態・索引・プロファイルは、台帳と正本 (ターン・利用者の操作) から **全件の決定論の導出** で作る。規則・関門・辞書を変えても、LLM を呼ばずに作り直せる |
| **P4** | **書かせる量を減らす** | 速度 (裏) | 区切りごとに 1 回の呼び出しで、検索の鍵・単位・訂正の判定をまとめる。根拠は文番号で指させる。裏の役割に速いモデルを選べる |
| **P5** | **学習は測れる形で、開発側と利用者側に分ける** | 学習の効果 | 利用者の明示の信号は 1 日に 0〜1 件の見込み (§9.1) なので、利用者の手元の学習だけでは材料が足りない。モデルごとに決まるもの (抽出の変種) は開発側で評価して表を同梱し、利用者の手元では、表に無いモデルの選択と、利用者固有の数値と辞書だけを学ぶ |
| **P6** | **裏の処理を時間で分ける** | 速度 (応答)・学習 | 微小待機・短い待機・長い待機・夜間 (opt-in) の階層 |

### 2.3 検討資料の案の採否 (性能で判断し直したもの)

| 検討資料の案 | 判断 | 性能の理由 |
|---|---|---|
| 区切りごとの 1 回の呼び出し・文番号で指す (C1・追加案 1) | **採る** (P4) | 根拠を写す生成が無くなる。単位の JSON (1 件 30〜40 トークン) と `keys` は残るので、生成の削減は 1/2 前後の見込み |
| 応答も入力に入れる (C2) | **S-17 で決める** (参照専用) | 叙法・時制・照応は良くなりうるが、応答の誤りや貼られた文書の要約に判定が引かれる (§5.1)。応答あり・なしで誤った事実の率を比べてから既定にする |
| モデル別の変種の選択 (C3) | **採る** (P5。開発側で表を作る) | モデルで型縛りの出力の質が違う (LFM2.5 は思考を切る指定と型縛りで空の出力になった、S-13)。同じモデルならどの利用者でも結果は同じなので、開発側で決める |
| `memory` の役割に速いモデル (追加案 2) | **採る** (選べる。**既定は chat と同じモデル**) | 裏の生成が約 3 倍。ただし主記憶の少ない機械では chat の KV を追い出しうる (S-15) |
| 埋め込みとリランカーで前にふるう (追加案 3) | **S-17 で決める** | 取りこぼしの率しだい |
| 夜間の実行 (C6) | **採る** (手動の `evorag sleep` を v0.5、予約実行 (opt-in) と TUI への受け渡しを v0.8) | 重い処理を応答と完全に分けられる。手動の版は受け渡しの危険が無く、裏の処理が終わらない問題への手当てを先に出せる |
| 起動直後の先読み・KV の保存 (C6) | 先読みは **採る** (段階 1)。KV の保存と復元は段階 4 | 保存した KV は忘れるの対象にする作りが要る |
| プロファイル (C7) | **採る** (§6.5) | 常に文脈にある記憶。値は関門を通った短い形だけ |
| 決定論の集計 (件数をコードで数える) | **採らない** → **列挙** | 種類の条件 (「結婚式」) を決定論で組めない。列挙して、数えるのはモデル |
| 道具をモデルに呼ばせる形 (C5b) | **採らない** | 呼ぶ往復の分だけ遅く、暗黙の問いで 4/12 |
| 入力中の小型モデルによる問いの分析 (C5a) | **採らない** | GPU を取り合い、間に合わない率が高い |
| 統合で向きを LLM に判定させる | **v0.8 より後の候補** (既定は決定論) | 判定の出力を台帳に持てば作り直しで呼び直さずに済む。効き目は knowledge-update で測る |
| `experience` 層 | **採らない** | 応答の誤りが想起を経て事実になる循環を作る。single-session-assistant は P1 で取れる |
| 自由記述の属性 | **採る** (`world` にも)。ただし **置き換えとプロファイルに効くのは辞書の属性だけ** | 属性の外の知識も覚えられる。統治の鍵は自由記述の属性に依らない (§7.1) |
| 専用の小型モデルの学習 (C4) | **採らない** (この計画の範囲の外) | 速度が未計測。保守の費用が大きい |

## 3. 応答の経路 (段階 1)

### 3.1 想起 (P1)

1. **問いの分析** (決定論、ほぼ 0 ms): 日付の表現、記憶を明示する問い、件数・合計・一覧の意図。
2. **候補**: 今のチャンクと検索の鍵の語彙とベクトルの索引から集め、RRF で 1 つの順位にし、往復にまとめる (今の 05 §3.3)。件数・合計・一覧の意図がある問いでは、候補と予算を広げる (段階 1 の列挙。単位を使う列挙は段階 2、§6.4)。
3. **関係の判定**: 往復の単位でリランクする (今の較正済みのしきい値と帯を使う)。最上位がしきい値以上なら Fire。2 件目以降は、**2 件目の下限** (しきい値と帯の下限の間。S-17 で決める) 以上の往復も採る。
4. **文の窓で詰める**: 採った往復のそれぞれで、問いに当たった文 (チャンクの中で語彙とベクトルの値が最も高い文) を中心に、前後の文を足した窓を、往復ごとの上限まで作る。表や箇条書きは、見出しの行 (表の 1 行目、箇条の前の文) を窓に足す。同じターンの重なる窓はまとめる。値の高い往復から、想起の予算に入るだけ詰める。
5. **予算は 2 段**: 先読みが当たったときは大きな予算 (既定 800 トークン)、当たらなかったときは小さな予算 (既定 300 トークン) にする (外れたときの TTFT を抑える)。数値は S-17 で決める。
6. **添える直前のふるい直し** (今の 04 §7.2 の「想起の途中」): DB に無い記録・伏せ字の前の改訂の番号・private と `[非表示]` の範囲を、詰めた窓の本文で確かめる。

- 文の区切りの規則を直す: 半角の `.` は、数字に挟まれたとき (「3.5」)、既知の略語 (「Mrs.」「Dr.」)、URL・ドメインの中では区切りにしない (今の `is_sentence_end` は割る)。
- 引用には、出典の番号・セッションの題名・日時・役割 (利用者 / 応答) を付ける。
- 縮退: 埋め込みが無い → 語彙だけで候補。リランカーが無い → 今の v0.1 の規則で 1〜2 件。どれも観測値に理由を残す。

### 3.2 投機的な先読み (P2)

```
入力中 ──(止まる: S-17 で 0.5〜1.5 秒と文末の記号の条件を比べる)──▶
   下書きで想起 → 引用の枠のバイト列を作って保持 (乱数・出典の番号・題名・日時を含む)
   └▶ 「履歴 + 引用の枠」までを、生成 1 トークンで chat のスロットに送る
送信 ──▶ (a) 本文が下書きと同じ: 保持した枠をそのまま使う → 発話の分だけを処理
         (b) 本文が違う: 想起し直す。枠のバイト列のハッシュが同じなら (a) と同じ枠を使う
         (c) 枠が違う: 小さな予算 (§3.1 の 5) で枠を作り直す
     どの場合も、添える直前のふるい直し (§3.1 の 6) は省かない
応答の後 ──▶ 次のターンの先頭 (履歴まで) を先に処理 (今の 05 §4.5)
```

- **当たりの条件**: 枠のバイト列のハッシュ・履歴の始まり (`history_from`)・**先読みの世代の番号** が、どれも同じとき。
- **先読みの世代の番号**: 忘れる・private・削除・プロファイルの差し替えのたびに上げる。古い番号の先読みの結果は捨てる。忘れるでは、スロットのキャッシュの消去を要求する前に、飛んでいる先読みを止めて、止まったことを確かめる。忘れるの間は、入力が止まっても先読みしない。
- **キャッシュの仕組みの確認** (S-17 の 2): Qwen3.5・LFM2.5 は再帰の層を持つ構成の可能性があり、その場合 llama-server は先頭の一致の途中からの再利用を、文脈のチェックポイントでしか行えない (S-13 で `--cache-reuse` は効かなかった)。先読みの打ち切り・外れ・2 段の先読み (次のターンの分 → 引用) で、`timings` の処理したトークン数を測り、全体の処理し直し (7〜14 秒) が起きないことを確かめる。起きるなら、先読みの範囲を「次のターンの分」だけに戻す。
- **外へ出さない**: 下書きは保存せず、ログに出さない。ループバック以外の接続先を許した構成では、役割 (chat・embed・rerank) ごとに判定して、入力中の先読みを切る。電池で動いている間は、電池の設定に従って先読みを減らす・止める。

### 3.3 プロファイルの差し替えの時機

- プロファイル (§6.5) が変わると先頭が変わり、履歴の全体を処理し直す (7〜14 秒)。差し替えるのは、(1) 新しいセッションの始め、(2) 古い発言をまとめて省くとき (どのみち処理し直す)、(3) 履歴が短いとき (目安 1,000 トークン未満)、のどれかに限る。それ以外は次の機会まで待つ。
- 忘れる・private・削除でプロファイルから値を除くときだけは、次のターンで必ず差し替える (待ちを受け入れる)。

## 4. データの形 (段階 2 で作り直す)

保存の仕組み (redb の 5 つの表・封筒・キーの符号化・ジャーナル・退避・原子的な入れ替え) は、耐久性を実測したものなのでそのまま使う。記録の種類を組み直す。

### 4.1 種類

| 種類 | 区分 | 中身 | ジャーナル |
|---|---|---|---|
| `session`・`turn` | 正本 | 今のとおり (改訂の番号を含む)。`turn` の観測値は §4.6 | 書く |
| `signal` | 正本 | 評価・再生成・想起への操作 (添えた・無関係)・`/memory` の操作の記録 | 書く |
| `directive` | 正本 | 利用者の明示の操作と、その結果として足す「終えた出来事」(§7.1) | 書く |
| `setting`・`model_binding` | 正本 | 今のとおり。役割に `memory` を足す | 書く |
| `adoption` | 正本 | 学習の採用の記録 (どの版を使っているか) と、利用者の明示の辞書の操作 (「まとめる」) | 書く |
| `segment` | 派生 | 話題の区切り (§4.2) | — |
| `proposal` | 派生 (台帳) | B2 の 1 回の呼び出しの生の出力 (§4.3) | — (**`Immediate` で書く**、§4.3) |
| `unit` | 派生 (導出) | §4.4 | — |
| `learned` | 派生 | 学習した数値・辞書の中身・選んだ変種 (§9) | — |
| `case` | 派生 | 学習と評価の事例 | — |
| `topic` | 派生 (導出) | 話題の群 (§9.6)。ID は核になる単位の集合から作る。見出しは台帳 (`proposal`) に載せる | — |
| `alias` | 派生 (導出) | 別名の鍵 (§9.9)。正本 (ターンの本文・`obs`・信号) から決定論で導く。根拠の記憶ときっかけの問いのターンへの結び付きを持つ。redb の表に置き、語彙の索引に混ぜない | — |
| `priority` | 派生 (導出) | 記憶ごとの優先度の成分 (§9.7) | — |
| `pin` | 正本 (`directive` の `op`) | 利用者が「重要」とした記憶 (単位の ID は中身から作るので安定する) | 書く |
| `note_confirmed` | 正本 (`directive` の `op`、v0.8 の条件付き) | 利用者が確かめた気づき: 確かめた文そのものと根拠の単位の ID。根拠を忘れたら一緒に消える | 書く |
| `instruction` | 正本 (v0.8) | 利用者が書く常設の答え方の指示 (§9.10) | 書く |
| `chunk`・`embedding`・`job`・`quarantine`・`model_probe` | 派生 | 今のとおり | — |

- 正本は DB とジャーナルの 2 か所に持つ (データを失わないため)。
- 今の `fact`・`correction`・`note`・`fact_directive`・`threshold`・`recall_feedback` は無くなる。

### 4.2 区切り (`segment`)

- 区切りは安定した ID を持つ記録にする。大きさは **モデルに依らない見積もり** (文字数と往復の数。上限は、生成の速さの実測から、1 回の呼び出しが短い待機の中で終わる量にする。S-17 の 4) で決める。
- セッションの往復を古い順に詰め、上限に達したか、最後のターンから 10 分過ぎたら **閉じる**。閉じた区切りは変えない。開いている末尾の区切りに往復が足されたら、その区切りの台帳を置き換える。
- 区切りの境界はモデル・変種で変わらないので、台帳を替えても区切りが揃う。

### 4.3 台帳 (`proposal`)

| 項目 | 内容 |
|---|---|
| `segment` | 区切りの ID |
| `sentences` | 文番号 → `{turn, rev, start, end}` の対応表 (台帳だけで導出できるように) |
| `inputs` | 入力を決めた版: 前のふるいと文の分割の規則の版、訂正の字句の型の版、見えていた最新の忘れるの指示の ID (`forgets_seen`)、`input_hash` |
| `variant`・`model_key` | プロンプトの変種と、使ったモデル |
| `output` | 節ごとに型が合った部分 (`keys`・`units`・`corrections`)。合わなかった節は理由だけ |
| `tokens` | 入力と出力のトークン数、時間 |
| `scrubbed` | 忘れる・private で取り除いた要素の数 (§7.2) |

- **有効な台帳**: `sentences` のすべての `{turn, rev}` が今と合い、`inputs` の版が今と合うもの。
- **使う台帳の選び方** (区切りごとに 1 つ): 今の選択 (採用の記録の変種とモデル) に合う最新の有効な台帳。無ければ、直前の選択に合う最新の有効な台帳。縮退で別のモデルを使った台帳は「直前の選択」として扱う (役割が戻るたびに作り直しが揺れないため)。
- **耐久性**: 台帳は失うと同じものが戻らず、作り直しは高い (LLM を呼ぶ)。区切りごとに `Immediate` で書き、退避と書き出しに含める。直前の選択の台帳は、次の採用が落ち着くまで (§9.5) 残す。
- 台帳は忘れた値・private の値を含みうるので、忘れる・private で **掃除する** (消さない。§7.2)。

### 4.4 単位 (`unit`)

| 項目 | 内容 |
|---|---|
| `id` | **中身から作る** (`layer`・`entity`・`aspect`・`vk` のハッシュ)。作り直しても同じ ID になる |
| `layer` | `world` (置き換えのある事実) / `episode` (出来事。置き換えない) |
| `entity` | 主語。`self` か、呼び名を正規化した文字列 (今の 04 §5.1 の規則) |
| `aspect` | **辞書の属性** (同梱。今の 20 属性から始め、版を上げて足す) か、**自由記述の属性** (候補の文字列を正規化したもの、40 文字まで) |
| `value`・`vk` | 根拠の文の部分文字列と、その値の鍵 (今の 04 §5.6 の正規化と HMAC) |
| `when` | `{from, to, basis}`。相対表現 (「先週」) は、**発話のターンに記録した UTC からのずれ** で解く (導出の時点のタイムゾーンを使わない。ターンに UTC からのずれを記録する項目を足す) |
| `tense`・`state`・`against`・`by` | `world` だけ。今の 4 状態と同じ規則 |
| `anchors` | 根拠の文の範囲と、値の位置の範囲 (`{turn, rev, start, end}`) の並び |
| `private` | 指示から導いた値 |

- 副索引: (entity, aspect)、`vk`、日付、出典のターン。private・Retracted の単位は `vk` と日付の副索引を持たない。

### 4.5 索引

- チャンクの語彙とベクトルの索引は今の形のまま (段階 1 も段階 2 も)。文の窓は問いのときに作るので、索引にしない。
- 単位の索引: 単位の `value`・自由記述の `aspect`・`entity` を語彙とベクトルに。単位は根拠のターンを指す (添えるのは窓の原文)。導出の結果が変わったら作り直して入れ替える (古いフォルダは消す)。

### 4.6 ターンの観測値 (段階 1 から足す)

段階 1 では、今の `turn` の観測値 (`TurnObs`) に任意の項目を足すだけ (今のデータの形のまま)。

| 項目 | 内容 |
|---|---|
| `candidates` | リランクした往復の ID と生の値 (上位 30 件まで)、融合の順位と由来 (語彙・ベクトル・鍵)、リランカーの model_key |
| `packed` | 詰めた窓の ID `{turn, rev, start, end}` (安定した形)・トークン数・使った予算と下限の版 |
| `query` | 問いの分析の結果 (日付・明示・件数の意図)、列挙だったか |
| `prefetch` | 当たり (a)・(b)・(c) のどれか、TTFT、処理したトークン数 |
| `tz_offset` | 発話のときの UTC からのずれ (分)。相対の日付 (「先週」) を後から正しく解くため。後から埋められないので v0.4 から記録する (今のコードには無い) |
| `rephrase` | 直前の問いで目当ての記憶が候補に無く、この問いで引けたときの、前の問いのターンの ID (別名の鍵の材料、§9.9) |
| `idle` | 前の発話から今の発話までの無操作の時間と、終了のときの裏の処理の残りの件数 (裏の処理が実際の使い方で終わるかを測る) |
| `profile` | プロファイルのバイト列のハッシュ |
| `versions` | 想起・文脈・学習した数値・変種・利用者の指示の版 |
| `degraded` | 縮退の理由 |

- 下書きの本文は記録しない。
- 段階 2 の取り込み (§4.7) で、観測値と信号を引き継ぐ。

### 4.7 段階 1 のデータからの取り込み (`import-v04`)

- 段階 2 (新しい形) は、段階 1 (v0.4) のデータ根からの一度きりの取り込みを持つ (会話を失わないことは信頼性の一部)。
- 取り込むもの: セッション・ターン (伏せ字の後の本文と改訂の番号)・信号・想起への操作・観測値・設定・モデルの記録・`memory.forget_key`・**`fact_directive` のすべて** (忘れる・private・private の解除・採る・戻す・印を解く。伏せ字の記録と `[非表示]` の範囲を含む)。
- 取り込まないもの: 事実・ノート・訂正・埋め込み・索引 (新しいエンジンで作り直す)。
- 忘れるの当て直しが残っている (`forget.recheck` が立っている) データ根は、断って、v0.4 で一度起動するよう案内する。
- v0.3 のデータ根は、v0.4 で一度開いてから取り込む (v0.4 は v0.3 の形のままなので開ける)。

## 5. 書き込みの経路 (段階 2)

### 5.1 1 回の呼び出し (B2)

- 閉じた区切り (と開いている末尾) ごとに、型縛りの呼び出し 1 回で次を出させる。
  - `keys`: 検索の鍵 (8 個まで)
  - `units`: `{s: 文番号, l: 層, e: 主語, a: 属性, v: 値, m: 叙法, tn: 時制, old: 置き換える値, when: 日付の表現}`
  - `corrections`: 字句の型 (決定論で見つけた訂正の候補) ごとの判定
- 利用者の発話の文に区切りの中で番号を振る。応答を入れる場合 (S-17 で決める) は `[参照のみ]` の枠に入れ、番号を振らない。
- 忘れるの `[非表示]` の範囲は伏せて渡す。private の値は伏せずに渡す (§7.3 で導出の時点にふるう)。
- 指示・辞書・型の説明はバイト列まで同じにし、裏のスロットのキャッシュを使い回す。既存の単位はプロンプトに入れない。
- **止められたとき**: 利用者の操作で 1 秒以内に止める。ストリームの途中で完結した要素を採って台帳に「途中まで」と記すかを、S-17 の 4 で比べる (区切りが長いと、止められては捨てるを繰り返すため)。

### 5.2 検証 (B3)

- 今の関門 1〜8 を、文番号で指した根拠に当てる。足すもの: 文の範囲 (利用者の発話の文だけ)、主語の一致、極性、数字の組、自由記述の属性 (40 文字まで、関門 6)、`keys` にも関門 6 (指示に読める語句を捨てる)。
- **機微な情報のふるい**: 健康・病気、宗教、政治、性的指向、正確な住所のカテゴリ (同梱の規則) の候補を捨てる。
- **辞書の写しは関門の前に**: 自由記述の属性を辞書の属性に写せるときは、写した後の属性の宣言 (手がかりの語・主語の許し・長さの上限) で関門を当て直す (写しで属性ごとの関門を迂回させないため)。

### 5.3 導出 (B4)

- **全件の導出を定義にする**: 入力 (使う台帳の候補で B3 を通ったもの・指示・辞書・規則の版) が同じなら、結果が同じ。増分の導出は、S-17 の 6 で全件の導出が遅い (単位 1 万件で数秒を超える) と分かったときだけ、全件と同じ結果になる最適化として足す (到着の順を乱しても同じ結果になることを性質の試験で確かめる)。
- **導出の指紋**: 使った台帳の ID の集合・指示の最大の ID・辞書の版・規則の版のハッシュを、単位と同じトランザクションに書く。起動時に合わなければ、全件を導き直す。
- 畳みの規則は今の 04 §5.3 (置き換えの条件・`Contested`・多値の `old`・時制・否定・訂正の向き) を使う。単位の ID は中身から作るので、繰り上げ・並びの決め手が作り直しで揺れない。
- 置き換えの鍵は (entity, aspect) で、**辞書の属性の単位だけ** が置き換えの対象。自由記述の属性の単位は多値として日付つきで並べる。
- 候補は、根拠のターンで区切りに帰属させる (同じターンの候補が 2 つの台帳から来ない)。
- 導出の結果が変わったら、単位の索引を作り直し、プロファイルを §3.3 の時機で差し替える。

## 6. 読み出しの経路 (v0.6 で足すもの)

### 6.1 単位を使う候補

- 単位の索引 (§4.5) を候補の由来に足す。単位で当たったら、根拠のターンの往復を候補にする (関係の判定は往復の単位のまま)。

### 6.2 当たった文の決め方

- 単位が当たったときは、その根拠の文を窓の中心にする (段階 1 の「チャンクの中で値の高い文」より正確)。

### 6.3 日付

- 窓の見出しに、単位の `when` (出来事の日付) を付ける。

### 6.4 列挙

- 件数・合計・一覧の意図があり、日付か entity が決まる問いでは、`current` の単位を副索引で引き (上限 200 件)、単位の `value`・`aspect` を問いに対してリランクし (上位 30 件まで)、**列挙用のしきい値** (往復のしきい値とは別に較正する) 以上の単位の根拠の窓を、日付の順に並べて添える。数える・足すのはモデル。
- 対象は `world` の Live・Superseded (日付つき) と `episode`。private の単位は件数にも入れない。`Contested` の値は、両方を並べて食い違うことを示す。
- 話題のまとめ (§9.6) があれば、まとめの単位の一覧を列挙の候補に足す。
- `episode` は置き換えないので、同じ出来事の言い直しは別の単位になりうる (同じ日付・同じ値の鍵はまとめる。言い換えは二重に数えうる。§14)。
- 予算に入らない件は、件数だけを示す。

### 6.5 プロファイル

- システムプロンプトに、辞書の属性の `world` の単位 (Live・private でない) を「属性: 値」の表で置く (予算 600 トークン)。並びは属性の順 → entity → 値の鍵 (中身で決まる順。作り直しで揺れない)。
- 自由記述の属性・出来事は入れない (指示の混入と誤った今の値を、信頼する枠に入れないため)。

## 7. 統治 (忘れる・private)

### 7.1 指示 (`directive`)

| `op` | 持つもの | 当て方 |
|---|---|---|
| `forget` | 忘れた値の値の鍵と照合の鍵の並び (`vks`)、entity とその時点の別名、属性 (辞書の属性なら名前、自由記述なら HMAC)、再び覚えない印、伏せ字の記録、`[非表示]` の範囲 | **値の鍵と entity の同値類で当てる。自由記述の属性では属性を見ない** (属性の揺れで当たらなくなるのを防ぐ。止めすぎは `unblock` で解ける) |
| `end` (自動で足す) | entity、aspect、終えた位置 (忘れた・消した単位の最も新しい根拠のターンの ID) | 導出で、その位置で今の値を終える (忘れた値の前の値を Live に戻さない。今の `Retracted` と繰り上げの規則 (OQ-49) を、値を持たずに表す)。忘れると、セッションの削除で足す |
| `private` | `vks`、entity、属性、根拠の位置 (ターンと値の範囲)、効く範囲 | 値の鍵 **か** 根拠の位置のどちらかで当てる。「後継まで」は辞書の属性だけ (自由記述は「この値だけ」) |
| `accept`・`revert` | `vk`、entity、属性、根拠の位置 | 根拠の位置で当てる。無ければ値の鍵で、同じ競合の組にあるときだけ |
| `unblock` | 対象の `forget` | 印を当てない |

- 指示は追記だけで、DB とジャーナルの 2 か所に持つ。自由記述の属性は指示と辞書の中では HMAC で持つ (属性の名前が値に近い内容を含みうるため)。
- **削除と private**: セッションの削除で出典が外れて「後継」でなくなる値には、今のとおり「この値だけ」の private を同じトランザクションで足す。

### 7.2 忘れるの手順

1. 計画を作る (伏せ字にするターンと範囲、消える単位、影響するほかの単位の見本)。画面が見本を確かめ、計画のハッシュを添えて実行する。生成中と、ほかの忘れるの途中は受け付けない。
2. 飛んでいる先読みを止め、先読みの世代の番号を上げる (§3.2)。
3. 1 つのトランザクションで:
   - 指示 (`forget` と `end`) を書く (ジャーナルが先)。
   - ターンを伏せ字にして改訂の番号を上げる (伏せ字にするとき)。
   - **すべての台帳を掃除する**: 根拠が伏せ字の範囲に掛かる要素、`v`・`old` が `vks` に当たる要素、`keys` のうち語句か部分文字列の値の鍵が `vks` に当たるものを除き、残った要素の位置を今の位置の写し直しの関数で直す。区切りのほかの単位は残る (LLM を呼ばない)。伏せ字にしないときも掃除する。
   - 導出し直す (全件)。単位の索引の作り直しの job、退避の写し直しの job、`compact.pending` を書く。
4. コミットの直後に、索引から除き、llama-server のスロットのキャッシュの消去を要求する。
5. 退避の写し直し (今の 03 §7.3 の手順)。

### 7.3 private の手順

- 指示を書き、導出し直す。`keys` の private のふるいは **導出の時点** に行う (台帳を作った後に private にした値も除く)。単位の索引を作り直し、プロファイルを差し替え (§3.3 の例外)、先読みの世代の番号を上げる。

### 7.4 消す・伏せる置き場所の一覧

| 置き場所 | 忘れる | private |
|---|---|---|
| ターンの本文 | 伏せ字 (選んだとき) | 想起で `[非表示]` |
| 台帳 (すべての選択の台帳) | 掃除 | `keys` を導出の時点でふるう |
| 単位・単位の索引・単位の埋め込み | 導出し直して除く | 導出で印。索引から除く |
| プロファイル | 次のターンで差し替え | 同じ |
| 学習の事例 (`case`)・辞書 (`learned`) | 忘れた値を含む事例を消す。忘れた単位だけに支えられた辞書の写しを消す | 事例のリプレイで `[非表示]` |
| 話題の群・時系列 (§9.6) | 導出し直す (同じトランザクション) | 導出で除く |
| 話題の見出しの台帳 (§9.6) | 忘れた値の値の鍵に当たる語を掃除する | 見出しを検索の鍵に足すときにふるう |
| 確かめた気づき (`note_confirmed`) | 根拠の単位を忘れたら、指示を無効にして文脈・`/memory` から除く (指示は追記だけなので、ジャーナルの書き直しで文を除く。04 §7.2 と同じ形) | 根拠に private を含むものは文脈に入れない |
| 別名の鍵 (§9.9) | 語句か部分文字列の値の鍵が `vks` に当たる別名をすべて消す (別の記憶に付いたものも)。きっかけの問いのセッションを消したら、その問いから足した別名を消す | 導出の時点でふるう |
| 優先度 (§9.7) | 忘れた記憶のものを消す | 効かない (private の記憶は優先度に関わらず除く) |
| `quarantine` | 対象の ID を消す | — |
| 先読みの結果・スロットのキャッシュ | 世代の番号で捨てる・消去を要求 | 世代の番号で捨てる |
| 退避 | 写し直し | — |
| 観測値 | ID と値の数値だけなので対象外 (本文を持たない) | — |

- 約束しない範囲は今の 04 §7.8 を保つ (利用者が書き出したファイル、OS のバックアップ、llama-server の主記憶のキャッシュ、言い換え・表記の違い)。
- 守りの試験に、「忘れる → 全件の導出 → 忘れた値の前の値が Live でない」「伏せ字にしない忘れる」「別の区切りの同じ値」「後から private」「辞書の採用の前後で指示が当たる単位の集合が縮まない」を入れる。

## 8. 段取り (B10)

| 階層 | きっかけ | 仕事 |
|---|---|---|
| 即時 | ターンの確定 | チャンク、語彙の索引 |
| 微小待機 | 入力が止まる (§3.2) | 投機的な先読み |
| 応答の後 | 応答を書き終えた | 次のターンの先頭の先読み |
| 短い待機 | 60 秒の無操作 | 埋め込み、区切りごとの B2 → B3 → 導出、索引 |
| 長い待機 | AC 電源で 10 分の無操作 | 台帳の作り直し (変種・モデルを替えた後)、学習の候補の評価 (§9) |
| 夜間 (opt-in) | OS のタスクスケジューラ | 全件の作り直し、話題の見出しと気づきの提案の生成、学習の候補の評価。**採用はしない** (候補を作るところまで。次に TUI を開いたときに知らせてから採る) |

- どの階層も、利用者が操作したら 1 秒以内に止め、続きから再開する。
- **手動の実行** (`evorag sleep`、v0.5): 前景で裏の処理を最後まで流す。TUI と同じくデータ根のロックを取るだけなので、受け渡しの危険が無い。話し終えてすぐ閉じる使い方で裏の処理が終わらないときの手当て。
- **夜間の実行** (`evorag sleep --until <時刻>`、v0.8): 既定は無効。setup で明示して登録する。TUI と同時に動かさない。TUI を開いたら、夜間の実行は 1 秒以内に止めてロックを放す (強制終了しても安全な受け渡しの手順を作り、守りの試験に入れる)。evorag は llama-server を起動しない。AC 電源のときだけ動く。

## 9. 自己学習 (B11)

### 9.1 材料の量と、学習の置き場所

- 利用者の明示の信号 (「無関係」・帯から添える・`/good`・`/bad`) は、1 日に 0〜1 件の見込み (発話 20〜40、Fire 1〜3 割から【推測】)。しきい値の決め方 (関係の無い問いの 9 割の点、S-14) には負例だけで 20〜30 件以上が要るので、**利用者の明示の信号だけでは、学習が成り立つまで数か月かかる**。段階 0 で、手元の v0.2・v0.3 のデータ根から実際の信号の率を数える (件数だけ。本文は見ない)。
- そこで、学習を次のように分ける。

| 置き場所 | 対象 | 材料 | 効き目の見込み |
|---|---|---|---|
| **開発側** (表を同梱する) | 抽出の変種 × モデルの組の選び方、想起の数値の既定 (リランカーごと)、列挙のしきい値 | 同梱の事例 (正解つき)・保留の問い | 大きい (どの利用者にも効く) |
| 利用者側・段 1 | 想起の数値 (2 件目の下限・予算) の利用者への合わせ込み | 観測値と信号、自動のラベル (§9.2) | 小〜中 (材料がたまってから) |
| 利用者側・段 2 | 表に無いモデルの変種の選択 | 同梱の事例 | 表に無いモデルでだけ |
| 利用者側・段 3 | 辞書 (自由記述 → 辞書の属性、entity の別名) | 同じ値が別の属性の名で繰り返し出る頻度 (自動)、利用者の「まとめる」 | 中 |
| 利用者側・段 4 | 既定の切り替えの提案 (§9.10。自動で指示の文を作る precept は採らない) | `/bad` の理由・`/retry` | 小 (材料が 1 日 0〜1 件) |
| 開発側 | 応答の指示の変種 (モデルごと、§9.10) | 同梱の事例 | 中 (どの利用者にも効く) |
| 利用者側・整理 (§9.6) | 時系列・決定論のつながり・話題の群と見出し | 単位と区切り (材料は毎日たまる) | 中〜大 (multi-session・temporal の問い、列挙、`/memory` の見やすさ) |
| 利用者側・優先度 (§9.7) | 記憶ごとの優先度 (詰める順と、同じ属性の中の選び方) | 言及の数・`pin`・明示の対 | 小〜中 |
| 利用者側・別名の鍵 (§9.9) | 言い方の違う問いと記憶を結ぶ別名 | 明示の対・言い直して引けた問い | 中 (言い方の違う問いが引けるようになる) |
| 利用者側・気づき (§9.8、条件付き) | 利用者が確かめた一段上のまとめ | 単位と話題の群 | 不確か (測る問いが無い。効き目が見えたときだけ有効) |

- 整理・優先度・別名の鍵は、毎日の会話から材料がたまる。そのため、利用者の手元の学習の効き目の主役はこの 3 つになる見込み。どれも **正本 (ターンの本文・観測値・信号・指示) からの決定論の導出** にし、機能ごとに切れる設定を置く (切った版と対で比べ、巻き戻せるようにするため)。
- 「記憶の重み」の名前は、モデルの重み (学習しない) と紛らわしいので、本書では **優先度** と呼ぶ。

### 9.2 ラベル

- 明示の信号 (「無関係」・添えた・`/good`・`/bad`) を正のラベルにする。「無関係」は **問いと記憶の対** の印 (その問いに関係が無い) で、記憶そのものの印ではない。
- 自動のラベル: 応答の本文と添えた窓の語の重なり (使われたか)、応答が示した引用の番号 (`cited`)。**記録するだけ** にし、記憶ごとの状態 (優先度・別名の鍵) を動かすのに使わない。前提の誤った問いに近い記憶が添わって誤答したときも「使われた」になるので、誤りを強める向きに働くため (v0.3.0 の abstention の失敗の形)。全体の数値の学習に使うのは、S-18 (§11.3) で同梱の事例の正解との一致率を測り、問いと履歴の語を除いた重なり・飽和 (log)・その後に `/bad`・`/retry`・「無関係」が無いことを条件にしてからにする。
- 目的の式には、正しさの項に加えて TTFT と誤って添える率の罰を入れる (緩める側にだけ動かないため)。

### 9.3 評価の方法

- **反実仮想の評価は候補を出す道具に限る**: 記録した候補と値から計算できるのは、しきい値と 2 件目の下限を記録の範囲で動かすときだけ。候補の数・窓の大きさ・予算は記録だけでは評価できないので、開発側の同梱の事例でだけ決める。
- **採否は正解つきの事例で決める**: 同梱の事例と、利用者の明示の操作から作った保留の事例 (時刻で分けた、学習に使っていないもの)。
- **改善の判定**: 事例ごとの結果の対の検定 (符号検定・McNemar)。最小の件数と最小の差を決める (決定論の評価では同じ版を 2 回流しても差は 0 なので、揺れは事例の標本の側で測る)。
- 段 2 (変種) の採点は、(根拠の文, 値の鍵, 層, 叙法, 時制, entity) の一致で取り、属性は辞書の属性だけ比べる。誤った単位を取りこぼしより重く数える。指示の混入と機微の事例は 1 件でも通したら不合格。同梱の安全の回帰事例を、どの段の評価でも必ず流す。

### 9.4 誤った採用を防ぐ

- 誤った採用の率: 保留の事例を再標本化 (ブートストラップ) して、改善の判定が偶然に通る率。5% を超える条件の判定では採らない。
- 評価の回数に上限を置く (1 日の候補の評価の回数)。保留の事例を採否に使う回数を限り、使い切ったら新しい期間の事例を待つ。
- 1 回の変化の幅と、同梱の既定からの累積の幅に上限を置く。
- 採用の後に、誤って添える率・TTFT・`/bad` の率を見て、悪くなったら自動で戻す。
- **一度に 1 つの段だけ採用する**。上流 (辞書・変種) を採用したら、下流 (想起の数値) の材料を `versions` で採用の後のものに絞る。

### 9.5 採用と巻き戻し

- 始めは **すべての段を承認制** にする (評価の定義と自動の巻き戻しが実データで働くことを確かめるまで)。段 1・3 は、v0.7 の判定で誤った採用の率が目標を満たしたら、自動にできる設定を足す。
- 採用の記録は正本 (`adoption`)。巻き戻しは 1 回の操作 (`/learned rollback`)。利用者の明示の「まとめる」は指示として持ち、学習の巻き戻しで消えない。
- 頻度から作った辞書の写しは、承認されるまで、置き換えとプロファイルに効かせない (検索と列挙のまとめにだけ使う)。
- 採用の前に「採用の前後で、指示が当たる単位の集合が縮まない」ことを決定論で確かめる (縮むなら採らない)。
- 学習の結果の持ち方: 想起の数値はリランカーの model_key ごと (しきい値はリランカーの目盛りで決まる)、予算は chat の model_key ごと、変種は `memory` の役割のモデルごと、辞書はデータ根ごと、応答の指示の変種と既定の切り替えは chat の model_key ごと。

### 9.6 記憶の整理 (時系列・つながり・話題の群)

会話を、利用者が後から引きやすい形に並べ直す。**整理した結果はすべて派生** で、単位からの決定論の導出か、台帳に載せた LLM の出力からの導出にする (§4.3・§5.3 と同じ形。忘れるは導出のし直しで当たる)。**LLM に自由な文を書かせて文脈に入れることはしない** (言い換えが値の鍵で当てる忘れる・private をすり抜けるため)。

| 整理の形 | 中身 | 作り方 | 使い方 | 版 |
|---|---|---|---|---|
| **時系列** | entity・話題ごとの出来事の並び | 単位の `when` から決定論で作る | 「いつ」「その後どうなった」の問い、列挙の並び、`/memory timeline` | v0.6 |
| **決定論のつながり** | 同じ entity・同じ日付・同じ区切りの単位どうしの関係 | 単位の副索引から決定論で作る (記録を持たない) | 列挙の候補を広げる (上限つき)。リランクの候補の枠には足さない (候補を増やすと質が落ちた、S-13 §5) | v0.6 |
| **話題の群** (`topic`) | 複数のセッションにまたがる 1 つの話題の、単位と区切りの一覧・期間 | 単位と区切りの埋め込みの群を決定論で作る。話題の ID は核になる単位の集合から作る (作り直しで揺れない) | `/memory` の目次、列挙の候補 | v0.6 |
| **話題の見出し** | 群に付ける短い名前 (「引っ越し」) と、群の中から選んだ代表の単位の ID の並び | 長い待機・夜間に、LLM には **見出しと単位の ID の選択だけ** を出させ、台帳に載せる。要点の行は、選んだ単位から決定論で描く (entity・属性・値・日付) | `/memory` の目次。見出しは検索の鍵にも足す (関門 6 を当てる)。文脈に入れるのは、描いた行 (決定論の文) だけで、測って効き目が見えてから | v0.7 |
| LLM が提案するつながり (原因と結果など) | — | — | 決定論で確かめる方法が無いので、**採らない** (後の版の候補) | — |

- **作り直し**: 単位が増えた・消えたら、関わる群・時系列を導出し直す (LLM を呼ばない)。見出しは、群の核が変わったときだけ次の長い待機で作り直す。
- **忘れる・private・削除**: 群・時系列・描いた行は単位からの導出なので、導出し直せば同じトランザクションで当たる。見出しの台帳は、忘れた値の値の鍵に当たる語を掃除する (§7.2 と同じ)。
- **プロファイルには入れない**。

### 9.7 記憶の優先度

記憶ごとに優先度を持ち、詰める順と、プロファイルで同じ属性の中から選ぶ値に使う。**優先度は関係の判定 (リランクの値としきい値) を覆さず、候補を足すことにも使わない** (候補を足すと、リランクの無い縮退の構成では語彙の比だけで Fire してしまうため。`crates/evorag-retrieval/src/recall.rs:167-173`)。

| 成分 | 材料 | 採るか |
|---|---|---|
| 言及の数 | 同じ単位を言い直した回数 (根拠の数) | 採る (導出) |
| `pin` | 利用者の明示 (`/memory pin`) | 採る (正本の指示) |
| 明示の対 | 帯から添えた (正)・「無関係」(負)。**問いと記憶の対** として持ち、近い問いでだけ効かせる (1 回の「無関係」で、すべての問いでその記憶を下げない) | 採る (v0.7) |
| 新しさ | 最後に言及した日時からの経過 | 今と同じく **同点の決め手だけ**。`world` の今の値 (Live) は経過で下げない (古くても正しい。有効かどうかは置き換えが表す) |
| 使われた回数 (自動のラベル) | — | **採らない** (記録だけ。§9.2) |
| B2 が付ける重要度 | — | **採らない** (記録だけ)。9B 前後のモデルの付け方は未計測で、「とても大事」と書いた文で上げられる |

- **使い方**: (1) 詰める順: しきい値を越えた往復の中で、値の差が「しきい値と帯の下限の差」の一定の割合より小さいときだけ、優先度の高い方を先に詰める (リランカーごとに値の目盛りが違うため、S-14)。(2) プロファイル: 属性の優先の順は保ち、同じ属性に多値があって予算を超えるときに、優先度の高い値から入れる。優先度は差し替えの時点で固定し、導出の指紋に入れる (プロファイルを台帳・指示・辞書だけの関数に保ち、先頭を揺らさないため)。
- **守り**: 優先度は忘れる・private に効かない。関門 (B3) に使わない。

|---|---|---|---|
| **気づき** | 複数の記憶から言える、利用者についての一段上のまとめ | §9.10 の「気づきの提案」 | v0.8 (条件付き) |
| **進行中のことの状態** | 利用者が続けていることの今の段階 | 先に、予定の単位 (`planned`) と最近の話題の群を、決定論で `/memory` に出す。LLM が書く状態は後の版の候補 | 決定論の表示は v0.6 |
| **答え方の型** | うまくいった応答と `/bad` になった応答の差から作る手順 | **採らない**。§9.10 の開発側の応答の指示の変種と、利用者の指示に役目を移す | — |

### 9.9 フックの語 (記憶を引く手がかり) の更新

記憶を引く手がかりを性質で分ける。**想起の手がかり (別名の鍵) は、明示の信号と、言い直して引けた問いからだけ足す。覚え方と守りの手がかりは自動では変えない。**

| 手がかり | 更新 | 版 |
|---|---|---|
| **別名の鍵** (問いの語 → 記憶) | **会話中に足す**。ただし、足すきっかけは (1) 帯から添えた (明示の対) と、(2) 言い直して引けた問い (前の問いの `obs.candidates` に目当ての記憶が無く、続く問いで引けて、`/bad`・`/retry`・「無関係」が無かった) の 2 つだけ。「引けて使われた」問いの語は、すでにその記憶を引けた語なので足さない (伸びしろが無い) | v0.7 (v0.4 から材料を記録) |
| 学習時の鍵の作り足し | **利用者側では行わない**。開発側で、B2 の `keys` の変種 (記憶が答えられる問いを書かせる形など) を、候補の再現率で比べて表に入れる | 開発側 (v0.6〜) |
| 当たらない鍵を外す | **行わない** (まれにしか引かない古い記憶の再現率を下げるため。鍵の費用はほぼ無い)。外すのは害のあった別名 (負の対を生んだもの) だけ | — |
| **entity の別名** | 学習の段 3 (辞書)。「○○って妻のことね」の型を決定論で見つけて候補にし、承認で採る | v0.7 |
| **問いの分析の語** | 引けなかった問いの語を候補にし、同梱の事例で確かめて足す (承認制) | v0.7 |
| **覚え方の手がかり** | **自動では変えない**。関門で捨てた候補のうち利用者が後で採ったものから候補を作り、開発側で確かめて同梱する | 開発側 |
| **守りの語** | **学習の対象にしない** (B3 の約束) | 開発側 |

- **置き場所**: 別名の鍵は、語彙の索引に混ぜず、redb の小さな表に置き、正本 (ターンの本文・`obs`・信号・指示) から決定論で導く。語彙の索引に既存の ID で足すと全体を書き直し (`crates/evorag-index/src/lex.rs:502-532`)、文書の長さの平均 (BM25 の `avgdl`) も変わるため。忘れると同じトランザクションで消せる。
- **使う場面**: リランクが働いたターンでだけ候補に使う。リランカーが無い・遅い・締切切れの縮退では使わない (語彙の比だけで Fire するため)。
- **足す語の取り方**: 前のふるいの後の本文から、貼り付けの範囲・コードブロック・引用の行を除いて取る (貼られた攻撃者の文の語を鍵にしない)。追い質問の指示語と、ありふれた語は取らない。関門 6 を当てる。private・忘れた記憶には足さない。
- **忘れる・private・削除**: 語句か部分文字列の値の鍵が忘れるの `vks` に当たる別名をすべて消す (別の記憶に付いたものも)。private は導出の時点でふるう。きっかけの問いのセッションを消したら、その問いから足した別名を消す。
- **速さ**: 応答の後に redb の表へ書くだけで、要求の先頭を変えないので、応答の速さに影響しない。

### 9.10 答え方の学習と気づき (旧 precept・答え方の型・気づきの見直し)

旧計画の precept (失敗の事例から、LLM が答え方の短い指示を作って学ぶ) は、実測と材料の量から見て、v0.8 までの費用に見合わない。

| 根拠 | 内容 |
|---|---|
| 効き方 | 本体の指示と食い違う指示は効かなかった (12 件中 0 件)。同じ文言でもモデルで 6/6 と 3/6 に割れた (S-13 §7) |
| 材料 | 失敗の材料 (`/bad` の理由・`/retry`) は 1 日 0〜1 件の見込み (§9.1)。提案のきっかけ (失敗 3 件) にも、保留の事例にも足りない |
| 費用 | 2 段目のリプレイは 1 回 1 時間前後 (旧 13 §10)。採用のたびに先頭が変わり、履歴の処理し直し (7〜14 秒) が起きる |
| 危険 | LLM が作る指示の文は、システムプロンプト (信頼する枠) に入る。事例の本文を経由した指示の混入の経路になる |

そこで、答え方を良くする手段を次の 4 つに置き換える。

| 手段 | 中身 | 場所 | 版 | 条件 |
|---|---|---|---|---|
| **応答の指示の変種** (開発側) | 凍結の核と、選べる既定の文の言い回しを、モデルごとに数個の変種で持ち、同梱の事例 (答え方の守り・引用の扱い・答えない判断・日本語の自然さ) で採点して、モデルごとの表を同梱する | 開発側 | v0.6 の開発側の表に足す | 安全の回帰事例が 1 件も悪化しない変種だけを表に入れる |
| **利用者の指示** (`instruction`) | 利用者が自分で書く、常設の答え方の指示 (「回答は箇条書きで」「専門用語には説明を付けて」)。`/instructions add・list・remove` | システムプロンプトの precept の枠 (500 トークンまで) | v0.8 (必須) | 正本 (DB とジャーナル)。利用者の文なので学習のゲートは要らないが、本体の安全の指示を打ち消す言い方 (同梱の規則) と URL は決定論で断る。足した・消したときの差し替えは §3.3 の時機 |
| **既定の切り替えの提案** | `/bad` の理由・`/retry` から、選べる既定 (長さ・書式・言語) の切り替えを提案する (例: 「長すぎる」が続いたら「短め」)。選択肢は同梱の文だけで、LLM は文を作らない | 利用者側 (承認制) | v0.8 (条件付き) | 理由の語の型 (同梱の規則) で決定論に判定する。同じ向きの信号が 3 件以上たまったときだけ提案し、利用者が承認して切り替える。既定で有効にする条件: S-18 で、作った筋書きの提案が意図と合う率 8 割以上 |
| **気づきの提案** | 複数の記憶から言える、利用者についての一段上のまとめ | 利用者側 (opt-in・承認制) | v0.8 (条件付き) | 下の通り |

**気づきの提案の仕様** (条件付き):

- **作る**: 夜間 (予約実行) か手動の `evorag sleep` で、話題の群ごとに LLM が 1 件まで提案する。根拠の単位を 2 つ以上 ID で指すことを必須にし、根拠が無い・private・忘れた単位を指す提案は捨てる。提案の生の出力は台帳 (`proposal`) に載せる。
- **見せる**: `/memory insights` に「確認待ち」として、提案の文と根拠の単位の行 (決定論で描く) を並べる。**確認待ちの提案は文脈に入れない。**
- **確かめる**: 利用者が採ったものは、採った文そのものと根拠の単位の ID を持つ利用者のノート (`note_confirmed`、正本の指示) になり、想起の候補 (信頼しない引用の枠、「利用者が確かめたノート」の印) になる。システムプロンプトには入れない。採らなかった提案は捨て、同じ根拠の組で同じ提案を繰り返さない。
- **守り**: 気づきを別の気づきの根拠にしない。根拠の単位を忘れたら、ノートを無効にして文を除く (§7.4)。機微な情報のふるい (§5.2) を提案の文に当てる。
- **既定で有効にする条件**: S-18 で、縦断の台の作った会話から作った提案のうち、人が見て正しいと判断する率が 8 割以上、根拠の誤り (根拠の単位から言えない内容) が 1 割以下、1 晩の生成が 10 分以下。満たさなければ、opt-in の設定として無効のまま出す。

## 11. 段階とスケジュール

### 11.1 版の配り方の考え方

- **どの版も、利用者に届く性能の向上を持つ** (基盤だけで終わる版を作らない)。
- **危険の大きい作業は、ほかの変更と混ぜずに 1 つの版に隔離する**。保存と統治の作り直し (v0.5) には読み出しの変更を入れず、判定も「悪化しない + 事実の正しさ・裏の速さ・守り」にする (書き込みの不具合と読み出しの調整が 1 つの判定に混ざらないため)。
- **暦の時間でしかたまらない記録は、最初の版 (v0.4) から取る**: ターンの UTC からのずれ、信号、詰めた窓、言い直しの対、待機の時間、先読みの当たり。
- **効き目が不確かな機能は条件付き** にし、効き目が見えたときだけ既定で有効にする (既定の切り替えの提案・気づきの提案、§9.10)。条件付きの機能が遅れても、凍結は止めない。
- **測る台を先に作る**: 保留の問いの切片 (§10.1) と、学習の効き目を測る縦断の台 (§10.1) は、使う版の前に作る。

## 14. 残る懸念

- **先読みの当たる率と、キャッシュの仕組み**: 下書きと送った発話で想起が違うことが多い、または再帰の層の構成で途中からの再利用が効かないと、P2 の効き目が減る (S-17 の 2)。効かなければ、先読みは今の「次のターンの分」だけに戻す。
- **件数・合計の正確さ**: 数えるのは 9B 前後のモデル。列挙で材料はそろうが、計算の誤りは残る (見込みで 6〜7 割)。
- **自由記述の属性と出来事の重なり**: 言い換えで別の単位になり、列挙で二重に数えうる。
- **利用者側の学習の材料**: 明示の信号が少なく、利用者側の学習の効き目は、材料がたまるまで小さい。学習の効果の大半は開発側の表と、決定論の整理 (v0.6) から来る見込み。別名の鍵の伸びしろ (言い直して引けた問いの多さ) と、9B 前後のモデルが作る見出し・気づきの質は未計測 (S-18)。
- **裏の処理が実際の使い方で終わるか**: B2・整理・学習は無操作の時間に載る。話し終えてすぐ閉じる使い方では終わらない。v0.4 で待機の時間と残りの件数を測り、v0.5 の手動の `evorag sleep` で手当てする。v0.3.0 の受入の未達がこれによるものかは、Q10 の調査で確かめる。
- **検出力**: 保留の切片 100 問の対の検定は、差が 12 ポイント前後より小さいと有意にならない (食い違い 18 対 6 で p ≈ 0.023、14 対 6 で p ≈ 0.115【推測: 計算】)。後の版ほど上積みは小さいので、累積の切片で判定する。
- **判定の照合の限界**: 今の照合では上限が 44〜45/50。照合を直すと起点の数値も変わるので、直した後に起点を取り直す。
- **ベンチマークの偏り**: LongMemEval は英語。日本語の評価の事例を段階 0 で足す。
