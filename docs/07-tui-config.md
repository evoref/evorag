## 1. 方針

- 画面はコアの API (02 §3) の命令を出し、イベントを描画するだけにする。
- 公開する名前 (スラッシュコマンド・サブコマンド・設定のキー) は、版の列で入る時期を示す。後の版のものも名前だけは予約し、別の意味で使わない。

## 2. 画面

### 2.1 構成

```
┌ evorag ─ セッション: 旅行の計画 ───────────────────────────────┐
│ あなた  10:02                                                  │
│   来月の京都の件、前に話した宿はどこだっけ？                    │
│ evorag  10:02                                                  │
│   以前の会話 [1] では「鴨川沿いの町家」を候補にしていました。    │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│ > _                                                            │
├────────────────────────────────────────────────────────────────┤
│ 127.0.0.1:8080 │ qwen3-32b │ 想起: 標準 │ 1,234/32,768 │ 待機中│
└────────────────────────────────────────────────────────────────┘
```

- **会話の表示**: ターンを時刻つきで並べる。スクロールできる。中断・失敗のターンと、応答の無いまま残った発話 (強制終了の後など) は印を付ける。
  - 時刻は地方時で示す。地方時のずれは、C を含む依存なしで OS から得る (ADR-0015): Windows は `SystemTimeToTzSpecificLocalTime` (時刻ごとに夏時間の規則を当てる)、Linux と macOS は `TZ` か `/etc/localtime` の TZif (遷移の表と末尾の POSIX TZ の規則)。得られなければ UTC で示し、`UTC` と添える。
- **入力欄**: 複数行。Enter で送信、Shift+Enter (端末が区別できないときは Alt+Enter) で改行。
- **状態の行**: 接続先、モデル、使ったトークン数 / n_ctx、裏の処理の状態 (待機中・整理中・学習中・退避を整理中・電池のため休止)。v0.5 から有効なカートリッジの数。
  - **想起の欄** (v0.2): 想起の状態を 1 つの欄にまとめる。`想起: 標準` (埋め込みとリランカーの両方)、`想起: 簡易` (縮退して語彙の規則などで動く)、`想起: 候補だけ` (しきい値が無く、自動では添えない)、`想起: 作り直し中 42%`。理由と次にすることは `/memory` と `/model` で示す。
  - 未設定 (あえて置いていない役割) は控えめに出す。繋がらない (「接続待ち」)・記録と違うモデル (06 §3)・較正に落ちたリランカーは目立たせ、「→ evorag setup」を添える。
  - 幅が足りないときは、カートリッジの数 → 裏の処理の状態 → トークン数 → 接続先の順に省く (想起の欄とモデルは残す)。
- **Markdown**: 見出し・太字・コードブロックだけを装飾する (FR-109)。
- **出典**: 応答の中の `[n]` を選ぶ (Tab で移動し Enter) と、出典の詳細を表示する (FR-110)。詳細の窓で「無関係」の印を付けられる (v0.2、05 §5.2)。振っていない番号は選べない (05 §5.1)。
- **候補の帯** (v0.2): 帯の往復 (05 §3.4) があれば、応答の下に「関係しそうな記録 (この応答には使っていません)」として、セッション名・日時・発話の冒頭を薄い色で出す。Tab で出典の番号と同じように選び、Enter で詳細の窓を開く (05 §5.2)。
- **詳細の窓の操作** (v0.2): 窓の下に、選べる操作 (帯の往復なら「添えて作り直す」「無関係」「閉じる」、出典なら「無関係」「閉じる」) を並べ、矢印 (または Tab) と Enter で選ぶ。日本語入力が有効なままでも選べるようにするため (英字のキーは IME に取られることがある)。英字の `a`・`x` は近道として受け付け、全角の `ａ`・`ｘ` が確定して届いたときも同じに扱う。

### 2.2 生成中

- 応答は逐次表示する。Esc で中断する (FR-102)。
- 生成中も入力欄に次の発話を書ける (送信は応答の完了か中断の後)。
- 思考の部分を出すモデルが思考している間は、応答の欄と状態の行に「考えています」と出す。思考の本文は表示も保存もしない (応答の本文だけをターンに書く)。

### 2.3 日本語入力

- 描画のたびに、端末の本当のカーソルを入力欄の入力位置に置き、隠さない (IME の候補の窓が入力位置に出るようにするため)。
- 文字の幅は `unicode-width`、書記素の区切りは `unicode-segmentation` で数える。

| 版 | 合格条件とする組み合わせ |
|---|---|
| v0.1 | Windows Terminal + Microsoft IME (新・旧)、Google 日本語入力、ATOK |
| v0.2 | GNOME Terminal + fcitx5、ibus (Linux) |
| v0.6 | Terminal.app + 日本語入力 (macOS、実機を確保したとき) |

- conhost (従来のコンソール) は best effort とし、合格条件に入れない。

### 2.4 外部のエディタ

- Ctrl+E で、入力欄の内容を一時ファイルに書いて外部のエディタで開く。閉じたら内容を入力欄に戻す (FR-107)。
- エディタは `VISUAL` → `EDITOR` → (Windows) `notepad.exe` の順に選ぶ。一時ファイルは所有者だけの権限で、状態のフォルダに置き、送った後に消す。

### 2.5 キー

| キー | 操作 |
|---|---|
| Enter | 送信 |
| Shift+Enter / Alt+Enter | 改行 |
| Esc | 生成の中断 / 画面の窓を閉じる |
| Ctrl+E | 外部のエディタで書く |
| PageUp / PageDown | 会話のスクロール |
| Tab | 出典の番号と候補の帯 (v0.2) の移動 |
| ↑ / ↓ と Enter (詳細の窓で) | 窓の下の操作を選ぶ (v0.2) |
| `a` (詳細の窓で、近道) | 候補の帯の往復を添えて、直前の応答を作り直す (v0.2) |
| `x` (詳細の窓で、近道) | 出典・候補の帯の往復に「無関係」の印を付ける。付いていれば取り消す (v0.2) |
| Ctrl+C | 生成中は中断。入力欄に文字があれば入力欄を空にする。入力欄が空なら、続けて 2 回で終了 |
| Ctrl+Q | 終了 |

| コマンド | 内容 | 版 |
|---|---|---|
| `/help` | コマンドの一覧と説明 | v0.1 |
| `/new [題名]` | セッションを作る | v0.1 |
| `/sessions` | セッションの一覧と再開 | v0.1 |
| `/rename <題名>` | 今のセッションを改名する | v0.1 |
| `/delete` | 今のセッションを消す (確認あり) | v0.1 |
| `/retry` | 直前の応答を作り直す (弱い信号として記録) | v0.1 |
| `/good`、`/bad [理由]` | 直前の応答の評価 (強い信号として記録) | v0.1 |
| `/sources` | このセッションで使う出典の切り替え (v0.1 はメモリの入り切りだけ、v0.5 からカートリッジの選択も) | v0.1 |
| `/model` | 役割ごとに、記録したモデル (ファイル名と model_key) と、繋がっているモデルを表示する。切り替えは `evorag setup` で行う (06 §3.2)。v0.1 の `/model [名前]` (設定の候補への切り替え) は v0.2 でやめ、名前を付けて打つと、切り替えは setup で行うことを示す | v0.1 (Should、切り替え) / v0.2 (表示だけ) |
| `/style` | 答え方の既定 (言語・長さ・書式) の表示と選択 (下の表、05 §4.1 の順 2)。選んだものは次の発話からすぐ効き、データ根に記録する | v0.2 |
| `/memory` | 直前の応答に添えたメモリ (往復と出典の番号)、候補の帯、縮退の理由と次にすること、このセッションの出典の番号と往復の対応。リランクの値は、しきい値との関係 (添えた・帯・下) と、しきい値からの差で示す (生の値は補足)。v0.3 から事実の一覧も | v0.2 |
| `/forget <ID>`、`/private <ID>` | 事実を忘れる・応答に添えないようにする | v0.3 |
| `/precepts`、`/precepts approve <ID>`、`/precepts rollback [版]` | precept の一覧と履歴、提案の承認、巻き戻し | v0.4 |
| `/quit` | 終了 | v0.1 |

- `/` で始まる文をそのまま送るときは、`//` で始める (先頭の `/` を 1 つ取って送る)。
- 後の版のコマンドを打ったときは、まだ使えないことを示す (知らないコマンドとは区別する)。

**`/style` の選択肢** (確定、[OQ-34](10-decisions.md#oq-34-システムプロンプトの-3-層と選べる既定)。それぞれ、プロンプトの言語ごとに同梱した文を 1 つ選ぶ):

| 項目 | 打ち方 | 値 | 既定 |
|---|---|---|---|
| 言語 | `/style language <値>` | `auto` (指定なし。発話の言語で答える)、`ja` (常に日本語)、`en` (常に英語) | `auto` |
| 長さ | `/style length <値>` | `auto` (指定なし)、`short` (短く要点だけ)、`long` (詳しく) | `auto` |
| 書式 | `/style format <値>` | `auto` (指定なし)、`plain` (見出しや箇条書きを使わない文章)、`structured` (見出しと箇条書きで整える) | `auto` |

- `/style` だけを打つと、今の値を示し、矢印と Enter で選べる窓を開く (値の英語の名前を覚えなくてよい)。
- 選んだときに、「すべてのセッションに効きます。次の応答は、始まるまで少し長くかかります」と示す (システムプロンプトが変わり、llama-server が先頭から処理し直すため、05 §4.1)。
- 値はデータ根の `setting` に記録し (03 §3.3)、設定ファイルには置かない (OQ-40 の 3)。ジャーナルにも書く。
- 選んだ既定は、学習で上書きしない。学習の提案は、既定の切り替えの候補として出す (v0.4、13 §3)。
- 値は足すだけにする。知らない値の記録 (新しい版で足した値) は、`auto` として扱い、`/style` で知らない値であることを示す。

## 4. 設定

### 4.1 ファイル

- 置き場所は 03 §2.1。TOML で、先頭に `version = 1` を持つ (版の移行は 03 §12.3)。
- 読めないキー・型の誤り・範囲外の値は、行番号つきのエラーを出して起動しない (FR-904)。後の版で足すキーを古い版が読んだときは、警告を出して無視する (古い版に戻しても起動できるようにするため)。
- **新しいキーの置き場所** (確定、[OQ-40](10-decisions.md#oq-40-古い版が新しい記録と設定を読めること) の 3): v0.1 が読み飛ばすのは、`memory`・`retrieval`・`learning`・`update`・`cartridge` の表と、`llm.embed`・`llm.rerank` の表と、`llm.chat.aux_request_extra` と、`context.budget` の中身だけ (`bins/evorag/src/config.rs` で確かめた)。新しいキーはこの下に置く。置けないキーを足すときは、設定の版 (`version`) を上げ、移行を入れる (03 §12.3)。
- **使わなくなったキーの通知**: 読んで無視するキー (`llm.chat.models`・`retrieval.thresholds`) は、通知で「消してかまいません (v0.1 に戻す予定なら残してください)」と示す。同じ内容のままなら、2 回目の起動からは出さない (通知したキーと内容のハッシュをデータ根に記録する)。
- 利用者が画面から変えた設定 (セッションごとの出典、答え方の既定) と、モデルの記録 (06 §3.1) は、`config.toml` ではなく DB に置く。

## 6. 文言 (i18n)

- コアは利用者に見せる文言を文言キー (`MessageKey`) と引数で返し、画面がカタログ (`locales/<言語>.toml`) で訳す (FR-907)。
- v0.1 は `ja` だけを同梱する。`en` は v0.3 で同梱する (v0.6 から前倒し、確定 (ユーザー回答)、[OQ-08](10-decisions.md#oq-08-ui-の言語とプロンプトの言語))。
- CI でカタログとコードの文言キーの差分を検査する (NFR-602)。
- ログは英語 (02 §7)。

### 6.1 プロンプトの言語

システムプロンプトと補助の呼び出し (ノートの検索の鍵、事実の抽出、訂正の検証、precept の提案、採点) のプロンプトの言語は、UI の言語とは別に扱い、**データ根ごとに 1 つに固定する** (確定 (ユーザー回答、2026-11-09)、OQ-08、FR-909)。

| 時点 | 動き |
|---|---|
| 初回の起動時 (新しいデータ根) | 設定 `prompt.language` があればその値にする。無ければ `evorag setup` (または最初の TUI の起動) で選ばせる。既定の選択肢は UI の言語 |
| 決めたとき | `evorag.redb` の `meta` に記録し、ジャーナルにも操作として残す |
| 以後の起動 | 記録した言語で動く。`prompt.language` が記録と違えば、記録した言語のまま動き、変えられない理由を警告する |
| 変えたいとき | 途中では変えられない。新しいデータ根で始める (`--data-root` か `evorag reset`)。**答える言語だけを変えたいときは、`/style language` で変えられる** (データ根を作り直す必要は無い。setup の言語の問いにも、このことを添える) |

- 答える言語は、答え方の既定 (§3 の `/style language`) で決める。既定の `auto` は「利用者の発話の言語で答える」の文で、プロンプトの言語が `ja` でも、英語の発話には英語で答える。v0.1 は、この指示をシステムプロンプトの本体に置いていた。v0.2 から凍結の核には置かない (核に置くと「常に日本語で」を選んでも効かない、S-13 §7、OQ-34 の 2)。
- 固定する理由: プロンプトを変えると作りの指紋が変わって学習の取り直しが起き (13 §8)、ノートの検索の鍵と事実の抽出の結果の言語もそろわなくなる。リランカーのしきい値の較正にも、この言語の事例を使う (05 §3.7)。
- 同梱するプロンプトは `ja` と `en` (v0.1 から両方を用意し、試験は両方で流す)。凍結の核、答え方の既定の文、補助の呼び出しのプロンプト、較正の事例を、言語ごとに同梱する。
