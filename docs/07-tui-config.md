## 1. 方針

- 画面はコアの API (02 §3) の命令を出し、イベントを描画するだけにする。
- 公開する名前 (スラッシュコマンド・サブコマンド・設定のキー) は、版の列で入る時期を示す。後の版のものも名前だけは予約し、別の意味で使わない。

## 2. 画面

### 2.1 構成

```
┌ evorag ─ セッション: 旅行の計画 ───────────────────────────────┐
│ あなた  10:02                                                  │
│   来月の京都の件、前に話した宿はどこだっけ？                    │
│ evorag  10:02                                                  │
│   以前の会話 [1] では「鴨川沿いの町家」を候補にしていました。    │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│ > _                                                            │
├────────────────────────────────────────────────────────────────┤
│ 127.0.0.1:8080 │ qwen3-32b │ 想起: 標準 │ 1,234/32,768 │ 待機中│
└────────────────────────────────────────────────────────────────┘
```

- **会話の表示**: ターンを時刻つきで並べる。スクロールできる。中断・失敗のターンと、応答の無いまま残った発話 (強制終了の後など) は印を付ける。
  - 伏せ字と、伏せ字にしないで忘れた値の範囲 (`[非表示]`) は、本文と見分けられる表示にする (v0.3、04 §7.3)。範囲 (書記素の境界にあるバイト位置) と種類はコアがターンの照会に添えるので、画面は本文を探さない。伏せ字の範囲は本文がすでに印なので、そのまま見分けられる色で出す。ただし、本文の印 (プロンプトの言語の印、04 §7.3) が UI の言語の印と違うときは、表示するときにその範囲を UI の言語の印 (`ja` は `[伏せ字]`、`en` は `[redacted]`) に置き換える (保存した本文と書き出しは変えない)。`[非表示]` の範囲は、本文に値が残っているので、表示するときにその範囲を `[非表示]` の印に置き換える。開いているセッションのターンに伏せ字か `[非表示]` の範囲ができたと知らされたら、そのターンを読み直して描き直す。
  - 時刻は地方時で示す。地方時のずれは、C を含む依存なしで OS から得る (ADR-0015): Windows は `SystemTimeToTzSpecificLocalTime` (時刻ごとに夏時間の規則を当てる)、Linux と macOS は `TZ` か `/etc/localtime` の TZif (遷移の表と末尾の POSIX TZ の規則)。得られなければ UTC で示し、`UTC` と添える。
- **入力欄**: 複数行。Enter で送信、Shift+Enter (端末が区別できないときは Alt+Enter) で改行。
  - 貼り付けは送らずに入力欄に入れ、中の改行は改行のまま残す。Windows の端末は貼り付けを 1 文字ずつのキーとして渡し、改行も Enter で届く (S-16)。そこで、一度にまとめて届いたキーに文字が 2 つ以上あれば貼り付けとみなし、その中の Enter を改行として扱う (人の打鍵は 1 回の読み取りに 2 文字以上たまらない)。
  - 端末が貼り付けを受け持たず Ctrl+V をキーとして渡すとき (conhost の raw mode)、Windows ではクリップボードの文字を読んで貼り付ける。CRLF は LF にそろえる。
- **状態の行**: 接続先、モデル、使ったトークン数 / n_ctx、裏の処理の状態 (待機中・整理中・学習中・退避を整理中・電池のため休止・空き不足のため休止。`memory.sleep_time = false` のときも「待機中」と出す)。v0.4 から、裏の処理の手順が残っている間は、残っている手順の数 (`整理中 (残り 3)`。手順は 04 §4 の忘れるの当て直し・埋め込み・ノート・抽出・訂正の検証・事実の表・片付け・退避。v0.5 からは、忘れるの当て直し・埋め込み・区切りの呼び出し (残りの区切りの数)・導出・プロファイル・片付け・退避、04) を出す (FR-421。話し終えてすぐ閉じると裏の処理が終わらないことに気付けるように)。v0.5 から、終了するときに区切りの呼び出しが残っていれば、終了の通知に「`evorag sleep` で済ませられます」と添える。v0.9 から有効なカートリッジの数。
  - **想起の欄** (v0.2): 想起の状態を 1 つの欄にまとめる。`想起: 標準` (埋め込みとリランカーの両方)、`想起: 簡易` (縮退して語彙の規則などで動く)、`想起: 候補だけ` (しきい値が無く、自動では添えない)、`想起: 作り直し中 42%`。理由と次にすることは `/memory` と `/model` で示す。
  - 未設定 (あえて置いていない役割) は控えめに出す。繋がらない (「接続待ち」)・記録と違うモデル (06 §3)・較正に落ちたリランカーは目立たせ、「→ evorag setup」を添える。
  - 幅が足りないときは、カートリッジの数 → 裏の処理の状態 → トークン数 → 接続先の順に省く (想起の欄とモデルは残す)。
- **Markdown**: 見出し・太字・コードブロックだけを装飾する (FR-109)。
- **出典**: 応答の中の `[n]` を選ぶ (Tab で移動し Enter) と、出典の詳細を表示する (FR-110)。詳細の窓で「無関係」の印を付けられる (v0.2、05 §5.2)。振っていない番号は選べない (05 §5.1)。
- **候補の帯** (v0.2): 帯の往復 (05 §3.4) があれば、応答の下に「関係しそうな記録 (この応答には使っていません)」として、セッション名・日時・発話の冒頭を薄い色で出す。Tab で出典の番号と同じように選び、Enter で詳細の窓を開く (05 §5.2)。
- **詳細の窓の操作** (v0.2): 窓の下に、選べる操作 (帯の往復なら「添えて作り直す」「無関係」「閉じる」、出典なら「無関係」「閉じる」) を並べ、矢印 (または Tab) と Enter で選ぶ。日本語入力が有効なままでも選べるようにするため (英字のキーは IME に取られることがある)。英字の `a`・`x` は近道として受け付け、全角の `ａ`・`ｘ` が確定して届いたときも同じに扱う。

### 2.2 生成中

- 応答は逐次表示する。Esc で中断する (FR-102)。
- 生成中も入力欄に次の発話を書ける (送信は応答の完了か中断の後)。
- 思考の部分を出すモデルが思考している間は、応答の欄と状態の行に「考えています」と出す。思考の本文は表示も保存もしない (応答の本文だけをターンに書く)。

### 2.3 日本語入力

- 描画のたびに、端末の本当のカーソルを入力欄の入力位置に置き、隠さない (IME の候補の窓が入力位置に出るようにするため)。
- 文字の幅は `unicode-width`、書記素の区切りは `unicode-segmentation` で数える。

| 版 | 合格条件とする組み合わせ |
|---|---|
| v0.1 | Windows Terminal + Microsoft IME (新・旧)、Google 日本語入力、ATOK |
| v0.2 | GNOME Terminal + fcitx5、ibus (Linux) |
| v0.6 | Terminal.app + 日本語入力 (macOS、実機を確保したとき) |

- conhost (従来のコンソール) は best effort とし、合格条件に入れない。

### 2.4 外部のエディタ

- Ctrl+E で、入力欄の内容を一時ファイルに書いて外部のエディタで開く。閉じたら内容を入力欄に戻す (FR-107)。
- エディタは `VISUAL` → `EDITOR` → (Windows) `notepad.exe` の順に選ぶ。一時ファイルは所有者だけの権限で、状態のフォルダに置き、送った後に消す。

### 2.5 キー

| キー | 操作 |
|---|---|
| Enter | 送信 |
| Shift+Enter / Alt+Enter | 改行 |
| Esc | 生成の中断 / 画面の窓を閉じる |
| Ctrl+E | 外部のエディタで書く |
| Ctrl+V (Windows) | クリップボードの文字を貼り付ける (端末が貼り付けを受け持たないとき。§2.1) |
| PageUp / PageDown | 会話のスクロール |
| Tab | 出典の番号と候補の帯 (v0.2) の移動 |
| ↑ / ↓ と Enter (詳細の窓で) | 窓の下の操作を選ぶ (v0.2) |
| `a` (詳細の窓で、近道) | 候補の帯の往復を添えて、直前の応答を作り直す (v0.2) |
| `x` (詳細の窓で、近道) | 出典・候補の帯の往復に「無関係」の印を付ける。付いていれば取り消す (v0.2) |
| Ctrl+C | 生成中は中断。入力欄に文字があれば入力欄を空にする。入力欄が空なら、続けて 2 回で終了 |
| Ctrl+Q | 終了 |

**`/style` の選択肢** (確定、[OQ-34](10-decisions.md#oq-34-システムプロンプトの-3-層と選べる既定)。それぞれ、プロンプトの言語ごとに同梱した文を 1 つ選ぶ):

| 項目 | 打ち方 | 値 | 既定 |
|---|---|---|---|
| 言語 | `/style language <値>` | `auto` (指定なし。発話の言語で答える)、`ja` (常に日本語)、`en` (常に英語) | `auto` |
| 長さ | `/style length <値>` | `auto` (指定なし)、`short` (短く要点だけ)、`long` (詳しく) | `auto` |
| 書式 | `/style format <値>` | `auto` (指定なし)、`plain` (見出しや箇条書きを使わない文章)、`structured` (見出しと箇条書きで整える) | `auto` |

- `/style` だけを打つと、今の値を示し、矢印と Enter で選べる窓を開く (値の英語の名前を覚えなくてよい)。
- 選んだときに、「すべてのセッションに効きます。次の応答は、始まるまで少し長くかかります」と示す (システムプロンプトが変わり、llama-server が先頭から処理し直すため、05 §4.1)。
- 値はデータ根の `setting` に記録し (03 §3.3)、設定ファイルには置かない (OQ-40 の 3)。ジャーナルにも書く。
- 選んだ既定は、学習で上書きしない。既定の切り替えの提案は、承認制の候補として出す (v0.8 の条件付き、ADR-0021)。
- 値は足すだけにする。知らない値の記録 (新しい版で足した値) は、`auto` として扱い、`/style` で知らない値であることを示す。

## 4. 設定

### 4.1 ファイル

- 置き場所は 03 §2.1。TOML で、先頭に `version = 1` を持つ (版の移行は 03 §12.3)。
- 読めないキー・型の誤り・範囲外の値は、行番号つきのエラーを出して起動しない (FR-904)。後の版で足すキーを古い版が読んだときは、警告を出して無視する (古い版に戻しても起動できるようにするため)。
- **新しいキーの置き場所** (確定、[OQ-40](10-decisions.md#oq-40-古い版が新しい記録と設定を読めること) の 3): v0.1 が読み飛ばすのは、`memory`・`retrieval`・`learning`・`update`・`cartridge` の表と、`llm.embed`・`llm.rerank` の表と、`llm.chat.aux_request_extra` と、`context.budget` の中身だけ (`bins/evorag/src/config.rs` で確かめた)。新しいキーはこの下に置く。置けないキーを足すときは、設定の版 (`version`) を上げ、移行を入れる (03 §12.3)。
  - **`llm.memory` の表** (v0.5): v0.4 までは `llm` の表の知らないキーを設定の誤りにする (`llm.embed`・`llm.rerank` のように読み飛ばす表に入っていない) ので、`[llm.memory]` を書いた設定を v0.4 が読むと起動しない。そこで (確定、2026-11-26、[OQ-55](10-decisions.md#oq-55-v05-で公開する名前と操作) の 3)、`[llm.memory]` の名前で置き、v0.5 で設定の版を `2` に上げる。移行は中身を変えず版だけを上げ、元のファイルを `config.toml.bak-v1` に写す。v0.4 に戻したときは `update rollback` の案内 (12 §7.2) で `.bak-v1` を示す (v0.5 の根を v0.4 は開かない (03 §12.4) ので、どのみち古い根へ戻す手順を要する)。公開する名前を役割の表で揃え、v1.0 からの互換で残る名前を素直にするため
- **使わなくなったキーの通知**: 読んで無視するキー (`llm.chat.models`・`retrieval.thresholds`) は、通知で「消してかまいません (v0.1 に戻す予定なら残してください)」と示す。同じ内容のままなら、2 回目の起動からは出さない (通知したキーと内容のハッシュをデータ根に記録する)。
- 利用者が画面から変えた設定 (セッションごとの出典、答え方の既定) と、モデルの記録 (06 §3.1) は、`config.toml` ではなく DB に置く。

**`evorag sleep`** (v0.5、提案書 §8): 話し終えてすぐ閉じる使い方で、裏の処理が終わらないときの手当て。

- 開くときの手順は TUI と同じ (ロック・ジャーナルの取り込み・compact・忘れるの当て直し・モデルの照合と点検、03 §8・06 §3)。chat に繋がらなければ 3、chat のモデルが記録と違えば 6 で終わる (B2 を記録と違うモデルで呼ばないため)。v0.4 の根なら、取り込むかを尋ねる (03 §12.4)。
- 裏の処理を、待機の時間 (`memory.idle_seconds`) を待たずに、残りが無くなるまで続ける。区切りを呼ぶ規則は裏の処理と同じで、開いている末尾の区切りを強制的に閉じない (04 §2。末尾は、前の呼び出しから往復が 2 つ以上増えていれば呼ぶ)。`evorag rebuild --ledgers` で求めた呼び直しが残っていれば、新しい区切りの後に続けて流す。手順ごとの残りの件数と経過の時間を 1 行ずつ出す (本文と値は出さない)。終えたら、区切りの数・作った台帳の数・生成トークン数・時間を示す。
- Ctrl+C (と SIGTERM、コンソールを閉じる) で 1 秒以内に裏の要求を止め、書き終えた台帳と結果を残して終わる (続きは次の `evorag sleep` か TUI の裏の処理)。
- 電池で動いているときは、そのことを示して続けるかを尋ねる (`memory.on_battery` が `stop` でも、利用者が打ったので尋ねて動かす。`--yes` で尋ねない)。`memory.sleep_time = false` でも動く (利用者が明示したため)。
- 終了コード: 0 (残りが無くなった)、1 (止めた・手順の一部が失敗した。残りの件数を示す)、2 (ロック・データ根が使えない)、3 (llama-server に繋がらない)、6 (応答のモデルが記録と違う)。
- 夜間の予約実行 (`--until`)・TUI への受け渡しは v0.8 (ADR-0021 の決定 5)。v0.5 の `evorag sleep` は TUI と同時に動かないので、受け渡しの手順を持たない。

- 共通のオプション: `--data-root <パス>`、`--config <パス>`、`--version`、`--help`。
- 終了コード: 0 正常、1 一般のエラー、2 データ根が使えない (ロック・危ない置き場所・新しい形式。v0.5 からは、取り込みの要る v0.4 の根 (03 §8・§12.4) も)、3 llama-server に繋がらない、4 設定の誤り、5 署名・検証の失敗、6 応答のモデルが記録と違う (v0.2、06 §3)。
- 確認 (`backups purge`・`reset`・`import-v04`・`sleep` の電池の問い) に y 以外を答えたとき (標準入力が終わった・読めないときを含む) は、何も変えずに 1 で終わる。起動のときの「戻すか」(03 §8) と、v0.4 の根の「取り込むか」(03 §12.4 の「きっかけ」、v0.5) を断ったときの 2 (データ根が使えない) とは分ける。
- `--version` の出力 (FR-906): 1 行目は `evorag <版>` で、この形は今後も変えない (後の版の `evorag update` が、置き換えの後の確かめと巻き戻しで読む、12 §7.2)。2 行目からは `commit:`・`target:`・`rustc:`・`installed via:` (入れ方、12 §7.4) の行を出し、v0.3 から `db format: <x.y>` (その版が書く DB の形式の版、03 §3.1.1) の行を足す。`--version` は通信せず、データ根・設定・`update/` に触れない。
- `evorag update` (v0.3、12 §7) は、設定を読むだけで、設定の移行 (03 §12.3) をしない。設定の版が新しくて読めないときも、`storage.data_root`・`storage.backup_dir`・`update.trusted_keys` だけを読んで動く (戻した後に `apply` で戻れるように)。`apply` の版は `0.4.0` の形で書き、先頭の `v` (`v0.4.0`) も受ける。
- `evorag update` の終了コード (v0.3、12 §7):
  - 0: 済んだ。`check` で新しい版が無いとき・新しい版を示したとき (`upgrade_from` の案内を含む)、`apply` で版を省いて今が最新のとき、`rollback` でデータの案内に警告があるときも 0。
  - 1: 改ざんを疑わない理由で断った・失敗した。通信の失敗 (接続・時間切れ・大きさの上限 (リリースの一覧・`release.json`・`.minisig`、`size` が 64 MiB を超える配布物)・許さない転送先・使えないプロキシの設定)、`release.json`・`.minisig` が無い (404。無い版・取り下げた版)、回数の制限、CPU の機能や証明書のルートが無い、`schema` を知らない、今の版が `upgrade_from` を下回る、今の対象の配布物を選べない、指定した版が今と同じか古い (通信の前に断る)、配布物の中の項目が条件に合わない (リンク・同じ名前・大きすぎる)、置き換えの後の確かめ (`--version`) に通らず元に戻した、`evorag.prev` が無い・evorag の版を出さない、インストール先に書き込めない・条件に合わない、ほかの `update` が動いている (`update/lock`)、状態のファイルの計画が読めない・別のフォルダのもの・役割に当たらない、残ったファイルを消せない、実行ファイルの名前や入れ方 (zip でない) で断った、始める前の確かめの 4 の続きで動いている版が外された (もう一度実行する)。TUI の起動の片付けで動いている版が外されたときも 1 で終わる (12 §7.3)。
  - 2: データ根のロックが取れない (evorag が動いている、03 §9)。
  - 4: `update.trusted_keys` の誤り (§4.2)。
  - 5: 改ざんを疑う理由で断った。署名が通らない (prehash でない署名を含む)、trusted comment の不一致、`name`・版・タグ・指定した版の不一致、`date` が今の版のリリースの日付より古い (凍結)、配布物の大きさ (`size` より長く届いて読むのを止めたときを含む)・`sha256`・`exe_sha256` の不一致。`check` が検証で断ったときも同じ分け方 (5 か 1) にする。

## 6. 文言 (i18n)

- コアは利用者に見せる文言を文言キー (`MessageKey`) と引数で返し、画面がカタログ (`locales/<言語>.toml`) で訳す (FR-907)。
- 同梱する言語は `ja` と `en` (`en` は v0.3 から。v0.6 から前倒し、確定 (ユーザー回答)、[OQ-08](10-decisions.md#oq-08-ui-の言語とプロンプトの言語))。設定 `ui.language` で選ぶ。
- 設定を読み終える前に出す文言 (`--help`・引数と設定の誤り) は、設定ファイルの `ui.language` だけを先に読んで選ぶ (読めない・知らない値は `ja`)。`--help` の説明の文はカタログから当てる。clap が足す `--help`・`--version` の文と見出し、引数の誤りの文は英語のまま。
- CI で、各言語のカタログがコードの文言キーと属性の一覧にちょうど合うこと、文言キーごとの引数の名前が `ja` と同じこと、`ja` 以外の文言に漢字・仮名・全角の文字が無いことを検査する (NFR-602、AC-FR-908-1)。
- ログは英語 (02 §7)。

### 6.1 プロンプトの言語

システムプロンプトと補助の呼び出し (v0.4 まではノートの検索の鍵、事実の抽出、訂正の検証。v0.5 からは区切りの呼び出し (B2、04) と、v0.7 からの話題の見出し) のプロンプトの言語は、UI の言語とは別に扱い、**データ根ごとに 1 つに固定する** (確定 (ユーザー回答、2026-11-09)、OQ-08、FR-909)。

| 時点 | 動き |
|---|---|
| 初回の起動時 (新しいデータ根) | 設定 `prompt.language` があればその値にする。無ければ `evorag setup` で選ばせる (既定の選択肢は UI の言語)。setup を経ずに最初の TUI を起動したときは、尋ねずに UI の言語にする |
| 決めたとき | `evorag.redb` の `meta` に記録し、ジャーナルにも操作として残す |
| 以後の起動 | 記録した言語で動く。設定に `prompt.language` を書いていて、それが記録と違えば、記録した言語のまま動き、変えられない理由を警告する (書いていなければ、UI の言語が記録と違っても警告しない) |
| 変えたいとき | 途中では変えられない。新しいデータ根で始める (`--data-root` か `evorag reset`)。**答える言語だけを変えたいときは、`/style language` で変えられる** (データ根を作り直す必要は無い。setup の言語の問いにも、このことを添える) |

- 答える言語は、答え方の既定 (§3 の `/style language`) で決める。既定の `auto` は「利用者の発話の言語で答える」の文で、プロンプトの言語が `ja` でも、英語の発話には英語で答える。v0.1 は、この指示をシステムプロンプトの本体に置いていた。v0.2 から凍結の核には置かない (核に置くと「常に日本語で」を選んでも効かない、S-13 §7、OQ-34 の 2)。
- 固定する理由: プロンプトを変えると作りの指紋が変わって学習の取り直しが起き (13 §8)、ノートの検索の鍵と事実の抽出の結果 (v0.5 からは台帳の `keys` と単位) の言語もそろわなくなる。v0.5 からは、言語が変わると B2 のプロンプトが変わり、すべての区切りの台帳が「今の選択に合わない」になって作り直しになる (04)。リランカーのしきい値の較正にも、この言語の事例を使う (05 §3.7)。
- 同梱するプロンプトは `ja` と `en` (v0.1 から両方を用意し、試験は両方で流す)。凍結の核、答え方の既定の文、補助の呼び出しのプロンプト、較正の事例を、言語ごとに同梱する。
