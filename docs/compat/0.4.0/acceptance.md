## 1. 受入のやり直し 1: 話した事実が現れる (08 §2.5 の合格条件 (7))

v0.3.0 の受入 (`docs/compat/0.3.0/acceptance.md` §1) で、事実が `/memory` に現れなかった構成 (思考するモデル、設定に `llm.chat.aux_request_extra` が無い) で確かめる。配布物は判定コミットで `cargo xtask dist` で作ったもの。

- [x] 設定に `llm.chat.aux_request_extra` を書かずに、思考するモデル (Qwen3.5 など) の llama-server で v0.4.0 を開くと、`evorag doctor` のモデルの点検に「思考を切る指定を自動で足しています」と出る。
- [x] 新しいセッションで、利用者についての事実 (住まい・ペットなど) を話し、AC 電源で操作をやめて待つと、状態の行の「残り」が消え、`/memory` に事実が現れる。
- [x] 別の新しいセッションでその事実を尋ねると、事実を答える。

自動の試験で同じ構成を実機で確かめた記録: `crates/evorag-core/tests/live_facts.rs::live_facts_appear_without_a_thinking_off_setting` (`cargo xtask live-llm`)。

| 日付 | 版 | OS | 結果 | 確かめた人 |
|---|---|---|---|---|
| 2026-11-21 | v0.4.0 (判定コミット 2087f68 で `cargo xtask dist` で作ったもの) | Windows 11 | 合格 | 利用者 |

## 4. 本体の更新の実際の取得 (09 §3.7、12 §7.5)

v0.4.0 の公開の後に、前の版 (v0.3.0) の配布物から行う (09 §9.2 の手順 10)。結果は Release のノートの「検証」の節に書く。

- [ ] `evorag update rollback` で v0.3.0 に戻る。
