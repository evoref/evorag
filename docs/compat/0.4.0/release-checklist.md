## 所見・例外

- **保留の切片 A の 1 回目の判定は無効にした。** 切片 A のデータ根には、取り込んだときの CPU のリランカーでの点検の値 (6 件のリランク 1,706 ms) が残っていて、起点も v0.4 も全問がリランクなし (`rerank_slow`) で答えた (起点 66・v0.4 70、片側 p = 0.17)。点検の値は、点検が無いか失敗したときにしか測り直されないため。データ根を GPU のリランカーで取り込み直し (点検 322 ms。別の重い処理と重なり、開発の組の 157 ms より遅いが、締め切りの 400 ms の内なので 6 件をリランクする)、同じ判定コミットと起点のエンジンで流し直した。09 §5.2 の保留の規律の流し直しの 1 回目 (上限 2 回) として数える。測り方の誤りを正しただけで、保留の結果を見てエンジンを調整してはいない。
- **点検の値が測り直されない** のは製品の問題でもある (リランカーを CPU から GPU に移しても、リランクなしのまま)。v0.5 で扱うことを提案する。
- **リランクの有無で切片 A の正答の数が大きく変わる。** リランクなし (1 回目) で起点 66・v0.4 70、リランクあり (流し直し) で起点 45・v0.4 66。リランカーが英語の LongMemEval で、起点の並び (やり取りを 1 つずつ選ぶ) を悪くしている見込み。v0.4 は往復で選ぶので下がり方が小さい。v0.5 で調べることを提案する。
- 切片 A の abstention の正しさは 5/6 → 4/6。件数の少ない層なので、保留の組の累積で見る (09 §5.2)。
- 1 回目の `cargo xtask live-llm` で、事実の想起の試験が終わる前に想起と TTFT の試験が走り、埋め込みの締め切り (`embed_deadline`) で言い換えの試験が落ち、BM-107 が時間切れになった。どちらも 1 つずつ (`--test-threads 1`) 流し直して合格した。`live-llm` が試験を 1 つずつ流すように直すのは、判定コミットの後には入れられないので v0.5 に回す。BM-107 の試験は 1 つで 205 秒かかり、nextest の時間切れ (300 秒) に近い。
- 事実の想起は 28/30 (必要 27) で、保存した事実の正しさは 18/22。v0.3.0 (30/30・22/22) より下がった。v0.4 の合格条件ではない (v0.5 の合格条件 (2) で、v0.4 と対の検定で比べる)。
- 日本語の事例 (`EVAL-ja.json`) は、起点 (v0.3.0) と比べて記録する予定 (09 §5.2) だったが、起点のエンジンの側に日本語の事例の試験が無く、起点の値は取れなかった。v0.4 は 11/15 (文の窓 6/6、abstain 3/3、事実 1/2、複数の往復を合わせる答え 1/4)。複数の往復を合わせる答えが弱い。
- LongMemEval の判定は、起点と v0.4 を 1 つずつ順に流した。性能の計測 (BM-101〜BM-201) はデータ根の保存し直しと、切片 A の取り込み直しは別の重いビルドと重なった。llama-server の計算はまとめ方で揺れるので、同じエンジンとデータ根でも答えが数問変わる。
- 後回しにしたもの: LongMemEval S の一部 (30 問) の起点、保留の切片 B〜F の取り込み。後の版の判定で使う前に取る。
- LongMemEval の判定は決定論 (文字列の比べ) なので、元の論文の値 (GPT-4o の判定) とは比べない。
