## 1. 忘れると古い版 (09 §3.6、AC-FR-307-6)

自動の試験 (`forget_wiring.rs::forgets_survive_a_round_trip_through_v0_2`) は、v0.2.x をストアの設定で模している。実際の v0.2.x の実行ファイルで、次を確かめる。

- [ ] v0.3 で忘れた後のデータ根を v0.2.x で開いて閉じると、`meta` の `compact.pending` と、`forget_backups` の job が残っている (v0.2.x が当てずに残す)。
- [ ] v0.2.x で開いている間、伏せ字にしたターンが伏せ字のまま表示される (伏せ字の前に戻らない)。
- [ ] v0.2.x で、伏せ字にしたターンのあるセッションに会話を足し、月をまたいだ日付の環境で閉じる (後の月のジャーナルのファイルに行が足される)。v0.3 で開き直すと、そのファイルも書き直され、データ根のどのファイルにも忘れた値が残らない (ID の時刻でファイルを選ばない)。
- [ ] v0.3 で開き直した後、`evorag repair` を実行しても、伏せ字の前の本文に戻らない。
- [ ] v0.3 で開き直した後、退避 (`backups/`) のどの DB にも忘れた値が残らない。

| 日付 | 版 (v0.2.x → v0.3) | OS | 結果 | 確かめた人 |
|---|---|---|---|---|
| 2026-11-19 | v0.2.0 → v0.3.0 (判定コミット 6f4d4df で `cargo xtask dist` で作ったもの) | Windows 11 | 未確認 (下の所見)。3 つ目の項目は対象外 | 利用者 |

所見 (2026-11-19):

- 別のデータ根と設定で、v0.3.0 で事実を話して操作の無い時間を待ったが、`/memory` に事実が 1 件も現れなかった。忘れる対象の事実が無いため、`/forget` から先 (1・2・4・5 つ目の項目) は実際の実行ファイルでは確かめていない。
- 3 つ目の項目 (月をまたいだ日付) は対象外とした。理由: PC の時計を変える必要がある。自動の試験 (`forget_wiring.rs::forgets_survive_a_round_trip_through_v0_2`) が、後の月のファイルを模して確かめている。
- 事実が現れなかった原因は調べていない。考えられるのは、待った時間が足りなかったこと (電池で動いているときは `memory.on_battery = "reduce"` により `idle_seconds` の 5 倍待つ、07)、抽出の関門で落ちたこと。自動の試験と、実際の LLM での評価 (`docs/perf/0.3.0/EVAL-facts.json`、保存した事実 22/22) では抽出が動いている。
- 利用者の判断で、この状態で v0.3.0 をリリースする。抽出と忘れるの仕組みは、リリースの後に見直す。

原因の確認 (2026-11-20、v0.4 の M4.0。ADR-0021 の 8):

- 受入のデータ根の写しを `evorag doctor` で読むと、モデルの点検 (chat) が「補助の呼び出しで思考を切れません (設定 `llm.chat.aux_request_extra` を確かめてください)。型縛りの出力が空か、型に合いません」と記録していた。DB には事実・ノート・job が 1 件も無かった。受入の設定には `llm.chat.aux_request_extra` が無い。
- 同じモデル (Qwen3.5-9B Q4_K_M) と同じビルドの llama-server で、型縛りの要求を思考を切る指定の有無で比べた。指定が無いと、思考が出力の上限まで続いて本文が空になる (`finish_reason` が `length`)。`chat_template_kwargs = { enable_thinking = false }` を足すと、型どおりの JSON が返る。
- よって原因は、点検の結果による型縛りの補助の呼び出し (抽出・ノート) の停止 (06 §3.3 のとおりの縮退) で、待ち時間 (電池で 300 秒) ではない。評価の台 (`EVAL-facts.json`) は思考を切る指定を入れていたので動いていた。データの失いや忘れた値の残りの類ではないので、v0.3.1 は出さない。
- 手当て: 点検で思考を切る指定を自動で試す ([OQ-52](../../10-decisions.md#oq-52-補助の呼び出しで思考を切る指定の自動の判定)、v0.4)。受入は v0.4 (話した事実が現れる) と v0.5 (忘れるまで) でやり直す ([08 §2.5・§2.6](../../08-roadmap.md))。

## 2. 本体の更新の実際の取得 (09 §3.7、12 §7.5)

自動の試験は偽の Releases で行う。実際の GitHub で次を確かめる (v0.3.0 のリリースの後に、次の版の候補で行う)。

- [ ] `evorag update check` が、新しい版と変更の要点を示す。
- [ ] `evorag update apply` が置き換え、新しい版の `--version` が合う。
- [ ] `evorag update rollback` で前の版に戻る。
