## 1. 方針

- メモリとカートリッジは索引を分け、同じ部品で引く。
- 応答が始まるまでに足す時間は、v0.1 は平均 100 ms 以内、v0.2 以降は言い換えとリランクを含めて平均 500 ms 以内 (NFR-102)。
- 最新のターンは、索引に入る前でも「直近の会話」として文脈に入る。
- 判定 (添えるか添えないか) は記録する (判定点、§3.4)。

## 2. 索引

### 2.1 語彙の索引 (v0.1)

規則は技術検証 S-04 (`spikes/S-04/REPORT.md`) の結果で決めた。

- **正規化** (索引と問いで同じ規則。規則は `evorag-retrieval` の 1 か所に置き、版を持つ):
  1. NFKC。
  2. 大文字・小文字の統一 (casefold)。
  3. **カタカナをひらがなに統一する** (長音の「ー」は残す)。
  4. 空白を 1 つにまとめる。
  5. 記号 (Unicode の P・S 類) は **区切り** として扱う。ただし、数字に挟まれた桁区切りの「,」は詰める。
- **単位**:
  - 区切りの中の文字の bi-gram。区切りが 1 文字ならその字を単位にする。辞書は使わない。
  - **漢字は 1 文字も単位に加える** (bi-gram に足す。置き換えではない)。
  - 英数字の並び (`[a-z0-9]+`) は語の単位も加える。
- **索引に入れるもの**: 利用者の発話と応答の両方。単位は v0.1 はターン、v0.2 からはチャンク。
- **形式**: impact 順の CSR の転置索引 (`lex.bin`)。
- **スコア**: BM25 (k1 = 1.2、b = 0.75)。順位付けはすべての単位で行う。
- **しきい値の比** (内容の比): 分子・分母とも **内容の単位** (元の表記でひらがなだけではない単位) だけで取ったスコアの比 (問いそのものを文書と見たときのスコアで割った 0〜1 の値)。ひらがなだけの単位 (「ですか」「って」など) は言い回しで別の話題と重なりやすいため、比から除く。

### 2.2 ベクトルの索引 (v0.2)

- 埋め込みは embed の役割 (06) で作り、int8 に量子化して全件を走査する。行ごとに scale (f32) を持つ。10 万件で 50 ms 以内の見込み (NFR-106、S-05) ([ADR-0009](10-decisions.md#adr-0009-ベクトルの検索は-int8-の全件走査から始める))。
- 件数が増えたら HNSW + RaBitQ に替える (v1.0 まで)。入れ物の trait は同じにする。
- 索引は埋め込みの model_key ごとに分ける。**model_key が変わったら** ベクトルの検索を止め、承認を得てから全件を埋め込み直す。その間は語彙の検索だけで答え、進み具合を状態の行に出す (FR-410)。

### 2.3 セグメントと入れ替え

```
index/
  memory/<embed の model_key、v0.1 は lex>/
    CURRENT              ← 使っているマニフェストの名前
    manifest-<id>.json   ← セグメントの一覧
    seg-<id>/
      header.json        ← 形式名・版・件数・次元・作成時刻・各ファイルのハッシュ
      ids.bin            ← 行番号 → 記録の ID
      vec.i8             ← N × 次元の int8 と、行ごとの scale (v0.2)
      lex.bin            ← bi-gram の語彙表と posting
  cartridge/<CartridgeId>@<version>/<embed の model_key>/   ← 同じ形 (v0.5)
```

- セグメントは一度書いたら変えない。裏の処理 (v0.1 は書き手スレッドの依頼) が新しいセグメントとマニフェストを作り、`CURRENT` を入れ替える。
- 書くときは通常の書き込みと書き切り (mmap で書かない)。`CURRENT` は一時名に書いて書き切ってから rename し、Unix ではフォルダも書き切る。読むときだけ mmap を使う。
- 読み手は「今のセグメントの一覧」への `Arc` を持ち (arc-swap)、開いた一覧を応答の間は使い続ける。応答の途中で索引が変わることはない。
- 古いセグメントは、参照が外れてから消す。消せないとき (Windows で開いたままなど) は、次の起動時に消す。
- `header.json` のハッシュが合わなければ、そのセグメントを捨てて作り直す (NFR-306)。
- v0.1 の語彙の索引の更新: ターンを確定するたびに小さなセグメントを足し、一定の数 (既定 16) を超えたら 1 つにまとめる。

## 3. 応答の前に行うこと

### 3.1 問いの準備

1. 発話を §2.1 の規則で正規化する。
2. 追い質問 (「それは？」のように前の発話が無いと意味が通らないもの。判定は長さと指示語の規則) は、直前 1 ターンを足した問いも作る。
3. 言い換え (v0.2、Should): 型縛りの短い LLM の呼び出し (64 トークンまで、締切 300 ms) で任意に行う。締切を過ぎたら元の問いで引く。
4. 問いの埋め込みは 5 分の間キャッシュする (v0.2)。

### 3.2 候補を集める

- メモリ (v0.1 はターン、v0.2 からチャンクとノート、v0.3 から事実) と、有効なカートリッジ (v0.5) のそれぞれで、語彙とベクトルの候補を並列に引き、和集合を取る。既定は各 50 件。
- `tombstone` の ID、`private` の事実、今のセッションの直近の会話に既に入っているターンは、ここで除く。

### 3.3 順位を付ける

- **リランカーが無いとき**: 語彙とベクトルの順位を RRF (reciprocal rank fusion、k = 60) で 1 つの順位にする。スコアの値を混ぜる計算はしない (確定、[OQ-18](10-decisions.md#oq-18-順位付けとしきい値の尺度))。
- **リランカーがあるとき**: RRF の上位 (既定 30 件) をリランカーで並べ替える (締切 300 ms。過ぎたら RRF の順位のまま)。

### 3.4 選ぶ

- **しきい値**: 候補は、リランカーがあればリランクの値で、無ければ語彙の値 (§2.1 の内容の比) か cosine の **どちらか** が、それぞれのしきい値を超えたときだけ添える。
  - 語彙の値の初期値は 0.14 (S-04)。さらに、上位の最大の値の 0.7 倍未満の候補は添えない。
  - しきい値だけでは、関係の無い問いを確実に Abstain にはできない (S-04 では関係の無い問いの約 3 分の 1 に何かが添えられた)。誤った想起が残る前提で、出典の画面での確認 (§5) と信頼しない引用の枠 (§4.2) を v0.1 から必須にする。リランクの値は 0〜1 ではない生のスコアで返る (S-02) ので、シグモイドで 0〜1 に写してから比べる。しきい値は埋め込みのモデルごとに設定で持ち、初期値は試作 (S-04・S-05) で決める。
- **判定点**: 添えたものがあれば Fire、候補はあったがしきい値を超えなかったら Abstain、索引や役割が無くて引けなかったら Skip を、ターンに記録する。
- **多様性**: 同じセッションの近いターン、同じ話題のノート、同じカートリッジの同じ節は、1 つの枠としてまとめて添える (下位を捨てない。捨てると正しい発言を落としやすい、S-04)。
- **新しさ**: メモリは新しいものを少し優先する (同点のときに新しい方を採る)。
- **事実**: `Live` のものだけを使う。
- **カートリッジ** (v0.5): 小さなチャンクで当てて、それを含む節を添える (予算を超えるならチャンクのまま)。

## 4. 文脈の組み立て

### 4.1 予算

`n_ctx` から **生成に残す量** (既定 `max(1024, n_ctx の 25%)`、設定 `context.reserve_for_output`) を引いた残りを、下の順で割り当てる。

| 順 | 中身 | 予算 (既定) | 入る版 |
|---|---|---|---|
| 1 | システムプロンプト (固定の安全の指示、今の日時 (地方時と UTC からのずれ。07 §2.1 と同じ方法で得る)、メモリとカートリッジの扱い方の指示) | 固定 | v0.1 |
| 2 | 有効な precept (13) | 500 トークンまで | v0.4 |
| 3 | 利用者についての事実 | 600 トークンまで | v0.3 |
| 4 | 以前の会話 (ターン・チャンク・ノート。日時つき) | 800 トークンまで | v0.1 |
| 5 | カートリッジ (出典つき) | 1,500 トークンまで | v0.5 |
| 6 | 直近の会話 | 残りすべて (古いものから省く) | v0.1 |

- 使わない枠の予算 (その版に無い枠、カートリッジが無効のとき) は、直近の会話に回す。
- `n_ctx` が小さく (目安 8,192 未満)、直近の会話に 2,000 トークンを残せないときは、4 → 3 → 5 の順に予算を半分にする。
- トークンの数は llama-server の `/tokenize` で数え、確定した部分の数はキャッシュする (06 §8)。

### 4.2 信頼しない引用の枠

- 以前の会話とカートリッジは「信頼しない引用」の枠に入れ、その中の指示には従わないようにシステムプロンプトで指示する (FR-407)。
- 枠の区切りは、要求ごとに作る乱数の並び (nonce) を含める。引用の本文に同じ並びが現れたら除く。
- 事実 (順 3) は、属性と値の表の形のデータとして入れる (04 §5.4)。

### 4.3 見当たらないとき・食い違うとき

- **見当たらない** (v0.5): しきい値を超えるカートリッジが無ければ、「カートリッジには見当たらない」ことを文脈で伝え、作り話をさせない (FR-706)。
- **食い違う**: メモリとカートリッジ (または古い事実と新しい事実) が食い違うときは、両方を出典つきで並べ、食い違うことを文脈で示す。

## 5. 出典の提示

- 添えた以前の会話 (と v0.5 からはカートリッジ) に番号を振り、応答でその番号を示させる。
- 画面は、番号から出典の詳細 (会話のセッション名・日時・本文の抜粋、カートリッジの文書名・見出し) を照会して表示する (FR-110)。
- どのメモリ・カートリッジを添えたかを、応答のターンに ID の一覧で残す (FR-408)。誤りの原因を追え、自己学習のリプレイでも使う。

## 6. 検索の評価

- 回帰台帳 (13) とは別に、検索の事例 (問い、正解の記録の ID の組) を `tests/retrieval/` に置く。事例は作った会話だけで作る (11 §9.7)。
- 測るもの: recall@k (k = 3, 10)、nDCG@10、待ち時間の平均と p95。
- 索引・正規化・設定を変える PR では、評価を流して前後を比べる (09 §5)。v0.2 は `cargo xtask eval-retrieval`、v0.6 から `evorag eval retrieval` として利用者のデータにも流せる (結果は外に出さない)。
