## 1. 方針

- メモリとカートリッジは索引を分け、同じ部品で引く。
- 応答が始まるまでに足す時間は、v0.1 は平均 100 ms 以内、v0.2 以降は問いの埋め込みとリランクを含めて平均 500 ms 以内 (NFR-102)。
- 最新のターンは、索引に入る前でも「直近の会話」として文脈に入る。
- 想起は毎ターン行い、添えるかどうかはリランカーの生の値で決める。LLM の判断 (言い換え、検索の計画、検索の道具をモデルに呼ばせる形) は応答の経路に入れない (確定、[ADR-0019](10-decisions.md#adr-0019-想起はリランカーの値で決めllm-の判断を応答の経路に入れない))。
- llama-server へ送る要求は、前のターンの要求と先頭が一致するように組み立てる (確定、[ADR-0017](10-decisions.md#adr-0017-要求の先頭を変えない-システムプロンプトの-3-層)、§4)。
- 判定 (添えるか添えないか) と、後から作り直せない観測値は、応答のターンに記録する (§3.6)。

## 2. 索引

### 2.1 語彙の索引 (v0.1)

規則は技術検証 S-04 (`spikes/S-04/REPORT.md`) の結果で決めた。

- **正規化** (索引と問いで同じ規則。規則は `evorag-retrieval` の 1 か所に置き、版を持つ):
  1. NFKC。
  2. 大文字・小文字の統一 (casefold)。
  3. **カタカナをひらがなに統一する** (長音の「ー」は残す)。
  4. 空白を 1 つにまとめる。
  5. 記号 (Unicode の P・S 類) は **区切り** として扱う。ただし、数字に挟まれた桁区切りの「,」は詰める。
- **単位**:
  - 区切りの中の文字の bi-gram。区切りが 1 文字ならその字を単位にする。辞書は使わない。
  - **漢字は 1 文字も単位に加える** (bi-gram に足す。置き換えではない)。
  - 英数字の並び (`[a-z0-9]+`) は語の単位も加える。
- **索引に入れるもの**: 利用者の発話と応答の両方。単位は v0.1 はターン、v0.2 からはチャンク (§2.4) と検索の鍵 (04 §2)。
- **形式**: impact 順の CSR の転置索引 (`lex.bin`)。
- **スコア**: BM25 (k1 = 1.2、b = 0.75)。順位付けはすべての単位で行う。
- **しきい値の比** (内容の比): 分子・分母とも **内容の単位** (元の表記でひらがなだけではない単位) だけで取ったスコアの比 (問いそのものを文書と見たときのスコアで割った 0〜1 の値)。ひらがなだけの単位 (「ですか」「って」など) は言い回しで別の話題と重なりやすいため、比から除く。v0.2 からは、リランカーを使えないときの縮退 (§3.5) でだけ使う。

### 2.2 ベクトルの索引 (v0.2)

- 埋め込みは embed の役割 (06) で作り、int8 に量子化して全件を走査する。行ごとに scale (f32) を持つ。10 万件で 50 ms 以内の見込み (NFR-106、S-05) ([ADR-0009](10-decisions.md#adr-0009-ベクトルの検索は-int8-の全件走査から始める))。
- 件数が増えたら HNSW + RaBitQ に替える (v1.0 まで)。入れ物の trait は同じにする。
- 索引は埋め込みの model_key ごとに分ける。埋め込みのモデルの扱いは 06 §3 ([ADR-0018](10-decisions.md#adr-0018-モデルは-setup-で記録し切り替えは-setup-でだけ行う))。
  - 繋がっている埋め込みのモデルが記録 (06 §3.1) と違うときは、ベクトルの検索を止め (§3.5 の縮退)、状態の行で知らせる。索引は消さない。
  - `evorag setup` で埋め込みのモデルを切り替えたら、全件を新しいモデルで作り直す (sleep-time の job)。その間は語彙の検索とリランクで答え、進み具合を状態の行に出す (FR-410)。
  - 前のモデルの索引は 1 世代だけ残す (前のモデルに戻したときに使う)。それより古い世代は消す。

### 2.3 セグメントと入れ替え

```
index/
  memory/
    lex/                       ← v0.1 の語彙の索引 (ターンが単位)。v0.2 は使わない (下の注)
    chunk-lex/                 ← v0.2 からの語彙の索引 (チャンクと検索の鍵が単位)
    vec-<embed の model_key>/  ← v0.2 からのベクトルの索引。前のモデルの分を 1 世代だけ残す
      CURRENT                  ← 使っているマニフェストの名前
      manifest-<id>.json       ← セグメントの一覧
      seg-<id>/
        header.json            ← 形式名・版・件数・次元・作成時刻・各ファイルのハッシュ
        ids.bin                ← 行番号 → 記録の ID と単位の種類 (チャンク・検索の鍵)
        vec.i8                 ← N × 次元の int8 と、行ごとの scale (vec-…/ だけ)
        lex.bin                ← bi-gram の語彙表と posting (chunk-lex/ だけ)
  cartridge/<CartridgeId>@<version>/   ← 同じ形 (chunk-lex/ と vec-<embed の model_key>/、v0.5)
```

- `chunk-lex/` と `vec-…/` は、それぞれ `CURRENT`・マニフェスト・セグメントを持つ (上は `vec-…/` の中だけを書いた)。
- セグメントは一度書いたら変えない。裏の処理 (v0.1 は書き手スレッドの依頼) が新しいセグメントとマニフェストを作り、`CURRENT` を入れ替える。
- 書くときは通常の書き込みと書き切り (mmap で書かない)。`CURRENT` は一時名に書いて書き切ってから rename し、Unix ではフォルダも書き切る。読むときだけ mmap を使う。
- 読み手は「今のセグメントの一覧」への `Arc` を持ち (arc-swap)、開いた一覧を応答の間は使い続ける。応答の途中で索引が変わることはない。
- 古いセグメントは、参照が外れてから消す。消せないとき (Windows で開いたままなど) は、次の起動時に消す。
- `header.json` のハッシュが合わなければ、そのセグメントを捨てて作り直す (NFR-306)。
- 語彙の索引の更新: ターンを確定するたびに小さなセグメントを足し、一定の数 (既定 16) を超えたら 1 つにまとめる。v0.2 では、確定したターンのチャンクをすぐ語彙の索引に足し、埋め込みは sleep-time に作る。
- **v0.1 の索引 (`lex/`)**: v0.2 は使わない。v0.2 の最初の起動 (形式の移行、03 §12.1) で消し、`chunk-lex/` を作る。v0.1.2 に戻すと、v0.1.2 が `lex/` を作り直す。
- **古い版が書いた後** (03 §4.2 の規則 12): 古い版は v0.2 の索引を直さない (削除を当てない) ので、前回書いた版が v0.2 より古ければ、`chunk-lex/` と `vec-…/` (前の世代の分を含む) を作り直す。

### 2.4 チャンク (v0.2)

- ターンを段落の区切り (空行) で分け、1 つのチャンクを 400 文字 (目安、設定しない) までにする。長い段落は文の区切りで分け、前のチャンクと 50 文字を重ねる。短いターンは 1 つのチャンクにする。
- コードブロック (```` ``` ```` で囲んだ範囲) は途中で切らない。400 文字を超えるときだけ、行の区切りで分ける。
- チャンクは、元のターンの ID と、本文の中の範囲 (文字の位置) を持つ (03 §3.3 の `chunk`)。本文を写して持たない (ターンの本文から作り直せる)。
- 語彙とベクトルのどちらの索引も、チャンクと検索の鍵 (04 §2) を単位にする。ターンの値は、そのターンのチャンクと、そのターンを指す鍵のうち最も良い値にする。

## 3. 応答の前に行うこと

### 3.1 問いの準備

1. 発話を §2.1 の規則で正規化する。
2. 追い質問 (「それは？」のように前の発話が無いと意味が通らないもの。判定は長さと指示語の規則) は、直前の利用者の発話を足した問いも作る (LLM は使わない)。
3. 言い換えはしない (v0.2 でやめた。LLM の補助の呼び出しは 1 回に 2.3〜6.5 秒かかり、締切に収まらない、S-13 §4)。言い換えの代わりに、sleep-time に作る検索の鍵 (04 §2) で語彙の違いを補う。
4. 問いの埋め込みは、同じ問いについて 5 分の間キャッシュする。入力が止まったときに先に作る (§4.5)。

### 3.2 候補を集める

- メモリ (v0.2 はチャンクと検索の鍵、v0.3 から事実の鍵) と、有効なカートリッジ (v0.5) のそれぞれで、語彙とベクトルの候補を並列に引く。既定は各 50 件。
- 次のものは、ここで除く。
  - `tombstone` の ID と、忘れた記録・private の事実から作った鍵 (04 §7)。
  - 出典のターンが DB に無い項目 (03 §4.2 の規則 12。古い版が消したターンは `tombstone` を残さないので、出典があるかで見分ける)。
  - 今のセッションの、文脈の履歴 (§4.1 の順 5) に入っているターン。
  - 読めない記録 (03 §4.2 の規則 11)。

### 3.3 順位を付け、往復にまとめる

1. 語彙とベクトルのそれぞれで、候補をターンの値 (§2.4) の順に並べ、RRF (reciprocal rank fusion、k = 60) で 1 つの順位にする。スコアの値を混ぜる計算はしない (確定、[OQ-18](10-decisions.md#oq-18-順位付けとしきい値の尺度))。同点は新しいターンを先にする。
2. 上位 6 ターン (設定しない。点検で減らすことがある、§3.4) を取り、それぞれを **往復** (利用者の発話と、それへの応答の組) にまとめる。同じ往復に当たったターンは 1 つにするので、往復は最大 6 件になる。往復の相手が無いターン (応答の無いまま残った発話、応答だけが残ったもの) は、そのターンだけで往復とみなす。
3. 往復の本文が、リランカーの入力の上限 (既定 512 トークン) を超えるときは、当たったチャンクを中心に切り詰める。チャンクを持つ M2.5 までは、発話の先頭 400 文字と応答の先頭 800 文字に切り詰める (較正の同梱の事例と同じ形にする、§3.7)。

### 3.4 リランクして選ぶ (v0.2)

- 往復の本文を、問いに対してリランクする (`/v1/rerank`)。値は生のスコア (S-02) のまま扱い、0〜1 に写さない。
- **添える**: 最上位の往復の値がしきい値以上なら、その 1 件だけを添える (Fire)。2 件目以降は添えない (上位 30 ターンをリランクすると遅く、質も下がる、S-13 §5)。
- **候補の帯**: 値が、しきい値の少し下の帯 (帯の下限以上、しきい値未満) にある往復は、文脈に入れずに、画面に「関係しそうな記録」として出す (§5.2)。最上位を添えたときも、2 件目以降で帯に入るものを出す (帯は最大 3 件)。最上位が帯にあるときの判定点は Abstain。
- **それより下**: 何もしない (Abstain)。
- **しきい値と帯の下限**: リランカーの model_key と、対象の種類 (`conversation`、v0.5 から `cartridge`、コーディングモードは `code`) ごとに持つ (03 §3.3 の `threshold`)。求め方は §3.7。
- **件数と締切**: 既定は上位 6 ターン (往復は最大 6 件)。リランクの締切は 400 ms、問いの埋め込みの締切は 200 ms。モデルの性質の点検 (06 §3.3) で測った往復 6 件のリランクの時間が締切を超えるときは、取るターンの数を減らす (下限 3)。3 ターンでも超えるときは、応答の経路でリランクを使わない (§3.5 の `rerank_slow`)。入力が止まったときに先に済ませた埋め込みとリランク (§4.5) は、締切に数えない。
- **多様性**: 添えるのは 1 件なので、まとめる規則は持たない。帯には、同じセッションの隣り合う往復を 2 つ以上出さない。
- **新しさ**: 値が同じときは、新しい往復を先にする。
- **事実** (v0.3): `Live` のものだけを使う。事実は鍵として引き、添えるのは事実の表 (§4.1 の順 4) と出典の往復にする (04 §5.4)。
- **カートリッジ** (v0.5): 小さなチャンクで当てて、それを含む節を添える (予算を超えるならチャンクのまま)。しきい値は `cartridge` の値を使う。
- **添える直前のふるい分け**: 添える往復と帯に出す往復を、`tombstone`・忘れた記録・private の事実ともう一度照らし合わせ、当たれば除く (候補を集めてから添えるまでの間に、忘れる・削除の操作が入りうるため、04 §7.2)。

### 3.5 縮退

役割が無いとき・使えないときは、次のとおりに動く。縮退したことと理由を、応答のターンの観測値 (`obs` の `degraded`、§3.6) に記録する。判定点の列挙 (Fire / Abstain / Skip) には値を足さない (03 §4.2 の規則 11)。

| 状態 | 動き | 理由の値 |
|---|---|---|
| 埋め込みが無い・記録と違う・作り直しの途中 | 語彙の候補だけで §3.3〜§3.4 を行う (上位 6 ターンを往復にまとめてリランクする) | `no_embed` |
| 問いの埋め込みが締切に間に合わない | 上と同じ (その要求だけ) | `embed_deadline` |
| リランカーが無い・記録と違う | v0.1 の規則に戻す: 語彙の値 (§2.1 の内容の比) が 0.14 以上で、上位の最大の値の 0.7 倍以上の候補を添える (S-04)。ベクトルの候補は使わない。帯は出さない | `no_rerank` |
| リランカーが遅く、3 ターンでも締切に収まらない (点検の結果、§3.4) | 上と同じ | `rerank_slow` |
| リランクが締切に間に合わない | 上と同じ (その要求だけ) | `rerank_deadline` |
| リランクの要求が失敗した (繋がらない、値の数が合わない) | 上と同じ (その要求だけ) | `rerank_error` |
| リランカーの較正の値が無い (§3.7) | 添えない。しきい値の代わりに、リランクの上位 3 件を帯に出す (見出しは「近い記録 (自動では添えていません)」にし、「関係しそうな記録」と分ける) | `no_threshold` |
| 埋め込みもリランカーも無い | 上の `no_rerank` と同じ | `no_embed,no_rerank` |
| 索引が無い・壊れていて引けない | 何も添えない (Skip) | `no_index` |

- v0.1 の規則では、関係の無い問いの約 3 分の 1 に何かが添えられる (S-04、S-13 §5)。リランカーの無い構成では、誤った想起が残る前提で、出典の画面での確認 (§5) と信頼しない引用の枠 (§4.3) で補う。
- v0.1 の規則の値 (0.14、0.7 倍) は、ターンを単位にして S-04 で求めた。v0.2 はチャンクと検索の鍵を単位にするので、M2.3 で想起の事例 (09 §5.2) を流して確かめ直し、違えばここを直す。
- `no_threshold` は、しきい値を求めるまでの短い間にだけ起きるようにする (§3.7 の「いつ」)。較正に落ちたリランカーでは続くので、状態の行に理由と「`evorag setup`」の案内を出す (07 §2.1)。
- 縮退の理由の値は、文字列の集まりとして記録する。値は足すだけにし、知らない値はそのまま表示する。

### 3.6 判定点と観測値

- **判定点**: 添えたものがあれば Fire、候補はあったが添えなかったら Abstain、索引や役割が無くて引けなかったら Skip を、応答のターンに記録する (v0.1 から。列挙の値は足さない、03 §4.2 の規則 11)。
- **観測値** (v0.2、[OQ-41](10-decisions.md#oq-41-ターンに残す観測値)): 後から作り直せない値を、応答のターンの任意の項目 (03 §3.3 の `turn` の `obs`) に残す。リランカーや設定を替えると、計算し直せないため。項目は次のとおり (括弧の中は `obs` の項目の名前。名前の無いものは、入れる版で決めてここに書き足す)。
  - リランクした往復ごとの ID と生の値 (`reranked`。値の高い順。ID は往復を代表するターン = 利用者の発話)、採点したリランカーの model_key (`reranker`)、使ったしきい値の版 (`threshold_version`)。
  - 帯に出した往復の ID (`band`)。
  - 添えた位置 (`recall_position` = `before_utterance`。後の版で位置を変えたときに見分けるため)。
  - 利用者が帯から選んで添えたこと (§5.2 の「添えて作り直す」)。
  - 縮退の理由 (`degraded`、§3.5)。埋め込みの候補を足す M2.5 までは、いつも `no_embed` を含む。
  - 出典の番号の始まり (`source_base`、§5.1) と、履歴に入れた最も古いターンの ID (`history_from`、§4.2)。
  - 選んでいた答え方の既定 (`answer`、§4.1 の順 2)。
  - v0.3 から事実の表の版、v0.4 から precept の版と、生成と検索の作りの指紋 (13 §8)。

### 3.7 しきい値の較正 (v0.2)

確定 ([OQ-38](10-decisions.md#oq-38-リランクのしきい値の較正))。しきい値の余裕は狭い (関係の無い問いの最大が −3.47、正解の低い値が −3.0、S-13 §5)。リランカーごとに求め直す。

- **いつ**: 記録したリランカーのしきい値が無いとき。利用者の入力は要らない (同梱の事例だけで決まる)。
  - `evorag setup` でリランカーを記録したとき・切り替えたとき・しきい値が無いとき: setup の中でその場で求める (進み具合を出す。途中で止めたときは、次の起動の後に裏で求める)。
  - setup を通らずに記録したとき (v0.1 のデータ根の最初の起動、後から rerank の接続を足した、06 §3.1) と、しきい値が無くなったとき (DB を失って戻した、03 §6): TUI を開いた後に、裏で自動で求める (モデルの性質の点検、06 §3.3 と同じ扱いの「起動後の点検」、04 §4。`memory.sleep_time` と `idle_seconds` に依らず、入力が途切れ応答を生成していない間に流し、操作で切って続きから求める)。求め終わるまでの短い間は `no_threshold` で動く。リランカーに繋がらない・失敗したときは、同じ起動の中では 5 分おいて求め直す。
- **事例**: 本体に同梱した事例 (作った会話と問い。プロンプトの言語 `ja`・`en` ごと) を使う。データ根のプロンプトの言語の事例を使う。組み方 (S-14): 言語ごとに 14 セッションほどの会話と、関係のある問い 36 件 (語の重なる問い easy、言い方を変えた問い variant、遠回しの問い para を同じ数) と関係の無い問い 24 件 (近い話題の外れと、別の話題を半分ずつ)。評価の事例 (`tests/retrieval/`) と話題を分ける。
- **候補**: 同梱の会話の語彙の索引の上位 6 往復 (関係のある問いでは正解の往復を必ず含める)。埋め込みには頼らない (埋め込みのモデルに左右されないため)。
- **求め方** (S-14 で確かめた。`spikes/S-14/REPORT.md`):
  - しきい値: 関係の無い問いの最上位の値の分布で、9 割の問いが下回る点の直上。
  - 帯の下限: 同じ分布で、7 割 5 分の問いが下回る点。
  - 合否: 次の 2 つを満たせば合格。満たさなければ較正の値を作らず、§3.5 の `no_threshold` で動かす。setup と状態の行に理由を出し、別のリランカーを勧める。
    - 順位: 関係のある問いの 8 割以上で、正解の往復が最上位。
    - 値: 語の重なる問い (easy・variant) の 8 割以上で、正解の往復が最上位かつしきい値以上。
    - 遠回しの問い (para) は値が低く、しきい値の下 (帯) に来やすい (S-14 では 12 件中 3〜6 件だけがしきい値以上)。帯に出すのが正しい振る舞いなので、合否には使わず、しきい値以上と帯の件数を記録するだけにする。
  - リランカーごとに値の目盛りが違う (S-14 では −4.1〜−5.5)。固定の値は持たない。
- **記録**: しきい値と帯の下限を、リランカーの model_key・対象の種類・版・求めた方法 (`bundled`)・使った同梱の事例 (`ja-1` など)・合否とともに記録する (03 §3.3 の `threshold`)。前の版を残し、巻き戻せる。合否に落ちた結果も記録し (値は使わない)、同じリランカーで起動のたびに求め直さない。同梱の事例を変えた版では、事例の名前が変わるので求め直す。
- **利用者の信号での較正** (v0.4): 「無関係」の印と、帯から添えた操作 (§5.2) を信号にし、LLM を使わない決定論のゲートでしきい値を動かす。1 回のコミットで入れ替え、版を持ち、巻き戻せる。承認を要するかは v0.4 の M4.0 で決める (OQ-38 の残り)。v0.2 は信号を記録するだけにする。

## 4. 文脈の組み立て

### 4.1 並べ方と予算

確定 ([ADR-0017](10-decisions.md#adr-0017-要求の先頭を変えない-システムプロンプトの-3-層)、[OQ-34](10-decisions.md#oq-34-システムプロンプトの-3-層と選べる既定)、[OQ-35](10-decisions.md#oq-35-文脈の並べ方-日時想起古い発言先の処理))。変わりにくいものを前に置き、毎ターン変わるものを今の発話の側に寄せる。llama-server は、前の要求と先頭が一致する部分の処理を省けるため (S-13 §3: 先頭を変えると 14 秒、変えなければ 1〜2 秒)。

`n_ctx` (スロットごとの値、06 §3) から **生成に残す量** (既定 `max(1024, n_ctx の 25%)`、設定 `context.reserve_for_output`) を引いた残りを、下の順で割り当てる。

| 順 | 置き場所 | 中身 | 変わるとき | 予算 (既定) | 版 |
|---|---|---|---|---|---|
| 1 | システムプロンプト | **凍結の核**: 安全の指示、引用の扱い方 (§4.3)、出典の番号の示し方、道具の使い方 (v1.0 より後)、カートリッジの扱い方 (v0.5)。プロンプトの言語 (07 §6.1) ごとに同梱する | evorag の版を上げたとき | 固定 | v0.2 |
| 2 | システムプロンプト | **選べる既定**: 答える言語・長さ・書式のそれぞれについて、同梱した文から選んだ 1 つ (07 §3 の `/style`) | 利用者が選び直したとき (すぐ効かせる) | 固定 | v0.2 |
| 3 | システムプロンプト | **precept** (学習した短い指示。採用したものを全部、13) | 採用・巻き戻しのとき | 500 トークンまで | v0.4 |
| 4 | システムプロンプト | 利用者についての事実の表 (04 §5.4) | 事実が変わったとき (訂正・忘れる・private)。次のターンで作り直す | 600 トークンまで | v0.3 |
| 5 | 履歴 | このセッションのターン。利用者の発話には、そのターンに記録した時刻から作った日時を付ける | ターンが増えるたびに末尾に足す。省き方は §4.2 | 残りすべて | v0.1 |
| 6 | 今の発話 | 想起の引用 (信頼しない引用の枠、§4.3)、カートリッジの引用 (同じ枠、v0.5)、今の日時、発話の本文の順 | 毎ターン。次のターンの要求では、引用を外した形で履歴に入る | 想起 800、カートリッジ 1,500 トークンまで | v0.2 |
| 7 | 今の発話の末尾 | 有効なカートリッジの一覧と、「カートリッジには見当たらない」の通知 (§4.4) | 毎ターン | 200 トークンまで | v0.5 |

- システムプロンプト (順 1〜4) に、今の日時・想起の引用・要求ごとに変わる区切りの印を入れない。
- **先頭が変わってよいとき**: 利用者が答え方の既定を選び直したとき (順 2)、precept が変わったとき (順 3)、事実の表が変わったとき (順 4)、古い発言をまとめて省いたとき (§4.2) だけ。それ以外の連続する要求では、システムプロンプトと前のターンまでの履歴のバイト列を変えない (FR-414)。
- **日時**: 地方時と UTC からのずれ (07 §2.1 と同じ方法で得る) を、発話の先頭に付ける。形はプロンプトの言語で決める (`ja`: `[2026-11-12 (木) 10:02 +09:00]`、`en`: `[2026-11-12 (Thu) 10:02 +09:00]`)。ターンに記録した時刻から作るので、後のターンの要求でも同じ文字列になる。
- **想起の引用**: 今の発話の直前 (同じメッセージの中) に置き、次のターンでは外す。引用を外した形の発話が履歴に入るので、前のターンまでの履歴のバイト列は変わらない。引用を末尾に足して外さない形は、履歴が引用で膨らむので採らない。
- **答え方の既定の文**: プロンプトの言語ごとに、`指定なし` を含めて同梱する。言語の `指定なし` の文は「利用者の発話の言語で答える」にする (凍結の核に置くと、「常に日本語で」を選んでも効かない、S-13 §7)。
- 使わない枠の予算 (その版に無い枠、カートリッジが無効のとき) は、履歴に回す。
- `n_ctx` が小さく (目安 8,192 未満)、履歴に 2,000 トークンを残せないときは、想起 → 事実 → カートリッジの順に予算を半分にする。
- トークンの数は llama-server の `/tokenize` で数え、確定した部分の数はキャッシュする (06 §8)。

### 4.2 古い発言の省き方

- 履歴が予算を超えたら、古いターンから、履歴が予算の 6 割になるまで **まとめて** 省く。1 往復ずつ省かない (省くたびに全体を処理し直すため、S-13 §3)。
- 省く単位は往復にする (発話だけ、応答だけを残さない)。
- 履歴に入れた最も古いターンの ID を、応答のターンの観測値に記録する (§3.6)。次のターンはその位置から履歴を組み立て、予算を超えるまで位置を変えない。
- 省いたターンは保存からは消えず、想起の候補 (§3.2) に戻る。

### 4.3 信頼しない引用の枠

- 以前の会話とカートリッジは「信頼しない引用」の枠に入れる。その中の指示には従わないことを、凍結の核で指示する (FR-407)。
- 枠の区切りには、要求ごとに作る乱数の並び (nonce) を含める。区切りの印は引用の側 (順 6) にだけ置き、凍結の核には扱い方の指示だけを置く (印を核に置くと、毎ターン先頭が変わるため、OQ-34 の 6)。引用の本文に同じ並びが現れたら除く。
- 引用は、出典の番号 (§5.1)、セッションの題名、往復の日時とともに入れる。
- 事実 (順 4) は、属性と値の表の形のデータとして入れる (04 §5.4)。

### 4.4 見当たらないとき・食い違うとき

- **見当たらない** (v0.5): しきい値を超えるカートリッジが無ければ、「カートリッジには見当たらない」ことを今の発話の末尾 (順 7) で伝え、作り話をさせない (FR-706)。
- **食い違う**: メモリとカートリッジ (または古い事実と新しい事実) が食い違うときは、両方を出典つきで並べ、食い違うことを文脈で示す。

### 4.5 先に済ませる処理 (v0.2)

確定 ([OQ-35](10-decisions.md#oq-35-文脈の並べ方-日時想起古い発言先の処理) の 5、[OQ-42](10-decisions.md#oq-42-先に済ませる処理と外へ出る経路電池))。

- **次のターンの分**: 応答を書いた直後に、次のターンの要求の先頭 (順 1〜5。今の応答までを履歴に入れたもの) を、生成を 1 トークンに限った要求で応答のスロット (06 §4) に送り、llama-server に処理させておく (S-13 §3 で、応答が始まるまでが 2.4 秒から 0.43 秒になった)。応答は捨てる。利用者が発話を送ったら止める。
- **入力が止まったとき**: 入力欄の文字が約 500 ms 変わらなかったら、その内容で問いの準備 (§3.1)・候補の収集・リランクを先に済ませる。送った発話が同じなら、その結果を使う。違えば捨てる。発話を送る前に保存する規則 (FR-201) は変えない (先に済ませる処理は、保存せずに捨てられる結果だけを作る)。
- **外へ出る経路**: ループバック以外の接続先を許した設定 (`llm.allow_remote = true`、06 §9) では、入力が止まったときの処理を既定で切る (送っていない入力が別の機械へ出るため、P2)。設定 `retrieval.precompute` で変えられる (07 §4.2)。次のターンの分は、送った会話だけを送るので切らない。
- **電池**: 電池で動いている間は、設定 `memory.on_battery` (07 §4.2) に従って減らす。`retrieval.precompute = true` を書いていても、電池の設定 (`reduce`・`stop`) が先に効く。
- 先に済ませる処理は、裏の処理 (04 §4) より先にし、利用者の要求より後にする (06 §4)。

## 5. 出典の提示

### 5.1 出典の番号

- 添えた以前の会話 (と v0.5 からはカートリッジ) に番号を振り、応答でその番号を示させる (凍結の核で指示する)。
- 番号は、**セッションの中の通し番号** にする (確定、OQ-35 の 3)。履歴に残る応答の中の番号と、新しい引用の番号がぶつからないようにするため。その応答で使った番号の始まりを観測値に記録する (§3.6)。v0.1 のターンは番号の始まりを持たないので、1 から始まったものとして読む。
- 画面は、番号から出典の詳細 (会話のセッション名・日時・往復の本文、カートリッジの文書名・見出し) を照会して表示する (FR-110)。詳細には、その出典を添えたのがこの応答か、前のターンか (「このセッションの出典 5。この応答で添えたもの」) を示す (通し番号は飛ぶので、番号だけでは分からないため)。
- 応答の中の番号のうち、どのターンでも振っていない番号 (モデルが作った番号) は選べないようにし、「出典なし」と分かる表示にする。
- `/memory` で、このセッションの番号と往復の対応を示す。
- どのメモリ・カートリッジを添えたかを、応答のターンに ID の一覧で残す (FR-408)。誤りの原因を追え、自己学習のリプレイでも使う。

### 5.2 候補の帯と「無関係」の印 (v0.2)

確定 ([OQ-36](10-decisions.md#oq-36-想起の規則-候補リランク添え方縮退) の 4)。

- 帯の往復 (§3.4) は、応答の下に「関係しそうな記録 (この応答には使っていません)」として、セッション名・日時・その往復の利用者の発話の冒頭 (1 行、30 文字ほど) で出す (本文は詳細の窓で見る)。出典の番号は振らない。
- 利用者は、帯の往復について次の操作ができる (07 §2.5)。
  - **添えて作り直す**: その往復を、すでに添えた往復に **足して** (予算の範囲で)、直前の応答を作り直す (前の応答も残す。`/retry` と同じ形で新しい応答のターンを作る)。作り直した応答のターンの観測値に、利用者が選んで添えたことを記録する。再生成の信号 (FR-311 の弱い信号) は記録しない (前の応答の質への評価ではなく、想起の不足のため)。最新の応答の帯でだけ使える。古い応答の帯では、理由を示して選べなくする。
  - **無関係**: 「この記録は、この問いには関係が無い」の印を付ける。
- 出典の詳細の窓 (添えた往復) でも、「無関係」の印を付けられる。
- 2 つの操作は利用者の明示の操作なので、`recall_feedback` の記録として DB とジャーナルに書く (03 §3.3・§6)。記録には、問いの応答のターン、対象の往復、その時のリランクの生の値とリランカーの model_key を持つ。
- **「無関係」の印の効き方** (v0.2): 記録するだけで、添える判定もしきい値も変えない (v0.4 で較正の信号にする、§3.7。印の意味をそこで決めるまで、判定を変えない)。画面では次のとおりに扱う。
  - 付けたときに「記録しました。今の版では、想起の判定は変わりません (後の版で調整に使います)」と示す。
  - 出典と帯の表示に印を付ける。もう一度選ぶと取り消せる (`recall_feedback` の記録を消す。ジャーナルにも削除の行を書く)。
  - 同じセッションでは、印を付けた往復を帯に出さない (表示だけ。観測値には帯の候補として残す)。

## 6. 検索の評価

- 回帰台帳 (13) とは別に、検索の事例 (問い、正解の記録の ID の組) を `tests/retrieval/` に置く。事例は作った会話だけで作る (11 §9.7)。
- 測るもの: recall@k (k = 3, 10)、nDCG@10、待ち時間の平均と p95。v0.2 からは、関係の無い問いで何も添えなかった割合と、正しく添えた割合も測る。
- 索引・正規化・設定を変える PR では、評価を流して前後を比べる (09 §5)。v0.2 は `cargo xtask eval-retrieval`、v0.6 から `evorag eval retrieval` として利用者のデータにも流せる (結果は外に出さない)。
- 較正の同梱の事例 (§3.7) は、`tests/retrieval/` とは分けて本体に同梱する (同じ事例でしきい値を求めて測ると、良く見えすぎるため)。
