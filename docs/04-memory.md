## 1. メモリとカートリッジ

evorag が応答に添える情報は、出どころで 2 つに分ける。

| | メモリ | カートリッジ (v0.5、[14](14-cartridge.md)) |
|---|---|---|
| 中身 | チャットの会話と、そこから作ったチャンク・ノート・事実 | 文書をまとめた、版のある束 |
| 誰のものか | 利用者とのやり取りそのもの | 外から持ち込んだ知識。配られたもの、または利用者が手元の文書から作ったもの |
| 変わり方 | 会話のたびに増え、sleep-time に統合される。訂正で置き換わる | 版ごとに中身は変わらない。更新は新しい版を入れて切り替える |
| 書き手 | 書き手スレッド (依頼は応答の経路と sleep-time から) | 導入と作成のときだけ (チャット中は読むだけ) |
| 応答での扱い | 「あなたについて覚えていること」「以前の会話」として添える | 「カートリッジ」として出典つきで添える |
| 消し方 | セッションの削除、事実を忘れる | カートリッジを無効化・削除する |
| 保存先 | `evorag.redb` | `cartridges/` (中身) と `evorag.redb` (導入の台帳) |

- 2 つは検索の部品 (05) を共有するが、索引も保存先も分ける。
- 利用者についての事実はメモリを優先し、一般の知識はカートリッジを優先する。両方が食い違うときは、両方を出典つきで添え、食い違うことを示す (05 §4.4)。
- **カートリッジからメモリへは何も書き写さない**。カートリッジの内容が利用者の事実として残ることはない。

## 2. 層

| 層 | 中身 | いつ書くか | 入る版 |
|---|---|---|---|
| セッション | 題名、モード、状態 | 作成・改名・削除のとき | v0.1 |
| ターン | 発話・応答の全文と付帯情報 (状態、model_key、生成の設定、添えたものの ID。v0.2 から観測値、05 §3.6) | 発話は送る前、応答は完了・中断・失敗のとき | v0.1 |
| 信号 | 評価・再生成の生の記録 | 発生したとき | v0.1 |
| 想起への操作 | 候補の帯から添えた操作と、「無関係」の印 (05 §5.2) | 利用者が操作したとき | v0.2 |
| チャンク | 検索のためにターンを区切ったもの (05 §2.4)。本文は持たず、ターンの中の範囲を持つ | ターンの確定のとき (語彙の索引)、sleep-time (埋め込み) | v0.2 |
| ノート | 話題ごとの **検索の鍵** (数往復〜1 セッションの話題を表す短い語句)。その話題の往復の一覧を指す | sleep-time | v0.2 |
| 事実 | 利用者や関わる人・物についての事実 (§5) | sleep-time (書き込みの入口は 1 つ) | v0.3 |
| 訂正 | 訂正の候補と、検証済みの訂正 (§6。種類 `correction`) | sleep-time | v0.3 |
| 事実への指示 | 利用者が事実にした明示の操作 (忘れる・private とその解除・矛盾の値を採る・履歴の値を戻す・印を解く。種類 `fact_directive`、§7.5) | 操作したとき | v0.3 |

- v0.1 では、語彙の索引 (05 §2.1) はターンを直接の単位にする。v0.2 からはチャンクと検索の鍵を単位にする。
- **正本と派生** (03 の冒頭の考え方): 事実と訂正は、ターンから作る派生物である。ただし LLM で作るので、作り直すと同じ結果になるとは限らない。そこで `evorag rebuild` は既定では事実を作り直さない (03 §10)。事実への指示は利用者の明示の操作なので正本にし、ジャーナルにも書く。事実への指示は事実の ID ではなく、作り直しても変わらない鍵 (§5.6・§7.5) に結び付け、事実を作るたびに当て直す。
- **往復**: 利用者の発話と、それへの応答の組。記録は持たず、ターンの `reply_to` から組み立てる。想起で添える単位にする (05 §3.3)。
- **ノートは検索の鍵にし、添えるのは原文にする** (確定、[OQ-36](10-decisions.md#oq-36-想起の規則-候補リランク添え方縮退) の 7): ノートは、問いと元の会話の語彙の違いを補うための索引の項目で、文脈には入れない。鍵で当たったら、鍵が指す往復をリランクして添える。要約が原文と食い違って誤りを持ち込むのを避けるため。
  - 1 つのノートは、1 つの話題の鍵の並びと、その話題の往復の一覧を持つ。索引の項目 (語彙とベクトル) は鍵ごとに作る。鍵で当たったときは、ノートが指す往復のそれぞれに、その鍵の値を付ける (05 §2.4 の「ターンの値」は、その往復のターンに付いた値の最良のもの)。
  - 1 つのノートの鍵は 8 個まで、1 つの鍵は 40 文字までにする。超える出力は切り捨てる。
  - ノートは、型縛りの補助の呼び出し (06 §6) で作る。鍵が出典の往復の本文に (正規化した上で) 含まれる語だけからなる必要はない (言い換えを補うため) が、命令形の文や URL を含む鍵は捨てる (02 §8)。
  - private の事実から鍵を作らない (v0.3)。
- **話題の区切り** (確定、2026-11-12。話題の推定に LLM を使わない。区切り方は派生の記録の作り方なので、`evorag rebuild` で作り直せる): セッションの往復を、古い順に先頭から詰めて区切る。
  - 往復は、利用者の発話と、それへの最新の完了した応答の組にする。完了した応答の無い発話は入れない。
  - 1 つの区切りは 8 往復まで、かつ鍵を作る呼び出しに渡す本文 (往復ごとに発話を 300 文字、応答を 500 文字までに切ったもの) が合わせて 1,600 文字までにする (1 往復は必ず入る)。裏の処理の要求を 2,048 トークンまでにする規則 (§4) に収めるため。
  - 区切りは、往復が 8 つになったか文字数が埋まったとき、またはそのセッションの最後のターンから 10 分過ぎたときに「区切りがついた」とする。
  - 区切りがついた後にセッションが続き、最後の区切りに往復が足されたら、その区切りのノートを作り直す (ノートの往復の一覧が区切りと違えば作り直す。古いノートと、その索引の項目と埋め込みは消す)。
- **鍵の検査** (決定論、`evorag-memory` に置く): 前後の空白を除き、40 文字を超える部分を切り捨てる。空のもの、URL (`://`・`www.`) を含むもの、命令形の文 (「ください」「しろ」「せよ」「無視して」、英語の `ignore`・`you must`・`please` など。一覧は `evorag-memory` に同梱し、プロンプトの言語に関わらず両方を当てる) を含むものを捨てる。重複を除き、9 個目からは捨てる。鍵が 1 つも残らないときは、鍵の無いノートを記録する (同じ区切りで呼び出しを繰り返さないため。索引の項目は作らない)。
- **鍵を作る呼び出し**: 型縛り (06 §6) で `{"keys": [文字列, …]}` を求める。temperature 0・固定の seed・裏の処理のスロット (06 §4) で出し、`llm.chat.aux_request_extra` を足す。点検 (06 §3.3) で型縛りか思考を切るのが通らなかった応答のモデルでは作らない (チャンクと埋め込みだけで動く)。点検がまだのモデルでは、点検を待つ。
- **ノートの版**: ノートは、区切りと鍵の作り方の版 (`rules`) と、作った応答のモデルの model_key を持つ。版が変わったら作り直す。応答のモデルを切り替えても作り直さない (鍵は検索の補助で、`evorag rebuild` で作り直せる)。
- **索引の項目の ID**: 語彙とベクトルの索引の項目は鍵ごとに作り、項目の ID はノートの ID にする (1 つのノートが鍵の数だけ項目を持つ。ノートを消すと、その ID の項目がすべて消える)。鍵の埋め込みの記録 (`embedding`) は、単位 `key` と鍵の位置 (0 から) を持つ。

## 3. 応答の経路での書き込み

1. 利用者が発話を送ると、まず発話のターン (状態「応答待ち」) を確定する (ジャーナル → DB、03 §3.4・§6)。確定に失敗したら、発話を入力欄に戻して知らせ、LLM に送らない。
2. 文脈を組み立てて (05) 生成を始める。
3. 応答は、完了・中断・失敗のいずれかの状態のターンとして書く。中断と失敗の応答も、受け取ったところまでの本文と理由を残す。
4. 応答の経路では、要約も抽出もしない。

- 入力欄の下書き (送る前の文章) は、所有者だけが読める一時ファイルに 5 秒ごとに保存し、次の起動時に戻す。外部のエディタで書いた一時ファイルも同じ置き場所に置き、送った後に消す。

## 4. sleep-time

利用者が操作していない間に進める裏の処理 (v0.2)。

- **起動後の点検** (確定、2026-11-12): モデルの性質の点検 (06 §3.3) とリランカーの較正 (05 §3.7) は、下の sleep-time の手順と分ける。入力が 2 秒途切れ (`idle_seconds` がそれより短ければその長さ)、応答を生成していない間に流し、`memory.sleep_time` と `idle_seconds` には縛らない (「TUI を開いた後に裏で、短い間に」済ませるため)。電池の設定の `stop` と空きの不足では止める。利用者が操作したら、下の「譲る」と同じく切り、次の機会に続ける (較正は済んだ問いの結果を覚えておき、続きから求める)。
- **繰り返しを防ぐ**: 終えたのにまだ要る手順 (結果を保存できなかったなど) と、失敗した較正は、5 分おいてから試し直す (繋がらないサーバや書けない DB に、要求を送り続けないため)。
- **外部のエディタ**: 利用者が外部のエディタで書いている間は、裏の要求を出さない (06 §4 の「入力している間は出さない」)。
- **アイドルの判定** (sleep-time の手順): 次のすべてを満たすときに始める。
  - キー入力が一定の時間 (既定 60 秒、設定 `memory.idle_seconds`) 無い。
  - 応答を生成していない。次のターンの分の先の処理 (05 §4.5) も終わっている。
  - llama-server の chat のスロットに空きがある (06 §4)。
  - 電池の設定 (`memory.on_battery`、07 §4.2) が止めていない。
- **譲る**: 利用者が操作したら (キー入力、発話の送信)、今の手順の LLM の要求 (chat・embed・rerank のどれでも) を 1 秒以内に止める (NFR-105、06 §4)。止めたところまでの結果は、作り直せるものだけを残す。
- **job による再開**: 各手順の進み具合は `job` の記録に残し、次の機会に続ける。強制終了の後も、起動してアイドルになったら続ける。ただし、進み具合を状態から求められる手順は job を書かない (2026-11-12): 埋め込み (手順 1) は「語彙の索引にあってベクトルの索引に無いチャンク」を 32 件ずつ埋め込み、記録と索引への反映を 1 回ごとに落とされない形で行うので、止めても強制終了しても、次の機会に足りない分から続く。ノート (手順 2) も、区切り (§2) と記録したノートを突き合わせて足りない分から作るので job を書かない (1 つのノートは 1 回の呼び出しと 1 回の書き込みで作る)。型が合わずにやり直しても合わなかった区切りは、このプロセスの間は飛ばす (job の代わり)。
- **要る作り直しは状態から求める**: job の記録は裏の処理の結果と同じく失いうる (ジャーナルに書かない、03 §6) ので、job が無いことを「作り直しが要らない」とみなさない。起動時に、軽い検査 (件数と、最後に処理した ID の比較。全件は走査しない、NFR-101) で次を確かめ、足りなければ job を作る。
  - チャンクの無いターン (古い版で足したターンを含む) が無いか。
  - 記録した埋め込みのモデルの索引が、すべてのチャンクと鍵を覆っているか。
  - ノートを作っていない区切りが無いか。
  - 記録したリランカーのしきい値があるか (無ければ較正を裏で流す、05 §3.7)。
- **冪等**: 各手順は **何度やっても結果が同じ** になるように作る。入力 (ターンの ID の範囲) と、手順の版と、使ったモデルの model_key を `job` に記録する。途中で止めてから再開しても、止めずに通したときと同じ結果になる。型縛りの呼び出しは temperature 0・固定の seed・固定のスロットで出す (06 §6)。
- 手順 (版):
  1. 新しいターンのチャンクの埋め込みを作る (v0.2。チャンクへの区切りと語彙の索引への追加は、ターンの確定のときに行う、05 §2.3)。
  2. 区切りのついた話題のノート (検索の鍵) を作る (型縛りの LLM の呼び出し、v0.2)。
  3. 利用者の発話から事実の候補を抽出する (型縛りの LLM の呼び出し、§5.2、v0.3)。
  4. 訂正の候補を字句の規則で見つけ、検証する (型縛りの LLM の呼び出し、§6、v0.3)。
  5. 事実を統合する (重複の除去、置き換え、矛盾の記録。LLM を使わない決定論の規則、§5.3、v0.3)。
  6. 索引の新しいセグメントを作り、入れ替える (事実から作る検索の鍵 (§5.5) を含む、v0.2)。埋め込みのモデルを切り替えたときの作り直し (05 §2.2) もここで進める。
  7. 事実の表を作り直し、変わっていれば次のターンの分を先に処理する (§5.4、v0.3)。
  8. 忘れる・削除の退避の写し直しが残っていれば続ける (写し直しは操作の直後に書き手スレッドの依頼として始め、アイドルの判定を待たない。03 §7.3、v0.3)。
  9. 自動の退避 (03 §7.1、v0.2 から sleep-time で行う)。
  10. カートリッジの埋め込みの不足分を作る (v0.5)。
  11. 自己学習の手順 (13、v0.4)。
- 型縛りの補助の呼び出しを使えないモデル (06 §3.3 の点検で通らない) では、手順 2〜4 を飛ばす (チャンクと埋め込みだけで動く。事実は増えないが、事実の表・忘れる・private は動く)。
- 同じ種類の LLM の呼び出しは続けて流す (抽出をすべて終えてから検証に移る)。どの呼び出しも、指示と属性の一覧の部分をバイト列まで同じにし、可変の部分を末尾に置く。裏のスロットに残ったプロンプトのキャッシュを使い回すため。
- 手順の結果は、入力にしたターンの改訂の番号 (§7.3) と一緒に書く (派生の記録の本体の任意の項目 `src_rev`、03 §3.3)。書き手スレッドは、番号が今のターンと合わない結果を捨てる (処理の途中で忘れる・削除が入ったとき、古い本文から作ったものを書き戻さないため)。
- 裏の処理の LLM の要求は、1 回に送るプロンプトを 2,048 トークン (暫定) までにする。長い入力は分けて送る。
- 裏の処理は、空きの不足 (03 §8)、設定 `memory.sleep_time = false`、電池の設定で止められる。止めても会話の保存と想起 (語彙の索引と、作ってある埋め込み) は動く。

## 5. 事実

### 5.1 事実の形

事実は「主語・属性・値」の組を、1 件ずつの記録 (種類 `fact`) として持つ。同じ組をあとで言い直したときは、新しい記録を作らずに出典を足す。

| 項目 | 内容 |
|---|---|
| `subject` | 誰・何についてか。`self` (利用者本人) か、発話にある呼び名 (「妻」「田中さん」など、正規化した文字列)。抽出で明示させ、既定を置かない |
| `attribute` | 属性の名前。属性の一覧 (同梱の TOML、`evorag-memory/attributes.toml`) にあるものだけ |
| `value` | 値 (文字列。属性ごとの上限、既定 200 文字。型付きの値は v1.0 より後)。値の鍵 (§5.6) を副索引に持つ |
| `tense` | `current` (今も成り立つ) / `past` (以前は成り立っていた) / `planned` (予定) |
| `valid_from` / `valid_to` | 現実で成り立っていた期間。発話に日付があり、決定論の規則で読めたときだけ埋める。分からなければ空 |
| `recorded_at` / `retracted_at` | 記録した時刻と、取り消した時刻 |
| `state` | 下の表 |
| `source` | 出典の集合。各々が、ターンの ID、そのターンの改訂の番号 (§7.3)、本文の中で根拠にした範囲 (span。保存した本文の UTF-8 のバイト位置で、書記素の境界に合わせる) |
| `private` | 応答に添えない印。`fact_directive` (§7.5) から決まる値で、事実の側では書き換えない |

| 状態 | 意味 | 事実の表 (§5.4) |
|---|---|---|
| `Live` | 今の値 | 入る |
| `Contested { against }` | 単値の属性で、今の値と違う値が、置き換えの条件 (§5.3) を満たさずに出てきたもの | 入らない。`/memory` に出す |
| `Superseded { by, at }` | 新しい値に置き換えられた、または以前は成り立っていた (`by` は任意。時制が `past` の値には無い)。`by` の記録が消えた後も、`by` は消えた ID を指したまま残す (§7.4) | 入らない |
| `Retracted { at }` | 忘れた。値と span を消し、出典のターンの ID だけを残す | 入らない |

- `fact` は v0.3 で新しく作る種類なので、状態の値はこの 4 つで始める。値を足すときは、知らない値の読み方 (03 §4.2) を先に決める。
- 属性の一覧は、属性ごとに、単値か多値か、値の長さの上限、事実の表での優先の順 (§5.4)、主語に `self` 以外を許すか、を宣言する。初期内容は v0.3 の着手前に決める (確定、[OQ-12](10-decisions.md#oq-12-属性の一覧の初期内容))。一覧に無い属性の候補は捨てて数え、`doctor` が報告する (一覧を広げる材料にする)。
- 一覧は版を持つ。属性を消したり意味を変えたりせず、足すだけにする。

### 5.2 抽出

抽出は sleep-time の手順 3 で、型縛りの LLM の呼び出し (06 §6) で行う。

- **出典は利用者の発話だけ** にする。応答・利用者が貼った引用・カートリッジからは抽出しない (確定、[OQ-20](10-decisions.md#oq-20-事実を抽出してよい出典))。貼られた文書に埋め込まれた指示が、事実として信頼する枠に入るのを防ぐため (02 §8)。
- **前のふるい** (LLM に送らないもの。決定論):
  - コードブロックと、引用の記号で始まる行を除く。
  - 端末の貼り付け (bracketed paste) の範囲では除かない。IME の確定の文字列も貼り付けとして届くことがあり (S-03)、端末によっては貼り付けを見分けられないため。貼り付けの範囲と、見分けが効いていたかはターンに観測値として残し、除く材料にするかは検証 (08 §3 の S-16) の結果で決める。引用の中の指示が事実に入るのは、関門 1〜6 で防ぐ。
  - 除いた残りが短い発話と、同梱の一覧 (挨拶・相槌) に当たる発話は送らない。短さのしきい値は言語ごとに決める (暫定で、日本語は内容の単位 (05 §2.1) が 4 つ未満、英語は語が 2 つ未満)。
- **束ね方**: 発話を `/tokenize` の数 (ターンごとにキャッシュする、06 §8) で束に詰め、1 回に渡す発話は 800 トークンまで (暫定) にする。1 回の呼び出しを 1 つの `job` の単位にする (止められたときに捨てる分を小さくするため)。
- **既存の事実はプロンプトに入れない**。要求が長くなり、先頭が毎回変わり、既存の値を写してしまう恐れがあるため。今の値との突き合わせは統合 (§5.3) で決定論に行う。
- **出力の型** (候補 1 件ごと。キーは短くする。候補が無ければ空の配列だけを返させる):

  | 項目 | 内容 |
  |---|---|
  | `t` | 束の中の発話の番号 (束の範囲だけの列挙) |
  | `s` | 主語 (`self` か呼び名) |
  | `a` | 属性 (一覧の名前だけの列挙) |
  | `v` | 値 |
  | `e` | 根拠の文字列 (発話からの逐語の写し) |
  | `m` | 叙法: `fact` (言い切り) / `negated` (否定) / `question` (問い) / `hypothetical` (仮定・願望) |
  | `tn` | 時制: `current` / `past` / `planned` |
  | `old` | 置き換える古い値が発話にあれば、その逐語の写し (無ければ空) |

- **関門** (決定論。1 つでも外れた候補は捨てて、理由ごとに数える):
  1. `e` が、番号 `t` の発話の (前のふるいの後の) 本文に含まれる。まず生の本文で照合し、外れたら値の鍵の正規化 (§5.6) の後で照合して、位置の対応表で元の位置に戻す (LLM が全角・半角や括弧を直して写すことがあるため。後者は別の理由として数える)。その位置を、前のふるいで除いた分を足し戻した保存した本文の位置に直して span にする。
  2. `v` が `e` に含まれる。`old` があれば、それも `e` に含まれる。照合は値の鍵の正規化の後で行い、英数字の並びは語の境界で一致させる ("Ann" を "annual" に当てない)。
  3. `m` が `fact` である。`negated` は、§5.3 の「否定」の規則にだけ使う。`question` と `hypothetical` は捨てる。
  4. `e` の中で、値が日本語の括弧 (「」『』) や引用符の内側にない。ただし同梱の規則 (TOML) で、名前の呼び方などの許す型を定める。
  5. `s` が `self` 以外なら、属性の一覧がその属性に主語の `self` 以外を許している。
  6. 値に、指示に読める文 (命令形の文・他の指示への言及。同梱の規則。名前の呼び方 ("Call me Ken"、「ケンと呼んで」) などの許す型を規則で定める)、改行 (U+2028・U+2029・NEL を含む)、表の区切り (`|`・`｜`・`│`)、URL が無い。判定は NFKC の後に行う。
  7. 値の長さが属性の上限の内にある。
  8. 再び覚えない印 (§7.6) に当たらない。
- 規則の TOML は言語ごとに持ち、版を持つ。規則は 2 つに分けて当てる。
  - **安全の規則** (関門 4・6、挨拶・相槌の一覧): 同梱のすべての言語の規則を合わせて当てる。プロンプトの言語が `ja` のデータ根でも、英語の発話は来るため (07 §6.1)。安全の側に倒れて取りこぼしが増えるのは受け入れる。
  - **読み取りの規則** (主語を明示する語、変化を示す語、訂正の型): 根拠 `e` の文字種から言語を判定して、その言語の規則を選ぶ。
  - 語の照合は、英語は語の境界で、日本語は除外の語の一覧 (「私」に対する「私立」「私鉄」など) を持って行う。

### 5.3 統合

統合は sleep-time の手順 5 で、**LLM を使わない決定論の規則** で行う (確定 (ユーザー回答)、[OQ-46](10-decisions.md#oq-46-事実の統合と事実への操作の結び付け先))。private の事実を、事実として LLM に渡すことは無い ([OQ-21](10-decisions.md#oq-21-private-の事実を裏の処理に渡すか) の注)。ただし、発話の本文は抽出・ノート・訂正の検証の入力として、private の値を含んだまま裏の呼び出しに渡りうる (`llm.allow_remote` の構成では外の機械に出る。private の確認の文言に書く)。

- **入力の順**: 候補は (ターンの ID, span の始まり) の順に 1 件ずつ当てる。出典は集合で持つので、同じ候補をやり直しで 2 回当てても結果は同じ。
- **同じ値**: (主語, 属性, 値の鍵) が同じ `Live`・`Contested` の事実があれば、出典を足すだけにする。
- **単値の属性**: 新しい値で今の `Live` を `Superseded` にするのは、次のどれかのときだけ。
  - 候補が `tn = current` の言い切りで、根拠の文字列に、主語を明示する語 (`self` なら「私」「僕」「自分」など、ほかの主語なら呼び名) か、変化を示す語 (「引っ越した」「変わった」「転職した」など) がある。どちらの語も同梱の TOML の規則で決定論に判定する。
  - 検証済みの訂正 (§6) が、今の値から新しい値への向きを持つ。
  - 同じ値の `Contested` の出典が、2 つ以上の別のターンになった (言い直された。最初の出典も数える)。
  - それ以外で今の値と違う値は `Contested { against: 今の Live の ID }` にする (「矛盾の記録」)。今の値が無ければ `Live` にする。
  - `Live` が替わったら、同じ (主語, 属性) の残りの `Contested` の `against` を新しい `Live` に付け替える。新しい `Live` と同じ値の `Contested` は、新しい `Live` に出典を合わせて消す。
- **多値の属性**: 古い値の 1 件を置き換えるのは、次のどちらかのときだけ。特定できなければ並べて足し、兄弟の値には触れない。
  - 候補の `old` の値の鍵 (§5.6) が、今の `Live` の値の 1 件とちょうど一致する。
  - 検証済みの訂正の古い値の値の鍵が、今の `Live` の値の 1 件とちょうど一致する。
- **時制**: `past` の候補は、その値が今の `Live` なら `Superseded` にして `valid_to` を埋める (今の値で置き換えたことにはしない)。今の値でなければ、`Superseded` の状態で履歴として足す。`planned` は、単値の属性でも `current` とは別の枠に 1 件だけ `Live` で持ち、事実の表では「予定」と示す。`planned` と同じ値の `current` の候補が来たら、予定の値を今の値に移す。
- **否定**: `negated` の候補は、値が今の `Live` の値と一致し、根拠に変化を示す語 (「もう」「やめた」"no longer" など) があるときだけ、その `Live` を `Superseded` にする (その属性は「今の値なし」になる)。それ以外の否定は捨てる。
- **削除しない**: 置き換えた値も残す。「いつ何を言っていたか」に答えられ、誤った置き換えを戻せる。
- **書き込みの入口は 1 つ**: 事実を書く関数は `evorag-memory` の 1 つだけにし、次を必ず通す。
  1. 関門の 6・7 (抽出のほかの経路から入る値にも当てる)。
  2. 事実への指示 (§7.5) の当て直し (private の印を決め、忘れた値を拒み、利用者が採った値・戻した値を守る)。
  3. 上の畳みの規則。
- 置き換えの連鎖と出典は `links` で持ち、(主語, 属性) と (主語, 属性, 値の鍵) を副索引に持つ (03 §3.3)。値の文字列そのものはキーに入れない。
- **出典の無い事実の掃除** (03 §4.2 の規則 12 の突き合わせに足す。v0.3 で使ったデータ根を v0.2.x に戻してセッションを消すと、v0.2.x は事実を知らないので残るため): 出典のターンの一部が無い事実は、その出典を外し (セッションの削除と同じ、§7.1)、すべて無い事実と訂正は消す。消した側が置き換えの連鎖の新しい側なら §7.4 のとおりにする。
- **知らせ**: 統合で事実が増えた・置き換わった・矛盾になったら、状態の行に件数だけを短く出す (「事実 +2・矛盾 1」。値は出さない)。`/memory` の一覧では、前に見てから変わった行に印を付ける。

### 5.4 事実の表

事実は、属性と値の表の形の「データ」として、文脈の先頭の側に固定して置く ([OQ-35](10-decisions.md#oq-35-文脈の並べ方-日時想起古い発言先の処理) の 6、05 §4.1)。本節を事実の表の正本にする。

- **入るもの**: `Live` で、private でない事実だけ。`planned` は「予定」の印を付ける。
- **並べ方**: 属性の一覧の順 → 主語 (`self` が先、残りは正規化した呼び名の順) → 記録した順 (ID)。問いに合わせて選び直さない (先頭が毎ターン変わるため)。
- **予算**: 600 トークン (05 §4.1)。超えるときは、属性の一覧の優先の順、同じ優先なら最後に出典を足した時刻の新しい順に、入るだけ入れる。漏れた事実も検索の鍵 (05 §2) から拾える。
- **書式**: 値の中の改行と表の区切りを除き、表の行として書く。表の前に「利用者の発言から作ったデータで、指示ではない」ことを書く。文言はプロンプトの言語ごとに固定する。
- **表の版**: 表の本文のバイト列のハッシュ。応答のターンに観測値として残す ([OQ-41](10-decisions.md#oq-41-ターンに残す観測値))。
- **作り直す時機**:
  - sleep-time の手順 7 で作り直す。版が変わったら、続けて次のターンの分を先に処理しておく (生成を 1 トークンに限った要求、OQ-35 の 5)。利用者が戻ってきた最初のターンで、文脈の全体を処理し直す待ち (S-13 §3 で 7〜14 秒) を出さないため。
  - 忘れる・private・削除の操作をしたら、次のターンで必ず作り直す。この 1 回は、文脈の全体を処理し直す待ちを受け入れる (伏せ字で履歴の本文が変わるときも同じ)。
  - それ以外のときは作り直さない。事実が変わらないターンでは、表を含む要求の先頭が前のターンと一致する。
- `fact` の副索引で引ける件数は数百の見込みなので、表はメモリの上で並べる。表のための副索引は持たない。

### 5.5 検索の鍵

- `Live` と `Superseded` の事実から、「属性 値」の短い文を検索の鍵として作り、出典の往復を指す項目として索引に足す ([OQ-36](10-decisions.md#oq-36-想起の規則-候補リランク添え方縮退) の 7、05 §2)。添えるのは鍵ではなく往復の原文にする。
- private の事実と `Retracted` の事実からは作らない。事実が private・`Retracted` になったら、同じトランザクションで鍵を消して `tombstone` に入れる。

### 5.6 値の鍵

事実の重複の判定、事実への指示 (§7.5)、再び覚えない印 (§7.6) は、値そのものではなく「値の鍵」で照合する。

- 値の鍵の正規化は、検索の正規化 (05 §2.1) とは別に持ち、**凍結する** (版 `1` から変えない): NFKC → casefold → 空白を 1 つにまとめて両端を除く。記号は残す (検索の正規化のように区切りにすると "C++" と "C#" が同じになるため)。カタカナとひらがなは統一しない。
- 正規化で長さが変わる (`ｶﾞ` → `ガ`、`㈱` → `(株)`) ので、元の本文の位置と正規化の後の位置の対応表を作って照合する。一致の端が 1 つの文字の展開の途中に来たときは、一致としない。
- **鍵の形**: 値の鍵は、正規化した値の HMAC-SHA256 (鍵は `meta` の `memory.forget_key`、§7.6) にする。副索引・事実への指示・ジャーナルには、この鍵だけを書き、値の文字列を書かない (03 §3.3)。再び覚えない印は、(主語, 属性, 値の鍵) をこの順に区切って連ねたものの HMAC-SHA256 にする。
- 正規化を変えるときは、版 `2` の正規化として足し、事実への指示と印に正規化の版を書く。古い版の印は古い版の正規化で照合する (値を持たないので、作り直せないため)。

## 6. 訂正

- **候補**: sleep-time に、利用者の発話を字句の規則 (同梱の TOML の、穴のある型。「{old}じゃなくて{new}」「{new}、{old}ではなく」"{new}, not {old}"、"I meant {new}" など) で調べ、当たったものを候補として `correction` に書く。信号の種類 (`signal`) には値を足さない (03 §4.2 の規則 11)。
- **検証**: sleep-time の手順 4 で、候補にだけ、型縛りの LLM の呼び出しで判定する (候補は少ないので、抽出とは別の呼び出しにする)。渡すのは、候補の発話と、その直前の応答 (信頼しない引用の枠に入れる。抽出の出典にはしない)。
  - 出力: 直したのは事実か応答の誤りか、古い値、新しい値、根拠の文字列。
  - 関門 (決定論): 新しい値と根拠が候補の発話に含まれる (照合は §5.2 の関門 1・2 と同じ)。古い値が、直前の応答か、利用者のそれより前の発話か、今の `Live` の値のどれかに含まれる。向きは、根拠を候補の型に当てて、否定の語 (「じゃなくて」「ではなく」"not" など) が付いた側を古い値とする (語の並びの前後では決めない。英語では新しい値が先に来ることが多いため)。引用 (§5.2 の前のふるい) の中ではない。
  - 関門を通ったものを、検証済みとして同じ `correction` に書く。
- **型**: `correction` の記録は段階 (候補 / 検証済み) を持つが、コードでは別の型にし、事実の置き換え (§5.3) と学習 (13) には検証済みの型しか渡せない。`correction` は v0.3 で新しく作る種類なので、段階の値はこの 2 つで始める。
- **事実への効き方**: 検証済みの訂正は、古い値の値の鍵 (§5.6) が今の `Live` の値の 1 件とちょうど一致するときだけ事実を置き換える。一致しなければ、学習 (13) にだけ使い、事実は変えない。

## 7. 忘れる・消す

### 7.1 操作と結果

| 操作 | 結果 | 版 |
|---|---|---|
| セッションの削除 (`/delete`) | ターン・信号・チャンク・ノート (検索の鍵)・埋め込み (前の世代の索引の分を含む)・想起への操作 (そのセッションの応答への操作と、そのセッションの往復を対象にした操作)・事実から作った検索の鍵を消す。そのセッションだけを出典とする事実と訂正も消す。他にも出典がある事実は、出典の集合から外す。回帰台帳の事例と検索の事例のうち、そのセッションのターンを入力に持つものも消す | v0.1 (ターン・信号) / v0.2 / v0.3 / v0.4 |
| 事実を忘れる (`/forget <番号>`) | 事実を `Retracted` にして値と span を消す。出典の発話の根拠の範囲を伏せ字にする (既定)。伏せ字にしたターンから作った派生物 (チャンク・ノート (検索の鍵)・埋め込み (前の世代の索引の分を含む)・事実から作った検索の鍵・訂正) を消して、作り直しを sleep-time に回す。再び覚えない印 (§7.6) を残す | v0.3 |
| 事実を private にする (`/private <番号>`) | 事実の表と検索の鍵から外し、想起で添える往復の中の値を伏せる (§7.5)。消しはしない。`/private off <番号>` で解く | v0.3 |
| 全消去 (`evorag reset`) | データ根を消す。設定は残す | v0.1 |

- **番号**: `/memory` が最後に表示した事実の一覧の番号 (07 §3)。出典の番号 (05 §5.1) と取り違えないように、`F1`・`F2` のように `F` を付けて示す (履歴の行は `H1`…、忘れた事実の一覧は `X1`…)。事実の ID は打たせない。番号は、その表示のときの一覧に結び付け (内部では事実の鍵で持つ)、表示の後に裏の処理で一覧が変わっても、別の事実を指さない。指した事実が変わっていたら (統合で置き換わった・消えた)、「一覧が更新されました」と出して実行せず、`/memory` をもう一度出す。`/memory history` と `/memory forgotten` は、それぞれ自分の一覧の番号を持つ。
- **確認の画面** (忘れる): 1 つの画面にし、既定のまま Enter で実行できる。対象の主語・属性・値と、伏せ字にする前と後の本文を 1 行ずつ見本として示す。次の選択は畳んで置く。
  - 出典の発話を伏せ字にするか、発話はそのままで事実だけを消すか。既定は伏せ字にする (確定 (ユーザー回答)、OQ-09)。
  - 選んだ値だけか、同じ (主語, 属性) の置き換えの履歴 (`Superseded` の値) もまとめて忘れるか。既定は選んだ値だけ。
  - 伏せ字にするとき: 同じ往復の応答の中で、値の鍵 (§5.6) が一致する範囲も伏せるか (既定は伏せる)。ほかのターンで一致する範囲の件数も示し、まとめて伏せることを選べる。
- **伏せ字にしないで忘れたとき**: 出典の発話は DB・ジャーナル・退避にそのまま残る。事実の表と検索の鍵からは消え、想起で添える往復と帯に出す往復の中の値 (出典の span と、同じ往復で値の鍵が一致する範囲) は、private と同じく `[非表示]` にする (§7.5)。確認の画面に、発話が残ることを書く。
- 確認の画面には、約束する範囲 (§7.2) と約束しない範囲 (§7.8) を書く (畳んでよい)。private の確認の画面には、消しはしないこと、今のセッションのこれまでのやり取りには残ること、llama-server には今の値を送らなくなるだけであることを書く。
- **会話の中の依頼**: 利用者が会話の中で「忘れて」「覚えておいて」と頼んでも、モデルには記録を変える手段が無い。システムプロンプト (凍結の核) に、その依頼には `/memory`・`/forget`・`/private` を案内し、忘れた・覚えたと答えないことを書く。

### 7.2 即時に反映する範囲 (約束する範囲)

削除と忘れるの操作をしたら、書き手スレッドが **すぐに** 次から取り除く (確定 (ユーザー回答)、[OQ-09](10-decisions.md#oq-09-忘れるの約束の範囲))。

| 場所 | 取り除き方 |
|---|---|
| `evorag.redb` | 1 つのトランザクションで、事実を `Retracted` にし (削除なら記録を消し)、ターンの本文を伏せ字にして改訂の番号を上げ、同じターンのほかの事実の span を写し直し、そのターンから作った派生物 (チャンク・ノート・埋め込み・検索の鍵・訂正) を消し、消した ID を `tombstone` に書く。次の起動時に compact する |
| ジャーナル | 操作 (削除の行、忘れるの `fact_directive` の `put` の行) を先に書く (03 §6)。コミットの後に、対象のターンの `put` の行を含む月のファイルを書き直して入れ替える。対象の ID の `put` の行はすべて (確定の前と後の両方) 対象にし、削除は行を除き、伏せ字は伏せ字にした封筒の `put` の行 1 つに差し替える。対象の ID を含む読めない行は除く |
| 索引 | 消した ID を読み出しの段階で除く。そのセグメントを優先して作り直す (セグメントの `header.json` に持つ ID の最小と最大から、対象を含み得るセグメントだけを選ぶ)。古いセグメントは参照が外れたらすぐ消す。消せないとき (Windows で写像したまま) は、読み手が入れ替わった後にもう一度消し、それでも残れば次の起動時に消す。残っている間は `doctor` が報告する。前のモデルの世代の索引 (05 §2.2) と、v0.1 の索引 (`lex/`) が残っていれば、それも同じく作り直すか消す |
| 退避 | 対象を含む退避を、対象を除いて写し直す (03 §7.3)。日次・週次と、移行と作り直しの前の退避 (03 §7.2) のすべて |
| `quarantine` | 対象の ID の記録を消す |
| `broken/` | ファイルがあれば、消すかを尋ねる |
| 想起の途中 | 候補を集めてから添えるまでの間に操作が入りうるので、添える直前と候補の帯に出す直前に、`tombstone` の ID、private の値、伏せ字の前の改訂の番号から作った派生物を、もう一度ふるい分ける (05 §3.4、[OQ-42](10-decisions.md#oq-42-先に済ませる処理と外へ出る経路電池) の 6)。先に済ませた処理 (05 §4.5) の結果と、問いの埋め込みのキャッシュ (05 §3.1) は捨てる |
| llama-server | サーバが消去の API を持つ構成 (`--slot-save-path` 付き) のときだけ、スロットのキャッシュの消去を要求する。既定の構成では消去の API が無い。キャッシュは主記憶に llama-server を再起動するまで残りうるので、§7.8 の約束しない範囲に入れる (OQ-42 の 5、06 §4) |

- **まとめて写し直す**: 退避の写し直しは費用が大きい (10 万件で 1 世代 1.2〜1.4 秒、S-01) ので、続けてした操作をまとめ、対象を含み得ない世代を飛ばす。手順は 03 §7.3 を正本にする。写し直しを待つ間も、restore はジャーナルの操作を当て直すので (下)、忘れたものは蘇らない。
- **ジャーナルの書き直し**: 書き直すファイルの選び方・突き合わせ・取っ手の開き直し・失敗のときの再試行は 03 §6 を正本にする。
- **検索の事例と回帰台帳**: 忘れるでは、伏せ字にしたターンを入力に持つ検索の事例を消し、回帰台帳の事例は 13 §4 のとおりに扱う (削除は §7.1 の表のとおり)。
- **派生の記録に届かない経路** (03 §4.2 の規則 12): 古い版 (v0.2.x など) は、新しい版の種類 (事実・訂正・事実への指示) を知らないので、セッションを消しても、それらを消さない。新しい版は、規則 12 の突き合わせで、出典の無くなった事実・訂正・事実から作った検索の鍵を消す (退避からも除く。§5.3 の「出典の無い事実の掃除」)。それまでの間も、出典の無い事実は、事実の表・想起・`/memory`・書き出しから除かれる。
- 削除のときに退避から除く ID には、派生の記録の ID も入れる (03 §7.3)。
- **当て直し**: restore・repair・ジャーナルの取り込みは、退避の後にした削除・忘れるを、ジャーナルから必ず当て直す。v0.3 の起動時にも、ジャーナルにあって書き直しの済んでいない忘れるを当てる (古い版で開いた間に取り込まれなかった分を含む)。
- **`apply_forget` の分け方**: 忘れるの当て直しは、次の 3 つの層で作る。何度当てても結果が同じになる。
  1. **純粋な核**: (本文, 改訂の番号, 伏せ字の範囲, 印) → 「当てた本文」/「当て済み」/「合わない」。
  2. **DB の層**: 核を、生きている DB と、退避を写した DB (写し直しの途中のもの) の両方に、同じ関数で当てる。
  3. **ジャーナルの層**: 核の結果で `put` の行を差し替える。

### 7.3 伏せ字

- 伏せ字は、本文の範囲を固定の印 (`[伏せ字]`。文言はプロンプトの言語ごと) に置き換える。範囲は保存した本文の UTF-8 のバイト位置で持ち、書記素の境界 (結合文字・異体字セレクタ・ZWJ の並びを分けない) に合わせる。
- 置き換える前に、範囲の文字列の値の鍵 (§5.6) が、忘れる値と一致することを確かめる。1 つでも合わなければ、その忘れるの操作の全体を中止し、本文も事実も変えずに理由を示す (関係の無い本文を失わず、事実だけが消えて発話が残る中途半端な状態も作らないため)。
- ターンは改訂の番号 (任意の項目、03 §3.3) を持ち、伏せ字にするたびに上げる。当て済みかどうかは、改訂の番号と伏せ字の後の本文のハッシュで判定する (伏せ字の前の本文のハッシュは持たない。伏せ字の後の本文に値の候補を入れて照合すれば、値を当てられるため)。
- 裏の処理の結果は、入力の改訂の番号が今と合わなければ捨てる (§4)。ターンの付帯の項目 (観測値など) を更新するときは、書き手のトランザクションの中で記録を読み直してから書く (外で読んだ本体を丸ごと書き戻さない)。
- 伏せ字で本文の長さが変わったら、同じトランザクションで、同じターンのほかの事実の span と貼り付けの範囲を写し直す。
- ターンの `v` は上げない。v0.2 は本文を書き換えず (状態の更新だけ)、本体の知らない項目を保つので、改訂の番号が古い版に壊されないため。`v` を上げると、v0.2 に戻したときにターンの状態を更新できなくなる。
- 伏せ字の印について、システムプロンプト (凍結の核) に「利用者が伏せた部分で、推測も言及もしない」と書く。画面では、伏せ字と `[非表示]` を本文と見分けられる表示にする。

### 7.4 削除と置き換えの連鎖

- セッションの削除で (確定 (ユーザー回答)、[OQ-49](10-decisions.md#oq-49-置き換えの連鎖の新しい側が消えたとき))、置き換えの連鎖の新しい側の事実が消えたとき、古い側の `Superseded` の事実を `Live` に戻さない。古い値を今の値として添えてしまうため。その (主語, 属性) は「今の値なし」になり、古い側の `by` は消えた ID を指したまま残す。
- 同じ (主語, 属性) に `Contested` の値があり、その出典の最も新しいターンが、消えた値の出典の最も新しいターンより後なら、それを `Live` にする (2 つ以上あれば、出典の最も新しいターンが最も後のもの)。
- 忘れるで `Live` の値を `Retracted` にしたときも同じ扱いにする。
- 利用者は `/memory` で、今の値が消えた属性と `Contested` の値を見て、次の操作で直せる (07 §3)。どちらも事実への指示 (§7.5) として残し、事実を作り直しても効く。
  - `/memory accept <番号>`: `Contested` の値を今の値にする。
  - `/memory revert <履歴の番号>`: 履歴の値を今の値に戻す。

### 7.5 事実への指示 (`fact_directive`)

利用者が事実にした明示の操作は、事実とは別の正本の記録として持つ。ジャーナルには、新しい操作の行ではなく `fact_directive` の `put` の行として書く (古い版は知らない種類の `put` を読み飛ばさずに保つが、知らない操作の行は読み飛ばし、取り込みの連番がその先へ進んでしまうため、03 §6)。事実を作り直しても (`rebuild --facts`、統合のやり直し)、指示を当て直せば同じ結果になる。

| 指示 | 持つもの | 当て方 |
|---|---|---|
| 忘れる | 伏せ字の一覧 (ターンの ID・伏せ字の後の改訂の番号・バイト範囲・伏せ字の後の本文のハッシュ)、再び覚えない印 (§7.6)、履歴もまとめたか、値の鍵の正規化の版 | `apply_forget` (§7.2)。値そのものは持たない |
| private | (主語, 属性)、値の鍵、効く範囲 (後継まで / この値だけ)、値の鍵の正規化の版 | 書き込みの入口 (§5.3) で、合う事実に private の印を付ける |
| private の解除 | 対象の private の指示の ID | 印を外す |
| 採る (`accept`) / 戻す (`revert`) | (主語, 属性)、値の鍵 | 書き込みの入口で、その値を今の値にする。後から統合が置き換えの条件を満たす値を見つけたら、通常どおり置き換える |
| 印を解く (`unblock`) | 対象の忘れるの指示の ID | 関門 8 (§5.2) でその印を照合しない |

- どの指示にも、操作したときの事実の ID を参考の情報として持たせてよい。当てるときは使わず、鍵 (主語・属性・値の鍵) と出典の (ターン, 範囲) で当てる (事実の ID は作り直すと変わるため)。
- **private の効く範囲** (確定 (ユーザー回答)、[OQ-47](10-decisions.md#oq-47-private-の効く範囲)): 既定は、指定した値と、同じ (主語, 属性) にあとで入る値 (後継) の両方にする。病名のような属性で、新しい値が private でないまま入るのを防ぐため。確認の画面で「この値だけ」も選べる。
- **想起での private**: 往復の原文を添えるとき (OQ-36 の 7)、private の事実の出典の span と、同じ往復の中で値の鍵が一致する範囲を、`[非表示]` (プロンプトの言語ごと) に置き換えてから添える。往復の全体は除かない (ほかの話題を落とさないため)。回帰台帳の事例 (13 §4) とリプレイにも同じ置き換えを当てる。

### 7.6 再び覚えない印

忘れた事実を、次の抽出や作り直しで再び覚えないための印 (確定 (ユーザー回答)、[OQ-48](10-decisions.md#oq-48-忘れた事実を再び覚えない印))。

- 伏せ字にした発話からは、値が消えているので再び抽出されない。そのため印が要るのは、伏せ字にしないことを選んだときと、同じ値を別のターンで言っていたとき。
- 印は、データ根ごとの乱数の鍵 (`meta` の `memory.forget_key`。最初に要るときに 1 度だけ作り、ジャーナルにも一度だけ書く `meta` の行として書く、03 §6) による HMAC-SHA256 で、(主語, 属性, 値の鍵) から作る (§5.6)。値だけのハッシュにしない (短い値は辞書で戻せるうえ、別の属性の同じ値まで止めてしまう)。
- 鍵はデータ根と退避の中にあるので、データ根を手に入れた者は値を推測して照合できる。これは約束しない範囲に書く (§7.8)。鍵を消すことで消す方式は OQ-27 で扱う。
- 抽出の関門 8 (§5.2) で印に当たった候補は、黙って捨てて数える (値を画面にも出さない)。利用者がまた覚えさせたいときは、`/memory forgotten` の一覧 (主語・属性・忘れた日時・出典のセッションの題名を示し、値は出さない) から `/memory unblock <番号>` で印を解く (07 §3)。

### 7.7 tombstone

- 消した ID は `tombstone` に記録し、索引を作り直すまでは読み出しの段階で除く。`tombstone` は本文を持たない。
- 伏せ字ではターンの ID は残るので、ターンの ID は `tombstone` に入れない。代わりに、そのターンから作った派生物の ID を入れる (§7.2)。

### 7.8 約束しない範囲 (確認の文言に書く)

- 利用者が書き出したファイル、OS のバックアップ (ファイル履歴、Time Machine)、SSD の物理的な消去、llama-server のログ (`-v` など)、llama-server が主記憶に持つプロンプトのキャッシュ (llama-server を再起動するまで残りうる、OQ-42 の 5) とスロットの保存 (`--slot-save-path`)。
- 古い版に戻して消したもの: v0.3 で使ったデータ根を v0.2.x で開いて消したセッションは、v0.3 の派生物 (事実・訂正・事実から作った検索の鍵) と、それを含む退避に、**v0.3 で開き直すまで残る** (v0.2.x はそれらを知らないため)。v0.2 の派生物については v0.2 のリリースノートのとおり。v0.3 のリリースノートに書く。
- 古い版では忘れるができない。v0.2.x で開いている間に、忘れた事実と同じ値を言っても、v0.3 で開き直したときに再び覚えない印で捨てる。
- 次の起動時の compact までの間、DB のファイルの空きの領域に残る消した記録。空きが足りず compact できないときは、次の起動時にやり直し、それまで `doctor` と状態の行で知らせる (03 §8)。Windows で消せずに残った索引のセグメント (次の起動時に消す)。
- 再び覚えない印から、値を推測して照合されうること (§7.6)。
