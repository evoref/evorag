## 1. メモリとカートリッジ

evorag が応答に添える情報は、出どころで 2 つに分ける。

| | メモリ | カートリッジ (v0.5、[14](14-cartridge.md)) |
|---|---|---|
| 中身 | チャットの会話と、そこから作ったチャンク・ノート・事実 | 文書をまとめた、版のある束 |
| 誰のものか | 利用者とのやり取りそのもの | 外から持ち込んだ知識。配られたもの、または利用者が手元の文書から作ったもの |
| 変わり方 | 会話のたびに増え、sleep-time に統合される。訂正で置き換わる | 版ごとに中身は変わらない。更新は新しい版を入れて切り替える |
| 書き手 | 書き手スレッド (依頼は応答の経路と sleep-time から) | 導入と作成のときだけ (チャット中は読むだけ) |
| 応答での扱い | 「あなたについて覚えていること」「以前の会話」として添える | 「カートリッジ」として出典つきで添える |
| 消し方 | セッションの削除、事実を忘れる | カートリッジを無効化・削除する |
| 保存先 | `evorag.redb` | `cartridges/` (中身) と `evorag.redb` (導入の台帳) |

- 2 つは検索の部品 (05) を共有するが、索引も保存先も分ける。
- 利用者についての事実はメモリを優先し、一般の知識はカートリッジを優先する。両方が食い違うときは、両方を出典つきで添え、食い違うことを示す (05 §4.4)。
- **カートリッジからメモリへは何も書き写さない**。カートリッジの内容が利用者の事実として残ることはない。

## 2. 層

| 層 | 中身 | いつ書くか | 入る版 |
|---|---|---|---|
| セッション | 題名、モード、状態 | 作成・改名・削除のとき | v0.1 |
| ターン | 発話・応答の全文と付帯情報 (状態、model_key、生成の設定、添えたものの ID。v0.2 から観測値、05 §3.6) | 発話は送る前、応答は完了・中断・失敗のとき | v0.1 |
| 信号 | 評価・再生成の生の記録 | 発生したとき | v0.1 |
| 想起への操作 | 候補の帯から添えた操作と、「無関係」の印 (05 §5.2) | 利用者が操作したとき | v0.2 |
| チャンク | 検索のためにターンを区切ったもの (05 §2.4)。本文は持たず、ターンの中の範囲を持つ | ターンの確定のとき (語彙の索引)、sleep-time (埋め込み) | v0.2 |
| ノート | 話題ごとの **検索の鍵** (数往復〜1 セッションの話題を表す短い語句)。その話題の往復の一覧を指す | sleep-time | v0.2 |
| 事実 | 利用者や関わる人・物についての事実 (§5) | sleep-time (書き込みの入口は 1 つ) | v0.3 |
| 訂正 | 訂正の候補と、検証済みの訂正 (§6。種類 `correction`) | sleep-time | v0.3 |
| 事実への指示 | 利用者が事実にした明示の操作 (忘れる・private とその解除・矛盾の値を採る・履歴の値を戻す・印を解く。種類 `fact_directive`、§7.5) | 操作したとき | v0.3 |

- v0.1 では、語彙の索引 (05 §2.1) はターンを直接の単位にする。v0.2 からはチャンクと検索の鍵を単位にする。
- **正本と派生** (03 の冒頭の考え方): 事実と訂正は、ターンから作る派生物である。ただし LLM で作るので、作り直すと同じ結果になるとは限らない。そこで `evorag rebuild` は既定では事実を作り直さない (03 §10)。事実への指示は利用者の明示の操作なので正本にし、ジャーナルにも書く。事実への指示は事実の ID ではなく、作り直しても変わらない鍵 (§5.6・§7.5) に結び付け、事実を作るたびに当て直す。
- **往復**: 利用者の発話と、それへの応答の組。記録は持たず、ターンの `reply_to` から組み立てる。想起で添える単位にする (05 §3.3)。
- **ノートは検索の鍵にし、添えるのは原文にする** (確定、[OQ-36](10-decisions.md#oq-36-想起の規則-候補リランク添え方縮退) の 7): ノートは、問いと元の会話の語彙の違いを補うための索引の項目で、文脈には入れない。鍵で当たったら、鍵が指す往復をリランクして添える。要約が原文と食い違って誤りを持ち込むのを避けるため。
  - 1 つのノートは、1 つの話題の鍵の並びと、その話題の往復の一覧を持つ。索引の項目 (語彙とベクトル) は鍵ごとに作る。鍵で当たったときは、ノートが指す往復のそれぞれに、その鍵の値を付ける (05 §2.4 の「ターンの値」は、その往復のターンに付いた値の最良のもの)。
  - 1 つのノートの鍵は 8 個まで、1 つの鍵は 40 文字までにする。超える出力は切り捨てる。
  - ノートは、型縛りの補助の呼び出し (06 §6) で作る。鍵が出典の往復の本文に (正規化した上で) 含まれる語だけからなる必要はない (言い換えを補うため) が、命令形の文や URL を含む鍵は捨てる (02 §8)。
  - private の事実から鍵を作らない (v0.3)。
- **話題の区切り** (確定、2026-11-12。話題の推定に LLM を使わない。区切り方は派生の記録の作り方なので、`evorag rebuild` で作り直せる): セッションの往復を、古い順に先頭から詰めて区切る。
  - 往復は、利用者の発話と、それへの最新の完了した応答の組にする。完了した応答の無い発話は入れない。
  - 1 つの区切りは 8 往復まで、かつ鍵を作る呼び出しに渡す本文 (往復ごとに発話を 300 文字、応答を 500 文字までに切ったもの) が合わせて 1,600 文字までにする (1 往復は必ず入る)。裏の処理の要求を 2,048 トークンまでにする規則 (§4) に収めるため。
  - 区切りは、往復が 8 つになったか文字数が埋まったとき、またはそのセッションの最後のターンから 10 分過ぎたときに「区切りがついた」とする。
  - 区切りがついた後にセッションが続き、最後の区切りに往復が足されたら、その区切りのノートを作り直す (ノートの往復の一覧が区切りと違えば作り直す。古いノートと、その索引の項目と埋め込みは消す)。
- **鍵の検査** (決定論、`evorag-memory` に置く): 前後の空白を除き、40 文字を超える部分を切り捨てる。空のもの、URL (`://`・`www.`) を含むもの、命令形の文 (「ください」「しろ」「せよ」「無視して」、英語の `ignore`・`you must`・`please` など。一覧は `evorag-memory` に同梱し、プロンプトの言語に関わらず両方を当てる) を含むものを捨てる。重複を除き、9 個目からは捨てる。鍵が 1 つも残らないときは、鍵の無いノートを記録する (同じ区切りで呼び出しを繰り返さないため。索引の項目は作らない)。
- **鍵を作る呼び出し**: 型縛り (06 §6) で `{"keys": [文字列, …]}` を求める。temperature 0・固定の seed・裏の処理のスロット (06 §4) で出し、`llm.chat.aux_request_extra` を足す。点検 (06 §3.3) で型縛りか思考を切るのが通らなかった応答のモデルでは作らない (チャンクと埋め込みだけで動く)。点検がまだのモデルでは、点検を待つ。
- **ノートの版**: ノートは、区切りと鍵の作り方の版 (`rules`) と、作った応答のモデルの model_key を持つ。版が変わったら作り直す。応答のモデルを切り替えても作り直さない (鍵は検索の補助で、`evorag rebuild` で作り直せる)。
- **索引の項目の ID**: 語彙とベクトルの索引の項目は鍵ごとに作り、項目の ID はノートの ID にする (1 つのノートが鍵の数だけ項目を持つ。ノートを消すと、その ID の項目がすべて消える)。鍵の埋め込みの記録 (`embedding`) は、単位 `key` と鍵の位置 (0 から) を持つ。

## 3. 応答の経路での書き込み

1. 利用者が発話を送ると、まず発話のターン (状態「応答待ち」) を確定する (ジャーナル → DB、03 §3.4・§6)。確定に失敗したら、発話を入力欄に戻して知らせ、LLM に送らない。
2. 文脈を組み立てて (05) 生成を始める。
3. 応答は、完了・中断・失敗のいずれかの状態のターンとして書く。中断と失敗の応答も、受け取ったところまでの本文と理由を残す。
4. 応答の経路では、要約も抽出もしない。

- 入力欄の下書き (送る前の文章) は、所有者だけが読める一時ファイルに 5 秒ごとに保存し、次の起動時に戻す。外部のエディタで書いた一時ファイルも同じ置き場所に置き、送った後に消す。

## 4. sleep-time

利用者が操作していない間に進める裏の処理 (v0.2)。

- **起動後の点検** (確定、2026-11-12): モデルの性質の点検 (06 §3.3) とリランカーの較正 (05 §3.7) は、下の sleep-time の手順と分ける。入力が 2 秒途切れ (`idle_seconds` がそれより短ければその長さ)、応答を生成していない間に流し、`memory.sleep_time` と `idle_seconds` には縛らない (「TUI を開いた後に裏で、短い間に」済ませるため)。電池の設定の `stop` と空きの不足では止める。利用者が操作したら、下の「譲る」と同じく切り、次の機会に続ける (較正は済んだ問いの結果を覚えておき、続きから求める)。
- **繰り返しを防ぐ**: 終えたのにまだ要る手順 (結果を保存できなかったなど) と、失敗した較正は、5 分おいてから試し直す (繋がらないサーバや書けない DB に、要求を送り続けないため)。
- **外部のエディタ**: 利用者が外部のエディタで書いている間は、裏の要求を出さない (06 §4 の「入力している間は出さない」)。
- **アイドルの判定** (sleep-time の手順): 次のすべてを満たすときに始める。
  - キー入力が一定の時間 (既定 60 秒、設定 `memory.idle_seconds`) 無い。
  - 応答を生成していない。次のターンの分の先の処理 (05 §4.5) も終わっている。
  - llama-server の chat のスロットに空きがある (06 §4)。
  - 電池の設定 (`memory.on_battery`、07 §4.2) が止めていない。
- **譲る**: 利用者が操作したら (キー入力、発話の送信)、今の手順の LLM の要求 (chat・embed・rerank のどれでも) を 1 秒以内に止める (NFR-105、06 §4)。止めたところまでの結果は、作り直せるものだけを残す。
- **job による再開**: 各手順の進み具合は `job` の記録に残し、次の機会に続ける。強制終了の後も、起動してアイドルになったら続ける。ただし、進み具合を状態から求められる手順は job を書かない (2026-11-12): 埋め込み (手順 1) は「語彙の索引にあってベクトルの索引に無いチャンク」を 32 件ずつ埋め込み、記録と索引への反映を 1 回ごとに落とされない形で行うので、止めても強制終了しても、次の機会に足りない分から続く。ノート (手順 2) も、区切り (§2) と記録したノートを突き合わせて足りない分から作るので job を書かない (1 つのノートは 1 回の呼び出しと 1 回の書き込みで作る)。型が合わずにやり直しても合わなかった区切りは、このプロセスの間は飛ばす (job の代わり)。
- **要る作り直しは状態から求める**: job の記録は裏の処理の結果と同じく失いうる (ジャーナルに書かない、03 §6) ので、job が無いことを「作り直しが要らない」とみなさない。起動時に、軽い検査 (件数と、最後に処理した ID の比較。全件は走査しない、NFR-101) で次を確かめ、足りなければ job を作る。
  - チャンクの無いターン (古い版で足したターンを含む) が無いか。
  - 記録した埋め込みのモデルの索引が、すべてのチャンクと鍵を覆っているか。
  - ノートを作っていない区切りが無いか。
  - 記録したリランカーのしきい値があるか (無ければ較正を裏で流す、05 §3.7)。
- **冪等**: 各手順は **何度やっても結果が同じ** になるように作る。入力 (ターンの ID の範囲) と、手順の版と、使ったモデルの model_key を `job` に記録する。途中で止めてから再開しても、止めずに通したときと同じ結果になる。型縛りの呼び出しは temperature 0・固定の seed・固定のスロットで出す (06 §6)。
- 手順 (版):
  1. 新しいターンのチャンクの埋め込みを作る (v0.2。チャンクへの区切りと語彙の索引への追加は、ターンの確定のときに行う、05 §2.3)。
  2. 区切りのついた話題のノート (検索の鍵) を作る (型縛りの LLM の呼び出し、v0.2)。
  3. 利用者の発話から事実の候補を抽出する (型縛りの LLM の呼び出し、§5.2、v0.3)。
  4. 訂正の候補を字句の規則で見つけ、検証する (型縛りの LLM の呼び出し、§6、v0.3)。
  5. 事実を統合する (重複の除去、置き換え、矛盾の記録。LLM を使わない決定論の規則、§5.3、v0.3)。
  6. 索引の新しいセグメントを作り、入れ替える (事実から作る検索の鍵 (§5.5) を含む、v0.2)。埋め込みのモデルを切り替えたときの作り直し (05 §2.2) もここで進める。
  7. 事実の表を作り直し、変わっていれば次のターンの分を先に処理する (§5.4、v0.3)。
  8. 忘れる・削除の退避の写し直しと、入れ替えに失敗したジャーナルの書き直しが残っていれば続ける (どちらも操作の直後に書き手スレッドの依頼として始め、アイドルの判定を待たない。03 §6・§7.3、§7.2、v0.3)。
  9. 自動の退避 (03 §7.1、v0.2 から sleep-time で行う)。
  10. カートリッジの埋め込みの不足分を作る (v0.5)。
  11. 自己学習の手順 (13、v0.4)。
- 型縛りの補助の呼び出しを使えないモデル (06 §3.3 の点検で通らない) では、手順 2〜4 を飛ばす (チャンクと埋め込みだけで動く。事実は増えないが、事実の表・忘れる・private は動く)。
- 同じ種類の LLM の呼び出しは続けて流す (抽出をすべて終えてから検証に移る)。どの呼び出しも、指示と属性の一覧の部分をバイト列まで同じにし、可変の部分を末尾に置く。裏のスロットに残ったプロンプトのキャッシュを使い回すため。
- 手順の結果は、入力にしたターンの改訂の番号 (§7.3) と一緒に書く (派生の記録の本体の任意の項目 `src_rev`、03 §3.3)。番号が今のターンと合わない結果は捨てる (処理の途中で忘れる・削除が入ったとき、古い本文から作ったものを書き戻さないため)。事実は、事実を書く経路のロック (§5.2.1) の下で記録を読み直して照合し、そのまま書き終える。忘れる・セッションの削除も同じロックを取るので、照合から書き終えるまでの間に本文は変わらない (書き手スレッドの中で照合するのと同じ効き目)。
- 裏の処理の LLM の要求は、1 回に送るプロンプトを 2,048 トークン (暫定) までにする。長い入力は分けて送る。
- 裏の処理は、空きの不足 (03 §8)、設定 `memory.sleep_time = false`、電池の設定で止められる。止めても会話の保存と想起 (語彙の索引と、作ってある埋め込み) は動く。

## 5. 事実

### 5.1 事実の形

事実は「主語・属性・値」の組を、1 件ずつの記録 (種類 `fact`) として持つ。同じ組をあとで言い直したときは、新しい記録を作らずに出典を足す。

| 項目 | 内容 |
|---|---|
| `subject` | 誰・何についてか。`self` (利用者本人) か、発話にある呼び名 (「妻」「田中さん」など、正規化した文字列)。抽出で明示させ、既定を置かない |
| `attribute` | 属性の名前。属性の一覧 (同梱の TOML、`evorag-memory/attributes.toml`) にあるものだけ |
| `value` | 値 (文字列。属性ごとの上限、既定 200 文字。型付きの値は v1.0 より後)。値の鍵 (§5.6) を副索引に持つ |
| `tense` | `current` (今も成り立つ) / `past` (以前は成り立っていた) / `planned` (予定) |
| `valid_from` / `valid_to` | 現実で成り立っていた期間。発話に日付があり、決定論の規則で読めたときだけ埋める。分からなければ空 |
| `recorded_at` / `retracted_at` | 記録した時刻と、取り消した時刻 |
| `state` | 下の表 |
| `source` | 出典の集合。各々が、ターンの ID、そのターンの改訂の番号 (§7.3)、本文の中で根拠にした範囲 (span。保存した本文の UTF-8 のバイト位置で、書記素の境界に合わせる) |
| `private` | 応答に添えない印。`fact_directive` (§7.5) から決まる値で、事実の側では書き換えない |

| 状態 | 意味 | 事実の表 (§5.4) |
|---|---|---|
| `Live` | 今の値 | 入る |
| `Contested { against }` | 単値の属性で、今の値と違う値が、置き換えの条件 (§5.3) を満たさずに出てきたもの | 入らない。`/memory` に出す |
| `Superseded { by, at }` | 新しい値に置き換えられた、または以前は成り立っていた (`by` は任意。時制が `past` の値には無い)。`by` の記録が消えた後も、`by` は消えた ID を指したまま残す (§7.4) | 入らない |
| `Retracted { at }` | 忘れた。値と span を消し、出典のターンの ID だけを残す | 入らない |

- `fact` は v0.3 で新しく作る種類なので、状態の値はこの 4 つで始める。値を足すときは、知らない値の読み方 (03 §4.2) を先に決める。
- **本体の形** (v1。最上位を平らにする。規則 7 で残るのは最上位の知らない項目だけなので、状態を入れ子にしない): `subject`、`attribute`、`value` (最初に言った表記。`Retracted` では null)、`vk` (値の鍵の 16 進。`Retracted` では null。副索引を本体から作り直すために本体に持つ)、`norm` (値の鍵の正規化の版)、`tense`、`valid_from`・`valid_to` (`YYYY`・`YYYY-MM`・`YYYY-MM-DD` の文字列か null)、`state` (`live`・`contested`・`superseded`・`retracted` の文字列)、`against`・`by` (事実の ID か null)、`state_at` (`Superseded`・`Retracted` になった時刻。`Superseded` は置き換えた候補のターンの時刻にする。作り直しても同じ値になるため)、`recorded_at`、`private`、`sources` (`{turn, rev, start, end}` の並び。(ターン, 始まり, 終わり) の順。`Retracted` では `turn` だけを残し、ほかは null)。上の表の `retracted_at` は `state_at` で表す。出典ごとに `rev` を持つので、本体の最上位に `src_rev` は置かない。
- **知らない状態の読み方**: 知らない `state` の事実は、`Live` ではないものとして事実の表・想起・`/memory` から除き、書き換えず、数えて `doctor` が報告する。忘れるで同じ (主語, 属性, 値の鍵) に当たったら、記録を消す (§7.7 のとおり読み出しで除き、退避の整理に入れる)。
- **`private` の項目**: 事実への指示 (§7.5) から計算した値の写しで、書き込みの入口が毎回計算し直す。正本は指示の側にある。
- **主語**: `self` か、呼び名に値の鍵の正規化 v1 (§5.6) を当てた文字列。正規化で `self` になる呼び名は捨てる。主語を明示する語 (読み取りの規則の `subject_self`。「私」「僕」"I"・"me" など、同梱のすべての言語) と一致する主語は `self` に直してから関門 5・8 を当てる (主語を「私」と書いて、`self` の再び覚えない印を抜けないため)。
- 属性の一覧は、属性ごとに、単値か多値か、値の長さの上限、事実の表での優先の順 (§5.4)、主語に `self` 以外を許すか、を宣言する。初期内容は v0.3 の着手前に決める (確定、[OQ-12](10-decisions.md#oq-12-属性の一覧の初期内容))。一覧に無い属性の候補は捨てて数え、`doctor` が報告する (一覧を広げる材料にする)。
- 一覧は版を持つ。属性を消したり意味を変えたりせず、足すだけにする。

### 5.2 抽出

抽出は sleep-time の手順 3 で、型縛りの LLM の呼び出し (06 §6) で行う。

- **対象のセッション**: チャットのセッション (モードが `chat`) の発話だけを対象にする。知らないモードのセッションは飛ばす。コーディングのセッション (15、v1.0 より後) では、ログやコードを囲みなしで貼ることが多く、プロジェクトの中身 (信頼しない文) が発話に混じるので、抽出するかはコーディングモードの着手のときに決める (15 §4.5)。事実の置き場所はチャットとコーディングで共有する (ADR-0020)。
- **出典は利用者の発話だけ** にする。応答・利用者が貼った引用・カートリッジからは抽出しない (確定、[OQ-20](10-decisions.md#oq-20-事実を抽出してよい出典))。貼られた文書に埋め込まれた指示が、事実として信頼する枠に入るのを防ぐため (02 §8)。
- **前のふるい** (LLM に送らないもの。決定論):
  - コードブロックと、引用の記号で始まる行を除く。行の区切りは `\r\n`・`\r`・`\n`・U+2028・U+2029・U+0085 のどれでもよい。囲みと引用の記号は、行の先頭の空白と Default_Ignorable の文字 (BOM・ゼロ幅の空白など) を飛ばしてから判定する。閉じの囲みは、囲みの記号 (開きと同じ文字を同じ数以上) と空白だけの行に限る (開きの行は info string を持てるが、閉じの行は持てない)。閉じていない囲みは本文の終わりまでとする。
  - 端末の貼り付け (bracketed paste) の範囲では除かない。S-16 (08 §3) で、今の入力の読み方 (crossterm 0.29) では、Windows の端末 (Windows Terminal・conhost) の貼り付けは `Event::Paste` にならず、IME の確定の文字列と同じ形 (1 文字ずつのキー) で届き、見分けられないことを確かめた。Windows Terminal は入力を VT の列として読めば見分けられるが、端末の層の変更 (07 §2) が要る。Linux の端末と tmux は確かめていない。
  - 貼り付けの範囲と、見分けが効いていたか (`Event::Paste` を受け取れる読み方だったか) はターンに観測値として残す。Windows では範囲を持たず、見分けが効いていないと記録する。除く材料にするかは、端末の層を VT の入力に替えるとき、または Linux の端末で確かめたときに改めて決める。引用の中の指示が事実に入るのは、関門 1〜6 で防ぐ。
  - 除いた残りが短い発話と、同梱の一覧 (挨拶・相槌) に当たる発話は送らない。短さのしきい値は言語ごとに決める (暫定で、日本語は内容の単位 (05 §2.1) が 4 つ未満、英語は語が 2 つ未満)。
  - 送らない理由は、チャットのセッションではない → コードブロックと引用の行を除くと何も残らない → 挨拶・相槌 → 短い の順に当て、最初に当たった理由で数える。短さのしきい値は、発話の文字種から決めた言語のものを使う。
- **束ね方**: 発話を `/tokenize` の数 (ターンごとにキャッシュする、06 §8) で束に詰め、1 回に渡す発話は 800 トークンまで (暫定) にする。1 回の呼び出しを 1 つの `job` の単位にする (止められたときに捨てる分を小さくするため)。
- **既存の事実はプロンプトに入れない**。要求が長くなり、先頭が毎回変わり、既存の値を写してしまう恐れがあるため。今の値との突き合わせは統合 (§5.3) で決定論に行う。
- **出力の型** (候補 1 件ごと。キーは短くする。候補が無ければ空の配列だけを返させる):

  | 項目 | 内容 |
  |---|---|
  | `t` | 束の中の発話の番号 (束の範囲だけの列挙) |
  | `s` | 主語 (`self` か呼び名) |
  | `a` | 属性 (一覧の名前だけの列挙) |
  | `v` | 値 |
  | `e` | 根拠の文字列 (発話からの逐語の写し) |
  | `m` | 叙法: `fact` (言い切り) / `negated` (否定) / `question` (問い) / `hypothetical` (仮定・願望) |
  | `tn` | 時制: `current` / `past` / `planned` |
  | `old` | 置き換える古い値が発話にあれば、その逐語の写し (無ければ空) |

- **関門** (決定論。1 から 8 の順に当て、最初に外れた関門の理由で数えて捨てる。関門 6 の中は、一般カテゴリ → 区切りの文字 → URL → 役割の詐称 → 文字体系の混在 → 命令形 → ほかの指示への言及 → 伏せ字の印 の順):
  1. `e` が、番号 `t` の発話の (前のふるいの後の) 本文に含まれる。まず生の本文で照合し、外れたら値の鍵の正規化 (§5.6) の後で照合して、位置の対応表で元の位置に戻す (LLM が全角・半角や括弧を直して写すことがあるため。後者は別の理由として数える)。その位置を、前のふるいで除いた分を足し戻した保存した本文の位置に直して span にする。 除いた範囲 (コードブロック・引用の行) をまたぐ一致は一致としない。読み取りの規則 (§5.3 の主語・変化の語) は、送った本文の根拠の範囲に当てる (除いた本文には当てない)。
  2. `v` が `e` に含まれる。`old` があれば、それも `e` に含まれる。照合は値の鍵の正規化の後で行い、英数字の並びは語の境界で一致させる ("Ann" を "annual" に当てない)。
  3. `m` が `fact` である。`negated` は、§5.3 の「否定」の規則にだけ使う。`question` と `hypothetical` は捨てる。
  4. 値が、前のふるいの後の発話の中の、根拠の範囲にある値の位置で、括弧 (「」『』【】〝〟«»‹›„“ など、同梱の規則) や引用符の内側にない (根拠 `e` の中だけでは見ない。根拠を選ぶのは LLM で、括弧の内側だけを写せば抜けてしまうため)。開きと閉じが同じ引用符 (`"` など) は、前が文頭・空白・記号のときだけ開き、後ろが文末・空白・記号のときだけ閉じとみなす (インチの記号などで内と外が入れ替わらないため)。閉じていない括弧は本文の終わりまで内側とする。同梱の規則で、名前の呼び方などの許す型を定める。
  5. `s` が `self` 以外なら、属性の一覧がその属性に主語の `self` 以外を許している。あわせて、呼び名に関門 6 (値と同じ検査) を当て、長さを 32 文字までにし、呼び名が根拠 `e` に含まれる (値の鍵の正規化の後で照合する) ことを求める。事実の表で `self` を表す語 (「利用者」・"user" など、表の書式の語) と同じ呼び名は捨てる (表の上で本人を詐称しないため)。主語は事実の表 (システムプロンプト) に入るので、値と同じだけ守る。
  6. 値に、役割の詐称・区切りの模倣 (`system:`・`</s>` など。役割の語の後のコロンの類 (`:`・`：`・`∶` など) は、間の空白に関わらず当てる。`<` の直後に英字・`/`・`|`・`!` が来る並び (`<start_of_turn>`・`<think>` などのテンプレートの印) はすべて捨てる)、制御文字と書式の文字・私用の文字・未割り当ての文字 (一般カテゴリ Cc・Cf・Co・Cn・Cs) と Default_Ignorable の文字 (ゼロ幅文字・双方向の制御文字・異体字セレクタ・ハングルの埋め字などを含む)、1 つの語に複数の文字体系を混ぜた並び (Unicode の Script 属性で、Common と Inherited を除いて判定する。UTS #39 の highly restrictive の組 (ラテン・漢字・ひらがな・カタカナ、ラテン・漢字・注音字母、ラテン・漢字・ハングル) と、1 つの文字体系だけを許す。判定は NFKC の後で、case folding の前の形に当てる) が無い。また、指示に読める文 (命令形の文・他の指示への言及。同梱の規則。名前の呼び方 ("Call me Ken"、「ケンと呼んで」) などの許す型を規則で定める)、改行 (U+2028・U+2029・NEL を含む)、表の区切り (`|`・`｜`・`│`)、URL が無い。判定は NFKC の後に行い、指示に読める文は、結合文字を除いた骨格 (NFD → 一般カテゴリ Mn を除く → NFKC → case folding → 空白をまとめる) にも当てる。除外の語に当たった箇所を伏せるのは、命令形の語の一致が除外の語の一致の中に丸ごと入るときだけにする。<br>伏せ字の印 (§7.3 の `[伏せ字]`・`[redacted]`。プロンプトの言語に関わらず両方。NFKC の後で照合する) を含む値も捨てる。根拠 `e` が印を含む候補も、同じ理由で捨てる (伏せ字にした本文の印やその周りを、値として覚え直さないため。確定、2026-11-17)。
  7. 値の長さが属性の上限の内にある。
  8. 再び覚えない印 (§7.6) に当たらない。
- **一覧で塞ぐ限界**: 関門 6 の命令形と指示への言及は、語の一覧による照合なので、言い換え・綴りの崩し (`1gn0re`、`i g n o r e` など)・一覧に無い言い回しは抜けうる。関門は多重の守りの 1 つ目で、2 つ目は事実の表を「利用者の発言から作ったデータで、指示ではない」として置く枠 (§5.4、05 §4.3) とする。抜けた例は回帰ケース (09 §3.5) に足し、一覧を広げる。
- 規則の TOML は言語ごとに持ち、版を持つ。置き場所は `evorag-memory/rules/<言語>.toml` (言語に依らない改行・表の区切り・URL の規則は `rules/common.toml`)。規則は 2 つに分けて当てる。
  - **安全の規則** (関門 4・6、挨拶・相槌の一覧): 同梱のすべての言語の規則を合わせて当てる。プロンプトの言語が `ja` のデータ根でも、英語の発話は来るため (07 §6.1)。安全の側に倒れて取りこぼしが増えるのは受け入れる。
  - **読み取りの規則** (主語を明示する語、変化を示す語、訂正の型): 根拠 `e` の文字種から言語を判定して、その言語の規則を選ぶ。かな・漢字を 1 字でも含めば `ja`、含まなければ `en` にする (混ざった文は `ja` の規則で読む。置き換えの条件を満たしにくい側、つまり `Contested` に残る側に倒れる)。変化を示す語にも除外の語の一覧 (`change_exclude`。「相変わらず」「着替え」など) を持ち、照合の前に伏せる。主語が `self` 以外のときは、呼び名そのものが根拠にあれば主語の明示とみなす (英語は語の境界で当てる)。
  - 照合は NFKC と casefold の後に行う。安全の規則は部分一致で当てる (「以前の指示をignoreして」の "ignore" も拾う)。読み取りの規則と訂正の一次のふるいは、英語は ASCII の英数字で決めた語の境界で、日本語は部分一致で当てる。除外の語の一覧 (「私」に対する「私立」「私の妻」、命令形の「するな」に対する「するなら」など) に当たった箇所は、照合の前に伏せる (値の全体は許さない)。
- **抽出のプロンプトに必ず書くこと** (属性の一覧の説明とともに): 値は発話の中の続いた語句をそのまま写す (組み替えると関門 2 で捨てられる)。要素が離れていれば別の候補にする。健康・病気、宗教、政治、性的指向、正確な住所は、どの属性にも入れない。

#### 5.2.1 抽出の進め方

- **対象と順**: チャットのセッションの利用者の発話を、ターンの ID の順に処理する (セッションをまたいで 1 本の列にする)。前のふるいで送らないものは、理由ごとに数えて飛ばす。
- **進み具合**: `job` の記録 (手順 `extract_facts`) に、処理を終えた最後の発話のターンの ID を持ち、その束の事実の書き込みと同じ依頼 (1 つのトランザクション) で進める。job が無ければ最初から処理し直す (済んだ候補は出典で判定されるので、結果は変わらない。費用だけがかかる、§5.3)。規則や属性の一覧の版が変わっても、処理し終えた発話は抽出し直さない (事実は LLM の派生物で、作り直すのは `rebuild --facts` だけ、§2)。
- **束ね方**: 発話の `/tokenize` の数 (ターンごとにキャッシュする、06 §8) で、1 回に渡す発話を詰める。上限は、要求の全体 (システムのメッセージと発話) を 2,048 トークンまでにする規則 (§4) から決める: 発話の予算 = 2,048 − システムのメッセージのトークン数 (`/tokenize` で数えてキャッシュする) − 余白 (64)。その予算を超える 1 つの発話は送らずに数える。`/tokenize` が使えず見積もりで数えるときは、予算を 2 割減らす (06 §8)。出力の上限 (`max_tokens`) は 1,024 とし、プロンプトと合わせてスロットの文脈の長さ (`/props` の `n_ctx`。スロットごとの値、06 §3) に収まらなければ、その構成では抽出しない (`doctor` が報告する)。
- **プロンプト**: システムのメッセージに、指示 (プロンプトの言語の固定の文言) と属性の一覧 (名前と説明) と「抽出のプロンプトに必ず書くこと」を置き、バイト列まで毎回同じにする (§4 のプロンプトのキャッシュ)。利用者のメッセージに、束の発話を `[番号] 本文` (前のふるいの後の本文) で並べる。番号は束の中で 1 から振る。
- **出力の型**: `{"c": [{"t": 整数, "s": 文字列, "a": 属性の名前の列挙, "v": 文字列, "e": 文字列, "m": "fact"|"negated"|"question"|"hypothetical", "tn": "current"|"past"|"planned", "old": 文字列}]}`。項目はすべて必須で、古い値が無ければ `old` は空の文字列にする。`t` が束の範囲の外の候補は捨てて数える。
- **型が合わないとき**: 1 回だけやり直し (06 §6。temperature 0・固定の seed なので、効き目は出力の揺れに限られる)、それでも合わなければその束を飛ばして数え、進み具合を先へ進める (事実は派生物なので、止まり続けて後の発話を処理できなくなるより、その束の事実を失う方を採る)。数は `doctor` が報告する。<br>**出力が上限で切れたとき** (`finish_reason` が `length`): 束が 2 つ以上の発話なら半分に分けて送り直す。1 つの発話なら型が合わないときと同じに飛ばす。<br>**失敗の扱い**: 4xx (要求そのものが受け付けられない) は、その束を飛ばして数え、先へ進める (06 §7 のとおり再試行しない)。締切切れと 5xx は進めずに次の機会に送り直すが、同じ束で 3 回続いたら飛ばして数える。接続の失敗 (サーバに繋がらない) だけは回数に入れず、進めずに待つ (サーバが戻れば続きから処理する)。
- **書き込みの直列化**: 事実を書く経路 (統合・事実への指示・出典の無い事実の掃除) は、1 つのロックで順に通す。ロックを取ってから記録を読み、畳み、書き手に渡して書き終えるまで放さない (読んでから書くまでの間に利用者の指示が入り、古い状態からの差で private の印が外れたり、忘れた値が戻ったりしないため)。
- **書き込みの入口での検査**: 統合は、候補の出典の改訂の番号が今のターンの改訂の番号と合わないものを捨てて数え (§4・§7.3)、候補の値に関門 6・7 を当て直す (抽出のほかの経路から入る値にも当てるため、§5.3 の書き込みの入口の 1)。
- **止めるとき**: `memory.forget_key` が使えない (03 §3.1.1 のフェイルクローズ)、点検で型縛りか思考を切るのが通らなかった (§4)、`memory.sleep_time = false` のときは抽出しない。
- **知らせ**: 1 回の裏の処理で事実が増えた・置き換わった・矛盾になったら、状態の行に件数だけを出す (§5.3 の「知らせ」)。

### 5.3 統合

統合は sleep-time の手順 5 で、**LLM を使わない決定論の規則** で行う (確定 (ユーザー回答)、[OQ-46](10-decisions.md#oq-46-事実の統合と事実への操作の結び付け先))。private の事実を、事実として LLM に渡すことは無い ([OQ-21](10-decisions.md#oq-21-private-の事実を裏の処理に渡すか) の注)。ただし、発話と応答の本文は、抽出・ノート (応答も含む)・チャンクの埋め込みの入力として、private の値を含んだまま裏の呼び出しに渡りうる (`llm.allow_remote` の構成では外の機械に出る。private の確認の文言に書く)。訂正の検証に渡す直前の応答だけは伏せる (§6)。

- **入力の順**: 候補と検証済みの訂正は (ターンの ID, span の始まり) の順に 1 件ずつ当てる。同じ位置のものは (1 回の畳みの中で。普段の経路では訂正を抽出の後の手順で畳むので、同じ発話の新しい値がいったん `Contested` になってから訂正で `Live` になりうる。結果は同じなので受け入れる)、span の終わり → 訂正 (訂正を候補より先に当てる) → 主語 → 属性 → 時制 (`current` → `planned` → `past`) → 叙法 (言い切り → 否定) → 正規化した値 → `old` の有無 の順にする。時制を値より先に比べるのは、「大阪から東京に引っ越した」の {東京, `current`} と {大阪, `past`} を、値の綴りに依らず置き換えの連鎖として当てるため。採る・戻すの指示 (§7.5) は、指示の ID の位置に混ぜて当てる (指示もターンも UUID v7 なので、1 本の列に並ぶ)。
- **済んだ候補**: 同じ (主語, 属性) で値の鍵が同じ事実が、すでにその候補の (ターン, 改訂の番号, span) を出典に持っていれば、その候補は当て済みとして何もしない (同じ候補を 2 回当てても結果は同じ)。否定・過去形で終えた発言も、出典として残るのでこの形で判定する。検証済みの訂正は、古い値がもう今の値でなければ効かないので、出典では判定しない (同じ範囲の候補の出典と取り違えないため)。
- **束をまたぐ順**: 抽出が遅れて古いターンの候補が後から来ると、それまでの畳みと `rebuild --facts` の結果が分かれうる。捨てた否定と、効かなかった訂正は出典を残さないので、後から当て直すとそのときの今の値に当たりうる。どちらも受け入れる (LLM で作る事実は、作り直しで同じになるとは限らない、§2。書き込みの入口は、当てた束を job の進み具合として記録し、同じ束を当て直さない)。
- **今の値を終えたときの矛盾**: 否定・過去形で今の値を終えて「今の値なし」になったときは、残った `Contested` の `against` は終えた値の記録を指したままにする (§7.4 の削除・忘れると同じ。後で新しい値が `Live` になったら、その値に付け替える)。
- **同じ値**: (主語, 属性, 値の鍵) が同じ `Live`・`Contested` の事実があれば、出典を足すだけにする。
- **単値の属性**: 新しい値で今の `Live` を `Superseded` にするのは、次のどれかのときだけ。
  - 候補が `tn = current` の言い切りで、根拠の文字列に、主語を明示する語 (`self` なら「私」「僕」「自分」など、ほかの主語なら呼び名) か、変化を示す語 (「引っ越した」「変わった」「転職した」など) がある。どちらの語も同梱の TOML の規則で決定論に判定する。
  - 検証済みの訂正 (§6) が、今の値から新しい値への向きを持つ。
  - 同じ値の `Contested` の出典が、2 つ以上の別のターンになった (言い直された。最初の出典も数える)。
  - それ以外で今の値と違う値は `Contested { against: 今の Live の ID }` にする (「矛盾の記録」)。今の値が無ければ `Live` にする。
  - `Live` が替わったら、同じ (主語, 属性) の残りの `Contested` の `against` を新しい `Live` に付け替える。新しい `Live` と同じ値の `Contested` は、新しい `Live` に出典を合わせて消す。
- **多値の属性**: 古い値の 1 件を置き換えるのは、次のどちらかのときだけ。特定できなければ並べて足し、兄弟の値には触れない。
  - 候補の `old` の値の鍵 (§5.6) が、今の `Live` の値の 1 件とちょうど一致する。
  - 検証済みの訂正の古い値の値の鍵が、今の `Live` の値の 1 件とちょうど一致する。
- **時制**: `past` の候補は、その値が今の `Live` なら `Superseded` にする (今の値で置き換えたことにはしない。記録の時制は元のまま変えない)。`valid_to` は、発話に日付があり決定論の規則で読めたときだけ埋める (§5.1)。今の値でなければ、時制 `past` の `Superseded` の記録として履歴に足す (同じ値の `Superseded` の記録 (時制を問わない) があれば、出典を足して 1 件にまとめる)。`planned` は、単値の属性では `current` とは別の枠に 1 件だけ `Live` で持ち、多値の属性では兄弟と並べて `Live` で持つ。どちらも事実の表では「予定」と示す。`planned` と同じ値の `current` の候補が来たら、予定の記録の時制を `current` にして出典を足す (新しい記録を作らない)。単値の属性では、そのとき今の値を置き換えてよいかを上の条件で決める。
- **終えた発言の出典**: 過去形 (`past`) か否定で今の値を終えたときは、終えた発言のターンを、終えた事実の出典に足す (その値を忘れたとき、その発言も伏せ字の対象にするため)。検証済みの訂正で今の値を置き換えたときも、訂正の発話の中で古い値に一致した範囲 (`{old}` の穴の中) を、置き換えた事実の出典に足す。
- **否定**: `negated` の候補は、値が今の `Live` の値と一致し、根拠に変化を示す語 (「もう」「やめた」"no longer" など) があるときだけ、その `Live` を `Superseded` にする (その属性は「今の値なし」になる)。それ以外の否定は捨てる。
- **削除しない**: 置き換えた値も残す。「いつ何を言っていたか」に答えられ、誤った置き換えを戻せる。
- **書き込みの入口は 1 つ**: 事実を書く関数は `evorag-memory` の 1 つだけにし、次を必ず通す。
  1. 関門の 6・7 (抽出のほかの経路から入る値にも当てる)。
  2. 事実への指示 (§7.5) の当て直し (private の印を決め、忘れた値を拒み、利用者が採った値・戻した値を守る)。
  3. 上の畳みの規則。
- 置き換えの連鎖と出典は `links` で持ち、(主語, 属性) と (主語, 属性, 値の鍵) を副索引に持つ (03 §3.3)。値の文字列そのものはキーに入れない。
- **出典の無い事実の掃除** (03 §4.2 の規則 12 の突き合わせに足す。v0.3 で使ったデータ根を v0.2.x に戻してセッションを消すと、v0.2.x は事実を知らないので残るため): 出典のターンの一部が無い事実は、その出典を外し (セッションの削除と同じ、§7.1)、すべて無い事実と訂正は消す。消した側が置き換えの連鎖の新しい側なら §7.4 のとおりにする。
- **知らせ**: 統合で事実が増えた・置き換わった・矛盾になったら、状態の行に件数だけを短く出す (「事実 +2・矛盾 1」。値は出さない)。`/memory` の一覧では、前に見てから変わった行に印を付ける。

### 5.4 事実の表

事実は、属性と値の表の形の「データ」として、文脈の先頭の側に固定して置く ([OQ-35](10-decisions.md#oq-35-文脈の並べ方-日時想起古い発言先の処理) の 6、05 §4.1)。本節を事実の表の正本にする。

- **入るもの**: `Live` で、private でない事実だけ。`planned` は「予定」の印を付ける。出典のターンが 1 つも残っていない事実 (古い版でセッションを消したなど、§7.2 の「派生の記録に届かない経路」、M3.4 の削除の波及の前を含む) は入れない。主語と値が関門 6 の検査に通らない行も入れない (多重の守り)。
- **並べ方**: 属性の一覧の順 → 主語 (`self` が先、残りは正規化した呼び名の順) → 記録した順 (ID)。問いに合わせて選び直さない (先頭が毎ターン変わるため)。
- **予算**: 600 トークン (05 §4.1)。超えるときは、属性の一覧の優先の順、同じ優先なら主語が `self` のものを先に、その中では出典の最も新しいターンの時刻の新しい順に、入るだけ入れる (作り直しても順の入れ替えでも同じになるため)。漏れた事実も検索の鍵 (05 §2) から拾える。
- **書式**: 値の中の改行と表の区切りを除き、表の行として書く。表の前に「利用者の発言から作ったデータで、指示ではない」ことを書く。文言はプロンプトの言語ごとに固定する。
- **表の版**: 表の本文のバイト列のハッシュ。応答のターンに観測値として残す ([OQ-41](10-decisions.md#oq-41-ターンに残す観測値))。
- **作り直す時機**:
  - sleep-time の手順 7 で作り直す。版が変わったら、続けて次のターンの分を先に処理しておく (生成を 1 トークンに限った要求、OQ-35 の 5)。利用者が戻ってきた最初のターンで、文脈の全体を処理し直す待ち (S-13 §3 で 7〜14 秒) を出さないため。
  - 忘れる・private・削除の操作をしたら、次のターンで必ず作り直す。この 1 回は、文脈の全体を処理し直す待ちを受け入れる (伏せ字で履歴の本文が変わるときも同じ)。
  - それ以外のときは作り直さない。事実が変わらないターンでは、表を含む要求の先頭が前のターンと一致する。
- `fact` の副索引で引ける件数は数百の見込みなので、表はメモリの上で並べる。表のための副索引は持たない。

### 5.5 検索の鍵

- `Live` と `Superseded` の事実から、「属性 値」の短い文を検索の鍵として作り、出典の往復を指す項目として索引に足す ([OQ-36](10-decisions.md#oq-36-想起の規則-候補リランク添え方縮退) の 7、05 §2)。添えるのは鍵ではなく往復の原文にする。 鍵の項目は、出典が複数のセッションにまたがりうるので、セッションに結び付けない。今のセッションだけを出典とする事実の鍵は、想起の候補を集める段階で除く (今のセッションのターンを添えないのと同じ、05 §3.2)。
- private の事実と `Retracted` の事実からは作らない。事実が private・`Retracted` になったら、コミットの直後に (利用者に知らせる前に) 鍵を索引から除く。読み出しでは事実の状態を読み直し、private・`Retracted` の事実の鍵は使わない (§7.7。`/private off` で同じ事実の鍵が戻るので、ID で拒む仕組みにしない)。

### 5.6 値の鍵

事実の重複の判定、事実への指示 (§7.5)、再び覚えない印 (§7.6) は、値そのものではなく「値の鍵」で照合する。

- 値の鍵の正規化は、検索の正規化 (05 §2.1) とは別に持ち、**凍結する** (版 `1` から変えない): NFKC → casefold → NFKC → 空白を 1 つにまとめて両端を除く。記号は残す (検索の正規化のように区切りにすると "C++" と "C#" が同じになるため)。カタカナとひらがなは統一しない。
  - casefold は Unicode の完全な case folding (CaseFolding.txt の状態 C と F。T は使わない) にする。`char::to_lowercase` は使わない (`ß` が `ss` にならず、Unicode の安定性の約束も無いため)。
  - 空白は Unicode の White_Space の性質を持つ文字にする。その連なりを U+0020 の 1 つにし、両端を除く。
  - 実装の依存 (NFKC と case folding の表) の版を上げて結果が変わったら気付けるように、すべての Unicode のスカラー値を 1 文字ずつ正規化した結果のハッシュを試験で固定する。変わったら、古い結果を例外の表で保つ (凍結のため)。正規化は冪等であること (2 回当てても同じ) も試験する。
  - 主語の呼び名にも同じ正規化を当てる (§5.1)。属性の名前は変えない。
- 正規化で長さが変わる (`ｶﾞ` → `ガ`、`㈱` → `(株)`) ので、元の本文の位置と正規化の後の位置の対応表を作って照合する。一致の端が 1 つの文字の展開の途中に来たときは、一致としない。
- **鍵の形**: 値の鍵は、正規化した値の HMAC-SHA256 (鍵は `meta` の `memory.forget_key` を復号した 32 バイト、03 §3.1.1) にする。副索引・事実への指示・ジャーナルには、この鍵だけを書き、値の文字列を書かない (03 §3.3)。HMAC に入れるバイト列は次のとおりに凍結する (`‖` は連結、`u32be` は 4 バイトのビッグエンディアンの長さ)。
  - 値の鍵: `"evorag.vk.1"` ‖ 0x00 ‖ UTF-8 (正規化 v1 (値))。記録には 64 桁の小文字の 16 進で書く。
  - 再び覚えない印: `"evorag.mark.1"` ‖ 0x00 ‖ u32be(len S) ‖ S ‖ u32be(len A) ‖ A ‖ 値の鍵の 32 バイト。S は UTF-8 の主語 (§5.1 の正規化の後)、A は属性の名前の ASCII。記録には 64 桁の小文字の 16 進で書く。
  - 先頭の文字列で値の鍵と印の入力を分け、長さを前に置いて区切りの曖昧さを無くす。
- 正規化を変えるときは、版 `2` の正規化として足し、事実への指示と印に正規化の版を書く。古い版の印は古い版の正規化で照合する (値を持たないので、作り直せないため)。

## 6. 訂正

- **候補**: sleep-time に、チャットのセッション (モードが `chat`) の利用者の発話を字句の規則 (同梱の TOML の、穴のある型。「{old}じゃなくて{new}」「{new}、{old}ではなく」"{new}, not {old}"、"I meant {new}" など) で調べ、当たったものを候補として `correction` に書く。信号の種類 (`signal`) には値を足さない (03 §4.2 の規則 11)。コーディングのセッションでは訂正の候補を探さない (「not」「wrong」が作業の会話に多く、検証の呼び出しが無駄に増えるうえ、学習はチャットとコーディングで分けるため、ADR-0020。コーディングの信号は 15 §8.2)。
- **検証**: sleep-time の手順 4 で、候補にだけ、型縛りの LLM の呼び出しで判定する (候補は少ないので、抽出とは別の呼び出しにする)。渡すのは、候補の発話と、その直前の応答 (信頼しない引用の枠に入れる。抽出の出典にはしない)。
  - 出力: 直したのは事実か応答の誤りか、古い値、新しい値、根拠の文字列。
  - 関門 (決定論。この順に当て、最初に外れた理由 (括弧の中の値) で数える):
    1. 訂正である: `new` が空でない (`not_correction`)。プロンプトに、訂正でなければ `new` を空にするよう書く (一次のふるいの誤検知に、LLM が値を作って返さないため)。
    2. 新しい値と根拠が、候補の発話の前のふるいの後の本文に含まれる (照合は §5.2 の関門 1・2 と同じ) (`new_not_in_utterance`)。
    3. 新しい値の位置が、括弧・引用符の内側にない (§5.2 の関門 4 と同じ規則。引用符で囲んで貼った他人の文の訂正を当てないため) (`quoted`)。関門 5 で置いた新しい値の一致は、括弧の内側に 1 文字でも掛かってはならず、型の固定の部分も括弧の内側にあってはならない (新しい値を閉じ括弧の外まで伸ばして、引用の中の訂正を当てないため)。
    4. 古い値が、直前の応答か、利用者のそれより前の発話か、今の `Live` の値のどれかに含まれ、関門 6 と 200 文字の上限に通る (古い値も信頼しない LLM の出力なので、記録して学習に渡す前に守る) (`old_not_found`)。
    5. 向き: 根拠を候補の型に当てて (型の固定の部分は根拠の中で探し、穴の範囲は根拠で切らずに前のふるいの後の本文の同じ文で決める。LLM が根拠を値の途中から始めて穴を縮めないため)、否定の語 (「じゃなくて」「ではなく」"not" など) が付いた側の穴に古い値が、もう一方の穴に新しい値がある (語の並びの前後では決めない。英語では新しい値が先に来ることが多いため)。値が穴の位置にあることは「訂正の型の使い方」の規則で確かめる。古い値と新しい値の値の鍵が同じなら落とす (`direction`)。
  - 関門を通ったものを、検証済みとして同じ `correction` に書く。
- **訂正の型の使い方**: 型は向き (どちらが古い値か) を決めるためだけに使う。値は検証の LLM の出力を使い、それが型の穴の位置にあることを確かめる。型は固定の部分の長いものから試す (「ではなく」より「ではなくて」を先に)。長さは読点と空白を数えずに比べ、同じ長さなら同梱の TOML の順に試す (読点を数えると「{new}、{old}ではなく」が先に当たり、「いや、大阪ではなく京都です」の新しい値の穴が「いや」になるため)。読点・空白と文末の「よ」「です」の有無は区別しない。
  - **穴の範囲**: 穴は、型の固定の部分から、同じ文の中 (文の区切り `。`・`．`・`.`・`!`・`?`・`！`・`？` と改行の手前) までにする (穴が本文の端まで伸びて、後ろの文の語を値にできないため)。半角の `.`・`!`・`?` は、後ろが空白・改行・本文の終わりのときだけ区切りとみなす (小数・URL・略語で文を切らないため)。
  - **読点だけの固定の部分**: 「{new}、{old}ではなく」のように、2 つの穴の間の固定の部分が読点だけの型は、本文の読点か空白で 2 つの穴を分ける (この型に限って読点の有無を区別する)。区切りが 2 つ以上あれば、後ろの穴の後に固定の部分が続く型 (「{new}、{old}ではなく」) は最後の区切りで、後ろの穴が末尾の穴の型は最初の区切りで分ける (どちらも、固定の部分に接する側の穴を短くする)。
  - **値の位置**: 値は、穴のうち固定の部分に接する端に置く。後ろに固定の部分がある穴では値の終わりを穴の終わりに、後ろに固定の部分が無い穴 (末尾の穴) では値の始まりを穴の始まりに合わせる (間の読点・空白は飛ばす)。「大阪じゃなくて東京に住んでいます」の新しい値「東京」は通り、「住んでいます」は通らない。「大阪じゃなくて、今は東京です」のように間に語が入ると落ちるが、安全の側に倒す (事実は抽出の経路で `Contested` から言い直しで置き換わりうる)。
  - **古い値は穴の全体**: 古い値は、どの事実を置き換えるかを決めるので、片側の端ではなく `{old}` の穴の全体と一致させる (穴の前後の読点・空白を除いて比べる)。`{old}` の穴は、文の区切りに加えて読点 (`、`・`，`・`,`) でも切る。「東大阪じゃなくて京都です」の古い値「大阪」は通らず、「いや、大阪じゃなくて京都です」の「大阪」は通る。「いや大阪じゃなくて」は落ちるが、安全の側に倒す。
  - **文末の「よ」「です」**: 除くのは、末尾の穴が文末で終わるときの穴の終わりの「よ」「です」の 1 回だけにする (「かよじゃなくて」の「かよ」を「か」にしないため)。
  - **一致の端と括弧**: 値の一致は、根拠の中だけでなく、前のふるいの後の本文の全体で語の境界 (英数字の並び) と括弧・引用符の内側を確かめる (LLM が根拠を語の途中で切って境界の検査を抜けたり、同じ値を括弧の内と外に書いて内側の一致を出典にしたりしないため)。置いた位置 (新しい値の、穴の端に接する一致) が括弧の内側なら、向きのほかの検査より先に `quoted` で落とす。
  - **区切りの文字の判定**: 文の区切りの判定は、NFKC の前の元の文字で行う (全角の `．`・`！`・`？` は常に区切り、半角の `.`・`!`・`?` は後ろが空白・改行・本文の終わりのときだけ区切り)。
  - **照合の費用**: 型の照合は、発話の長さに対しておおむね線形で終える (4,000 文字の上限は NFKC の後の長さにも当てる)。
  - 1 つの発話に型が 2 つ以上当たっても、最初に当たった 1 つ (固定の部分の長い型から。同じ型なら本文の前から) だけを候補にする。
  - 前のふるいの後の本文が 4,000 文字 (暫定) を超える発話には型を当てない (長い貼り付けで照合の費用が膨らむため。長い発話の中の訂正は取りこぼす)。
- **型**: `correction` の記録は段階 (候補 / 検証済み) を持つが、コードでは別の型にし、事実の置き換え (§5.3) と学習 (13) には検証済みの型しか渡せない。`correction` は v0.3 で新しく作る種類なので、段階の値はこの 2 つで始める。
- **事実への効き方**: 検証済みの訂正は、古い値の値の鍵 (§5.6) が今の `Live` の値の 1 件とちょうど一致するときだけ事実を置き換える。一致しなければ、学習 (13) にだけ使い、事実は変えない。一致する値が 2 つ以上の (主語, 属性) にあるときも、どれを直したのか決められないので、事実は変えない。
  - 古い値の穴の無い型 (`I meant {new}`、「正しくは{new}」「違う、{new}」など) の訂正は、事実を変えない (学習にだけ使う)。古い値の位置を発話で確かめられず、今の値のどれにでも当たりうるため (信頼しない直前の応答に誘導されて、利用者の別の事実を置き換えないため)。
  - 今の値は、時制 `current` の `Live` に限る。予定 (`planned`) の値は訂正で置き換えない。
- **関門の順**: 上の関門の 1〜5 の順に当て、最初に外れた理由で数える。引用 (コードブロック・引用の行) の中の訂正は、型を前のふるいの後の本文に当てるので候補にならない。型が引用の外に当たり、検証の LLM が引用の中の値を返したときは、新しい値を前のふるいの後の本文で照合するので、新しい値の関門で落ちる。訂正の型は、発話の一部に当たればよい (発話の全体と一致しなくてよい)。
- **記録の形** (`correction` の本体 v1。最上位を平らにする): `stage` (`candidate`・`verified` の文字列。知らない値は読むだけにする)、`turn` (候補の発話のターン)、`rev` (その改訂の番号)、`previous` (直前の応答のターンの ID か null)、`pattern` (当たった訂正の型の文字列)、`dir_old`・`dir_new` (型の `{old}`・`{new}` の穴 (同じ文の中) に当たった本文。穴の前後の読点・空白と文末の「よ」「です」を除き、ほかは除かない (「奈良でした」のように型の後ろの語を含みうる)。200 文字までを書く。古い値の無い型では `dir_old` は null。向きの関門は、記録の文字列ではなく、検証のときに型を当て直した穴で確かめる)、`checked` (検証を済ませたか)、`rejected` (検証を済ませたが検証済みにならなかった理由か null。関門で落ちた `not_correction`・`new_not_in_utterance`・`quoted`・`old_not_found`・`direction`、検証の前か結果を書く前に改訂の番号が変わった `stale_source`、§5.2.1 の扱いで飛ばした `invalid_output` (型が合わない)・`truncated` (出力が上限で切れた)・`request_rejected` (4xx)・`failed` (締切切れと 5xx が 3 回続いた)、要求が予算に収まらない `too_long`、検証の結果が忘れた値だった `forgotten` (§7.5)。知らない値は読むだけにする。落ちた・飛ばした候補は `candidate` のまま残し、検証し直さない)、検証済みのとき `target` (`fact`・`response`)・`old`・`new`・`old_vk`・`new_vk`・`norm`・`start`・`end` (新しい値の、候補の発話の保存した本文の中のバイト位置)・`old_start`・`old_end` (古い値の、`{old}` の穴の中で一致した範囲のバイト位置。古い値の無い型では null。§5.3 の「終えた発言の出典」に使う)。出典の ID (`turn`・`previous`) を本体に持つ (03 §4.2 の規則 12)。出典の改訂の番号は `rev` で持ち、03 §3.3 の `src_rev` を別に置かない (`fact` の出典ごとの `rev` と同じ)。作り直せる派生の記録なので、ジャーナルに書かない。
- **候補を見つける時機**: 抽出 (§5.2.1) と同じ発話の列を同じ進み具合で処理するときに、前のふるいの後の本文に一次のふるい (`triggers`) と型を当て、当たれば候補を書く (LLM を使わない)。前のふるいで抽出に送らない発話 (短い・挨拶・相槌) にも、コードブロックと引用の行を除いた本文が残れば型を当てる (「いや、大阪じゃなくて東京」は短くても訂正になるため)。抽出の事実と同じ依頼で書く。同じターンの候補がすでにあれば書かない (進み具合を失って処理し直しても 1 件のまま)。忘れるの指示の `turns`・`redactions`・`hidden` に入るターンの発話からは候補を書かない (伏せ字にしないで忘れた発話を、進み具合を失って処理し直したとき、忘れた値の写しを訂正の記録に戻さないため。§7.5 の「忘れると訂正」)。`rebuild --facts` の抽出は、訂正の候補を書かない (§7.5 の「作り直しと訂正」)。書く前に、事実を書く経路のロックの下で、ターンがあり改訂の番号が読んだときと合うことを確かめ、合わなければ書かない (読んでから書くまでに削除・忘れるが入ったとき、消した本文の写しを書き戻さないため)。
- **検証の時機**: sleep-time の手順 4 で、`checked` でない候補を ID の順に 1 件ずつ検証する (抽出の呼び出しをすべて終えてから)。直前の応答は、候補の発話より前の、同じセッションの最後の応答のターン。古い値の関門の「利用者のそれより前の発話」は、同じセッションの、候補の発話より前の利用者の発話の、前のふるいの後の本文にする (セッションをまたがない)。プロンプトには、候補の発話は型に当たった位置を含む 800 文字 (暫定)、直前の応答は末尾の側 (候補の発話に近い側) の 800 文字までを入れる。直前の応答には、想起で添えるときと同じ `[非表示]` の置き換え (§7.5) を当ててから入れる (private の値と、伏せ字にしないで忘れた値を裏の呼び出しに渡さないため)。要求の全体を `/tokenize` で数えて §5.2.1 と同じ予算 (2,048 − システムのメッセージ − 64) に収め、超えれば直前の応答をさらに半分に切って数え直し、2 回で収まらなければ `too_long` で飛ばす。本文の中の枠の印は、変わらなくなるまで除く (入れ子で枠を閉じられないため)。関門は、切る前の保存した本文で照合する。結果を書くときは、ロックの下で改訂の番号を読み直し、変わっていれば `stale_source` にする。検証済みになる結果の `old_vk`・`new_vk` のどちらかが、忘れるの指示の `vks` (§7.5) のどれかと同じなら、値の項目 (`dir_old`・`dir_new`・`old`・`new`・`old_vk`・`new_vk`) を null にして、`rejected` を `forgotten` にする (忘れた値の写しを訂正の記録に残さないため)。検証の呼び出しは抽出と同じ設定 (型縛り・temperature 0・固定の seed・裏のスロット) で、出力の型は `{"target": "fact"|"response", "old": 文字列, "new": 文字列, "e": 文字列}`。型が合わない・失敗したときの扱いは抽出と同じ (§5.2.1)。
- **統合への渡し方**: 検証済みの訂正は、新しい値の範囲を出典として、書き込みの入口 (§5.3) に渡す。入口は抽出の候補と同じく、出典の改訂の番号を確かめ、事実を書く経路のロックの下で畳む。`target = response` の訂正も事実の置き換えの条件 (古い値が今の値の 1 件と一致する) を当てる。

## 7. 忘れる・消す

### 7.1 操作と結果

| 操作 | 結果 | 版 |
|---|---|---|
| セッションの削除 (`/delete`) | ターン・信号・チャンク・ノート (検索の鍵)・埋め込み (前の世代の索引の分を含む)・想起への操作 (そのセッションの応答への操作と、そのセッションの往復を対象にした操作)・事実から作った検索の鍵を消す。そのセッションだけを出典とする事実と訂正も消す。他にも出典がある事実は、出典の集合から外す。回帰台帳の事例と検索の事例のうち、そのセッションのターンを入力に持つものも消す | v0.1 (ターン・信号) / v0.2 / v0.3 / v0.4 |
| 事実を忘れる (`/forget <番号>`) | 事実を `Retracted` にして値と span を消す。出典の発話の、根拠の範囲の中で値に一致する箇所を伏せ字にする (既定。§7.3)。取り消した事実から作った検索の鍵 (§5.5) とその埋め込みを消す。伏せ字にしたターンから作った派生物 (チャンク・ノート (検索の鍵)・埋め込み (前の世代の索引の分を含む)・訂正) を消して、作り直しを sleep-time に回す。伏せ字にしないときは、`[非表示]` の範囲を持つ往復のノートを消し、伏せた本文から作り直す。忘れた値を持つ訂正も消す (§7.5 の「忘れると訂正」)。再び覚えない印 (§7.6) を残す | v0.3 |
| 事実を private にする (`/private <番号>`) | 事実の表と検索の鍵から外し、想起で添える往復の中の値を伏せる (§7.5)。消しはしない。`/private off <番号>` で解く | v0.3 |
| 全消去 (`evorag reset`) | データ根を消す。設定は残す | v0.1 |

- **番号**: `/memory` が最後に表示した事実の一覧の番号 (07 §3)。出典の番号 (05 §5.1) と取り違えないように、`F1`・`F2` のように `F` を付けて示す (履歴の行は `H1`…、忘れた事実の一覧は `X1`…)。事実の ID は打たせない。番号は、その表示のときの一覧に結び付け、表示の後に裏の処理で一覧が変わっても、別の事実を指さない。番号と行の対応は画面が持ち、コアには行の参照を渡す。参照は、事実への指示と同じ鍵 (主語, 属性, 値の鍵) と、表示したときの状態の種類 (`Live`・`Contested`・`Superseded`) と時制で持つ (事実の ID は作り直すと変わるので、照合に使わない。参考として持つのはよい)。指した行が変わっていたら (統合で置き換わった・消えた。同じ鍵の記録が、表示したときの状態の種類と時制で今は無い)、「一覧が更新されました」と出して実行せず、同じ読み取りで作った新しい一覧を出す。出典の増減、`against`・`by` の付け替え、private の印の変化は「変わった」に数えない (private は利用者自身の操作で変わるため。操作の前提が合わないとき (private でない行への `/private off` など) は、別の理由で断る)。
  - 番号を振る行: 今の値と `Contested` の値に加え、今の値が消えた属性 (§7.4) と、値が 1 つも無いが後継まで効く private の指示だけが残る属性にも、行として番号を振る (両方に当たるときは private の指示だけが残る行にする。履歴にはその行からも届く。予定の値だけがある属性には、今の値が消えた行を振らない。`Contested` があって今の値が無い属性には、`Contested` の行と並べて今の値が消えた行も振る) (前者から `/memory history` で履歴に届き、後者を `/private off` で解けるようにするため)。`/memory history <番号>` は、その行の (主語, 属性) の履歴を出す。`accept` は `Contested` の行にだけ、`/forget` は値の行 (今の値と `Contested` の値) にだけ当てられる。
  - `/memory history` と `/memory forgotten` は、それぞれ自分の一覧の番号を持つ。番号は頭の `F`・`H`・`X` を省いてもよい (省いたときは、その命令が取る一覧の番号とみなす)。一覧をまだ出していないときに番号を打ったら、`/memory` を先に出すよう案内する。
  - 事実の一覧は、データ根の全体のものなので、セッションを開いていなくても出せる。前に見てから変わった行の印は、画面が前に出した一覧と比べて付ける (プロセスの間だけ覚える)。
- **確認の画面** (忘れる): 1 つの画面にし、既定のまま Enter で実行できる。対象の主語・属性・値と、伏せ字にする前と後の本文を 1 行ずつ見本として示す。次の選択は畳んで置く。
  - 出典の発話を伏せ字にするか、発話はそのままで事実だけを消すか。既定は伏せ字にする (確定 (ユーザー回答)、OQ-09)。
  - 選んだ値だけか、同じ (主語, 属性) の置き換えの履歴 (`Superseded` の値。時制を問わない) もまとめて忘れるか。既定は選んだ値だけ。`Contested` の値は履歴に含めない (その行を `/forget` で忘れる)。
  - 同じ往復の応答の中で、値の鍵 (§5.6) が一致する範囲も伏せるか (既定は伏せる)。同じ往復の応答は、出典の発話を `reply_to` に持つすべての応答 (中断・失敗を含む) で、本文の全体で探す。
  - ほかのターンで値の鍵が一致する範囲もまとめて伏せるか (既定は伏せない)。ほかのターンは、すべてのセッションの利用者の発話と応答のうち、上の 2 つに入らないもの。件数を見本と一緒に示す。読めないターン (読めない記録・`v` が新しい記録) は探さずに飛ばし、その数を見本に示す (中止の理由にしない)。
  - 伏せ字にしないときも、後の 2 つの選択は効き、選んだ範囲を `[非表示]` の範囲 (§7.5 の `hidden`) にする (出典の根拠の範囲に値の一致が見つからないときは、private と同じく、書記素の境界に広げた根拠の範囲の全体を `[非表示]` の範囲にする)。
  - 出典のターンの根拠の範囲に値の跡がまったく無いとき (正規化しても値の文字列が無い) は、値と出典が食い違っているので中止する (F11)。値はあるが書記素の境界で切り出せないとき、または範囲がすでに伏せ字の印を含むとき (後から、影響を受けた事実を忘れる場合) は、そのターンを伏せ字にせず、見本に示す。応答 (echo) の中の読めないターンも、ほかのターンと同じく飛ばして数を示す。
  - 取り消す事実は、同じ (主語, 属性) の `Retracted` でない事実のうち、値の鍵が `vks` にあるものすべてにする (履歴をまとめないときも、同じ値の `Superseded` の記録と、履歴の値と値の鍵が同じ `Contested` の記録を含む。当て直しの印による取り消しと同じ結果にするため)。
- **見本と計画** (確定、2026-11-17): 見本はコアが作る (02 §3 の「忘れるの見本」)。コアは、対象と選択から、伏せ字にするターンと範囲・取り消す事実・消す派生の記録の一覧 (計画) を、記録を変えずに作り、次を返す。画面は選択を変えるたびに求め直す。ほかのターンの一致はすべてのターンを読むので、裏のスレッドで探し、画面を止めない。
  - 伏せ字にする前と後の本文の見本、ほかのターンの一致の件数、まとめて忘れる履歴の件数、影響するほかの事実 (下) の行、伏せ字にしない出典のターン、飛ばした読めないターンの数、警告 (下の「中止」に当たること)、計画のハッシュ。
  - 計画のハッシュは、実行で変わるものだけを覆う: ターンごとの伏せ字の範囲と伏せ字の前の改訂の番号、取り消す事実 (まとめる履歴を含む)、影響するほかの事実。消す派生の記録の ID と、選んでいないほかのターンの件数は覆わない (裏の処理で派生の記録が増えても、見本を出し直さないため)。
  - 実行の命令は、見本の計画のハッシュを添える。コアは、書き込みの直前にロック (§7.2 の「ロックの順」) の下で計画を作り直し、ハッシュが違えば (見本の後に会話が増えた・裏の処理で事実が変わったなど) 実行せずに新しい見本を返す (利用者が見ていない範囲を伏せないため)。
- **影響するほかの事実**: 伏せ字にするターンの別の事実で、伏せ字の範囲と span が重なるもの (値の一部が伏せ字に掛かる) は、自動では取り消さない。span を写し直し (§7.3)、見本に行 (主語・属性と、事実の一覧の番号) として示す。取り消すかは、利用者がその行を `/forget` で選ぶ (確定、2026-11-17)。
- **中止**: 伏せ字にするとき、伏せ字にするターンが読めない (読めない記録・`v` が新しい記録) か、取り消す事実の出典の改訂の番号が今のターンと合わないときは、操作の全体を中止し、本文も事実も変えない (§7.3 の値の鍵の検査と同じ扱い)。伏せ字は本文を解釈して書き換えるので、03 §4.2 の規則 6 の「本体を解釈せずにできる」に当たらない (削除と、伏せ字にしないで忘れるは、本体を解釈せずにできるので、新しい `v` のターンにも行う)。見本を作るときに同じ検査を記録を変えずに当てて警告に示し、伏せ字にしないで忘れる (事実だけを消す) ことを勧める。
- **受け付けないとき**: どれかのセッションで応答を生成している間は、忘れるを受け付けない (伏せ字にするターンや往復が生成の途中にありうるため。§7.7 の 3)。
- **伏せ字にしないで忘れたとき**: 出典の発話は DB・ジャーナル・退避にそのまま残る。事実の表と事実から作った検索の鍵からは消え (`[非表示]` の範囲を持つ往復のノートは、伏せた本文から作り直す)、想起で添える往復と帯に出す往復の中の値 (出典の根拠の範囲の中で値に一致する箇所と、選んだときは同じ往復の応答とほかのターンで値の鍵が一致する範囲。上の確認の画面) は、private と同じく `[非表示]` にする (§7.5)。確認の画面に、発話が残ることを書く。
- 確認の画面には、約束する範囲 (§7.2) と約束しない範囲 (§7.8) を書く (畳んでよい)。private の確認の画面には、消しはしないこと、今のセッションのこれまでのやり取りには残ること (後で開き直したセッションも、そのやり取りは伏せずに送る)、伏せるのは事実の表と、事実の出典の往復の中の値だけで、事実になっていない発言 (問い・仮定、まだ抽出していないもの) や表記の違う書き方 (ひらがなとカタカナなど、§5.6) には効かないことを書く。
- **会話の中の依頼**: 利用者が会話の中で「忘れて」「覚えておいて」と頼んでも、モデルには記録を変える手段が無い。システムプロンプト (凍結の核) に、その依頼には `/memory`・`/forget`・`/private` を案内し、忘れた・覚えたと答えないことを書く。

### 7.2 即時に反映する範囲 (約束する範囲)

削除と忘れるの操作をしたら、書き手スレッドが **すぐに** 次から取り除く (確定 (ユーザー回答)、[OQ-09](10-decisions.md#oq-09-忘れるの約束の範囲))。

| 場所 | 取り除き方 |
|---|---|
| `evorag.redb` | 1 つのトランザクションで、事実を `Retracted` にし (削除なら記録を消し)、ターンの本文を伏せ字にして改訂の番号を上げ、伏せ字にするターンのほかの事実の span を写し直し、消す派生の記録 (下の「当て直しの一覧」の 4) を消す。削除では、消した ID を退避の整理と索引の掃除の job (03 §7.3) に書く。忘れるでは、消した ID を索引の掃除の job (`purge_indexes`、§7.7 の 2) に、退避の写し直しを `forget_backups` の job (03 §7.3) に書く。同じコミットで `meta` の `compact.pending` を書き (03 §3.1.1)、次の起動時に compact する (03 §8) |
| ジャーナル | 操作を先に書く (03 §6)。忘れるでは、1 回の追記で、`fact_directive` の `put` の行を先に、伏せ字にしたターンの封筒の `put` の行をその後に、新しい連番で書く。コミットの後に、対象の ID の `put` の行を含むファイルを書き直して入れ替える。対象の ID の `put` の行はすべて (確定の前と後の両方) 対象にし、削除は行を除き、忘れるは封筒の `id` が対象で、最上位の改訂の番号が伏せ字の後の番号より小さい行を除く (伏せ字の後の行は残す)。ほかに除くのは、チェックサムが合わず対象の ID を含む行だけ (03 §6) |
| 索引 | コミットの直後に、消した ID を今の世代と前の世代のすべての索引から除く。除けなかった分は job に残して再試行し、`doctor` が報告する (§7.7)。読み出しの段階でも DB で確かめて除く。そのセグメントを優先して作り直す (セグメントの `header.json` に持つ ID の最小と最大から、対象を含み得るセグメントだけを選ぶ)。古いセグメントは参照が外れたらすぐ消す。消せないとき (Windows で写像したまま) は、読み手が入れ替わった後にもう一度消し、それでも残れば次の起動時に消す。残っている間は `doctor` が報告する。前のモデルの世代の索引 (05 §2.2) と、v0.1 の索引 (`lex/`) が残っていれば、それも同じく作り直すか消す |
| 退避 | 対象を含む退避を、対象を除いて写し直す (03 §7.3)。日次・週次と、移行と作り直しの前の退避 (03 §7.2) のすべて |
| `quarantine` | 対象の ID (伏せ字にしたターンと、消した記録と派生の記録) の記録を消す (隔離した原文に伏せる前の本文が残るため) |
| `broken/` | ファイルがあれば、実行の後に消すかを尋ねる (03 §8。中身を読まないので、伏せ字にはできない) |
| 想起の途中 | 候補を集めてから添えるまでの間に操作が入りうるので、添える直前と候補の帯に出す直前に、DB に無い記録 (と出典が DB に無いもの)、private の値、伏せ字の前の改訂の番号から作った派生物を、もう一度ふるい分ける (05 §3.4、[OQ-42](10-decisions.md#oq-42-先に済ませる処理と外へ出る経路電池) の 6)。先に済ませた処理 (05 §4.5) の結果と、問いの埋め込みのキャッシュ (05 §3.1) は捨てる |
| llama-server | 構成を見分けずに、応答 (`chat`) の役割のモデルごとに、すべてのスロットについてキャッシュの消去 (`/slots/{id}?action=erase`、06 §4) を要求し、断られたら (既定の構成の 501 など) 無視する。消去の API は `--slot-save-path` 付きの構成でだけ使え、既定の構成では使えない。キャッシュは主記憶に llama-server を再起動するまで残りうるので、§7.8 の約束しない範囲に入れる (OQ-42 の 5、06 §4) |

- **まとめて写し直す**: 退避の写し直しは費用が大きい (10 万件で 1 世代 1.2〜1.4 秒、S-01) ので、続けてした操作をまとめ、対象を含み得ない世代を飛ばす。手順は 03 §7.3 を正本にする。写し直しを待つ間も、restore はジャーナルの操作を当て直すので (下)、忘れたものは蘇らない。
- **ジャーナルの書き直し**: 書き直すファイルの選び方・突き合わせ・取っ手の開き直し・失敗のときの再試行は 03 §6 を正本にする。
- **検索の事例と回帰台帳**: 忘れるでは、伏せ字にしたターンを入力に持つ検索の事例を消し、回帰台帳の事例は 13 §4 のとおりに扱う (削除は §7.1 の表のとおり)。どちらも v0.4 で足す種類なので、v0.3 の忘れるは、消す派生の記録の一覧に種類を足せる形にしておき、v0.4 で足す。
- **ロックの順**: 忘れるは、セッションの削除と同じく、索引を書き換える経路の直列化を取ってから、事実を書く経路のロック (§5.2.1) を取る。逆の順で取る経路を作らない。計画を作り直してから (§7.1 の「見本と計画」)、書き手のコミットと索引から除くのを終えるまで放さない。
- **捨てるキャッシュ**: 忘れるでは、先に済ませた処理 (05 §4.5) の結果と、問いの埋め込みのキャッシュ (05 §3.1) を、どのセッションの分も捨てる (上の表の「想起の途中」)。
- **派生の記録に届かない経路** (03 §4.2 の規則 12): 古い版 (v0.2.x など) は、新しい版の種類 (事実・訂正・事実への指示) を知らないので、セッションを消しても、それらを消さない。新しい版は、規則 12 の突き合わせで、出典の無くなった事実・訂正・事実から作った検索の鍵を消す (退避からも除く。§5.3 の「出典の無い事実の掃除」)。それまでの間も、出典の無い事実は、事実の表・想起・`/memory`・書き出しから除かれる。
- 削除のときに退避から除く ID には、派生の記録の ID も入れる (03 §7.3)。
- **当て直し** (確定、2026-11-17): restore・repair・ジャーナルの取り込みは、退避の後にした削除・忘れるを、ジャーナルから必ず当て直す。v0.3 の起動時にも、忘れるの指示をすべて当て直す (古い版で開いた間に取り込まれなかった分と、書き直しの済んでいない分を含む)。
  - **当て直しの一覧**: 層ごとに判定する。ターンがもう伏せ字になっていても、2〜4 は毎回確かめる。どれも何度当てても同じ。
    1. ターンの本文: 下の核で伏せ字にする。
    2. 取り消し: 印 (§7.6) に当たる事実を取り消す (§7.4 の繰り上げも当てる)。使う印は、印を解く指示 (`unblock`) の相手になっていない忘れるの指示の印だけ。
    3. span: 出典の改訂の番号が伏せ字の前の番号と同じ事実だけ、span を写し直して (§7.3) 改訂の番号を伏せ字の後の番号にする。すでに伏せ字の後の番号の事実には触れない。
    4. 消す派生の記録: 伏せ字にしたターンを出典とし、出典の改訂の番号が今と合わない派生の記録 (チャンク・ノート・埋め込み・訂正)、取り消した事実から作った検索の鍵とその埋め込み、忘れると訂正 (§7.5) で消す訂正、伏せ字にしないときの `hidden` の範囲を持つ往復のノート、伏せ字にしたターンの `quarantine` の記録。
  - **記録を変えたとき**: 当て直し (起動時・取り込み・restore・repair) が DB の記録を変えたら、同じコミットで、消した ID を `purge_indexes` の job に書き、その指示の `forget_backups` の job (03 §7.3) と `compact.pending` (03 §3.1.1) を書く。退避は job からだけ写し直す (起動時に退避を開いて中を確かめない)。
  - **伏せ字の行を先に書く**: 当て直しが生きている DB のターンを伏せ字にするときも、操作のときと同じく、伏せ字にしたターンの封筒の `put` の行を先にジャーナルに書いてからコミットする (03 §6 の順序)。
  - **起動の順** (03 §8): ジャーナルの取り込み → 開くときの削除 (03 §6) → compact → 書き手を作る → 忘れるの当て直し → 照会と命令の受け付け (compact はファイルを置き換えるので書き手の前に行い、当て直しで変えた分は次の起動で compact する)。当て直しを終えるまで、照会 (`/memory`・セッションのターンなど) も命令も受け付けない。sleep-time の前にも残りが無いかを確かめる。書き出しは、残りがあれば断る (03 §11)。
  - **ジャーナルの層の見つけ方**: 済んだかどうかの印を別に持たない。書き込みでデータ根を開くとき、ジャーナルを開く処理が、ターンの `put` の行の改訂の番号と、その行のあるファイルを ID ごとに集める (このプロセスで追記した行も足す)。書き直すファイルは、この集めた結果で選ぶ (ID の時刻では選ばない。古い版で後から足した行もあるため)。
  - ジャーナルの書き直しが入れ替えに失敗したとき (Windows でほかのプロセスが開いている) は、sleep-time に書き手スレッドの依頼として試し直す (03 §6)。残っている行の数は `doctor` と状態の行が示す (§7.8)。ジャーナルの層のための job の種類は足さない (ジャーナルと指示から、いつでも求め直せるため)。
- **`apply_forget` の分け方** (確定、2026-11-17): 忘れるの当て直しは、次の 3 つの層で作る。何度当てても結果が同じになる。
  1. **純粋な核** (`evorag-store` に置く。値の鍵を使わない): (本文, 今の改訂の番号, 1 つのターンの伏せ字の範囲と伏せ字の前と後の改訂の番号と後のハッシュ, 伏せ字の文字列) → 「当てた本文」/「当て済み」/「合わない」/「先の指示が要る」。改訂の番号の無いターンは 0 として読む。
     - 改訂の番号が伏せ字の後の番号と同じで、本文の SHA-256 がハッシュと合う → 当て済み。
     - 改訂の番号が伏せ字の前の番号と同じ → 範囲を伏せ字の文字列に置き換える。置き換えた本文のハッシュが合えば「当てた本文」、合わなければ「合わない」。
     - 改訂の番号が伏せ字の後の番号より大きい → 当て済み (後の忘れるが当たっている)。
     - 改訂の番号が伏せ字の前の番号より小さい → 先の忘れるが当たっていない。層は、同じターンの指示を指示の ID の順に、先のものから当てる。
     - それ以外 (改訂の番号が伏せ字の後の番号と同じで、ハッシュが合わない) → 合わない。
     - 値の鍵の検査 (§7.3) は操作のときだけに行い、当て直しでは行わない (ハッシュで確かめる)。
  2. **DB の層**: 核を、生きている DB と、退避を写した DB (写し直しの途中のもの) の両方に、同じ関数で当てる。同じターンには、生きている DB から読んだそのターンのすべての忘れるの指示を、指示の ID の順に当てる。合わないとき、または先の指示が無い・読めないとき:
     - 生きている DB: ジャーナルに、そのターンの、改訂の番号が伏せ字の後の番号で本文のハッシュが合う `put` の行があれば、それを当てる。無ければ本文を変えずに「合わないターン」とし、想起・候補の帯・裏の LLM の呼び出し・書き出しから除き、状態の行に示し、`doctor` が数える (関係の無い本文を失わず、伏せ字の前かもしれない本文も外へ出さないため)。
     - 退避の写し: そのターンを写しから除く (restore は、ジャーナルから伏せ字の後の行を足すので、伏せ字の本文で戻る)。
     - 上の一覧の 2〜4 は、本文の結果に関わらず当てる。派生の記録が出典の改訂の番号 (`src_rev`) を持つことに頼る (03 §3.3)。
  3. **ジャーナルの層**: その ID の、伏せ字の後の改訂の番号以上の `put` の行があるときだけ、それより小さい番号の行を除く (伏せ字の後の行が無ければ、何も除かない。DB の層が戻せなくなるため)。除く行の選び方は 03 §6。

### 7.3 伏せ字

- 伏せ字は、本文の範囲を固定の印 (`ja` は `[伏せ字]`、`en` は `[redacted]`。プロンプトの言語で選ぶ) に置き換える。伏せる範囲は、出典の根拠の範囲 (§5.1 の `source` の span) の中で、値の鍵 (§5.6) が忘れる値と一致する箇所に加え、出典の発話の中で根拠の範囲の外にある一致する箇所にする (既定。応答 (echo) と同じく選択で外せる。根拠の外に同じ値があると、伏せ字にしても出典の本文に値が残るため)。根拠の全体は伏せない (周りの文を残すため)。範囲は保存した本文の UTF-8 のバイト位置で持ち、書記素の境界 (結合文字・異体字セレクタ・ZWJ の並びを分けない) に合わせる。
- **書記素の境界と値の鍵の検査** (確定、2026-11-17): 値の鍵の検査 (次の項) は、値に一致した範囲 (境界に広げる前) で行い、記録して置き換える範囲は、その両端を書記素の境界まで広げたものにする (広げた範囲で値の鍵を取ると、結合文字などが付いて一致しなくなるため)。
- 置き換える前に、範囲の文字列の値の鍵 (§5.6) が、忘れる値と一致することを確かめる。1 つでも合わなければ、その忘れるの操作の全体を中止し、本文も事実も変えずに理由を示す (関係の無い本文を失わず、事実だけが消えて発話が残る中途半端な状態も作らないため)。ほかの中止の理由は §7.1 の「中止」。
- ターンは改訂の番号 (任意の項目、03 §3.3) を持ち、伏せ字にするたびに上げる。当て済みかどうかは、改訂の番号と伏せ字の後の本文のハッシュで判定する (伏せ字の前の本文のハッシュは持たない。伏せ字の後の本文に値の候補を入れて照合すれば、値を当てられるため)。
- **範囲・改訂の番号・ハッシュ** (確定、2026-11-17): 1 回の忘れるの操作は、1 つのターンの改訂の番号を、範囲がいくつあっても 1 だけ上げる。範囲は伏せ字の前の本文 (伏せ字の前の改訂の番号) の位置で持ち、始まりの順に並べ、重なる範囲と接する範囲 (前の範囲の終わりが次の範囲の始まりと同じ) は 1 つにまとめる (印が 1 つになる)。ハッシュは、そのターンのすべての範囲を置き換えた後の本文の SHA-256 にする。伏せ字の一覧 (§7.5) は範囲ごとに 1 つの要素を持ち、同じターンの要素はすべて同じ伏せ字の後の改訂の番号とハッシュを持つ。
- **位置の写し直し** (確定、2026-11-17): 伏せ字の前の位置を後の位置に直すのは、1 つの関数で行う。1 つの指示の 1 つのターンの範囲 (まとめた後のもの) について、位置との比べは伏せ字の前の位置で行う。位置 p は、p 以前に終わる範囲 (終わり ≦ p) の (範囲の長さ − 印の長さ) の和だけ前へずらす。範囲の内側 (始まり < p < 終わり) の p は、始まりの位置なら印の始まりへ、終わりの位置なら印の終わりへ寄せる (範囲の始まりちょうどの p は、その範囲ではずらさない)。指示が 2 つ以上あれば、指示の ID の順に、1 つずつ当てる (次の指示の範囲は、前の指示の後の本文の位置で書かれているため)。出典の改訂の番号が、その指示の伏せ字の前の番号でない span は写さない (§7.2 の「当て直しの一覧」の 3)。
  - 使うところ: ほかの事実の span と貼り付けの範囲 (伏せ字と同じトランザクションで写す)、`[非表示]` の範囲 (§7.5 の `hidden`。指示は書き換えず、読むときに、その指示より後の忘れるの伏せ字で写す)、当て直しの DB の層 (§7.2)。
  - `[非表示]` の範囲が後の伏せ字の範囲に重なるときは、写した範囲 (印を含む) を伏せる。
- 裏の処理の結果は、入力の改訂の番号が今と合わなければ捨てる (§4)。ターンの付帯の項目 (観測値など) を更新するときは、書き手のトランザクションの中で記録を読み直してから書く (外で読んだ本体を丸ごと書き戻さない)。
- 伏せ字で本文の長さが変わったら、同じトランザクションで、同じターンのほかの事実の span と貼り付けの範囲を写し直し、その出典の改訂の番号を新しい番号にする (§4 の「番号が今と合わない結果を捨てる」に当たらないようにするため)。
- ターンの `v` は上げない。v0.2 は本文を書き換えず (状態の更新だけ)、本体の知らない項目を保つので、改訂の番号が古い版に壊されないため。`v` を上げると、v0.2 に戻したときにターンの状態を更新できなくなる。
- 伏せ字の印について、システムプロンプト (凍結の核) に「利用者が伏せた部分で、推測も言及もしない」と書く。画面では、伏せ字と `[非表示]` を本文と見分けられる表示にする。
- **画面への印の範囲** (確定、2026-11-17): コアは、セッションのターンの照会 (02 §3) に、本文 (保存したまま。変えない) と一緒に印の範囲の並び (範囲と種類) を添える。範囲は今の本文の UTF-8 のバイト位置で、書記素の境界にある。種類は 2 つ: 伏せ字 (本文のその範囲がすでに印の文字列) と `[非表示]` (本文には値が残っていて、画面が表示するときにその範囲を `[非表示]` の印に置き換える)。範囲は、忘れるの指示の伏せ字の一覧と `hidden` から、上の「位置の写し直し」で求める。開いているセッションのターンに伏せ字か `[非表示]` の範囲ができたら、セッションと対象のターンをイベントで知らせ、画面はそのターンを読み直す (07 §2.1)。

### 7.4 削除と置き換えの連鎖

- セッションの削除で (確定 (ユーザー回答)、[OQ-49](10-decisions.md#oq-49-置き換えの連鎖の新しい側が消えたとき))、置き換えの連鎖の新しい側の事実が消えたとき、古い側の `Superseded` の事実を `Live` に戻さない。古い値を今の値として添えてしまうため。その (主語, 属性) は「今の値なし」になり、古い側の `by` は消えた ID を指したまま残す。
- 同じ (主語, 属性) に `Contested` の値があり、その出典の最も新しいターンが、消えた値の出典の最も新しいターンより後なら、それを `Live` にする (2 つ以上あれば、出典の最も新しいターンが最も後のもの。同じなら事実の ID の大きいもの)。`Live` にした値があれば、残りの `Contested` の `against` はその値に付け替える (§5.3)。そうでなければ `Contested` の値は `Contested` のまま残し、`against` は消えた値の記録を指したままにする (今の値なし。利用者が `/memory accept` で採れる)。今の値を過去形・否定で終えた記録 (§5.3) が消えたときは、`Contested` を繰り上げない。
- 忘れるで `Live` の値を `Retracted` にしたときも同じ扱いにする。
- 利用者は `/memory` で、今の値が消えた属性と `Contested` の値を見て、次の操作で直せる (07 §3)。どちらも事実への指示 (§7.5) として残し、事実を作り直しても効く。
  - `/memory accept <番号>`: `Contested` の値を今の値にする。
  - `/memory revert <履歴の番号>`: 履歴の値を今の値に戻す。

### 7.5 事実への指示 (`fact_directive`)

利用者が事実にした明示の操作は、事実とは別の正本の記録として持つ。ジャーナルには、新しい操作の行ではなく `fact_directive` の `put` の行として書く (古い版は知らない種類の `put` を読み飛ばさずに保つが、知らない操作の行は読み飛ばし、取り込みの連番がその先へ進んでしまうため、03 §6)。事実を作り直しても (`rebuild --facts`、統合のやり直し)、指示を当て直せばおおむね同じ結果になる (例外は下)。ただし、作り直しは忘れた事実の `Retracted` の記録を作らない (値の無い記録を候補から作れないため)。忘れた値は、再び覚えない印で拒まれて記録にならない。
- **作り直しで変わりうること** (確定、2026-11-17): `Retracted` の記録が無いので、忘れた値を相手にした結果は、作り直すと変わりうる。たとえば、今の値を忘れて「今の値なし」になり `Contested` のまま残った値 (§7.4 で繰り上げなかった値) は、作り直すと、忘れた値が記録にならないので今の値になる。この差は受け入れる (事実は LLM の派生物で、作り直しで同じになるとは限らない、§2。忘れた値の時刻や順を、値を持たずに残す仕組みを足さない)。回帰ケースに筋書きを置く (`tests/memory-cases/forget.toml` の F13)。
- **退避から戻したとき**: 退避の写し直し (03 §7.3) は、印に当たる事実を `Retracted` に書き換えずに消す。restore の後は記録が無いので §7.4 の繰り上げは起きず、`Contested` の値の扱いが、忘れた直後の DB と違いうる (上と同じく受け入れる)。
- **作り直しと訂正**: `rebuild --facts` は、訂正の候補を書かず (§6 の「候補を見つける時機」)、検証もし直さない。残っている検証済みの訂正を、事実の候補と一緒に入力の順 (§5.3) で当て直す (忘れるで消した訂正を作り直さないため、下の「忘れると訂正」)。

| 指示 | 持つもの | 当て方 |
|---|---|---|
| 忘れる | (主語, 属性)、再び覚えない印の並び (§7.6。忘れた値の鍵ごとに 1 つ。履歴もまとめたときは複数。同じ値の鍵の履歴の値は 1 つにまとめる)、忘れた事実の出典のターンの並び (`/memory forgotten` でセッションの題名を示すため)、忘れた値の鍵の並び (履歴もまとめたときはそのすべて。訂正を消して書かせないため、下の「忘れると訂正」)、伏せ字の一覧 (ターンの ID・伏せ字の前と後の改訂の番号・伏せ字の前の本文でのバイト範囲・伏せ字の後の本文の SHA-256。§7.3)、伏せ字にしないときに想起で `[非表示]` にする範囲 (ターンの ID・そのときの改訂の番号・バイト範囲。読むときに後の伏せ字で写す、§7.3)、履歴もまとめたか、伏せ字にしたか、値の鍵の正規化の版 | `apply_forget` (§7.2)。値そのものは持たない |
| private | (主語, 属性)、値の鍵、効く範囲 (後継まで / この値だけ)、値の鍵の正規化の版 | 書き込みの入口 (§5.3) で、合う事実に private の印を付ける |
| private の解除 | 対象の private の指示の ID | 印を外す。`/private off <番号>` は、その行に効いているすべての private の指示 (後継まで効くもの、その値だけのもの、削除で足したもの) を解く。ほかの行の印も外れるときは、確認の画面でその行を示す (履歴の値 (`Superseded`) で外れるものも、件数と行を示す) |
| 採る (`accept`) / 戻す (`revert`) | (主語, 属性)、値の鍵、値の鍵の正規化の版 | 書き込みの入口で、その値を今の値にする。後から統合が置き換えの条件を満たす値を見つけたら、通常どおり置き換える |
| 印を解く (`unblock`) | 対象の忘れるの指示の ID | 関門 8 (§5.2) でその印を照合しない |

- **本体の形** (v1): 種類は 1 つにし、`op` (`forget`・`private`・`private_off`・`accept`・`revert`・`unblock` の文字列) で分ける。最上位を平らにし、使わない項目は null か空の並びにする。共通の項目は `op`・`subject`・`attribute`・`vk`・`norm`・`fact` (参考の事実の ID)・`target` (解く相手の指示の ID)・`origin` (誰が足したか。`user` は利用者の操作、`delete` は削除で足した指示 (§7.5 の後継)。無い・知らない値は `user` として読む)。忘れるは `marks`・`vks` (忘れた値の鍵の 16 進の並び)・`turns`・`redactions` (`{turn, rev_before, rev_after, start, end, hash}` の並び。`hash` は 64 桁の小文字の 16 進)・`hidden` (`{turn, rev, start, end}` の並び)・`history`・`redact` を、private は `scope` (`successors`・`value_only`) を持つ。`redactions` と `hidden` の位置は、それぞれ `rev_before`・`rev` の本文の UTF-8 のバイト位置。
- **追記だけ**: 指示は書き換えも削除もしない。解くときは、解く指示を新しく足す。
- **当てる時点**: 採る・戻すは、指示の ID の時点で 1 回だけ当てる出来事にする (§5.3 の入力の順。後から条件を満たす値が来れば置き換わるため)。private・private の解除・忘れるの印・印を解くは、時点に依らず常に効く制約にする。
- **後継** (private の効く範囲): 同じ (主語, 属性) の事実のうち、出典の最も新しいターンの ID が、private の指示の ID より後のもの (指示の後に言われた値)。作り直しても同じになるよう、記録した時刻ではなくターンの ID で比べる。最も新しい出典で比べるので、抽出が遅れて古い出典が足されても外れない。指示の前から知っていた値でも、指示の後に言い直されれば private になる (安全の側に倒す)。セッションの削除 (§7.1・規則 12 の掃除を含む) で出典が外れて後継でなくなり、private でなくなる事実には、同じ依頼で、その値だけ (`value_only`) の private の指示を足す (消したセッションの言い直しで private になっていた値を、削除によって事実の表に出さないため)。
- **解く指示の相手**: private の解除は private の指示だけを、印を解くは忘れるの指示だけを解く (種類の違う相手を指していれば当てない)。
- **`/private` を当てられる行**: 今の値と `Contested` の値の行 (`Contested` の値も添える文脈に出うるため)。
- **忘れた事実の一覧**: 主語・属性・忘れた日時と、出典のセッションの題名を示す。出典のターンが無くなった分は、その数だけを示す。印を解いた指示は一覧から除く (伏せ字にしないで忘れた範囲の `[非表示]` は、印を解いた後も続く)。
- **private の理由の表示**: `/memory` の private の印は、利用者が選んだ値か、後継の規則で private になった値か、削除で足した指示で private の値かを見分けて示す (自分で選んでいない値に印が付く理由を示すため)。
- **戻すの重なり**: 戻す値と同じ値の鍵の事実が、すでに `Live` か `Contested` にあれば、履歴の記録は戻さない (単値で `Contested` なら、その記録を今の値にする)。同じ値の開いた記録を 2 件作らないため。
- **再び覚えない印と訂正・戻す**: 印は、候補だけでなく、検証済みの訂正の新しい値と、戻す値にも当てる (忘れた値を、訂正や戻すで蘇らせないため)。
- **伏せ字にしない忘れるの当て直し**: `[非表示]` の範囲を持つ往復のノートと訂正は、当て直しのたびに区別できない (作り直した新しいものと、範囲を作る前の古いもの) ので、指示の ID より古いものだけを消す (UUID v7 の順。指示の後に作ったものは、範囲を当てた本文から作ったもの)。
- **忘れると訂正** (確定、2026-11-17): 忘れるは、同じトランザクションで次の訂正を消す。伏せ字にしないで忘れるときも消す (訂正の記録は値の文字列を持つため)。
  - 対象のターンを `turn` に持つ訂正 (段階を問わない)。対象のターンは、伏せ字にするときは伏せ字にしたターン、伏せ字にしないときは忘れた事実の出典のターンと `[非表示]` の範囲を持つターン。
  - `old_vk`・`new_vk` のどちらかが `vks` のどれかと同じ検証済みの訂正 (どのターンのものも)。
  - 消した訂正は作り直さない: 指示の `turns`・`redactions`・`hidden` のターンからは候補を書かず、検証の結果が忘れた値なら値を書かずに `forgotten` で落とす (§6)。`rebuild --facts` は候補を書かない (上の「作り直しと訂正」)。
- **知らない `op` の読み方**: 新しい版の指示は、`marks` (再び覚えない印) だけを当てて残し、ほかは当てずに数える (忘れた値を古い版の作り直しで蘇らせないため。印は `op` を見ずに副索引で引く)。

- どの指示にも、操作したときの事実の ID を参考の情報として持たせてよい。当てるときは使わず、鍵 (主語・属性・値の鍵) と出典の (ターン, 範囲) で当てる (事実の ID は作り直すと変わるため)。
- **private の効く範囲** (確定 (ユーザー回答)、[OQ-47](10-decisions.md#oq-47-private-の効く範囲)): 既定は、指定した値と、同じ (主語, 属性) にあとで入る値 (後継) の両方にする。後継には、置き換えた値に限らず、多値の属性であとで並べて足した値も含む。機微になりうる値 (食べないもの、家族のことなど) で、新しい値が private でないまま入るのを防ぐため。確認の画面で「この値だけ」も選べる。
- **想起での private**: 往復の原文を添えるとき (OQ-36 の 7)、private の事実の出典の根拠の範囲の中で値に一致する箇所と、同じ往復の中で値の鍵が一致する範囲を、`[非表示]` (`en` は `[hidden]`。プロンプトの言語で選ぶ) に置き換えてから添える (同じ往復の中を値の鍵で探すのは、その事実の出典のどれかの改訂の番号が今のターンと合うときだけ。根拠の範囲の中に値の一致が見つからなければ、根拠の範囲の全体を伏せる。リランクに渡す本文にも当てる)。往復の全体は除かない (ほかの話題を落とさないため)。回帰台帳の事例 (13 §4) とリプレイにも同じ置き換えを当てる。

### 7.6 再び覚えない印

忘れた事実を、次の抽出や作り直しで再び覚えないための印 (確定 (ユーザー回答)、[OQ-48](10-decisions.md#oq-48-忘れた事実を再び覚えない印))。

- 伏せ字にした発話からは、値が消えているので再び抽出されない。そのため印が要るのは、伏せ字にしないことを選んだときと、同じ値を別のターンで言っていたとき。
- 印は、データ根ごとの乱数の鍵 (`meta` の `memory.forget_key`。作る時機と探し方は 03 §3.1.1) による HMAC-SHA256 で、(主語, 属性, 値の鍵) から作る (§5.6)。忘れるの指示は印を並びで持つ (値の鍵ごとに 1 つ。履歴もまとめて忘れたときは、忘れた値の鍵の数だけ)。値だけのハッシュにしない (短い値は辞書で戻せるうえ、別の属性の同じ値まで止めてしまう)。
- 鍵はデータ根と退避の中にあるので、データ根を手に入れた者は値を推測して照合できる。これは約束しない範囲に書く (§7.8)。鍵を消すことで消す方式は OQ-27 で扱う。
- 抽出の関門 8 (§5.2) で印に当たった候補は、黙って捨てて数える (値を画面にも出さない)。利用者がまた覚えさせたいときは、`/memory forgotten` の一覧 (主語・属性・忘れた日時・出典のセッションの題名を示し、値は出さない) から `/memory unblock <番号>` で印を解く (07 §3)。

### 7.7 消した記録を読み出しで除く仕組み

消した ID を残す専用の種類 (以前の版の仕様の `tombstone`) は持たない (2026-11-17)。古い版が消したものには残らず、伏せ字 (ターンの ID は残る) と `/private off` (同じ事実の鍵が戻る) には ID で拒む仕組みが効かないため。代わりに、次の 5 つで、消した・忘れた本文が蘇らないようにする。

1. **読み出しは DB で確かめる**: 派生の記録と索引の項目を読み出す経路はすべて、使う直前に、自分と出典が DB にあること、出典の改訂の番号 (`src_rev`・`rev`) が今のターンと合うこと、事実なら状態 (`Retracted`・private でない) を、DB で確かめる (許す一覧で判定する。今後足す経路 (回帰台帳の事例・カートリッジなど) も同じ)。書き出しは、private の事実を除かずに private の印のまま書く (利用者が自分のデータを持ち出す経路なので。03 §11)。ほかの確かめ (DB にあること・改訂の番号) は書き出しにも当てる (書き出しはコアのメモリの層を通して確かめ、確かめられない派生の種類は書き出さない、03 §11)。
2. **索引からすぐ除く**: コミットの直後に、利用者に知らせる前に、消した ID を今の世代と前の世代のすべての索引から除く。除く対象の ID は、削除では退避の整理と同じ job (03 §7.3) に、忘れるでは索引だけの job (`purge_indexes`。退避は `forget_backups` の job が受け持つ) に、コミットと同じ依頼で書いて残す。除けなかった分 (強制終了・Windows の写像) は job から再試行し、索引と退避の両方が済むまで job を消さない。起動時の突き合わせで前の世代の索引から除けなかった行は、退避に触れない索引だけの job (`purge_indexes`) に残す (前の世代の行の ID は、生きている記録と同じ ID のことがあるため)。終わるまで `doctor` が報告する。起動時の突き合わせ (DB に無い項目を除く) も、すべての世代の索引に当てる (古い版 (v0.2.x) は同じ job を退避の整理だけで消すので、索引の分はこの突き合わせで補う)。
3. **書き戻させない**: 書き手は、ジャーナルの削除の行 (開くときに集める) とこのプロセスで消した ID の記録を、`put` で作り直さない (古い封筒を書き直す経路で、消したものが蘇らないため。同じ依頼の中で消してから作るのも許さない)。ジャーナルの取り込みも、削除の行のある ID の `put` を当てない (03 §6、§4.2 の規則 0)。ターンの本文と改訂の番号は、書き手のトランザクションの中で読み直してから更新する (§7.3)。削除は、そのセッションで応答を生成している間は受け付けない。忘れるは、どれかのセッションで応答を生成している間は受け付けない (§7.1。伏せ字にするターンはどのセッションにもありうるため)。
4. **派生物は出典を確かめてから書く**: 派生の記録 (チャンク・ノート・埋め込み・事実・訂正) を作る手順は、書く前に、書き手のトランザクションか事実を書く経路のロックの下で、出典が DB にあり改訂の番号が読んだときと合うことを確かめ、合わなければ書かない。複数のターンを出典とする派生の記録 (ノート) は、出典ごとに改訂の番号を持つ。
5. **退避と整理を直列にする**: 退避を作る処理と退避の整理は同じ順序で通す。整理の job を書いた後に作り終えた退避も、整理の対象にする。開けない退避があれば job を残して再試行する (03 §7.3)。

- ジャーナルの削除の行と、忘れるの `fact_directive` が、消した・忘れたものの永続する記録になる (restore・repair・ジャーナルの取り込みは、ここから当て直す、§7.2)。

### 7.8 約束しない範囲 (確認の文言に書く)

- 利用者が書き出したファイル、OS のバックアップ (ファイル履歴、Time Machine)、SSD の物理的な消去、llama-server のログ (`-v` など)、llama-server が主記憶に持つプロンプトのキャッシュ (llama-server を再起動するまで残りうる、OQ-42 の 5) とスロットの保存 (`--slot-save-path`)。
- 古い版に戻して消したもの: v0.3 で使ったデータ根を v0.2.x で開いて消したセッションは、v0.3 の派生物 (事実・訂正・事実から作った検索の鍵) と、それを含む退避に、**v0.3 で開き直すまで残る** (v0.2.x はそれらを知らないため)。v0.2 の派生物については v0.2 のリリースノートのとおり。v0.3 のリリースノートに書く。
- 古い版では忘れるができない。v0.2.x で開いている間に、忘れた事実と同じ値を言っても、v0.3 で開き直したときに再び覚えない印で捨てる。
- 次の起動時の compact までの間、DB のファイルの空きの領域に残る消した記録。空きが足りず compact できないときは、次の起動時にやり直し、それまで `doctor` と状態の行で知らせる (03 §8)。Windows で消せずに残った索引のセグメント (次の起動時に消す)。
- ジャーナルの書き直しが入れ替えに失敗している間 (Windows でほかのプロセスがファイルを開いている): 伏せ字の前の行がジャーナルに残る。試し直して入れ替わるまで、`doctor` と状態の行で知らせる (§7.2)。
- 書き直しの前に古い版 (v0.2.x) に戻したとき: v0.2.x は忘れるの書き直しをしないので、伏せ字の前の行は、v0.3 で開き直して書き直すまでジャーナルに残る。
- 消すかを尋ねて残した `broken/` のファイル、ファイルシステムのスナップショット (ZFS・Btrfs・ボリュームシャドウコピーなど)。
- `/bad` に添えた理由の文 (信号の記録、03 §3.3) は、忘れるの対象にしない (値を書いていれば残る。消すにはセッションを消す)。
- 伏せ字の印は固定の長さだが、伏せ字の一覧の範囲の長さ (バイト数) から、忘れた値の長さが分かる。
- セッションの題名: 忘れるは題名を伏せ字にしない (題名は利用者が付けたもので、値の鍵で探す範囲に入れない。題名に値を書いていれば残る。`/memory forgotten` は題名を示す)。題名を変えても、前の題名はジャーナルと退避に残る。消すには、セッションを消す。
- 伏せ字の範囲に掛かったほかの事実 (§7.1 の「影響するほかの事実」): 自動では取り消さないので、利用者が選んで忘れるまで、値の文字列は事実に残る。
- 再び覚えない印から、値を推測して照合されうること (§7.6)。
