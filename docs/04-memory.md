## 1. メモリとカートリッジ

evorag が応答に添える情報は、出どころで 2 つに分ける。

| | メモリ | カートリッジ (v0.5、[14](14-cartridge.md)) |
|---|---|---|
| 中身 | チャットの会話と、そこから作ったチャンク・ノート・事実 | 文書をまとめた、版のある束 |
| 誰のものか | 利用者とのやり取りそのもの | 外から持ち込んだ知識。配られたもの、または利用者が手元の文書から作ったもの |
| 変わり方 | 会話のたびに増え、sleep-time に統合される。訂正で置き換わる | 版ごとに中身は変わらない。更新は新しい版を入れて切り替える |
| 書き手 | 書き手スレッド (依頼は応答の経路と sleep-time から) | 導入と作成のときだけ (チャット中は読むだけ) |
| 応答での扱い | 「あなたについて覚えていること」「以前の会話」として添える | 「カートリッジ」として出典つきで添える |
| 消し方 | セッションの削除、事実を忘れる | カートリッジを無効化・削除する |
| 保存先 | `evorag.redb` | `cartridges/` (中身) と `evorag.redb` (導入の台帳) |

- 2 つは検索の部品 (05) を共有するが、索引も保存先も分ける。
- 利用者についての事実はメモリを優先し、一般の知識はカートリッジを優先する。両方が食い違うときは、両方を出典つきで添え、食い違うことを示す (05 §4.3)。
- **カートリッジからメモリへは何も書き写さない**。カートリッジの内容が利用者の事実として残ることはない。

## 2. 層

| 層 | 中身 | いつ書くか | 入る版 |
|---|---|---|---|
| セッション | 題名、モード、状態 | 作成・改名・削除のとき | v0.1 |
| ターン | 発話・応答の全文と付帯情報 (状態、model_key、生成の設定、添えたものの ID) | 発話は送る前、応答は完了・中断・失敗のとき | v0.1 |
| 信号 | 評価・再生成の生の記録 (v0.3 から訂正の候補と検証の結果も) | 発生したとき | v0.1 |
| チャンク | 検索のためにターンを区切ったもの | sleep-time | v0.2 |
| ノート | 話題ごとのまとめ (数ターン〜1 セッション) | sleep-time | v0.2 |
| 事実 | 利用者や関わる人・物についての事実 | sleep-time (書き込みの入口は 1 つ) | v0.3 |

- v0.1 では、語彙の索引 (05 §2.1) はターンを直接の単位にする。v0.2 からはチャンクを単位にする。

## 3. 応答の経路での書き込み

1. 利用者が発話を送ると、まず発話のターン (状態「応答待ち」) を確定する (ジャーナル → DB、03 §3.4・§6)。確定に失敗したら、発話を入力欄に戻して知らせ、LLM に送らない。
2. 文脈を組み立てて (05) 生成を始める。
3. 応答は、完了・中断・失敗のいずれかの状態のターンとして書く。中断と失敗の応答も、受け取ったところまでの本文と理由を残す。
4. 応答の経路では、要約も抽出もしない。

- 入力欄の下書き (送る前の文章) は、所有者だけが読める一時ファイルに 5 秒ごとに保存し、次の起動時に戻す。外部のエディタで書いた一時ファイルも同じ置き場所に置き、送った後に消す。

## 4. sleep-time

一定の時間 (既定 60 秒、設定 `memory.idle_seconds`) 操作が無く、llama-server の chat のスロットに空きがあるときに進める裏の処理 (v0.2)。

- 利用者が操作したら、今の手順を止める (06 §4)。進み具合は `job` の記録に残し、次の機会に続ける。
- 各手順は **何度やっても結果が同じ** (冪等) になるように作る。入力 (ターンの ID の範囲) と、手順の版を `job` に記録する。
- 手順 (版):
  1. 新しいターンをチャンクに区切り、埋め込みを作る (v0.2)。
  2. 区切りのついた話題をノートにまとめる (型縛りの LLM の呼び出し、v0.2)。
  3. 利用者の発話から事実の候補を抽出する (型縛りの LLM の呼び出し、v0.3)。
  4. 訂正の候補を検証する (v0.3)。
  5. 事実を統合する (重複の除去、置き換え、矛盾の記録、v0.3)。
  6. 索引の新しいセグメントを作り、入れ替える (v0.2)。
  7. 自動の退避 (03 §7.1、v0.2 から sleep-time で行う)。
  8. カートリッジの埋め込みの不足分を作る (v0.5)。
  9. 自己学習の手順 (13、v0.4)。
- 裏の処理の LLM の要求は、1 回に送るプロンプトを 2,048 トークン (暫定) までにする。長い入力は分けて送る。
- 裏の処理は、空きの不足 (03 §8) や設定 `memory.sleep_time = false` で止められる。止めても会話の保存と語彙の想起は動く。

## 5. 事実

### 5.1 事実の形

| 項目 | 内容 |
|---|---|
| `subject` | 誰・何についてか (既定は利用者本人) |
| `attribute` | 属性の名前。属性の一覧 (同梱の TOML、`evorag-memory/attributes.toml`) で、単値か多値か、値の長さの上限を宣言する |
| `value` | 値 (文字列。既定の上限 200 文字。型付きの値は v1.0 より後) |
| `valid_from` / `valid_to` | 現実で成り立っていた期間。分からなければ空 |
| `recorded_at` / `retracted_at` | 記録した時刻と、取り消した時刻 |
| `state` | `Live` / `Superseded { by, at }` / `Retracted { at }` |
| `source` | 出典のターンの ID の一覧と、古い値の位置 (span) |
| `private` | 応答に添えない印 (利用者が指定したもの) |

- 属性の一覧の初期内容は v0.3 の着手前に決める (確定、[OQ-12](10-decisions.md#oq-12-属性の一覧の初期内容))。一覧に無い属性の候補は捨てて数え、`doctor` が報告する (一覧を広げる材料にする)。

### 5.2 抽出と統合

- **抽出の出典は利用者の発話だけ** にする。応答・利用者が貼った引用 (コードブロック、引用の記号で始まる行)・カートリッジからは抽出しない (確定、[OQ-20](10-decisions.md#oq-20-事実を抽出してよい出典))。貼られた文書に埋め込まれた指示が、事実として信頼する枠に入るのを防ぐため (02 §8)。
- 抽出は型縛り (06 §6) で、属性は一覧の内側だけ、値は長さの上限の内だけを受け付ける。
- 抽出した値が出典の発話に (正規化した上で) 含まれない候補は捨てる (決定論の関門)。

### 5.3 置き換え

- **単値の属性**: 新しい値で古い値を `Superseded` にする。
- **多値の属性**: 古い値の位置が特定できたときだけ、その 1 件を置き換える。特定できなければ並べて足し、兄弟の値には触れない。
- **削除しない**: 置き換えた値も残す。「いつ何を言っていたか」に答えられ、誤った置き換えを戻せる。
- **書き込みの入口は 1 つ**: 事実を書く関数は `evorag-memory` の 1 つだけにし、畳みの規則と private の検査を必ず通す。

### 5.4 応答での使い方

- 文脈に添えるのは `Live` で `private` でない事実だけ (05 §4)。
- 事実は「データ」として、属性と値の表の形で文脈に入れる。値に指示に読める文 (命令形の文、他の指示への言及) を含むものは、表に入れずに捨てて数える。
- `private` の事実は、文脈・リプレイ (13) には渡さない。sleep-time の統合 (重複の判定と置き換え) にだけ渡す (同じ PC の llama-server の中で閉じるため、提案、[OQ-21](10-decisions.md#oq-21-private-の事実を裏の処理に渡すか))。

## 6. 訂正

- **候補**: 字句の規則 (「違います」「ではなく」「じゃなくて」など。規則は同梱の TOML) で見つけたものは、候補として `signal` に記録するだけにする (v0.1 から記録する)。
- **検証**: sleep-time に、型縛りの LLM の呼び出しで判定し、決定論の関門を通ったものだけを「検証済みの訂正」にする (v0.3)。
  - 関門: 訂正した語が発話に逐語で含まれる、向き (古い値 → 新しい値) が合っている、引用ではない。
- **型**: 候補と検証済みは別の型にし、事実の置き換えと学習 (13) には検証済みの型しか渡せない。

## 7. 忘れる・消す

### 7.1 操作と結果

| 操作 | 結果 | 版 |
|---|---|---|
| セッションの削除 (`/delete`) | ターン・信号・チャンク・ノート・埋め込みを消す。そのセッションだけを出典とする事実も消す。他にも出典がある事実は、出典の一覧から外す。回帰台帳の事例のうち、そのセッションのターンを入力に持つものも消す | v0.1 (ターン・信号) / v0.2 / v0.3 / v0.4 |
| 事実を忘れる (`/forget <ID>`) | 事実を `Retracted` にして値を消す。さらに、出典の発話のうちその事実の部分を伏せ字にし (ターンの本文の該当の範囲を置き換える)、そのターンから派生したチャンク・ノート・埋め込みを作り直す。同じ事実を再び抽出しない印を残す (値のハッシュだけを持つ) | v0.3 |
| 事実を private にする (`/private <ID>`) | 応答に添えない (§5.4)。消しはしない | v0.3 |
| 全消去 (`evorag reset`) | データ根を消す。設定は残す | v0.1 |

- 「忘れる」で出典の発話を伏せ字にするか、発話はそのままで事実だけを消すかは、確認の画面で選ばせる。既定は伏せ字にする (確定 (ユーザー回答)、OQ-09)。

### 7.2 即時に反映する範囲 (約束する範囲)

削除と忘れるの操作をしたら、書き手スレッドが **すぐに** 次から取り除く (確定 (ユーザー回答)、[OQ-09](10-decisions.md#oq-09-忘れるの約束の範囲))。

| 場所 | 取り除き方 |
|---|---|
| `evorag.redb` | 同じトランザクションで記録を消し、`tombstone` を書く。次の起動時に compact する |
| ジャーナル | 該当する月のファイルを書き直して入れ替える (03 §6) |
| 索引 | 消した ID を読み出しの段階で除き、そのセグメントを優先して作り直す。古いセグメントは参照が外れたらすぐ消す |
| 退避 | 対象を含む退避を写し直す (03 §7.3) |
| `quarantine` | 対象の ID の記録を消す |
| `broken/` | ファイルがあれば、消すかを尋ねる |
| llama-server | サーバが消去の API を持つ構成 (`--slot-save-path` 付き) のときだけ、スロットのキャッシュの消去を要求する。既定の構成では消去の API が無く、キャッシュは次の要求で上書きされるので、§7.3 の約束しない範囲に入れる (06 §4) |

- restore と repair は、ジャーナルの操作の行から、退避の後にした削除・忘れるを必ず当て直す。古い退避から戻して、忘れたものが蘇ることはない。

### 7.3 約束しない範囲 (確認の文言に書く)

- 利用者が書き出したファイル、OS のバックアップ (ファイル履歴、Time Machine)、SSD の物理的な消去、llama-server のログ (`-v` など)、スロットのキャッシュ (次の要求で上書きされるまでメモリに残る) とスロットの保存 (`--slot-save-path`)。

### 7.4 tombstone

- 消した ID は `tombstone` に記録し、索引を作り直すまでは読み出しの段階で除く。`tombstone` は本文を持たない。
