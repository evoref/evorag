## 1. メモリとカートリッジ

evorag が応答に添える情報は、出どころで 2 つに分ける。

| | メモリ | カートリッジ (v0.9、[14](14-cartridge.md)) |
|---|---|---|
| 中身 | チャットの会話と、そこから作ったチャンク・区切り・台帳・単位・検索の鍵 | 文書をまとめた、版のある束 |
| 誰のものか | 利用者とのやり取りそのもの | 外から持ち込んだ知識。配られたもの、または利用者が手元の文書から作ったもの |
| 変わり方 | 会話のたびに増え、裏の処理で台帳を作って単位を導き直す。訂正・置き換えは導出の規則で表す | 版ごとに中身は変わらない。更新は新しい版を入れて切り替える |
| 書き手 | 書き手スレッド (依頼は応答の経路と裏の処理から) | 導入と作成のときだけ (チャット中は読むだけ) |
| 応答での扱い | 「あなたについて覚えていること」(プロファイル) と「以前の会話」(往復の原文) として添える | 「カートリッジ」として出典つきで添える |
| 消し方 | セッションの削除、単位を忘れる | カートリッジを無効化・削除する |
| 保存先 | `evorag.redb` | `cartridges/` (中身) と `evorag.redb` (導入の記録) |

- 2 つは検索の部品 (05) を共有するが、索引も保存先も分ける。
- 利用者についての事実はメモリを優先し、一般の知識はカートリッジを優先する。両方が食い違うときは、両方を出典つきで添え、食い違うことを示す (05 §4.4)。
- **カートリッジからメモリへは何も書き写さない**。カートリッジの内容が利用者の単位として残ることはない。

## 2. 層

| 層 | 区分 | 中身 | いつ書くか | 入る版 |
|---|---|---|---|---|
| セッション (`session`) | 正本 | 題名、モード、状態 | 作成・改名・削除のとき | v0.1 |
| ターン (`turn`) | 正本 | 発話・応答の全文と付帯情報 (状態、model_key、生成の設定、添えたものの ID、改訂の番号 (§7.3)。v0.2 から観測値、v0.4 から発話のときの UTC からのずれ、05 §3.6) | 発話は送る前、応答は完了・中断・失敗のとき | v0.1 |
| 信号 (`signal`) | 正本 | 評価・再生成の生の記録 | 発生したとき | v0.1 |
| 想起への操作 (`recall_feedback`) | 正本 | 候補の帯から添えた操作と、「無関係」の印 (05 §5.2)。v0.5 は今の形のまま (信号へまとめるかは v0.7 で決める、03 §3.3) | 利用者が操作したとき | v0.2 |
| 指示 (`directive`) | 正本 | 利用者の明示の操作 (忘れる・private とその解除・採る・戻す・印を解く) と、その結果として足す「終えた」出来事 (`end`) (§7.5) | 操作したとき (`end` は忘れる・削除と同じトランザクション) | v0.5 |
| チャンク (`chunk`) | 派生 | 検索のためにターンを区切ったもの (05 §2.4)。本文は持たず、ターンの中の範囲を持つ | ターンの確定のとき (語彙の索引)、裏の処理 (埋め込み) | v0.2 |
| 区切り (`segment`) | 派生 | 1 つの話題の往復の並び (下の「話題の区切り」) | 裏の処理 | v0.5 |
| 台帳 (`proposal`) | 派生 (LLM の生の出力) | 区切りごとの 1 回の呼び出し (B2) の出力と、それを導出に使うための対応表と版 (§5.2.1) | 裏の処理 (区切りごとに `Immediate`) | v0.5 |
| 単位 (`unit`) | 派生 (導出) | 利用者や関わる人・物についての事実 (`world`) と出来事 (`episode`) (§5.1) | 導出のとき (§5.3) | v0.5 |
| 検索の鍵 | 派生 (索引の項目) | 区切りの鍵 (台帳の `keys`) と単位の鍵 (単位から作る短い語句) (§5.5)。文脈には入れない | 導出の後の索引の作り直し | v0.2 (v0.5 で作り方を変えた) |
| プロファイル | 派生 (記録を持たない) | システムプロンプトに置く「属性: 値」の表 (§5.4)。v0.3〜v0.4 の事実の表に代わる | 導出の後に作り、05 §4.1 の時機で差し替える | v0.5 |

- 正本は DB とジャーナルの 2 か所に持つ (03)。`setting`・`model_binding` (v0.5 から役割 `memory` を足す、06) も正本。
- 後の版で足す種類 (名前は 03 §3.3 で予約): 話題の群 (`topic`)・優先度 (`priority`) (v0.6)、学習の事例 (`case`)・学習の結果 (`learned`)・採用の記録 (`adoption`)・別名の鍵 (`alias`) (v0.7)、利用者の指示 (`instruction`) (v0.8)。どれも、忘れるの置き場所の一覧 (§7.9) に行を足してから入れる。
- v0.1 では、語彙の索引 (05 §2.1) はターンを直接の単位にした。v0.2 からはチャンクと検索の鍵を単位にする。
- **正本と派生** (v0.5、ADR-0021、提案書 §2.2 の P3): 単位は、台帳と正本 (ターンの本文・指示) と、同梱の辞書・規則の版だけの関数にする (**全件の導出**、§5.3)。入力が同じなら結果は同じで、LLM を呼ばずに何度でも作り直せる。台帳は派生だが、LLM で作るので、失うと同じものが戻らず、作り直しは高い。そこで台帳は `Immediate` で書き、退避と書き出しに含める (03 §3.4・§11)。選択 (変種と `memory` の役割のモデル) や規則の版が変わっても、古い区切りの台帳は自動では作り直さない。作り直すのは、利用者が明示したとき (`evorag rebuild --ledgers`) だけにする (§5.2.1)。利用者の操作は単位の ID ではなく、値の鍵・entity・根拠の位置に結び付けた指示にし (§7.5)、導出のたびに当てる。
- **持ち続ける記録は単位の ID に結び付けない** (確定、2026-11-26): 単位の ID は中身から作り、辞書の写しや entity の別名で中身が変わると変わる。そこで、正本と、作り直せない派生 (台帳) は、単位の ID ではなく (entity, aspect, vk) か根拠の位置で単位を指す。単位の ID を持ってよいのは、導出のたびに作り直す派生の記録 (単位の `by`・`against`、索引の項目、画面の一時の参照) と、参考の情報 (指示の `unit`。当てるときは使わない) だけにする。
- **往復**: 利用者の発話と、それへの応答の組。記録は持たず、ターンの `reply_to` から組み立てる。想起で添える単位にする (05 §3.3)。
- **検索の鍵は索引にし、添えるのは原文にする** (確定、[OQ-36](10-decisions.md#oq-36-想起の規則-候補リランク添え方縮退) の 7): 検索の鍵は、問いと元の会話の語彙の違いを補うための索引の項目で、文脈には入れない。鍵で当たったら、鍵が指す往復をリランクして添える。要約が原文と食い違って誤りを持ち込むのを避けるため。作り方は §5.5。
- **話題の区切り** (`segment`。v0.5、提案書 §4.2。話題の推定に LLM を使わない): セッションの往復を、古い順に先頭から詰めて区切る。区切りの境界はモデル・変種に依らないので、台帳を替えても区切りが揃う。
  - 対象はチャットのセッション (モードが `chat`) だけ。知らないモードのセッションは区切らない。
  - 往復は利用者の発話ごとに 1 つとし、その発話を `reply_to` に持つ最新の完了した応答を組にする (応答が無ければ発話だけの往復)。区切りの中身は発話で決まり、応答は呼び出しの時点のものを読む (後から応答が完了・再生成されても区切りは変わらない)。
  - 大きさは **モデルに依らない見積もり** (往復の数と、前のふるい (§5.2) の後の利用者の発話の文字数) で決める。1 往復は必ず入る。前のふるいで送らない発話 (挨拶・相槌・短い) も往復として区切りに入れ、文字数には数えない (区切りの境界を前のふるいの規則の版で動かさないため)。8 往復・1,600 文字 (今の話題の区切りと同じ。発話を 300 文字・応答を 500 文字に切った本文の合計)。日本語の事例の 8 往復の区切りで、単位は 1 区切り平均 7〜12 件・最大 16 件、生成は最大約 1,100 トークンで、Qwen3-4B (約 20 tok/s) で最大 51 秒、gemma-4-12b (約 6 tok/s) で最大 179 秒かかった。遅いモデルでは短い待機の中で終わらないことがあるので、止められたときは途中まで採る (§5.2.1 の `partial`) (S-17 の 4・5・6 で決めた、2026-11-26。spikes/S-17/REPORT.md §5〜§7)
  - 区切りは、上限に達したか、そのセッションの最後のターンから 10 分過ぎたときに **閉じる**。閉じた区切りは変えない (後から同じセッションに往復が足されたら、新しい区切りを始める)。閉じていない末尾の区切りに往復が足されたら、その区切りの台帳を置き換える (§5.2.1)。
  - **決め方の細目** (M5.2 で決めた、2026-11-27。境界を決定論にし、時計と本文の変化で閉じた境界を動かさないため):
    - 往復の順は、発話のターンの ID の順にする。「最新の完了した応答」は、状態が完了の応答のうち ID が最も大きいもの (中断・失敗の応答だけなら発話だけの往復)。
    - 文字数は、保存した本文に前のふるいを当てた本文 (前後の空白を除いたもの) の Unicode のスカラー値の数にする。前のふるいが送るとした発話だけを数え、訂正の候補のために送る短い発話 (§5.2 の「文番号」) は数えない (訂正の字句の型の版で境界を動かさないため)。`[非表示]` の印に置き換える前の本文で数える。
    - 上限に達したとは、往復の数が 8 か、文字数が 1,600 以上になったこと (ちょうどで閉じる)。足すと 1,600 文字を超える往復は入れずに、前の区切りを閉じて新しい区切りを始める。1 往復で 1,600 文字を超えるときは、その往復だけで閉じる。
    - 最後のターンの時刻は、セッションのすべてのターン (発話と応答) の作成の時刻の最大にし、今がそれから 10 分以上後なら閉じる (ちょうど 10 分で閉じる)。時計が戻っても、最大で見るので早くは閉じない。
    - 記録した区切りは決め直さない。開いている末尾の区切りの記録があれば、その往復と `chars` をそのまま前に置いて往復を足す (伏せ字で本文が変わっても境界を動かさない)。記録した区切りの前や間にある、どの区切りにも入っていない往復 (読めなかったターンが読めるようになったときなど) は、その位置で詰めて閉じた区切りにする (後ろに区切りがあるので末尾にならない)。後ろに区切りがある開いた区切りは閉じる。
    - 区切りの往復の発話のターンが見えなくなっても (読めない記録・隔離。v0.5 に個別のターンを消す操作は無く、セッションの削除は区切りごと消す、§7.1)、区切りは変えない (計画で見えない往復として知らせるだけ)。その区切りの台帳は、`sentences` と `refs` の改訂の番号が今のターンと合わないので有効でなくなる (§5.2.1)。
  - **閉じた区切りは `Immediate` で書く** (確定、2026-11-26): 大きさの見積もりは前のふるいの後の文字数なので、閉じた区切りの記録を失って決め直すと、前のふるいの規則の版によっては境界が動く。そこで閉じた区切りは、閉じたときに `Immediate` のコミットで書き (03 §3.4)、決め直さない。台帳のある区切りのターンは、区切りの記録を失っても区切り直さず、台帳の `segment` と `sentences` から区切りを戻す。区切り直すのは、閉じた区切りにも台帳にも入っていない往復 (開いている末尾) だけにする。
    - **台帳から戻す細目** (M5.2 で決めた、2026-11-28。`sentences` は番号を振った文の発話しか持たず、前のふるいで送らない発話を戻せないため。`evorag-memory` の `restore_segment`): 往復は、台帳の `inputs` の `through` から戻す。セッションの今の発話 (ID の順) のうち、`through` の発話で終わる `through` の数の発話を往復とし、最初の往復から作った区切りの ID が台帳の `segment` と合うことで確かめる。その区切りの `through` を持つ台帳 (状態と有効性は問わない) がすべて合えば、往復の最も多い台帳の並びを使い、台帳の `sentences`・`corr` の発話と、`refs` の今読める応答が答える発話が、その並びの中にあることを確かめる。戻した区切りは閉じたものとし (台帳を書いた後に足された往復は分からない。入れた往復を別の区切りへ動かさず、台帳を呼び直さないため、後の往復は新しい区切りにする)、`chars` は今の前のふるいで数え直す。`through` を持つ台帳が無い・`through` の発話が無い・数が合わない・区切りの ID が合わない (間の発話が読めない・増えた)・台帳の発話が並びの外にある・記録した区切りと範囲が重なるときは戻さず、その往復を区切り直す (台帳は消さない。区切りの ID が変われば、その台帳は使われない)。
  - **区切りの ID** (確定、2026-11-26): 区切りの最初の往復の発話のターンの ID から、決定論で別の値を作る。SHA-256 (`"evorag.seg.1"` ‖ 0x00 ‖ ターンの ID の 16 バイト) の頭の 16 バイトにする。決め直しても同じ ID になり、台帳の `segment` と結び付く。ターンの ID と同じ値にしないのは、関係 (`links`)・副索引・索引の項目・掃除の ID の一覧で、ターンと区切りの ID を取り違えないため。区切りを並べる順は、ID ではなく、最初の往復の発話のターンの ID の順にする。
  - **区切りの本体** (v1。本節を `segment` の本体の項目の正本にし、03 §3.3 は耐久性・関係・副索引だけを持つ): `session` (セッションの ID)・`pairs` (区切りの中の往復の利用者の発話のターンの ID の並び。古い順で 1 つ以上。往復の数はこの長さ)・`closed` (閉じたか)・`chars` (大きさの見積もり。前のふるいの後の利用者の発話の文字数)。閉じた区切りの記録は書き換えない。区切りの記録を書くときは、外で読んだ前の区切りの本体が、書き手のトランザクションの中でも同じであること (前が無かったなら、無いままであること) を確かめ、違えば書かない (その間に閉じた区切りを、古い本体で上書きしないため)。
  - **末尾の区切りを呼ぶ時機** (確定、2026-11-26): 閉じていない末尾の区切りは、前の呼び出しから往復が 2 つ以上増えたとき (台帳の `inputs` の `through` と比べる、§5.2.1) と、閉じたときに呼ぶ (閉じたときは、台帳の `through` がすでに区切りのすべての往復を入れていれば呼ばない。`through` の往復が区切りに無いか、数が合わなければ呼ぶ。M5.2 で決めた、2026-11-27) (短い待機のたびには呼ばない。話しながら待機を繰り返すと、同じ区切りを往復の数だけ呼び直して生成トークンが増えるため)。`evorag sleep` も同じ規則で呼び、末尾の区切りを強制的に閉じない (閉じた区切りは変えないので、閉じるのを早めると後の往復が別の区切りに分かれるため)。BM-108 の生成トークンには、末尾の呼び直しの分も含めて測る (09 §5.1)。
- **文の分け方 v1** (確定、2026-11-26): 文番号 (§5.2) を振る文の分け方は、`evorag-memory` に置いて版を持たせ、v1 で凍結する (台帳の `sentences` と `inputs` の版が、この分け方に結び付くため)。中身は v0.4 の文の窓の分け方 (05 §3.8 の 1) を移したもの (`evorag-memory` の `split_v1`。版は `SPLITTER_V1`)。出力は golden の試験で固定し、変えるときは v1 を直さずに v2 を足して `inputs` の `splitter` を上げる。v1 は、全角の `．`・半角の `｡`・`\r` だけの改行・U+2028 では切らず、後ろが空白でない半角の `!`・`?` (URL の中を含む) では切る (v0.4 の文の窓のまま)。文の窓 (05 §3.8) は v1 を呼び、別に持たない (M5.2 で決めた、2026-11-27。文番号の文と窓の文を揃えるため)。関門 3 の補いの文 (§5.2) と訂正の穴の文 (§6) は v1 に寄せず、§6 の「区切りの文字の判定」で分ける (M5.2 で決めた、2026-11-27。どちらの分け方にも外れる事例があり、今の関門の出力を変えないため。v1 では「住まいは東京．大阪じゃなくて京都です」の古い値の穴が「住まいは東京．大阪」に伸び、「Yahoo!じゃなくてGoogleです」の古い値の穴が空になり、閉じの括弧を前の文に含めるので、括弧で閉じた問い (「明日は？」) の文が問いの印で終わらない。§6 の分け方は略語の `.` で切るので、"I live near Dr. Kim's clinic in Osaka." の "Osaka" は関門 3a で落ち、"Is Osaka near Dr. Kim's place?" の "Osaka" は問いの文の補いを抜ける。食い違う事例は試験で固定する)。関門を移すとき (M5.2) に見直し、関門 3 の補いの問いの文の判定だけ、略語の後ろの `.` で切らないことにした (§5.2 の関門 3 の「文」。M5.2 で決めた、2026-11-28)。関門 3a・3b と訂正の穴は §6 の区切りのままにする。

## 3. 応答の経路での書き込み

1. 利用者が発話を送ると、まず発話のターン (状態「応答待ち」) を確定する (ジャーナル → DB、03 §3.4・§6)。確定に失敗したら、発話を入力欄に戻して知らせ、LLM に送らない。
2. 文脈を組み立てて (05) 生成を始める。
3. 応答は、完了・中断・失敗のいずれかの状態のターンとして書く。中断と失敗の応答も、受け取ったところまでの本文と理由を残す。
4. 応答の経路では、LLM で記憶を作らない (呼び出しと導出は裏の処理で行う、§4)。発話のターンには、発話のときの UTC からのずれを記録する (v0.4、05 §3.6。単位の相対の日付を解くため、§5.1)。

- 入力欄の下書き (送る前の文章) は、所有者だけが読める一時ファイルに 5 秒ごとに保存し、次の起動時に戻す。外部のエディタで書いた一時ファイルも同じ置き場所に置き、送った後に消す。

## 4. sleep-time

利用者が操作していない間に進める裏の処理 (v0.2)。v0.5 から、仕事をきっかけの時間で階層に分けて段取りする (提案書 §8 の B10)。

| 階層 | きっかけ | 仕事 | 版 |
|---|---|---|---|
| 即時 | ターンの確定 | チャンクに区切り、語彙の索引に足す (05 §2.3) | v0.2 |
| 微小待機 | 入力が止まる | 投機的な先読み (05 §4.5) | v0.4 |
| 応答の後 | 応答を書き終えた | 次のターンの先頭を先に処理する (05 §4.5) | v0.2 |
| 短い待機 | 下の「アイドルの判定」(既定 60 秒の無操作) | 下の「手順」: 埋め込み、区切り、区切りごとの 1 回の呼び出し (B2) → 関門 (B3) と導出 (B4)、索引、プロファイル | v0.2 (B2〜B4 は v0.5) |
| 長い待機 | AC 電源で 10 分の無操作 | 台帳の作り直し (明示の操作で求めたもの、§5.2.1)、学習の候補の評価 (13) | v0.7 |
| 夜間 (opt-in) | OS のタスクスケジューラ (`evorag sleep --until`) | 全件の作り直し、話題の見出しと気づきの提案の生成、学習の候補の評価。採用はしない (次に TUI を開いたときに知らせてから採る) | v0.8 |

- **手動の実行** (`evorag sleep`、v0.5): 短い待機の手順を、アイドルの判定を待たずに前景で最後まで流す (話し終えてすぐ閉じる使い方で、裏の処理が終わらないときの手当て)。TUI と同じくデータ根のロックを取るので、TUI と同時には動かない (03 §9)。打ち方・進み具合の表示・終了コードは 07 §5 を正本にする。本書の手順・冪等・失敗の扱いの規則は手動の実行にも同じく当てる (「譲る」の相手は、利用者の中止の操作になる)。
- v0.5 には長い待機の階層が無いので、台帳の作り直しを明示したとき (`evorag rebuild --ledgers`、§5.2.1 の「台帳を作り直すとき」) は、短い待機の手順 3 の新しい区切りの後に続けて流す (`evorag sleep` でも同じ順に流す)。
- **起動後の点検** (確定、2026-11-12): モデルの性質の点検 (06 §3.3) とリランカーの較正 (05 §3.7) は、下の sleep-time の手順と分ける。入力が 2 秒途切れ (`idle_seconds` がそれより短ければその長さ)、応答を生成していない間に流し、`memory.sleep_time` と `idle_seconds` には縛らない (「TUI を開いた後に裏で、短い間に」済ませるため)。電池の設定の `stop` と空きの不足では止める。利用者が操作したら、下の「譲る」と同じく切り、次の機会に続ける (較正は済んだ問いの結果を覚えておき、続きから求める)。
- **繰り返しを防ぐ**: 終えたのにまだ要る手順 (結果を保存できなかったなど) と、失敗した較正は、5 分おいてから試し直す (繋がらないサーバや書けない DB に、要求を送り続けないため)。
- **外部のエディタ**: 利用者が外部のエディタで書いている間は、裏の要求を出さない (06 §4 の「入力している間は出さない」)。
- **アイドルの判定** (短い待機の手順): 次のすべてを満たすときに始める。
  - キー入力が一定の時間 (既定 60 秒、設定 `memory.idle_seconds`) 無い。
  - 応答を生成していない。次のターンの分の先の処理 (05 §4.5) も終わっている。
  - llama-server の chat のスロットに空きがある (06 §4)。
  - 電池の設定 (`memory.on_battery`、07 §4.2) が止めていない。
- **譲る**: 利用者が操作したら (キー入力、発話の送信)、今の手順の LLM の要求 (chat・embed・rerank・`memory` のどれでも) を 1 秒以内に止める (NFR-105、06 §4)。止めたところまでの結果は、作り直せるものだけを残す (台帳の呼び出しを止めたときは §5.2.1 の「止められたとき」)。
- **job による再開**: 各手順の進み具合は `job` の記録に残し、次の機会に続ける。強制終了の後も、起動してアイドルになったら続ける。ただし、進み具合を状態から求められる手順は job を書かない (2026-11-12): 埋め込み (手順 1) は「語彙の索引にあってベクトルの索引に無いチャンク」を 32 件ずつ埋め込み、記録と索引への反映を 1 回ごとに落とされない形で行うので、止めても強制終了しても、次の機会に足りない分から続く。台帳 (手順 3) も、区切り (§2) と記録した台帳を呼び直すかの判定 (§5.2.1 の `needs_call`) で突き合わせて足りない分から作るので job を書かない (1 つの台帳は 1 回の呼び出し (分けたときは数回) と 1 回の書き込みで作る)。ただし `evorag rebuild --ledgers` で求めた呼び直しは、状態から求められない明示の操作なので job に残す (§5.2.1)。導出 (手順 4) は、導出の指紋 (§5.3) で要るかが分かるので job を書かない。
- **要る作り直しは状態から求める**: job の記録は裏の処理の結果と同じく失いうる (ジャーナルに書かない、03 §6) ので、job が無いことを「作り直しが要らない」とみなさない。起動時に、軽い検査 (件数と、最後に処理した ID の比較。全件は走査しない、NFR-101) で次を確かめ、足りなければ job を作る。
  - チャンクの無いターン (古い版で足したターンを含む) が無いか。
  - 記録した埋め込みのモデルの索引が、すべてのチャンクと鍵を覆っているか。
  - 呼び直すかの判定 (§5.2.1 の `needs_call`) に当たる区切りが無いか (区切りの数と台帳の数を比べ、足りなければ手順 2・3 で突き合わせる)。
  - 導出の指紋 (§5.3) と一緒に記録した成分 (台帳の件数と最大の ID・指示の件数と最大の ID・版・今の選択と直前の選択) が今と合うか (合わなければ全件を導き直す)。
  - 記録したリランカーのしきい値があるか (無ければ較正を裏で流す、05 §3.7)。
- **冪等**: 各手順は **何度やっても結果が同じ** になるように作る。入力 (ターンの ID の範囲。台帳は区切りと `sentences`) と、手順の版と、使ったモデルの model_key を `job` (台帳は台帳の本体) に記録する。途中で止めてから再開しても、止めずに通したときと同じ結果になる。型縛りの呼び出しは temperature 0・固定の seed・固定のスロットで出す (06 §6)。ただし LLM の出力は、同じ設定でもモデルのビルドやスロットの状態で揺れうるので、台帳は一度書いたら、呼び直すかの判定 (§5.2.1 の `needs_call`。末尾の区切り・`partial`・`failed` の後にモデルが変わった) に当たるときのほかは呼び直さない (台帳を導出の入力にし、作り直しを決定論にするため、§2)。
- 手順 (短い待機。この順に流す。版):
  1. 新しいターンのチャンクの埋め込みを作る (v0.2。チャンクへの区切りと語彙の索引への追加は、ターンの確定のときに行う、05 §2.3)。
  2. 区切りを決める (§2。LLM を使わない。閉じた区切りと末尾の区切りの記録を書く、v0.5)。
  3. 呼び直すかの判定 (§5.2.1 の `needs_call`) に当たる区切りごとに、1 回の呼び出し (B2、§5.2) をして台帳を書く。区切りの古い順に流す。訂正の候補 (§6) は、呼び出しの入力を作るときに字句の規則で見つけ、台帳の `inputs` の `corr` に書く (LLM を使わない、v0.5)。
  4. 台帳が増えた・変わったとき、または導出の指紋が合わないときは、全件の導出 (B3 → B4、§5.3) を行い、単位と指紋を書く (LLM を使わない。1 回の短い待機の中で 1 回にまとめる、v0.5)。
  5. 索引の新しいセグメントを作り、入れ替える (台帳の `keys` と単位から作る検索の鍵 (§5.5) を含む、v0.2)。埋め込みのモデルを切り替えたときの作り直し (05 §2.2) もここで進める。検索の鍵の埋め込みは、手順 1 と同じく足りない分から作る。

  7. 忘れる・削除の退避の写し直しと、入れ替えに失敗したジャーナルの書き直しが残っていれば続ける (どちらも操作の直後に書き手スレッドの依頼として始め、アイドルの判定を待たない。03 §6・§7.3、§7.2、v0.3)。

## 5. 単位

### 5.1 単位の形

単位は、利用者や関わる人・物についての 1 つの記憶を、1 件ずつの記録 (種類 `unit`) として持つ (提案書 §4.4)。単位は導出 (§5.3) の結果で、台帳と正本から何度でも同じものが作られる。同じ記憶を後で言い直したときは、新しい単位を作らずに根拠 (`anchors`) を足す。

| 項目 | 内容 |
|---|---|
| `id` | **中身から作る** (下の「単位の ID」)。作り直しても同じ ID になる |
| `layer` | `world` (置き換えのある事実。今の値と履歴を持つ) / `episode` (出来事。置き換えない) |
| `entity` | 主語。`self` (利用者本人) か、発話にある呼び名 (「妻」「田中さん」など) に値の鍵の正規化 v1 (§5.6) を当てた文字列。呼び出しで明示させ、既定を置かない |
| `aspect` | **辞書の属性** (同梱の TOML、`evorag-memory/attributes.toml`。v0.4 の属性の一覧を初版にし、版を上げて足す) か、**自由記述の属性** (呼び出しが出した属性に正規化 v1 を当てたもの。40 文字まで)。どちらかを本体で見分ける |
| `value` | 値。根拠の文の部分文字列 (§5.2 の「記録する文字列」)。長さの上限は辞書の属性ごと (既定 200 文字)、自由記述の属性は暫定 60 文字(S-17 の 4・5・6 で決めた、2026-11-26。spikes/S-17/REPORT.md §5〜§7) |
| `vk` | 値の鍵 (§5.6) |
| `free` | 自由記述の属性なら true、辞書の属性なら false |
| `when` | `{from, to, basis}`。根拠の順で最初の、解けた `when` (下の「日付」)。根拠ごとの `when` は `anchors` に持つ。どの根拠でも解けなければ null |
| `tense` | `current` (今も成り立つ) / `past` (以前は成り立っていた) / `planned` (予定) |
| `state`・`against`・`by`・`state_at` | `world` だけ (下の表)。`episode` では null |
| `anchors` | 根拠の並び。各々が、ターンの ID、そのターンの改訂の番号 (§7.3)、根拠の文の範囲、値の範囲、種類 (`said`: 値を言った、`ended`: 過去形・否定で終えた発言、`corrected`: 訂正の古い値の穴、§5.3)、その根拠の候補の `when` を解いたもの (無ければ null)。範囲は保存した本文の UTF-8 のバイト位置で、書記素の境界に合わせる。(ターン, 値の始まり) の順 |
| `private` | 応答に添えない印。指示 (§7.5) から導出で決まる値 |

| 状態 | 意味 | プロファイル (§5.4) |
|---|---|---|
| `Live` | 今の値 | 辞書の属性なら入る |
| `Contested { against }` | 単値の辞書の属性で、今の値と違う値が、置き換えの条件 (§5.3) を満たさずに出てきたもの | 入らない。`/memory` に出す |
| `Superseded { by, at }` | 新しい値に置き換えられた、または以前は成り立っていた (`by` は任意。時制が `past` の値と、`end` (§7.4) で終えた値には無い)。`by` の単位が消えた後も、`by` は消えた ID を指したまま残す | 入らない |

- **忘れた値は単位にならない** (関門 8 と台帳の掃除、§7)。v0.4 までの `Retracted` (値を消して出典だけを残す状態) は持たない。忘れた値の前の値を今の値に戻さないことは、指示 `end` (§7.4) で表す。
- 自由記述の属性の `world` の単位は置き換えないので、状態は `Live` か (時制 `past` で) `Superseded` だけになる (§5.3)。
- **単位の ID**: `layer`・`entity`・`aspect` (辞書の属性は名前、自由記述の属性は正規化した文字列)・`free` (辞書か自由記述かの別。同じ綴りの辞書の属性と自由記述の属性を別の単位にするため、確定、2026-11-26)・`vk` から作る。`episode` は、加えて `when` を解いた日付 (無ければ発話の日、下の「日付」) を入れる (同じ値の別の日の出来事を、別の単位にして数えるため)。ハッシュは、`"evorag.unit.1"` ‖ 0x00 の後に、(名前, 値) の組を名前の決まった順に、名前と値をそれぞれ u32be の長さを前に置いて並べたバイト列の SHA-256 にし、頭の 16 バイトを ID にする (導出の指紋 (§5.3) と同じ並べ方)。同じ中身の単位は 1 件にまとめる (`world` で、置き換えられた値を後でまた言ったときも、同じ単位が状態を変えて今の値に戻る。置き換えの前後の時期は `anchors` のターンの時刻から読む)。値の文字列そのものは ID に入れない (値の鍵は HMAC、§5.6)。
- **本体の形** (v1。最上位を平らにする。本節を `unit` の本体の項目の正本にし、03 §3.3 は耐久性・関係・副索引だけを持つ): `layer`、`entity`、`aspect`、`free` (自由記述の属性なら true)、`value`、`vk`、`norm` (値の鍵の正規化の版)、`when` (`from`・`to` は `YYYY`・`YYYY-MM`・`YYYY-MM-DD` の文字列か null、`basis` は `stated`・`relative`・`utterance`・`no_offset` の文字列)、`tense`、`state` (`live`・`contested`・`superseded` の文字列か null)、`against`・`by` (単位の ID か null)、`state_at` (`Superseded` になったときの、置き換えた候補か `end` の位置のターンの時刻。作り直しても同じ値になるため)、`private`、`anchors` (`{turn, rev, start, end, s_start, s_end, kind, when}` の並び。`start`・`end` は値の範囲、`s_start`・`s_end` は根拠の文の範囲、`when` は上の `when` と同じ形か null)。
- **主語**: `self` か、呼び名に値の鍵の正規化 v1 (§5.6) を当てた文字列。呼び名は、LLM の写しからではなく、根拠の文の中で一致した保存した本文の部分文字列から作る (§5.2 の「記録する文字列」)。正規化で `self` になる呼び名は捨てる。主語を明示する語 (読み取りの規則の `subject_self`。「私」「僕」"I"・"me" など、同梱のすべての言語) と一致する主語 (正規化 v1 か照合の形 (§5.6) のどちらかで一致すればよい。「わ たし」も当たる) は `self` に直してから関門 5・8 を当てる (主語を「私」と書いて、`self` の忘れるの指示を抜けないため)。
- **辞書**: 辞書の属性ごとに、単値か多値か、値の長さの上限、プロファイルでの優先の順 (§5.4)、主語に `self` 以外を許すか、値を言った文に手がかりの語を求めるか (`cue`。省くと false。§5.2 の関門 3a)、層 (v0.5 の辞書の属性はすべて `world`)、別名 (`aliases`。自由記述の属性をその属性に写す語の一覧。§5.2 の「属性の決め方」。初版は空)、値の意味が否定を含むか (`negative`。§5.2 の関門 3b を当てない。初版では `dietary` だけ) を宣言する。初期内容は v0.4 の属性の一覧 ([OQ-12](10-decisions.md#oq-12-属性の一覧の初期内容)) にする。
- 辞書は版を持つ。属性を消したり意味を変えたりせず、足すだけにする。`cue`・説明・別名は、属性の意味を変えない範囲で直してよい (直したときも版を上げる)。辞書の版は導出の指紋 (§5.3) に入るので、版を上げると LLM を呼ばずに全件を導き直す (v0.4 までの「処理し終えた発話は抽出し直さない」は要らなくなった)。辞書の説明を変えると呼び出しのプロンプトも変わるので、変種の版も上げる (§5.2.1 の「プロンプトを変えるとき」)。
- **自由記述の属性** (提案書 §2.3): 辞書の外の知識も覚えるために、`world` にも `episode` にも使う。ただし **置き換えとプロファイルに効くのは辞書の属性だけ** にする (指示の混入と誤った今の値を、信頼する枠に入れないため。§5.3・§5.4)。統治 (忘れる・private) の当て方は自由記述の属性の文字列に依らない (§7.5)。
- **日付** (`when`): 日付の表現は、同梱の規則 (`rules/<言語>.toml` の `[dates]`) で決定論に解く。絶対の日付 (「2026年3月」「3/14」) は `basis = stated`。相対の表現 (「先週」「来月」「昨日」) は、発話のターンに記録した UTC からのずれ (05 §3.6 の `tz_offset`) で、そのターンの時刻を利用者の暦の日に直してから解く (`basis = relative`)。導出の時点のタイムゾーンは使わない (作り直しても同じ結果にするため)。ずれの記録の無いターン (v0.4 より前に書いた発話) では、相対の表現を解かず、`from`・`to` を null にして `basis = no_offset` を残す (解けなかったことを見分けるため)。読めない表現は null。`episode` で表現が無いか読めないときは、発話の日 (ずれで直した暦の日。ずれが無ければ UTC の日) を `basis = utterance` として持つ (同じ出来事の言い直しをまとめる、§5.3)。`world` の `when` は、v0.4 までの `valid_from`・`valid_to` (現実で成り立っていた期間) の後継で、表現が無ければ null。
- **副索引** (03 §3.3): `ea` ((entity, aspect))、`vk`、`date` (日付)、`src` (根拠のターン)。private の単位は `vk` と日付の副索引を持たない (列挙で件数に出さないため、v0.6)。
- **知らない値**: 単位は導出の結果なので、導出の指紋 (§5.3) が合わないとき (新しい版が作った単位を含む) は全件を導き直す。知らない状態・層の単位を読んで使うことはない。

### 5.2 1 回の呼び出し (B2) と関門 (B3)

閉じた区切りと末尾の区切り (§2) ごとに、型縛りの LLM の呼び出し 1 回 (06 §6) で、検索の鍵・単位の候補・訂正の判定をまとめて出させる (提案書 §5.1、P4)。生の出力は台帳に書き (§5.2.1)、関門は導出のたびに当てる (§5.3。関門を直しても、LLM を呼ばずに全件に当て直せる)。

- **対象のセッション**: チャットのセッション (モードが `chat`) の区切りだけを対象にする。知らないモードのセッションは飛ばす。コーディングのセッション (15、v1.0 より後) では、ログやコードを囲みなしで貼ることが多く、プロジェクトの中身 (信頼しない文) が発話に混じるので、呼ぶかはコーディングモードの着手のときに決める (15 §4.5)。単位の置き場所はチャットとコーディングで共有する (ADR-0020)。
- **根拠は利用者の発話だけ** にする。応答・利用者が貼った引用・カートリッジからは単位を作らない (確定、[OQ-20](10-decisions.md#oq-20-事実を抽出してよい出典))。貼られた文書に埋め込まれた指示が、単位として信頼する枠に入るのを防ぐため (02 §8)。
- **応答は `[参照のみ]` の枠で入れる** (確定、2026-11-26。S-17 の 4): 同じ往復の応答を、頭の 500 文字まで、信頼しない引用の枠 (`[参照のみ]`) に入れ、文番号を振らない (`s` は利用者の発話の文だけを指す)。500 文字は v0.4 までのノートの鍵の入力と同じ範囲で、区切りの鍵 (`keys`) が応答だけにある話題も覆うようにするため (読み出しを v0.4 から変えない、08 §2.6)。応答の文は単位の根拠にしない (関門 1)。計測では、単位の正しさは入れない形と変わらず、生成トークンが約 2 割増えた。BM-108 (09 §5.1) で生成トークンの目標に届かなければ、入れない形を見直す。入れた応答は、台帳の `inputs` の `refs` (`[{turn, rev}]`) に持ち、有効性・書く前の確かめ・掃除の対象のターン (§5.2.1・§7.2) に入れる。
- **前のふるい** (文番号を振らず、呼び出しに送らないもの。決定論):
  - コードブロックと、引用の記号で始まる行を除く。行の区切りは `\r\n`・`\r`・`\n`・U+2028・U+2029・U+0085 のどれでもよい。囲みと引用の記号は、行の先頭の空白と Default_Ignorable の文字 (BOM・ゼロ幅の空白など) を飛ばしてから判定する。閉じの囲みは、囲みの記号 (開きと同じ文字を同じ数以上) と空白だけの行に限る (開きの行は info string を持てるが、閉じの行は持てない)。閉じていない囲みは本文の終わりまでとする。
  - 端末の貼り付け (bracketed paste) の範囲では除かない。S-16 (08 §3) で、今の入力の読み方 (crossterm 0.29) では、Windows の端末 (Windows Terminal・conhost) の貼り付けは `Event::Paste` にならず、IME の確定の文字列と同じ形 (1 文字ずつのキー) で届き、見分けられないことを確かめた。Windows Terminal は入力を VT の列として読めば見分けられるが、端末の層の変更 (07 §2) が要る。Linux の端末と tmux は確かめていない。
  - 貼り付けの範囲と、見分けが効いていたか (`Event::Paste` を受け取れる読み方だったか) はターンに観測値として残す。Windows では範囲を持たず、見分けが効いていないと記録する。除く材料にするかは、端末の層を VT の入力に替えるとき、または Linux の端末で確かめたときに改めて決める。引用の中の指示が単位に入るのは、関門 1〜6 で防ぐ。Windows で貼った文書の中の言い切りが単位になりうることは、既知の穴として §7.8 と 02 §8 に書く。
  - **長い一度の入力** (確定、2026-11-26): 端末の 1 回の読み取りでまとめて届いた複数行の入力で、暫定 400 文字を超えるもの (貼り付けの見分けが効かない端末でも分かる) は、その範囲をターンの観測値に残す。値の位置がその範囲にある候補は、単値の辞書の属性の置き換えの条件 (§5.3) を満たさないものとし、`Contested` に留める (貼った文書の言い切りで、今の値を黙って置き換えないため)。
  - 除いた残りが短い発話と、同梱の一覧 (挨拶・相槌) に当たる発話は送らない。短さのしきい値は言語ごとに決める (暫定で、日本語は内容の単位 (05 §2.1) が 4 つ未満、英語は語が 2 つ未満)。
  - 送らない理由は、チャットのセッションではない → コードブロックと引用の行を除くと何も残らない → 挨拶・相槌 → 短い の順に当て、最初に当たった理由で数える。短さのしきい値は、発話の文字種から決めた言語のものを使う。
- **文番号**: 前のふるいの後の利用者の発話の本文を文に分け、区切りの中で 1 から通しの番号を振る。文の分け方は v1 (§2 の「文の分け方 v1」。「3.5」・略語・URL の `.` では切らない) にし、その規則の版を台帳の `inputs` に書く。前のふるいで送らない発話 (挨拶・相槌・短い) には番号を振らない。ただし訂正の候補 (§6) のある発話は、短くても番号を振って送る。
- **既存の単位はプロンプトに入れない**。要求が長くなり、先頭が毎回変わり、既存の値を写してしまう恐れがあるため。今の値との突き合わせは導出 (§5.3) で決定論に行う。
- **忘れると private**: 忘れるの `[非表示]` の範囲 (§7.5 の `hidden`) は、印に置き換えてから渡す。private の値は伏せずに渡す (private は導出の時点で当てるので、台帳を作った後に private にした値も同じく除ける、提案書 §5.1。`llm.allow_remote` の構成では外の機械に出るので、private の確認の文言に書く、§7.1)。
- **出力の型** (台帳の `output`。v0.7 までに使う項目を入れて確定し、以後は「項目を足すだけ」にする、08 §2.6 の M5.0・[OQ-53](10-decisions.md#oq-53-b2-の出力の型の確定) (確定、2026-11-26)・03 §3.3 の「台帳の本体の互換」。本節を型の正本にする):

  `{"keys": [文字列], "units": [{"s": 整数, "l": "world"|"episode", "e": 文字列, "a": 文字列, "v": 文字列, "m": "fact"|"negated"|"question"|"hypothetical", "tn": "current"|"past"|"planned", "old": 文字列, "when": 文字列}], "corrections": [{"id": 整数, "verdict": "accept"|"reject"|"unclear"}]}`

  | wire の名前 | Rust の名前 | 内容 |
  |---|---|---|
  | `keys` | `keys` | 検索の鍵 (区切りの鍵、§5.5)。区切りの話題を表す短い語句の並び。文法で 8 個まで (`maxItems`)、1 つ 40 文字まで |
  | `units` | `units` | 単位の候補。無ければ空の配列だけを返させる。数は24 (8 往復の区切りで実測の最大 16 件に余裕を足した) (S-17 の 4・5・6 で決めた、2026-11-26。spikes/S-17/REPORT.md §5〜§7)まで |
  | `s` | `sentence` | 根拠の文の番号。**整数 1 つ** (文法で、その区切りの文番号 1..N の列挙にする)。並びにしない。2 文にまたがる根拠が要ると分かったら、後の版で任意の `s2` を足す (項目を足すだけ) |
  | `l` | `layer` | 層: `world` (今も続く事実・状態) / `episode` (一度の出来事) |
  | `e` | `entity` | 主語 (`self` か呼び名) |
  | `a` | `aspect` | 属性 (辞書の属性の名前か、短い自由記述。40 文字まで) |
  | `v` | `value` | 値 (根拠の文の中の続いた語句) |
  | `m` | `mood` | 叙法: `fact` (言い切り) / `negated` (否定) / `question` (問い) / `hypothetical` (仮定・願望)。v0.4 と同じ 4 つ (計測した値)。依頼・他人の言葉の引き写しの値は入れない (足すのは、計測で効くと分かったときだけ。列挙の値を足すのは「足すだけ」の変更として許す) |
  | `tn` | `tense` | 時制: `current` / `past` / `planned` |
  | `old` | `old` | 置き換える古い値が根拠の文にあれば、その部分文字列 (無ければ "") |
  | `when` | `when` | 日付の表現が根拠の文にあれば、その部分文字列 (無ければ ""。解くのは導出、§5.1) |
  | `corrections` | `corrections` | 訂正の候補 (§6。決定論で見つけたもの) ごとの判定。候補が無ければ空の配列 |
  | `id` | `id` | 候補の番号 (台帳の `inputs` の `corr` の `id`。文法で候補の番号の列挙にする) |
  | `verdict` | `verdict` | `accept` (訂正である)・`reject` (訂正でない)・`unclear` (決められない)。新しい値と古い値は候補の側が本文の穴から持つので、出させない |

  - wire の名前は、計測した形のまま凍結する。Rust の型と試験の事例のファイルは長い名前を使い、`#[serde(rename)]` で wire の名前に結ぶ。列挙は 1 文字の記号にしない (S-17 の 4 の計測で、生成トークンが減らなかった)。
  - **根拠の指し方は文番号** (確定、2026-11-26。S-17 の 4: Qwen3-4B で厳しい一致が 25 件中 20 件、根拠を写す今の形は 16 件): 根拠の写しは出させない。v0.4 までの根拠の写しの照合 (関門 1 の写しの形) は持たない。
  - **書くときの型** (文法): `units` と `corrections` の要素の項目はすべて必須にし、無いものは "" にさせる。`keys`・`units`・`corrections` の上限は文法の `maxItems` で縛る。
  - **読むときの型** (寛容にする): 書くときの型と読むときの型を、Rust で別の型に分ける (今の `extract.rs` の `deny_unknown_fields` の形を台帳の読み手に使わない)。`output` は節ごとに保存し、導出のときに読むときの型で読む。`s`・`a`・`v` を欠く要素は、その要素だけを型が合わないとして捨てて数える。ほかの項目は既定値で読む (`l` は `world`、`e` は `self`、`m` は `fact`、`tn` は `current`、`old`・`when` は "")。知らない項目は残す (03 §4.2 の規則 7)。知らない列挙の値を持つ要素は、その要素だけを捨てて数える (台帳の全体は読めない記録にしない、03 §3.3)。型の違う項目を持つ要素 (`e` が文字列でないなど) も同じく捨てて数える。`corrections` の要素は `id`・`verdict` を欠けば捨てて数え、`keys` の文字列でない要素も捨てて数える。
  - 節ごとに型を確かめ、合った節だけを台帳に入れる (合わない節は理由だけを書く、§5.2.1)。`s` が区切りの番号の外の候補と、`id` が候補の番号の外の判定は、関門 1 と訂正の関門で捨てて数える。上限を超えた要素は、切らずに捨てて数える。
  - **入れないもの** (確定、2026-11-26): 重要度・見出し・単位どうしのつながり・叙法の追加の値・`s` の並び。v0.7 の話題の見出しと v0.8 の気づきの提案は B2 に入れず、台帳の `call` を `topic_title`・`insight` にした別の呼び出しにする (下の表)。
  - **v0.7 までの項目** (08 §2.6 の M5.0 の「B2 の型の確定」): 台帳は失うと戻らず、後の版で出力の項目を足すと全件の呼び直し (S の一部の取り込みで 20〜45 時間) になるので、v0.6・v0.7 で使う項目を v0.5 の型に入れる。

    | 後の版で使うもの (提案書) | 要る項目 | v0.5 の扱い |
    |---|---|---|
    | 時系列・日付の副索引・窓の見出し (§6.3・§9.6、v0.6) | 単位の日付の表現 | 型に入れる (`when`。v0.5 でも `episode` の ID とまとめ方に使う) |

- **関門** (B3。決定論。導出のたびに、使う台帳 (§5.2.1) の候補に当てる。属性の決め方の後、1・2・3・3a・3b・4・5・6・6a・7・8 の順に当て、最初に外れた関門の理由で数えて捨てる。関門 6 の中は、一般カテゴリ → 区切りの文字 → URL → 役割の詐称 → 文字体系の混在 → 命令形 → ほかの指示への言及 → 伏せ字の印 → 符号化の塊 の順。番号は v0.4 までの関門に合わせ、足した関門は枝番にする):
  - **属性の決め方** (関門の前。提案書 §5.2 の「辞書の写しは関門の前に」): `a` に正規化 v1 を当て、辞書の属性の名前と同じならその辞書の属性にする。辞書の属性の別名 (`aliases`、§5.1) と同じなら、その辞書の属性に写す (v0.7 からは承認された学習の写しも、13)。どちらでもなければ自由記述の属性にする。写した後の属性の宣言 (手がかりの語・主語の許し・長さの上限・層) で、以下の関門を当てる (写しで属性ごとの関門を迂回させないため)。辞書の属性で `l` が辞書の層と違うときは、辞書の層に直して `layer_fixed` として数える (受け付けても別に数える理由)。自由記述の属性は、空のもの・40 文字を超えるもの・関門 6 に通らないものを `aspect` で捨てる。
  1. **根拠の文** (`evidence`): `s` がその台帳の `sentences` にある文番号で、その文が、今の利用者の発話のターンの、今の前のふるいの後の本文の中にあり (前のふるいの規則を直した後も、今の規則で除く範囲は根拠にならない)、忘れるの `[非表示]` の範囲 (§7.5) の外の部分を持つ。応答の文 (`[参照のみ]`) と、前のふるいで除いた範囲 (コードブロック・引用の行) は根拠にならない。文の位置は台帳の `sentences` の範囲 (伏せ字の後に写し直したもの、§7.2) を使う。読み取りの規則 (§5.3 の主語・変化の語) は、根拠の文に当てる (除いた本文には当てない)。
  2. **値** (`value_not_in_evidence`): `v` が根拠の文の中に一致する。照合は、生の本文 → 正規化 v1 (§5.6) → 照合の形 (§5.6) の順に行い、位置の対応表で元の位置に戻す (LLM が全角・半角や括弧を直して写すことと、漢字・かなと英数字の間の空白を足したり除いたりして写すことがあるため。正規化 v1 で通ったものは `value_normalized`、照合の形で通ったものは `value_loose` として別に数える)。英数字の並びと数字の並び (一般カテゴリ Nd) は語の境界で一致させる ("Ann" を "annual" に、"12" を "120" に当てない)。語の境界は、根拠の文の端ではなく、前のふるいの後の本文の全体で判定する (LLM が値を語の途中で切っても、"Annabelle" から "Ann" を、"RTX4070Ti" から "RTX4070" を記録しないため)。忘れるの `[非表示]` の範囲に掛かる一致は一致としない。<br>`old` があれば、同じ照合で根拠の文に含まれるかを見る。含まれなければ、候補は捨てずに `old` を空として扱い、`old_ignored` として数える (LLM は、区切りの中のほかの発話の値を `old` に写すことがあるため。2026-11-18)。`when` も同じく、根拠の文に含まれなければ空として扱い、`when_ignored` として数える (**数字の組**: LLM がほかの文の日付や数字を組み合わせて写したものを、日付として解かないため。提案書 §5.2)。
  3. **叙法** (`mood`): `m` が `fact` である。`negated` は、§5.3 の「否定」の規則にだけ使う (辞書の属性の `world` の候補だけ。ほかの `negated` は捨てる)。`question`・`hypothetical` は捨てる。<br>**問いの節の補い** (決定論、2026-11-18): `m` が `fact` か `negated` でも、値の位置 (下の「記録する文字列」の値の位置。括弧の内側に掛からない一致が無ければ、根拠の文の中の最初の一致) が、問いの文の最後の節に掛かれば `question` とみなして捨てる (同じ理由 `mood` で数える。LLM は、相談の問いの中の語句を言い切りの事実として返すことがあるため。"Any tips for drying laundry indoors?" の "drying laundry" など)。
     - **文**: 前のふるいの後の発話の本文を、§6 の文の区切り (`。`・`．`・`！`・`？`・`.`・`!`・`?` と改行。半角の `.`・`!`・`?` は後ろが空白・改行・本文の終わりのときだけ。判定は §6 の「区切りの文字の判定」と同じ) で分けたもの。値の位置が掛かる文をすべて見る (呼び出しの文番号 (§2 の文の分け方 v1) とは別の分け方で、値の位置の周りの文と節を見るためだけに使う。v1 には寄せない (M5.2 で決めた、2026-11-27、§2))。<br>ただし、**問いの文かを見るとき** (この補い) だけは、半角の `.` の前の語が略語 (文の分け方 v1 の略語の一覧。"Dr"・"Mr"・"etc" など) なら切らない (M5.2 で決めた、2026-11-28。略語の後ろで切ると "Is Osaka near Dr. Kim's place?" の "Osaka" が問いの文の外になり通るため。文が長くなるほど問いとして捨てる側にだけ倒れる)。関門 3a の手がかりの語と関門 3b の節は §6 の区切りのままの文で見る (略語で終わる文と次の文を 1 つにすると、隣の文の手がかりの語・否定の印で通す側に広がるため。"I live near Dr. Kim's clinic in Osaka." の "Osaka" は v0.4 と同じく `no_cue` で落ちる)。
     - **問いの文**: 文の末尾から空白と、`?`・`？` 以外の文の区切りの文字を除いた形が、問いの印 (読み取りの規則の `question_end`。`?`・`？`、問いの形の文末 (「ですか」「ますか」「でしょうか」「ませんか」「のか」「ないか」「だろうか」など)、「教えて」「教えてください」など) のどれかで終わる文。「か」だけ・「ください」だけは印にしない (「娘の名前はあすか」「好きな果物はすいか」の値や、「ミナトと呼んでください」の名前を捨てないため)。
     - **最後の節**: 問いの文を、節の区切り (読み取りの規則の `clause_break`。`、`・`，`・`,`・`;` と「ですが」「ますが」「たが」「だが」「けど」「けれど」「ので」など) で分けた最後の部分。読点の無い「東京に住んでいますがおすすめの店はありますか？」の「東京」も、最後の節の外にあるので通る。「趣味は将棋なんですが、おすすめは？」の「将棋」は最後の節の外にあるので通る。
     - 問いの印と節の区切りの照合は、読み取りの規則と同じく NFKC と casefold の後に行い (英語は語の境界、日本語は部分一致。記号だけの語 (`,`・`;` など) は、語の端が英数字の側だけ境界を見る)、位置の対応表で元の位置に戻す。
     - **関門 3a: 属性の手がかりの語** (決定論、2026-11-18。関門 3 (補いを含む) の後、関門 3b の前に当てる。番号を振り直さないため 3a とする): 辞書で `cue = true` の属性 (§5.1。初版では `residence` だけ) は、値の位置 (関門 3 の補いと同じ) が掛かる文 (関門 3 の補いと同じ分け方) のどれかに、その属性の手がかりの語 (読み取りの規則の `<属性>_cue`。`residence_cue` の初めの一覧は、日本語が「住む」「住ん」「住み」「住ま」「住め」「居住」「在住」「暮ら」「引っ越」「引越」「移住」「転居」「移り住」(語幹で書く。「住」だけにすると「住所」「住友」にも当たるため)、英語が "live"・"lives"・"living"・"lived"・"based in"・"moved to"・"relocated"・"reside"・"resides"・"residing"・"resident"。広げるときは規則の版を上げる) があるときだけ通す。無ければ `no_cue` で捨てる (LLM は、旅行の行き先 (「来月、金沢へ一人旅をする予定です」) や「うち」を住む地域として返すことがあるため)。照合は関門 1 と同じく、生の文 → 正規化 v1 → 照合の形 (§5.6) の順に当て、どれかで当たれば通す (どの段も casefold の後に、英語は語の境界、日本語は部分一致で当てる)。手がかりの語を言わない言い方 (「地元の大阪で」) は取りこぼすが、安全の側に倒す (知られた取りこぼし)。
     - **関門 3b: 極性** (`polarity`、v0.5。提案書 §5.2): 値の位置が掛かる節 (関門 3 の補いと同じ節の区切りで分けたもの) に否定の印 (読み取りの規則の `negation_mark`。「ない」「ません」「じゃない」"not"・"never"・"no longer" など。除外の語 (「間違いない」「少なくない」など、`negation_mark_exclude`) を照合の前に伏せる) があるのに `m` が `fact`、または否定の印が無いのに `m` が `negated` なら捨てる (LLM が否定を言い切りとして返すと、否定した値を今の値として覚えるため)。照合は関門 3 の問いの印と同じく、同梱のすべての言語のものを合わせて当てる。以下は M5.2 で決めた (2026-11-28)。
       - **節**: 値の位置より前の最後の区切りの後から、値の位置より後の最初の区切りの前まで。区切りは関門 3 の補いの `clause_break` ではなく、3b の節の区切り (`polarity_clause_break`。「けど」「が、」「ので」「から、」「し、」「ながら」「ていて」「て、」「で、」`;`・"but"・"so"・"because" などの接続の区切り) にし、読点だけ (`、`・`,`) では切らない (日本語は否定の述語が節の最後に来るので、「東京には、もう住んでいません」の否定を「東京」の節に入れるため。"Osaka, I never lived there." も同じ)。区切りの一致は正規化 v1 と照合の形の対応表で元の位置に戻す。
       - **印を見る範囲**: 値の位置の中の印は数えない (値の意味の一部なので。「何も考えずに過ごすこと」)。日本語の印は値の後ろから節の終わりまでで見る (述語が値の後ろに来るので。「猫ではなく犬が好き」の「犬」に前の「なく」を当てない)。英語の印は節の中の値の前と後ろの両方で見る。
       - **印の一覧** (`negation_mark`): 「ない」「ません」に加えて、過去形・連用形 (「なかっ」「なく」)、「なし」、文語・方言 (「ず」の形、「へん」「ねえ」)、英語の短縮形 (アポストロフィの無い "dont"・"ain't"・"mustn't" などを含む)。除外の語 (「まず、」「たいへん」「ねえさん」など) を合わせて足す。
       - **値の意味が否定を含む属性** (辞書の宣言 `negative`、§5.1。初版では `dietary` だけ): 否定の印を見ない (辞書の説明が「〜は食べられません」も `fact` にさせ、否定の印があっても値が「食べないもの」の意味を持つため。v0.4 の関門と同じ)。その `negated` (今の値を終える向き) は、値の位置が掛かる文に否定を終える語 (`negative_end`。「食べられるようになった」「治った」"no longer allergic"・"outgrew" など) があるときだけ通し、無ければ `mood` で捨てる (LLM の誤り 1 つで、食べられないものの記録を終えないため)。
  4. **括弧** (`quoted`): 値が、前のふるいの後の発話の中の、根拠の文にある値の位置で、括弧 (「」『』【】〝〟«»‹›„“ など、同梱の規則) や引用符の内側にない (括弧の開きと閉じは、根拠の文の中だけでなく前のふるいの後の本文の全体で見る。文の区切りで括弧の内と外を取り違えないため)。根拠の文の中の値の一致 (照合は関門 2 と同じ) のうち、括弧・引用符の内側に 1 文字も掛からないものが 1 つ以上あれば通る (一部だけが内側に掛かる一致は、内側とみなす)。開きと閉じが同じ引用符 (`"` など) は、前が文頭・空白・記号・語を空白で区切らない文字 (§5.6 の照合の形と同じ判定) のときだけ開き、後ろが文末・空白・記号・語を空白で区切らない文字のときだけ閉じとみなす (インチの記号などで内と外が入れ替わらないため)。閉じていない括弧は本文の終わりまで内側とする。同梱の規則で、名前の呼び方などの許す型を定める。
  5. **主語** (`subject`): `e` が `self` 以外なら、辞書の属性ではその属性が主語に `self` 以外を許している (自由記述の属性は許す)。あわせて、呼び名に関門 6 (値と同じ検査) を当て、長さを 32 文字までにし、呼び名が根拠の文に含まれる (照合は関門 2 と同じ) ことを求める (**主語の一致**、提案書 §5.2: 根拠の文に無い呼び名を主語にしない)。記録する主語は、根拠の文の中の最初の一致の保存した本文に正規化 v1 を当てた文字列にし (下の「記録する文字列」)、この関門の残りの検査はその主語に当てる。プロファイルで `self` を表す語 (「利用者」・"user"・「ユーザー」・「ユーザ」など、表の書式の語と利用者本人を表す語)、応答する側を表す語 ("assistant"・"AI"・「アシスタント」・「システム」・"bot" など。同梱の規則、確定、2026-11-26)、役割の語 (`rules/common.toml` の `role_words`。"system"・"developer"・"model"・"human" など)、二人称 (「あなた」「君」「お前」・"you"・"your" など) と同じ呼び名は捨てる (表の上で本人やモデルを詐称しないため。役割の語と二人称は M5.2 で足した、2026-11-28)。どれも呼び名の全体と同じときだけ当て (「田中君」は捨てない)、モデルの名前 ("Claude" など) は人の名前と見分けられないので一覧に入れない。主語を明示する語 (§5.1) と表の書式の語との比べは、正規化 v1 と照合の形の両方で行い、どちらかで同じなら当たったとみなす (「利用 者」も捨てる)。主語はプロファイル (システムプロンプト) に入るので、値と同じだけ守る。
  6. 値に、役割の詐称・区切りの模倣 (`system:`・`</s>` など。役割の語の後のコロンの類 (`:`・`：`・`∶` など) は、間の空白に関わらず当てる。`<` の直後に英字・`/`・`|`・`!` が来る並び (`<start_of_turn>`・`<think>` などのテンプレートの印) はすべて捨てる)、制御文字と書式の文字・私用の文字・未割り当ての文字 (一般カテゴリ Cc・Cf・Co・Cn・Cs) と Default_Ignorable の文字 (ゼロ幅文字・双方向の制御文字・異体字セレクタ・ハングルの埋め字などを含む)、1 つの語に複数の文字体系を混ぜた並び (Unicode の Script 属性で、Common と Inherited を除いて判定する。UTS #39 の highly restrictive の組 (ラテン・漢字・ひらがな・カタカナ、ラテン・漢字・注音字母、ラテン・漢字・ハングル) と、1 つの文字体系だけを許す。判定は NFKC の後で、case folding の前の形に当てる) が無い。また、指示に読める文 (命令形の文・他の指示への言及。同梱の規則。名前の呼び方 ("Call me Ken"、「ケンと呼んで」) などの許す型を規則で定める)、改行 (U+2028・U+2029・NEL を含む)、表の区切り (`|`・`｜`・`│`)、URL が無い。判定は NFKC の後に行い、指示に読める文は、結合文字を除いた骨格 (NFD → 一般カテゴリ Mn を除く → NFKC → case folding → 空白をまとめる) にも当てる。除外の語に当たった箇所を伏せるのは、命令形の語の一致が除外の語の一致の中に丸ごと入るときだけにする。語の一覧で当てる検査 (役割の詐称・命令形・ほかの指示への言及・伏せ字の印) は、値の照合の形 (§5.6) にも当てる (漢字・かなの間に空白を挟んで一覧を抜けないため)。文字体系の混在の判定は照合の形に当てない (空白を除くと、別の語が 1 つの語に繋がるため)。<br>伏せ字の印 (§7.3 の `[伏せ字]`・`[redacted]`。プロンプトの言語に関わらず両方。NFKC の後で照合する) を含む値も捨てる。根拠の文の中で、値の一致が印に接する (間に空白と記号しか無い) 候補も、同じ理由で捨てる (伏せ字にした本文の印やその周りを、値として覚え直さないため。2026-11-17 に確定した「根拠の写しが印を含む候補を捨てる」を、文番号の根拠に合わせた。文の全体で見ると、同じ文のほかの記憶まで捨てるため)。<br>**足した型** (M5.2 で決めた、2026-11-28。v0.4 と同じ穴だが、自由記述の属性で面が広がったため): URL には、スキームの無い URL (英数字の後の `.`・2 文字以上の英字・`/` の並び。`example.com/x`) と Markdown のリンク (`](`) も含める。役割の詐称には、見出しの区切り (`#` の連なり) の後の役割の語 (`### system`) も含め、語の一覧の照合には、ラテン文字と見た目が同じキリル文字・ギリシャ文字をラテン文字に写した形 (`ѕуѕтем`) も使う。最後に **符号化の塊** (`encoded`。`[A-Za-z0-9+/=]` の 40 文字以上の続きで、英字と数字の両方を含むもの。base64 で包んだ指示) を捨てる。関門 6 の中の順は、上の順の最後に符号化の塊を足す。<br>関門 6 は、値に加えて、記録する `old`・自由記述の属性・主語 (関門 5)・検索の鍵 (§5.5) にも当てる (提案書 §5.2)。
     - **関門 6a: 機微な情報** (`sensitive`、v0.5。提案書 §5.2): 値・`old`・自由記述の属性が、健康・病気、宗教、政治、性的指向、正確な住所のカテゴリと、[OQ-56](10-decisions.md#oq-56-関門-6a-の機微な情報の種類) で足した種類 (人種・信条・社会的身分・犯罪の経歴・犯罪の被害・障害の語、電話番号・カード番号・メールアドレスの形) (同梱の規則 `[sensitive]`。カテゴリごとの語の一覧と、番地・号室・郵便番号の形の型。安全の規則なので、同梱のすべての言語を合わせて当てる) に当たる候補を捨てる。
       - **当て方** (M5.2 で決めた、2026-11-28): 日本語の語は部分一致、英語の語は ASCII の英数字で決めた語の境界で当てる (安全の規則は部分一致という下の規則の例外。部分一致では "hiv" が "archive" に、"gay" が "Gaylord" に、"islam" が "Islamabad" に当たり、ふつうの値を落としすぎるため)。英語の語幹は末尾の `*` で書き、語の頭だけに境界を求める (`pregnan*`・`depress*`・`therap*`)。除外の語 (`exclude`。「病院」「臆病」「甘党」「左翼手」「ゲイン」、"political science"、星座の "Cancer" の言い方など) の一致にすっかり収まる一致は数えない。「〜病」「〜党」は一覧の語「病」「党」と除外の語で当てる。
       - **形の型**: 番地・号室 (`{n}丁目`・`{n}番{n}号`・`{n}号室`)、町名の後の `{n}-{n}-{n}`・`{n}-{n}` (前が漢字かカタカナのときだけ。日付の `2026-11-28` を落とさないため)、郵便番号 (`〒{n3}-{n4}`・`{n3}-{n4}`)、英語の通りの名前 (複数の語の名前と "street"・"terrace"・"way"・"court"・"place" など)。電話番号 (`+` で始まる 8〜15 桁、0 で始まる 10〜11 桁、3・3・4 に分かれた 10 桁)・カード番号 (13〜19 桁で Luhn の検査に合うもの)・メールアドレスは、言語に依らないコードの型で見る。
       - 語の一覧は初版で、v0.5 のリリースの準備で利用者が見直す (OQ-56)。根拠の文の全体には当てない (同じ文のほかの記憶まで捨てないため。カテゴリの語を値に含まない言い方は取りこぼす。プロンプトにも書いて二重にする、下の「プロンプトに必ず書くこと」)。
  7. 値の長さが属性の上限の内にある (`too_long`)。
  8. **忘れるの指示** (`forgotten`。§7.6): 効いている忘れるの指示に当たらない。当て方は §7.5 の「当て方の述語」(値の鍵と照合の鍵、entity の同値類、辞書の属性なら属性。台帳の掃除と `doctor --deep` と同じ関数)。記録する値 (下) の値の鍵と照合の鍵の両方で引く (空白の有無だけが違う書き方で、忘れた値を覚え直さないため)。印を解いた (`unblock`) 指示も、根拠のターンの ID が `unblock` の指示の ID より小さい候補には当て続ける (§7.5)。
- **記録する文字列** (関門の後に記録する値・主語・`old`): LLM の写し (`v`・`e`・`old`) ではなく、発話の保存した本文の部分文字列にする (値の鍵・再び覚えない印・伏せ字の照合を、利用者が書いた形にそろえるため。LLM が足した空白などを記録に入れないため)。
  - **値**: 根拠の文の中の値の一致 (関門 2 の照合) のうち、括弧・引用符の内側に 1 文字も掛からない最初の一致 (関門 4 と同じ規則) を、保存した本文の位置に戻した範囲の部分文字列。位置を保存した本文に戻せないときは `value_not_in_evidence` で捨てる (根拠の文の全体で代えない)。関門 3 の補い・3a・3b はこの記録する値の位置で、関門 4〜8 (6a を含む) はこの記録する値に当てる。関門 6 は LLM の写し `v` にも当てる (どちらかで外れたら、その理由で捨てる)。値の鍵 (§5.6) は記録する値から作る。
  - **主語**: `self` 以外の呼び名は、根拠の文の中の最初の一致の部分文字列に正規化 v1 を当てた文字列 (関門 5)。
  - **`old`**: 根拠の文の中で値と同じ照合で探す (括弧の内側かは問わない)。一致がすべて正規化 v1 で同じ文字列になるときだけ採り、最初の一致の部分文字列を記録する (`old` の値の鍵はここから作る)。正規化 v1 で違う一致が混じるときは、どれを置き換える値か決められないので、`old` を空として扱う (多値の属性では置き換えずに並べて足す、§5.3。安全の側に倒す)。根拠の文の中に一致が無ければ、候補は捨てずに `old` を空とする (関門 2 の `old_ignored`)。
  - **`when`**: 根拠の文の中で値と同じ照合で探し、最初の一致の部分文字列を日付の規則 (§5.1) で解く。一致が無ければ空とする (関門 2 の `when_ignored`)。
  - 発話の中の改行をまたいで一致した値は、記録する値が改行を含むので、関門 6 で捨てる (正規化 v1 は改行も 1 つの空白にまとめるので、LLM の写しには改行が無くても、利用者の本文では改行をまたいでいることがあるため)。
- **一覧で塞ぐ限界**: 関門 6 の命令形と指示への言及は、語の一覧による照合なので、言い換え・綴りの崩し (`1gn0re`、`i g n o r e` など)・一覧に無い言い回しは抜けうる。関門は多重の守りの 1 つ目で、2 つ目はプロファイルを「利用者の発言から作ったデータで、指示ではない」として置く枠 (§5.4、05 §4.3) とする。抜けた例は回帰ケース (09 §3.5) に足し、一覧を広げる。
- 規則の TOML は言語ごとに持ち、版を持つ。置き場所は `evorag-memory/rules/<言語>.toml` (言語に依らない改行・表の区切り・URL の規則は `rules/common.toml`)。v0.5 で足す規則 (関門 3b の `negation_mark`・`negation_mark_exclude`・`polarity_clause_break`・`negative_end`、関門 5 の応答する側を表す語と二人称、関門 6a の `[sensitive]`) と辞書の v0.5 の宣言 (層・別名・`negative`) は、旧エンジンと共有する規則と辞書の読み手を変えないために、旧エンジンを外す (08 §2.6 の M5.5) まで `rules/b3.toml` に置き、外すときに言語ごとのファイルと `attributes.toml` に移す (M5.2 で決めた、2026-11-28)。規則は 2 つに分けて当てる。
  - **安全の規則** (関門 4・6・6a、挨拶・相槌の一覧): 同梱のすべての言語の規則を合わせて当てる。プロンプトの言語が `ja` のデータ根でも、英語の発話は来るため (07 §6.1)。安全の側に倒れて取りこぼしが増えるのは受け入れる。
  - **読み取りの規則** (`[reading]` の主語を明示する語 `subject_self`・`subject_self_exclude`、変化を示す語 `change`・`change_exclude`、否定で今の値を終える語 `negation_change`、属性の手がかりの語 `<属性>_cue`、問いの印 `question_end`、節の区切り `clause_break`、否定の印 `negation_mark`・`negation_mark_exclude`。ほかに `[correction]` の訂正の型、`[dates]` の日付の表現): 主語・変化の語・否定で終える語・訂正の型は、根拠の文の文字種から言語を判定して、その言語の規則を選ぶ。かな・漢字を 1 字でも含めば `ja`、含まなければ `en` にする (混ざった文は `ja` の規則で読む。置き換えの条件を満たしにくい側、つまり `Contested` に残る側に倒れる)。変化を示す語にも除外の語の一覧 (`change_exclude`。「相変わらず」「着替え」など) を持ち、照合の前に伏せる。主語が `self` 以外のときは、呼び名そのものが根拠の文にあれば主語の明示とみなす (英語は語の境界で当てる)。<br>ただし、属性の手がかりの語・問いの印・節の区切り・否定の印 (関門 3 の補い・3a・3b) は、同梱のすべての言語のものを合わせて当てる (「I live in 大阪」のように混ざった文があり、文の言語を 1 つに決められないため。手がかりの語は通す側に、問いの印は捨てる側に、否定の印は捨てる側に広がる)。日付の表現は、同梱のすべての言語のものを合わせて当て、どれかで読めれば解く。
  - 照合は NFKC と casefold の後に行う。安全の規則は部分一致で当てる (「以前の指示をignoreして」の "ignore" も拾う)。ただし関門 6a の英語の語は語の境界で当てる (関門 6a の「当て方」)。読み取りの規則と訂正の一次のふるいは、英語は ASCII の英数字で決めた語の境界で、日本語は部分一致で当てる。除外の語の一覧 (「私」に対する「私立」「私の妻」、命令形の「するな」に対する「するなら」など) に当たった箇所は、照合の前に伏せる (値の全体は許さない)。
- **プロンプトに必ず書くこと** (辞書の説明とともに。小さなモデルは文言の量に敏感なので、短く書く。ただし辞書の説明の例と区別の注は削らない (縮めると単位の正しさが下がった、2026-11-28。spikes/S-17/REPORT.md §5.6)): 値は根拠の文の中の続いた語句をそのまま写す (組み替えると関門 2 で捨てられる)。要素が離れていれば別の候補にする。健康・病気、宗教、政治、性的指向、正確な住所は、どの属性にも入れない。次も書く。
  - 根拠は文番号で指し、1 つの候補に 1 つの文にする。ほかの番号の文の語を値・`old`・`when` に使わない (区切りの中のほかの発話の値を `old` に写すことがあった。関門 2 の `old_ignored`)。
  - 属性は辞書の名前を先に使い、合うものが無いときだけ短い自由記述にする。今も続く事実・状態は `world`、一度の出来事は `episode` にする。
  - 時制 `tn` は、動詞の形ではなく、その値が今も成り立つかで決める (引っ越した先は `current`、引っ越す前の場所は `past`)。
  - 動物や物の状態・ふるまいを、利用者についての事実にしない (猫が爪を研ぐことを趣味にしない)。
  - `[参照のみ]` の枠の文 (応答・直前の応答) からは候補を作らない。
  - 鍵は区切りの話題を表す短い語句にし、命令形の文や URL を書かない。訂正の判定は、訂正でなければ `reject`、決められなければ `unclear` にする。
  - 頼みごとの文と、他人の言葉をそのまま伝える文からは、候補を作らない (叙法の列挙には入れない)。

#### 5.2.1 呼び出しの進め方と台帳

- **プロンプトを変えるとき**: 指示・辞書の説明・「プロンプトに必ず書くこと」・出力の型・利用者のメッセージの形 (枠・候補の行・応答の長さ) のどれかを変えたら、変種の版を上げる (新しい変種になり、選択が変わる。古い変種の台帳は「直前の選択」として使える)。出力の型を変えたら `schema` の版も上げる (項目を足すだけ、§5.2 の「v0.7 までの項目」)。プロンプトの言語 (07 §6.1) は変えないので、データ根を作り直す必要は無い。B2 のプロンプトは凍結の核 (05 §4.1) ではないので、その規則は掛からない。変えた後の最初の要求だけは、裏のスロットに残ったプロンプトのキャッシュが効かない。
- **型が合わないとき**: 全体が JSON として読めないか、どの節も型が合わないときは、その呼び出しを 1 回だけやり直し (06 §6。区切りを分けて呼んだときは呼び出しごとに 1 回。temperature 0・固定の seed なので、効き目は出力の揺れに限られる)、それでも合わなければ `status` が `failed` の台帳 (出力なし、理由つき) を書いて先へ進める (台帳は派生なので、止まり続けて後の区切りを処理できなくなるより、その区切りの単位を失う方を採る。数は `doctor` が報告し、モデルが変われば呼び直す (上の `needs_call`)。明示の作り直しでも呼び直せる)。一部の節だけが合わないときは、合った節を入れ、合わない節の理由を書く (`status` は `complete`)。<br>**出力が上限で切れたとき** (`finish_reason` が `length`): 区切りを往復の境で半分に分けて送り直す (上の「収まらない区切り」と同じまとめ方)。1 つの往復なら型が合わないときと同じに扱う。<br>**失敗の扱い** (確定、2026-11-26。分類は M5.2 で直した、2026-11-28): 4xx (要求そのものが受け付けられない。408・429 を除く) は再試行せず (06 §7)、台帳を書かずに先へ進め、下の「続けて失敗したとき」に数える (設定の誤り (`request_extra` など) が多く、`failed` を書くと、設定を直しても model_key と `build_info` が同じなので呼び直されず、記憶が黙って空になるため。v0.5 は `invalid` の符号 `request_rejected` を書かない)。構成の誤り (接続先の形・ループバック以外の接続先・ルーターのモデルの名前が無い) は、台帳を書かずにすぐ区切りの呼び出しを止め、状態で知らせる。締切切れ・5xx・408・429・逐次表示の途中の切断・ルーターのモデルの読み込みの失敗は一時の失敗として、書かずに次の機会に送り直し、同じ区切りで 3 回続いたら `failed` の台帳を書く。回数は書き手のプロセスの中で数え、書く台帳の `attempts` に残す (強制終了の後は数え直しになるが、その分だけ多く試すだけで、結果は変わらない)。「次の機会」は、裏の処理の「繰り返しを防ぐ」(§4、5 分) の後にする (一時の過負荷で、続けて 3 回送って `failed` に固定しないため)。締切は 1 回の要求ごとに暫定 600 秒 (生成の上限を 12B 級のモデル (約 6 tok/s) で出し切る約 340 秒に、プロンプトの処理と余裕を足したもの) にする (M5.2 で決めた、2026-11-28)。接続の失敗 (サーバに繋がらない) だけは回数に入れず、書かずに待つ (サーバが戻れば続きから処理する)。<br>**続けて失敗したとき**: 続けて N 個 (暫定 3 区切り) の区切りが 4xx か、一時の失敗が続いて諦めたもの (締切切れ・5xx などで `failed` になったもの) になったら、その区切りの `failed` の台帳を書かずに区切りの呼び出しを止め、状態の行と `doctor` で知らせる (構成の誤り (`request_extra` の誤りなど) で、記憶が黙って空にならないため)。次の起動か、呼ぶ先が変わったときに試し直す (M5.2 で決めた、2026-11-28: 「続けて」はこのプロセスの中で数え、型の合った出力のある区切りで 0 に戻す。型が合わずに `failed` になった区切りは数を変えない (区切りの中身による失敗で、系の問題ではないため)。「呼ぶ先が変わった」は、呼ぶ先の model_key・`build_info`・要求の付け足し (点検が足す思考を切る指定を含む。06 §3.3 の `extra_hash` の作り方) のどれかが変わったことで、変われば止めを解いて数え直す)。
- **止められたとき** (提案書 §5.1。確定、2026-11-26): 利用者の操作で 1 秒以内に止める (§4 の「譲る」)。止めた区切りに型の合った出力が 1 つも無ければ (分けた呼び出しの前のものが失敗していても)、台帳を書かず、続けての失敗にも数えない (M5.2 で決めた、2026-11-28。止めた区切りを `failed` にしないため)。止めたときは、ストリームの途中で型の上で完結した要素 (`keys` の節、`units`・`corrections` の要素ごと) を採り、`status` が `partial` の台帳に書く (区切りが長いと、止められては捨てるを繰り返すため。完結した要素が 1 つも無ければ書かない)。`partial` の台帳は使える台帳として導出に使い (上の「使う台帳の選び方」)、次の機会に同じ区切りを呼び直して `complete` の台帳で置き換える (上の `needs_call`・「台帳を消すとき」)。
- **要求と読み取りの細目** (M5.2 で決めた、2026-11-27。2026-11-28 に、レビューと検証用のモデルでのトークン数の計測を受けて直した。要求と台帳を決定論にし、プロンプトの変化を試験で見えるようにするため。`evorag-memory` の `b2`。見本は `tests/fixtures/b2/`):
  - **文番号の文**: 文の分け方 v1 の文を、前のふるいで除いた行の境 (保存した本文の続いた片の境) でさらに分ける (片をまたぐ文は保存した本文の範囲に戻せないため。v1 は `\n` で切るので、`\r`・U+2028 などだけで区切った引用の行の前後でだけ起きる)。文の中の改行は、プロンプトでは空白にして 1 行に並べる。
  - **利用者のメッセージの形**: 往復ごとに、発話の文の行 (`[番号] 本文`) と応答の枠 (`[参照のみ]` の行・本文・`[/参照のみ]` の行。英語のデータ根は `[reference only]`・`[/reference only]`) を並べる。番号を振らない発話の往復も、応答の枠は入れる。訂正の候補があれば、空行と「訂正の候補:」の行の後に、候補ごとに `(候補 番号) 文 [文番号]、型「型」、古い側「…」、新しい側「…」` の行 (古い値の穴の無い型は古い側を書かない) と、「直前の応答:」の行と枠 (無ければ「直前の応答: (なし)」) を並べる。候補の番号は、往復の順・`{new}` の穴・`{old}` の穴・型の順に 1 から振り (入力の順に依らない)、文番号は `{new}` の穴の始まりを含む文にする (番号を振った文に無い候補は送らない)。応答は頭の 500 文字 (縮めた形は 200 文字) で、直前の応答は末尾の 800 文字で切る。
  - **信頼しない文字列の括弧** (2026-11-28。前の「枠の印を変わらなくなるまで除く」に代えた): 枠に入れる応答の本文と、候補の型・穴の文字列の中で、NFKC で `[` を含む文字を `〔` に、`]` を含む文字を `〕` に替える (`〔`・`〕` は NFKC で変わらない)。`[非表示]` の印は替えない (置き換えた後に入れる)。全角・小さい形・ゼロ幅の文字や双方向の制御文字を挟んだ形でも、枠の印も `[番号]` の文の偽装も作れなくなる (印を除く形は、除いた後に別の印ができる並びと、紛らわしい字を追い続けることになるため)。利用者の文の行は替えない (値を写す元の本文なので)。
  - **出力の型の縛り**: 書くときの型に加えて、`keys` の要素に `maxLength` 40、`corrections` に `maxItems` (送った候補の数) を付ける。`a` の長さは縛らない (文法で切り詰めた属性が関門を通って残らないように、40 文字を超える属性は関門で捨てる。2026-11-28)。`s`・`id` の列挙は、その呼び出しで送った文番号と候補の番号にする。

  - **予算での分け方** (上の「収まらない区切り」。2026-11-28 に順を直した。1 区切りを 1 回の呼び出しに保つため (S-17 の 4 は 1 回の呼び出しで測った)): 行 (文の行・応答の枠の 500 文字と 200 文字・訂正の候補 (直前の応答を 800 文字にしたものと 400 文字にしたもの)) ごとに「行 + 改行」で数え、「訂正の候補:」の見出しも固定の行として数える。(1) 区切りの全体が予算に入れば 1 回で呼ぶ。(2) 入らなければ、すべての往復の応答の枠を 200 文字に縮め、(3) それでも入らなければ応答の枠を外す。(4) それでも入らなければ (枠を外したまま)、往復を古い順に詰めて、予算を超える往復の前で次の呼び出しに分ける。(5) 1 つの往復だけで予算を超えるときは、直前の応答を半分にし、それでも超えれば文を前から予算に入るだけ送る (送らない文の候補は送らない)。番号を振った文の無い呼び出しは作らない (その応答の枠は送らない)。組み立てた後に利用者のメッセージの全体を `/tokenize` で数えられるときは、それで確かめ、超えていれば超えた分だけ予算を減らしてその呼び出しの往復を決め直す。`sentences`・`corr`・`refs` には送ったものだけを書く (送らなかった文の番号は欠ける)。
  - **全部を送れなかった区切り** (2026-11-28): 番号を振った文はあるのに、予算に入らず 1 文も送れなかった区切りは、台帳を書かず、`doctor` で数える (番号を振った文の無い区切りの、出力が空の台帳と分ける)。数は記録に持たない (M5.2 で決めた、2026-11-28。作り直せる数のために種類や項目を足さないため): 裏の処理は、その区切りと往復の数をこのプロセスの間だけ覚えて、往復が変わるまで呼び直さず (要るかの判定で毎回数え直さないため)、覚えた区切りの数をコアの状態として持つ。`doctor` は、記録から求められる「台帳の無い閉じた区切り」の数として示す (まだ呼んでいない区切りを含む。`doctor` の表示は M5.5 の段取りの PR で入れる)。
  - **書くときの読み取り**: 全体を JSON として読み、節が並びなら、要素を読むときの型 (`keys` は文字列) で確かめ、合わない要素と上限 (`keys` 8・`units` 24・`corrections` は送った候補の数) を超えた要素を捨てて数え、残りを wire の形のまま (要素の知らない項目を含めて) 入れる。知らない節は入れずに数える。`s`・`id` の範囲と文字列の長さは見ない (関門と区切りの鍵の検査で捨てて数える)。`invalid` の符号は `not_json`・`not_object` (全体)、`missing`・`not_array` (節)、`truncated` (1 つの往復の呼び出しで、やり直しても上限で切れた)、`request_rejected` (4xx。v0.5 は書かない、下の「失敗の扱い」)、`server_error` (締切切れか 5xx が 3 回続いた)。`failed` の台帳は、3 つの節のすべてに合わなかった理由の符号を書く。ストリームが途中で切れた (5xx・接続の切断) 出力は読まず、その呼び出しは締切切れ・5xx として送り直す (途中の出力で台帳を書かない)。
  - **状態の決め方**: 1 つの呼び出しでは、型の合った節が 1 つ以上あれば `complete` (全体が JSON のオブジェクトとして読めれば、止められても `complete`)。止められて読めないときは、閉じた `keys` の節と、`units`・`corrections` の閉じた要素だけを採り、1 つ以上あれば `partial` (届かなかった節は理由を書かずに無いままにする)。番号を振る文の無い区切りの台帳は、3 つの節を空の並びにし、`input_hash` を null、トークン数を 0 にする。
  - **分けた呼び出しのまとめ方** (2026-11-28 に直した): 失敗の単位は分けた呼び出し 1 つにする。やり直し (呼び出しごとに 1 回) の後も失敗した呼び出しは何も出さず、その呼び出しの文・候補・応答は台帳の `sentences`・`corr`・`refs` と `input_hash` から外し、数を `failed_parts` に書く。ほかの呼び出しの出力は、節ごとに呼び出しの順につなぐ (`keys` は重複を除いて 8 個まで)。成功した呼び出しの中で一部の節だけが合わないときは、合った呼び出しの要素をつなぎ、`invalid` の理由は、どの呼び出しでも合わなかった節にだけ書く。止められた呼び出しを含むか、止めたので送らなかった呼び出しが残れば `partial` (送らなかった呼び出しは台帳に書かない)、すべての呼び出しが失敗したときだけ `failed` (入力は送った呼び出しのもの)、ほかは `complete`。失敗した呼び出しの残る `complete` の台帳は、`failed` と同じく model_key か `build_info` が変わったときに呼び直す (上の `needs_call`。`partial` にすると次の機会に毎回呼び直し、同じ所で失敗し続けるため)。
  - **版**: 変種は `sr2` (2026-11-28。S-17 の 4 の SR のシステムのメッセージの文言と順に、`corrections` の節と、§5.2 の「プロンプトに必ず書くこと」のうち SR に無かった文言を足したもの。辞書の説明は `attributes.toml` の `describe` をそのまま使い、説明を直したら変種の版も上げる。システムのメッセージは Qwen3-4B で約 1,400 トークン、gemma-4-12b で約 1,190 トークン (`/tokenize`)。前の `sr1` は文言と辞書の説明を縮めて (Qwen3-4B で 837 トークン)、厳しい一致が Qwen3-4B で 20 → 16、gemma-4-12b で 20 → 18 (25 件中) に下がったので、文言を戻した (spikes/S-17/REPORT.md §5.6)。日本語は検証用のモデルで測った (sr2 の日本語のシステムのメッセージは、測った文言とバイト列まで同じ)。英語は同じ形に訳したもので未計測。生成トークンは BM-108 で確かめる。システムのメッセージ・利用者のメッセージの形の見本・JSON Schema のハッシュを試験で変種に結び付け、どれかを変えると版を上げるまで試験が落ちる)。前のふるいの版は 1 (判定か同梱の規則の `[prefilter]` を変えたら上げる。規則の中身は試験で固定する)。訂正の字句の型の版は、候補を見つける側が渡す。
- **書き込みの直列化**: 単位を書く経路 (台帳の書き込み・導出・指示の書き込み・忘れる・削除) は、1 つのロックで順に通す。ロックを取ってから記録を読み、導き、書き手に渡して書き終えるまで放さない (読んでから書くまでの間に利用者の指示が入り、古い状態から導いた単位で private の印が外れたり、忘れた値が戻ったりしないため)。台帳を書く前の確かめは §4 のとおり。

### 5.3 導出 (B4)

導出は裏の処理の手順 4 で、**LLM を使わない決定論の規則** で行う (確定 (ユーザー回答)、[OQ-46](10-decisions.md#oq-46-事実の統合と事実への操作の結び付け先) の 1。v0.5 で全件の導出にした、ADR-0021・提案書 §5.3)。private の単位を、単位として LLM に渡すことは無い ([OQ-21](10-decisions.md#oq-21-private-の事実を裏の処理に渡すか) の注)。ただし、発話と応答の本文は、呼び出しとチャンクの埋め込みの入力として、private の値を含んだまま裏の呼び出しに渡りうる (`llm.allow_remote` の構成では外の機械に出る。private の確認の文言に書く)。

- **全件の導出を定義にする** (確定、2026-11-26): 入力 (使う台帳 (§5.2.1) の候補のうち関門 (§5.2) を通ったもの・訂正の判定のうち関門 (§6) を通ったもの・指示・辞書・規則の版) が同じなら、結果は同じ。導出は、すべての区切りの候補を全体の位置の順 (下の「入力の順」) に 1 本の列にして先頭から畳み、単位を丸ごと置き換える。畳みの中の単位の集合は (entity, aspect, 辞書か自由記述かの別) で引く形にする (線形に探さない)。出力は単位の ID の順に並べる。
- 全件の導出だけにする (増分の導出は足さない)。ただし、今の関門と畳みをそのまま全件に当てると単位 1 万件で 2.1 秒 (関門 1.7 秒・畳み 0.36 秒。関門は 1 候補あたり約 0.17 ms で線形、畳みは件数の 2 乗) で、目安の 1 秒を超える。そこで、関門 1〜7 の結果を (要素・根拠の文と `rev`・根拠のターンの今の状態 (無い・指示と本文が合わない・今の `rev` と `[非表示]` の範囲)・規則の版 (前のふるい・文の分け方・関門・辞書を含む)・値の鍵の鍵の由来) で覚え (M5.2 で成分を決めた、2026-11-28。鍵が同じなら結果が同じことを性質の試験で確かめる) (作り直せる派生の値。ディスクに置くかは M5.3 で決める)、関門 8 と private を指示の集合の軽い引き当てにし、畳みを (entity, aspect, free の別) で引く形にする (全件の導出と同じ結果になることを性質の試験で確かめる、09 §3.5.1)。1 万件の合成データのベンチを M5.3 に置き、1 秒以内を確かめる (08 §2.6) (S-17 の 4・5・6 で決めた、2026-11-26。spikes/S-17/REPORT.md §5〜§7)
- **導出の指紋** (確定、2026-11-26。03 §3.1.1 の `memory.derive_fingerprint`): `"evorag.derive.1"` ‖ 0x00 の後に、(名前, 値) の組を決まった順に、名前と値をそれぞれ u32be の長さを前に置いて並べたバイト列の SHA-256。成分は次のとおり。単位と同じトランザクションで書く。
  - 台帳ごとの (台帳の ID, 本体のバイト列の SHA-256) の集合 (ID の順。掃除で本体が変われば指紋も変わる)。
  - 指示の件数と最大の ID。
  - 辞書の版、規則 (前のふるい・文の分け方・関門・読み取り・訂正の型・日付・機微) の版、畳みの規則の版 (`derive`)、プロファイルの規則の版、区切りの鍵の作り方の版 (`segment_keys`、§5.5。2026-11-28)。
  - 今の選択と直前の選択 (§5.2.1)。
  - 起動時の軽い検査 (§4 の「要る作り直しは状態から求める」) では、指紋と一緒に記録した成分 (台帳の件数と最大の ID・指示の件数と最大の ID・版・今の選択と直前の選択) を今と比べ、合わなければ全件を導き直す (全件の走査は導き直しのときだけにする、NFR-101)。`doctor --deep` は、全件を導き直して指紋と単位の全体を比べる (03 §10.1)。入力を変える操作 (台帳の追加・掃除・置き換え・指示の追加・版・選択) で指紋が必ず変わることを、性質の試験で確かめる (09 §3.5.1)。
- **訂正を当てる位置** (確定、2026-11-26): 訂正の関門 (§6) のうち 1〜3 と 5 は畳みの前に当てる。関門 4 (古い値が導出のその時点の今の値などに含まれるか) と単位への効き方 (§6) は、畳みの中で、訂正の位置 (下の「入力の順」) に来たときに当てる。
- **候補の帰属**: 候補は、根拠の文のターンで区切りに帰属させる。区切りは往復を重ねないので、同じターンの候補が 2 つの台帳から来ることは無い。
- **入力の順**: 候補と関門を通った訂正は、(根拠のターンの ID, 値の始まり) の順に 1 件ずつ当てる。同じ位置のものは、値の終わり → 訂正 (訂正を候補より先に当てる) → entity → 属性 → 時制 (`current` → `planned` → `past`) → 叙法 (`fact` → `negated`) → 正規化した値 → `old` の有無 の順にする。時制を値より先に比べるのは、「大阪から東京に引っ越した」の {東京, `current`} と {大阪, `past`} を、値の綴りに依らず置き換えの連鎖として当てるため。採る・戻すの指示 (§7.5) は指示の ID の位置に、`end` (§7.4) は終えた位置のターンの候補の後に混ぜて当てる (指示もターンも UUID v7 なので、1 本の列に並ぶ)。
- **済んだ候補**: 同じ (entity, 属性) で値の鍵が同じ単位が、すでにその候補の (ターン, 改訂の番号, 値の範囲) を根拠に持っていれば、当て済みとして何もしない (同じ候補を 2 回当てても結果は同じ)。検証済みの訂正は、古い値がもう今の値でなければ効かないので、根拠では判定しない (同じ範囲の候補の根拠と取り違えないため)。
- **到着の順に依らない**: 全件の導出は入力の順で畳むので、台帳が届いた順・呼び出しの順に依らない (v0.4 までの「抽出が遅れて古いターンの候補が後から来ると、それまでの畳みと作り直しの結果が分かれうる」は起きない)。
- **今の値を終えたときの矛盾**: 否定・過去形で今の値を終えて「今の値なし」になったときは、残った `Contested` の `against` は終えた値の単位を指したままにする (§7.4 の削除・忘れると同じ。後で新しい値が `Live` になったら、その値に付け替える)。
- **同じ値**: (entity, 属性, 値の鍵) が同じ `Live`・`Contested` の単位があれば、根拠を足すだけにする。同じ単位が `Superseded` なら、その候補で今の値にするかを下の条件で決め、今の値にするなら同じ単位を `Live` に戻す (単位の ID は中身から作るので 1 件のまま、§5.1)。今の値が無く、同じ値の `Contested` があれば、それを `Live` にする (`end` の後に言い直された値、§7.4)。
- **単値の辞書の属性**: 新しい値で今の `Live` を `Superseded` にするのは、次のどれかのときだけ。
  - 候補が `tn = current` の言い切りで、根拠の文に、主語を明示する語 (`self` なら「私」「僕」「自分」など、ほかの主語なら呼び名) か、変化を示す語 (「引っ越した」「変わった」「転職した」など) がある。どちらの語も同梱の TOML の規則で決定論に判定する。
  - 検証済みの訂正 (§6) が、今の値から新しい値への向きを持つ。
  - 同じ値の `Contested` の根拠が、2 つ以上の別のターンになった (言い直された。最初の根拠も数える)。
  - それ以外で今の値と違う値は `Contested { against: 今の Live の ID }` にする (「矛盾の記録」)。今の値が無ければ `Live` にする。
  - 値の位置が長い一度の入力 (§5.2 の前のふるい) の範囲にある候補は、上の条件を満たさないものとして扱い、3 つ目の言い直しの数にも数えない (`Contested` に留める。確定、2026-11-26)。
  - `Live` が替わったら、同じ (主語, 属性) の残りの `Contested` の `against` を新しい `Live` に付け替える。新しい `Live` と同じ値の `Contested` は同じ単位なので、その単位が `Live` になる。
- **多値の辞書の属性**: 古い値の 1 件を置き換えるのは、次のどちらかのときだけ。特定できなければ並べて足し、兄弟の値には触れない。
  - 候補の `old` の値の鍵 (§5.6) が、今の `Live` の値の 1 件とちょうど一致する。
  - 検証済みの訂正の古い値の値の鍵が、今の `Live` の値の 1 件とちょうど一致する。
- **時制**: `past` の候補は、その値が今の `Live` なら `Superseded` にする (今の値で置き換えたことにはしない。記録の時制は元のまま変えない)。`when` の終わりは、日付の表現があり決定論の規則で読めたときだけ埋める (§5.1)。今の値でなければ、時制 `past` の `Superseded` の記録として履歴に足す (同じ値の単位は 1 件なので、あれば根拠を足す)。`planned` は、単値の属性では `current` とは別の枠に 1 件だけ `Live` で持ち、多値の属性では兄弟と並べて `Live` で持つ。どちらもプロファイルでは「予定」と示す。`planned` と同じ値の `current` の候補が来たら、予定の単位の時制を `current` にして根拠を足す (同じ単位)。単値の属性では、そのとき今の値を置き換えてよいかを上の条件で決める。
- **終えた発言の根拠**: 過去形 (`past`) か否定で今の値を終えたときは、終えた発言の値の範囲を、終えた単位の根拠 (`anchors` の種類 `ended`) に足す (その値を忘れたとき、その発言も伏せ字の対象にするため)。検証済みの訂正で今の値を置き換えたときも、訂正の発話の中で古い値に一致した範囲 (`{old}` の穴の中) を、置き換えた単位の根拠 (種類 `corrected`) に足す。
- **否定**: `negated` の候補は、値が今の `Live` の値と一致し、根拠の文に変化を示す語 (「もう」「やめた」"no longer" など) があるときだけ、その `Live` を `Superseded` にする (その属性は「今の値なし」になる)。それ以外の否定は捨てる。
- **削除しない**: 置き換えた値も残す。「いつ何を言っていたか」に答えられ、誤った置き換えを戻せる。
- **自由記述の属性**: `world` の候補は置き換えない。(entity, 属性, 値の鍵) ごとに多値として並べ、`when` と根拠の日付を持つ (提案書 §5.3)。時制 `past` の値は `Superseded` (`by` なし)、それ以外は `Live` にする。`negated` は捨てる。
- **出来事** (`episode`): 置き換えない。同じ entity・属性・値の鍵・日付 (§5.1 の単位の ID) の候補は 1 つの単位にまとめ、根拠を足す。言い換えは別の単位になる (列挙で二重に数えうる、提案書 §14)。状態は持たない。`negated` は捨てる。
- **導出の流れ**: (1) 区切りごとに使う台帳を選ぶ (§5.2.1)。(2) 台帳ごとに、`keys`・単位の候補・訂正の判定に、畳みの前の関門を当てる (§5.5・§5.2・§6 の 1〜3・5)。(3) 指示 (§7.5) を当てる: 忘れるは関門 8 で候補を捨て、採る・戻す・`end` は畳みの列に混ぜ、private は畳んだ後に印を付ける。(4) 上の畳みの規則で単位を作る。(5) 単位・指紋・数えた理由の件数を 1 つのトランザクションで書く。導出の関数は `evorag-memory` の 1 つだけにし、生きている導出・忘れるの計画 (§7.1)・`doctor --deep` (03 §10.1) で同じ関数を使う。
- **単位の副索引**: (entity, aspect)・`vk`・日付・根拠のターン (03 §3.3)。値の文字列そのものはキーに入れない。
- **根拠の無い候補**: 根拠のターンが無い候補は、関門 1 で捨てる (セッションの削除と同じ)。規則 12 の突き合わせ (03 §4.2) は、単位を 1 件ずつ消さずに全件を導き直す。
- **導出の結果が変わったら**: 単位の鍵 (§5.5) の索引を作り直し、プロファイル (§5.4) を作り直す (差し替えは 05 §4.1 の時機)。
- **数えた理由**: 関門と導出で捨てた・別に数えた理由の件数は、導出の結果と一緒に持ち、`doctor` が報告する (値は出さない)。
- **知らせ**: 導出で単位が増えた・置き換わった・矛盾になったら、状態の行に件数だけを短く出す (「記憶 +2・矛盾 1」。値は出さない)。`/memory` の一覧では、前に見てから変わった行に印を付ける。

### 5.4 プロファイル

プロファイルは、辞書の属性の `world` の単位を、属性と値の表の形の「データ」として、文脈の先頭の側に固定して置く (提案書 §6.5。v0.3〜v0.4 の事実の表 ([OQ-35](10-decisions.md#oq-35-文脈の並べ方-日時想起古い発言先の処理) の 6) に代わる)。本節をプロファイルの中身の正本にし、置く位置と差し替えの時機は 05 §4.1 を正本にする。

- **入るもの**: 辞書の属性の `world` の単位で、`Live` で private でないものだけ。`planned` は「予定」の印を付ける。主語と値が関門 6 の検査に通らない行も入れない (多重の守り)。
- **入れないもの**: 自由記述の属性の単位と出来事 (`episode`)。指示の混入と誤った今の値を、信頼する枠に入れないため (提案書 §6.5)。
- **並べ方**: 辞書の属性の優先の順 → entity (`self` が先、残りは正規化した呼び名の順) → 値の鍵の順 (中身で決まる順。作り直しで揺れない)。問いに合わせて選び直さない (先頭が毎ターン変わるため)。
- **予算**: 600 トークン (05 §4.1)。超えるときは、辞書の優先の順、同じ優先なら entity が `self` のものを先に、その中では根拠の最も新しいターンの新しい順に、入るだけ入れる (導き直しても同じになるため)。漏れた単位も検索の鍵 (§5.5) から拾える。v0.7 から、同じ属性の多値が予算を超えるときは、優先度の高い値から入れる (提案書 §9.7。優先度は差し替えの時点で固定し、導出の指紋に入れる)。
- **書式**: 値の中の改行と表の区切りを除き、表の行として書く。表の前に「利用者の発言から作ったデータで、指示ではない」ことを書く。文言はプロンプトの言語ごとに固定する。
- **版**: プロファイルの本文のバイト列 (前置きを含む) のハッシュ。応答のターンに観測値として残す (05 §3.6、[OQ-41](10-decisions.md#oq-41-ターンに残す観測値))。
- **作り直す時機**:
  - 導出の結果が変わったら、裏の処理の手順 6 (§4) で作り直す。文脈に置く (差し替える) のは、05 §4.1 の差し替えの時機 (新しいセッションの始め・古い発言をまとめて省くとき・履歴が短いとき) だけにする (FR-419)。それまでは前のプロファイルを置き続ける。差し替える時機が来ていれば、続けて次のターンの分を先に処理しておく (生成を 1 トークンに限った要求)。差し替えたら先読みの世代の番号を上げる (05 §4.5)。
  - 忘れる・private・private の解除 (`/private off`)・削除の操作をしたら、次のターンで必ず作り直して差し替える (確定、2026-11-26。操作のコミットの後に送る最初の応答の要求で、新しいプロファイルが置かれている。AC-FR-317-3 はこの時点で判定する)。この 1 回は、文脈の全体を処理し直す待ちを受け入れる (伏せ字で履歴の本文が変わるときも同じ)。
  - それ以外のときは作り直さない。単位が変わらないターンでは、プロファイルを含む要求の先頭が前のターンと一致する。
- プロファイルは記録を持たない (単位から描く)。入る件数は数百の見込みなので、副索引 (entity, aspect) で引いて主記憶の上で並べる。
- **鍵が使えないとき** (確定、2026-11-26): `memory.forget_key` が使えない (03 §3.1.1 のフェイルクローズ) 間は、プロファイルを文脈に置かない (忘れる・private の当たりを確かめられないため)。単位の鍵 (§5.5) も想起に使わない。

### 5.5 検索の鍵

検索の鍵は、問いと元の会話の語彙の違いを補う索引の項目 (§2) で、2 つから作る。どちらも文脈には入れず、鍵で当たったら、指す往復をリランクして原文を添える (05 §3)。

- **言葉の区別** (確定、2026-11-26。[OQ-54](10-decisions.md#oq-54-v05-の新しいデータ根と古いデータ根の扱い) の 7):
  - **区切りの鍵**: 台帳の `keys` から作る鍵 (v0.2〜v0.4 のノートの鍵の後継)。v0.5 で作る。
  - **単位の鍵**: 単位から作る短い語句の鍵 (v0.3〜v0.4 の事実から作った検索の鍵の後継)。v0.5 で作る。範囲は辞書の属性の `world` の `Live` と `Superseded` だけ (v0.4 の事実の鍵と同じ範囲。読み出しを v0.4 から変えず、忘れるの置き場所を増やさないため)。
  - **単位の索引**: 単位を想起の候補の由来にする索引 (提案書 §4.5・§6.1。単位の値・自由記述の属性・entity の語彙とベクトルの索引)。v0.6 で、使う版と一緒に作る。v0.5 では作らない。

| 鍵 | 中身 | 指す往復 | 索引の項目の ID | 版 |
|---|---|---|---|---|
| 区切りの鍵 | 使う台帳 (§5.2.1) の `keys` で関門を通ったもの | 区切りのすべての往復 | 区切りの ID (1 つの区切りが鍵の数だけ項目を持つ。区切りの項目を消すと、その ID の項目がすべて消える) | v0.5 (v0.2〜v0.4 のノートの鍵の後継) |
| 単位の鍵 | 辞書の属性の `world` の `Live`・`Superseded` の単位の「属性 値」の短い文 | 単位の根拠のターンの往復 | 単位の ID (派生の索引の項目なので、単位の ID を持ってよい、§2) | v0.5 (v0.3〜v0.4 の事実から作った鍵の後継) |

- **区切りの鍵の検査** (B3): 前後の空白を除き、40 文字を超える部分を切り捨てる。空のものと、関門 6 (§5.2。URL・命令形・役割の詐称・区切りの模倣・文字体系の混在などを含む) に通らないものを捨てる。重複を除き、9 個目からは捨てる。鍵が出典の往復の本文に (正規化した上で) 含まれる語だけからなる必要はない (言い換えを補うため)。private の指示の値の鍵か照合の鍵か、導出で private の印を付けた単位 (後継・根拠の位置で private になったものを含む) の値の鍵か照合の鍵に、語句か部分文字列 (書記素の境界で切ったもの。正規化の後の長さが 256 文字以下のもの、§7.2 の「掃除の補い」) の値の鍵か照合の鍵が当たる鍵は、導出の時点で除く (提案書 §7.3。台帳を作った後に private にした値も除けるため。2026-11-27 に、後継・根拠の位置で private になった値を足した)。
- **区切りの鍵の作り方の補い** (2026-11-28。M5.2 で純粋な関数を書くときに決めた):
  - **文字数と切り方**: 40 文字は、前後の空白 (White_Space) を除いた生の文字列の Unicode のスカラー値の数で数える (B2 の文法の `maxLength` と同じ数え方)。超えるときは 40 文字以下に収まる最後の書記素の境界で切り (書記素の途中では切らない。結合文字・異体字セレクタだけが残って関門 6 で捨てられないため)、切った後の後ろの空白も除く。
  - **重複**: 検査の後の鍵 (切った後) の値の鍵 (正規化 v1、§5.6) で比べ、最初の書き方を残す。関門 6 で捨てた鍵は重複に数えない (捨ててから比べる)。8 個の上限は、重複を除いた後に数える。
  - **当てる順**: 検査 (切る → 空 → 関門 6 → 重複 → 上限) を先に当て、導出の時点のふるい (忘れる → private) はその後に当てる。ふるいで除いても 9 個目以降の鍵は戻らない (private を付け外ししても、ほかの鍵が入れ替わらないため)。鍵の並びは台帳の `keys` の順のまま。関門 6a (機微な情報) は当てない (鍵は文脈に入れないため。v0.4 のノートの鍵と同じ)。
  - **忘れた値**: 導出の時点でも、忘れるの指示の `vks` に語句か部分文字列の値の鍵か照合の鍵が当たる鍵を除く (§7.2 の台帳の掃除の 4 の前半と同じ述語。印を解いた指示は、区切りの最初の往復の発話のターンで比べる)。掃除した台帳では何も除かない多重の守り (単位の候補に掃除と関門 8 の両方を当てるのと同じ)。
  - **数える理由**: 捨てた鍵は理由ごとに数える (`empty`・関門 6 の理由の名前 (§5.2)・`duplicate`・`over_limit`・`forgotten`・`private`。値は出さない)。
  - **埋め込み**: 埋め込みを指す「鍵の文字列の値の鍵」は、検査の後の鍵 (切った後) の値の鍵にする。台帳を掃除で変えたときに消す埋め込みは、掃除の前と後の台帳に検査を当てた結果の差 (前にあって後に無い値の鍵) にする (同じ値の鍵の別の書き方が残れば消さない)。導出の時点のふるいで除いた鍵は、索引の項目だけを除き、埋め込みは残す (`/private off` で同じ鍵が戻るため。台帳の `keys` も残す、§7.9)。
  - **版**: 作り方 (検査の切り方・重複・上限と、導出の時点のふるい) の版 `segment_keys` (`1` から) を持ち、導出の指紋の成分 (§5.3) にする。変われば区切りの鍵の項目をすべて作り直す。関門 6 の規則の版は関門の版が持つ。
- **単位の鍵の範囲**: 上の「言葉の区別」のとおり、辞書の属性の `world` の `Live`・`Superseded` だけ。自由記述の属性と出来事の単位は、v0.6 の単位の索引で引く。 private の単位からは作らない。根拠のターンが今のセッションだけの単位の鍵は、想起の候補を集める段階で除く (今のセッションのターンを添えないのと同じ、05 §3.2)。
- 鍵の項目は、指す往復が複数のセッションにまたがりうるので、セッションに結び付けない。
- 鍵の埋め込みの記録 (`embedding`) は、区切りの鍵は (台帳の ID, 鍵の文字列の値の鍵 (§5.6 の HMAC)) で指し、単位の鍵は単位の ID で指す (03 §3.3。確定、2026-11-26)。区切りの鍵を鍵の位置で指さないのは、台帳の掃除で `keys` の位置がずれるため (§7.2)。
- **作り直し**: 導出の結果が変わったら、変わった区切りと単位の項目を作り直して入れ替える (§4 の手順 5)。区切りの使う台帳が替わったら、その区切りの ID の項目を入れ替える。
- **忘れる・private**: 単位が private になった・忘れたら、コミットの直後に (利用者に知らせる前に) その単位の鍵を索引から除く。読み出しでは単位と台帳を読み直し、private・忘れた値の鍵は使わない (§7.7。`/private off` で同じ鍵が戻るので、ID で拒む仕組みにしない)。区切りの鍵の掃除は §7.2。

### 5.6 値の鍵

単位の重複の判定と ID (§5.1)、指示 (§7.5)、忘れるの当て方 (§7.6) は、値そのものではなく「値の鍵」で照合する。忘れるの指示の `vks` には、値の鍵に加えて照合の鍵 (下の「照合の形」) も入れる。

- 値の鍵の正規化は、検索の正規化 (05 §2.1) とは別に持ち、**凍結する** (版 `1` から変えない): NFKC → casefold → NFKC → 空白を 1 つにまとめて両端を除く。記号は残す (検索の正規化のように区切りにすると "C++" と "C#" が同じになるため)。カタカナとひらがなは統一しない。
  - casefold は Unicode の完全な case folding (CaseFolding.txt の状態 C と F。T は使わない) にする。`char::to_lowercase` は使わない (`ß` が `ss` にならず、Unicode の安定性の約束も無いため)。
  - 空白は Unicode の White_Space の性質を持つ文字にする。その連なりを U+0020 の 1 つにし、両端を除く。
  - 実装の依存 (NFKC と case folding の表) の版を上げて結果が変わったら気付けるように、すべての Unicode のスカラー値を 1 文字ずつ正規化した結果のハッシュを試験で固定する。変わったら、古い結果を例外の表で保つ (凍結のため)。正規化は冪等であること (2 回当てても同じ) も試験する。
  - 主語の呼び名と自由記述の属性にも同じ正規化を当てる (§5.1)。辞書の属性の名前は変えない。
- 正規化で長さが変わる (`ｶﾞ` → `ガ`、`㈱` → `(株)`) ので、元の本文の位置と正規化の後の位置の対応表を作って照合する。一致の端が 1 つの文字の展開の途中に来たときは、一致としない。
- **鍵の形**: 値の鍵は、正規化した値の HMAC-SHA256 (鍵は `meta` の `memory.forget_key` を復号した 32 バイト、03 §3.1.1) にする。副索引・指示・ジャーナルには、この鍵だけを書き、値の文字列を書かない (03 §3.3)。HMAC に入れるバイト列は次のとおりに凍結する (`‖` は連結、`u32be` は 4 バイトのビッグエンディアンの長さ)。
  - 値の鍵: `"evorag.vk.1"` ‖ 0x00 ‖ UTF-8 (正規化 v1 (値))。記録には 64 桁の小文字の 16 進で書く。
  - 再び覚えない印 (v0.4 までの忘れるの指示の `marks`。`import-v04` で写した指示に残るが、v0.5 からは当てない、§7.6): `"evorag.mark.1"` ‖ 0x00 ‖ u32be(len S) ‖ S ‖ u32be(len A) ‖ A ‖ 値の鍵の 32 バイト。S は UTF-8 の主語 (§5.1 の正規化の後)、A は属性の名前の ASCII。記録には 64 桁の小文字の 16 進で書く。
  - 先頭の文字列で値の鍵と印の入力を分け、長さを前に置いて区切りの曖昧さを無くす。
  - 照合の鍵 (下の「照合の形」): `"evorag.vk.1"` ‖ 0x00 ‖ UTF-8 (照合の形 v1 (値))。値の鍵と同じ形で、正規化 v1 の代わりに照合の形を入れたもの。照合の鍵から作る印は、上の印の値の鍵の 32 バイトを照合の鍵の 32 バイトに代えたもの。記録には 64 桁の小文字の 16 進で書く。
  - 自由記述の属性の鍵 (v0.5): `"evorag.asp.1"` ‖ 0x00 ‖ UTF-8 (正規化 v1 (属性))。指示には、自由記述の属性の文字列ではなくこの鍵を書く (属性の名前が値に近い内容を含みうるため、提案書 §7.1)。記録には 64 桁の小文字の 16 進で書く。
- 正規化を変えるときは、版 `2` の正規化として足し、指示に正規化の版を書く。古い版の鍵は古い版の正規化で照合する (値を持たないので、作り直せないため)。
- **照合の形** (v1。**凍結する**。照合の鍵が忘れるの指示の `vks` に入るため、§7.6): LLM は値や根拠を写すときに、漢字・かなと英数字の間の空白を足したり除いたりする (「7月22日」を「7 月 22 日」と写す)。これを吸収するために、照合にだけ使う形を値の鍵とは別に持つ。値の鍵の正規化 v1 は変えない (凍結のまま。照合の形で値の鍵を作り直さない)。
  - **作り方**: 正規化 v1 の結果からではなく、元の本文から作る (正規化 v1 は改行も 1 つの空白にまとめてしまい、改行をまたいだかが分からなくなるため)。手順は正規化 v1 と同じ (NFKC → casefold → NFKC → 空白の連なりを U+0020 の 1 つにまとめて両端を除く) で、元の本文の空白の連なり (White_Space の文字の続いた並び) のうち、次の両方に当たるものだけは、1 つにまとめずに除く。
    1. 連なりのすべての文字が一般カテゴリ Zs (U+0020・U+3000・U+00A0 など) である。Cc (タブ・改行・CR・VT・FF・NEL など)・Zl・Zp を 1 つでも含む連なりは除かない (正規化 v1 と同じく 1 つの空白にする)。
    2. 連なりの直前の書記素の最初の文字か、直後の書記素の最初の文字が、語を空白で区切らない文字である。語を空白で区切らない文字は、Script_Extensions に Han・Hiragana・Katakana のどれかを含む文字 (Script_Extensions が Common か Inherited の文字は含めない。長音符「ー」・「々」・半角のカタカナは含む)。判定は元の本文の文字で行う。関門 4 の引用符の判定 (§5.2) と同じ述語を使う。
  - 前後のどちらも語を空白で区切らない文字でない空白 (英字・数字・ハングル・記号の間) は残す ("Ann a" を "Anna" に、"5 kg" を "5kg" に当てない)。NFKC が文字の展開で作った空白は、元の本文の空白の連なりではないので除かない。
  - 述語の表の Unicode の版は、試験で固定する (版が変わったら気付けるように。値の鍵の正規化のハッシュの試験と同じ扱い)。照合の形の版は、値の鍵の正規化の版 (`norm`) と組にする (`norm` が `1` なら照合の形も v1。照合の形を変えるときは、正規化の版を上げて足す)。
  - **位置**: 照合の形でも、元の本文の位置と照合の形の位置の対応表を作り、一致した位置を元の本文 (前のふるいの後の本文なら、そこから保存した本文) の位置に戻す。一致の範囲は、一致の最初の文字の元の位置から、最後の文字の元の終わりまでにする (除いた空白の上や中で始まり・終わる範囲は作らない)。一致の端の条件 (1 つの文字の展開の途中に来たら一致としない・書記素の境界・英数字の語の境界) は、正規化 v1 と同じにする。
  - **照合の順**: どこで使うときも、生の本文 → 正規化 v1 → 照合の形 の順に試し、前の段で一致しなかったときだけ次の段に進む (前の段で通る候補の結果は変わらない)。本文の中の一致をすべて探すとき (伏せ字・`[非表示]` の範囲、§7.1・§7.3・§7.5) は、正規化 v1 で一致した範囲を先に採り、照合の形では、それと重ならない一致だけを足す (空白の有無だけが違う写しを残さないため)。
  - **使うところ**: 関門 2・4 (根拠の文の中の値・`old`・`when` の位置)・5 (主語。主語を明示する語と表の書式の語との比べを含む)、関門 6 の語の一覧の検査 (値の照合の形にも当てる。文字体系の混在の判定には使わない)、訂正の関門 (§6。古い値を探す相手、穴の位置、向きの関門の同じ値の判定)、忘れるの `vks` (照合の鍵、§7.5・§7.6)、台帳の掃除 (§7.2)、伏せ字と `[非表示]` の範囲の探し方 (§7.1・§7.3・§7.5)。値の鍵そのもの、単位の重複の判定と ID (§5.1・§5.3)、採る・戻すの指示の鍵は、正規化 v1 の値の鍵だけを使う (private の指示は、忘れると同じく値の鍵と照合の鍵の両方を `vks` に持ち、両方で引く、§7.5。2026-11-27 に §7.5 の表に合わせた)。
  - 値の鍵は照合の形を使わないので、空白の有無だけが違う 2 つの書き方 (「7月22日」と「7 月 22 日」) は、単位としては別の値になる (導出で `Contested` になりうる)。記録する値は利用者の書いた形 (§5.2 の「記録する文字列」) なので、利用者が書き方を変えたときだけ起きる。

## 6. 訂正

- **候補**: 呼び出しの入力を作るとき (§4 の手順 3) に、区切りの利用者の発話の前のふるいの後の本文を字句の規則 (同梱の TOML の、穴のある型。「{old}じゃなくて{new}」「{new}、{old}ではなく」"{new}, not {old}"、"I meant {new}" など) で調べ、当たったものを候補にする (LLM を使わない)。候補は、送った候補の表として台帳の `inputs` の `corr` (`[{id, turn, rev, pattern, new: {start, end}, old: {start, end} か null}]`。`pattern` は当たった型、`new`・`old` は穴の範囲) に書き、規則の版も `inputs` に書く (§5.2.1)。導出は候補を見つけ直さず、この表で `corrections` の `id` を引く (確定、2026-11-26。規則の版を上げても、送った候補と判定の組がずれないため)。伏せ字の後は表の位置を写し直し (§7.3)、忘れるの掃除は表の要素を消す (§7.2)。信号の種類 (`signal`) には値を足さない (03 §4.2 の規則 11)。コーディングのセッションでは訂正の候補を探さない (「not」「wrong」が作業の会話に多く、判定が無駄に増えるうえ、学習はチャットとコーディングで分けるため、ADR-0020。コーディングの信号は 15 §8.2)。
- **判定**: 候補は、区切りの 1 回の呼び出し (§5.2) の `corrections` の節で判定させる (v0.4 までの別の検証の呼び出しをまとめた、提案書 §5.1)。呼び出しに出させるのは訂正かどうか (`verdict`) だけで、新しい値と古い値は、決定論で型の穴から決める (OQ-53 の 7。v0.4 までは検証の LLM に古い値・新しい値・根拠を写させていた)。プロンプトには、候補ごとに番号 `id`、文番号、当たった型と穴の文字列を示し、候補の発話の直前の応答 (同じセッションの、候補の発話より前の最後の応答のターン。状態 (完了・中断・失敗) は問わない。忘れるの指示と合わないターンなら、直前の応答は無いものとする (M5.2 で決めた、2026-11-28)) を信頼しない引用の枠 (`[参照のみ]`) に入れる (根拠にはしない)。直前の応答には、忘れるの `[非表示]` の範囲を印に置き換えてから入れる。直前の応答は、末尾の側の 800 文字までにする (確定、2026-11-26。v0.4 までの検証と同じ。直したのが事実か応答の誤りかの判定に使う。下の「判定の入力」)。
  - 出力: 候補ごとの `verdict` (§5.2 の出力の型)。
  - **値の決め方**: 古い値は `{old}` の穴の全体 (下の「古い値は穴の全体」)。新しい値は、同じ根拠の文の単位の候補 (§5.2 の関門を通ったもの) のうち、値の位置が `{new}` の穴の、固定の部分に接する端にあるもの (下の「値の位置」)。そのような候補が無ければ、訂正は単位を変えない (学習 (v0.7) にだけ使う)。
  - 関門 (決定論。導出のたびに、この順に当て、最初に外れた理由 (括弧の中の値) で数える。1〜3・5 は畳みの前に、4 は畳みの中で訂正の位置に来たときに当てる、§5.3):
    1. 訂正である: `verdict` が `accept` (`not_correction`。`reject`・`unclear` はここで落とす)。プロンプトに、決められなければ `unclear` にするよう書く (一次のふるいの誤検知を、訂正として当てないため)。
    2. 新しい値がある: 上の「値の決め方」で新しい値の単位の候補が決まる (`new_not_in_utterance`)。古い値の穴の無い型は、この関門の前で「単位を変えない訂正」として扱う (下の「単位への効き方」)。
    3. 新しい値の位置が、括弧・引用符の内側にない (§5.2 の関門 4 と同じ規則。引用符で囲んで貼った他人の文の訂正を当てないため) (`quoted`)。新しい値の一致は、括弧の内側に 1 文字でも掛かってはならず、型の固定の部分も括弧の内側にあってはならない (新しい値を閉じ括弧の外まで伸ばして、引用の中の訂正を当てないため)。
    4. 古い値が、直前の応答か、利用者のそれより前の発話か、導出のその時点の今の値 (`Live` の単位の値) のどれかに含まれ (照合は生の本文 → 正規化 v1 → 照合の形 (§5.6) の順)、関門 6 (語の一覧の検査は照合の形にも当てる、§5.2) と 200 文字の上限に通る (古い値も信頼しない本文から取るので、導出と学習に渡す前に守る) (`old_not_found`)。
    5. 向き: 否定の語 (「じゃなくて」「ではなく」"not" など) が付いた側の穴が `{old}`、もう一方が `{new}` になる型の向きで決める (語の並びの前後では決めない。英語では新しい値が先に来ることが多いため)。記録する古い値と新しい値の値の鍵が同じか、照合の形 (§5.6) で同じなら落とす (空白の有無だけが違う値への訂正を、向きのある訂正として当てないため) (`direction`)。
  - 関門を通ったものを、検証済みの訂正として導出に渡す (下の「導出への渡し方」)。
- **訂正の型の使い方**: 型は向き (どちらが古い値か) を決めるためだけに使う。新しい値の位置は同じ文の単位の候補の値で探し (照合は生の本文 → 正規化 v1 → 照合の形 (§5.6) の順)、それが型の穴の位置にあることを確かめる。記録する新しい値 `new` は `{new}` の穴の位置で一致した保存した本文の部分文字列に、古い値 `old` は `{old}` の穴の位置で一致した保存した本文の部分文字列にし、`new_vk`・`old_vk` はこの文字列から作る (LLM の写しではなく、利用者が書いた形にそろえるため。§5.2 の「記録する文字列」と同じ)。古い値の穴の無い型では、古い値を持たない (単位を変えないので、学習 (v0.7) にだけ使う)。記録する `old`・`new` には §5.2 の関門 6 を当て、外れたら、`old` は `old_not_found`、`new` は `new_not_in_utterance` で落とす (訂正を導出と学習に渡す前に守るため)。型は固定の部分の長いものから試す (「ではなく」より「ではなくて」を先に)。長さは読点と空白を数えずに比べ、同じ長さなら同梱の TOML の順に試す (読点を数えると「{new}、{old}ではなく」が先に当たり、「いや、大阪ではなく京都です」の新しい値の穴が「いや」になるため)。読点・空白と文末の「よ」「です」の有無は区別しない。
  - **穴の範囲**: 穴は、型の固定の部分から、同じ文の中 (文の区切り `。`・`．`・`.`・`!`・`?`・`！`・`？` と改行の手前) までにする (穴が本文の端まで伸びて、後ろの文の語を値にできないため)。半角の `.`・`!`・`?` は、後ろが空白・改行・本文の終わりのときだけ区切りとみなす (小数・URL・略語で文を切らないため)。
  - **読点だけの固定の部分**: 「{new}、{old}ではなく」のように、2 つの穴の間の固定の部分が読点だけの型は、本文の読点か空白で 2 つの穴を分ける (この型に限って読点の有無を区別する)。区切りが 2 つ以上あれば、後ろの穴の後に固定の部分が続く型 (「{new}、{old}ではなく」) は最後の区切りで、後ろの穴が末尾の穴の型は最初の区切りで分ける (どちらも、固定の部分に接する側の穴を短くする)。
  - **値の位置**: 値は、穴のうち固定の部分に接する端に置く。後ろに固定の部分がある穴では値の終わりを穴の終わりに、後ろに固定の部分が無い穴 (末尾の穴) では値の始まりを穴の始まりに合わせる (間の読点・空白は飛ばす)。「大阪じゃなくて東京に住んでいます」の新しい値「東京」は通り、「住んでいます」は通らない。「大阪じゃなくて、今は東京です」のように間に語が入ると落ちるが、安全の側に倒す (単位は `Contested` から言い直しで置き換わりうる)。
  - **古い値は穴の全体**: 古い値は、どの単位を置き換えるかを決めるので、片側の端ではなく `{old}` の穴の全体と一致させる (穴の前後の読点・空白を除いて比べる)。`{old}` の穴は、文の区切りに加えて読点 (`、`・`，`・`,`) でも切る。「東大阪じゃなくて京都です」の古い値「大阪」は通らず、「いや、大阪じゃなくて京都です」の「大阪」は通る。「いや大阪じゃなくて」は落ちるが、安全の側に倒す。
  - **文末の「よ」「です」**: 除くのは、末尾の穴が文末で終わるときの穴の終わりの「よ」「です」の 1 回だけにする (「かよじゃなくて」の「かよ」を「か」にしないため)。
  - **一致の端と括弧**: 値の一致は、根拠の中だけでなく、前のふるいの後の本文の全体で語の境界 (英数字の並び) と括弧・引用符の内側を確かめる (LLM が値を語の途中で切って境界の検査を抜けたり、同じ値を括弧の内と外に書いて内側の一致を根拠にしたりしないため)。置いた位置 (新しい値の、穴の端に接する一致) が括弧の内側なら、向きのほかの検査より先に `quoted` で落とす。
  - **区切りの文字の判定**: 文の区切りの判定は、NFKC の前の元の文字で行う (全角の `．`・`！`・`？` は常に区切り、半角の `.`・`!`・`?` は後ろが空白・改行・本文の終わりのときだけ区切り)。文番号の文の分け方 v1 (§2) には寄せない (M5.2 で決めた、2026-11-27。§2)。
  - **照合の費用**: 型の照合は、発話の長さに対しておおむね線形で終える (4,000 文字の上限は NFKC の後の長さにも当てる)。
  - **`corr` に書く穴の範囲** (2026-11-28 に明確にした): `new`・`old` は、値を比べる範囲 (上の「文末の「よ」「です」」で 1 回だけ除いた後の穴) を、候補の発話の保存した本文の UTF-8 のバイト位置 (書記素の境界) にしたもの。長さでは切らない (古い値の 200 文字の上限は関門 4 で当てる。v0.4 までの検証の入力は穴の本文を 200 文字で切っていた)。プロンプトの候補の行に示す穴の文字列も切らない (M5.2 で決めた、2026-11-28。穴は 1 つの文の中にあり、その文は番号を振って全文を送るので、切っても要求はほとんど短くならず、切ると利用者のメッセージの形が変わって変種の版を上げることになるため)。穴の端が NFKC で 1 文字が複数の文字になる書記素の途中に来るか、前のふるいで除いた行をまたいで保存した本文に戻せないときは、ほかの型を試さずに、その発話を候補にしない。訂正の字句の型の版 (`inputs` の `correction`) は、型と一次のふるい (同梱の TOML の `[correction]`) と照合の手順のどちらを変えても上げる (規則の中身は試験で固定する)。
  - 1 つの発話に型が 2 つ以上当たっても、最初に当たった 1 つ (固定の部分の長い型から。同じ型なら本文の前から) だけを候補にする。
  - 前のふるいの後の本文が 4,000 文字 (暫定) を超える発話には型を当てない (長い貼り付けで照合の費用が膨らむため。長い発話の中の訂正は取りこぼす)。
- **型**: 関門を通った訂正は、コードでは候補と別の型にし、単位の置き換え (§5.3) と学習 (v0.7、13) には検証済みの型しか渡せない。
- **単位への効き方**: 検証済みの訂正は、辞書の属性の `world` の単位だけを置き換える。古い値の値の鍵 (§5.6) が今の `Live` の値の 1 件とちょうど一致し、新しい値の単位の候補が同じ (entity, 属性) にあるときだけ、置き換えの条件 (§5.3 の「単値の辞書の属性」の 2 つ目) を満たす。一致しなければ、学習 (v0.7) にだけ使い、単位は変えない。一致する値が 2 つ以上の (entity, 属性) にあるときも、どれを直したのか決められないので、単位は変えない。自由記述の属性と出来事は置き換えないので、訂正は効かない。
  - 古い値の穴の無い型 (`I meant {new}`、「正しくは{new}」「違う、{new}」など) の訂正は、単位を変えない (学習にだけ使う)。古い値の位置を発話で確かめられず、今の値のどれにでも当たりうるため (信頼しない直前の応答に誘導されて、利用者の別の単位を置き換えないため)。
  - 今の値は、時制 `current` の `Live` に限る。予定 (`planned`) の値は訂正で置き換えない。
- **関門の順**: 上の関門の 1〜5 の順に当て、最初に外れた理由で数える。引用 (コードブロック・引用の行) の中の訂正は、型を前のふるいの後の本文に当てるので候補にならない。訂正の型は、発話の一部に当たればよい (発話の全体と一致しなくてよい)。
- **記録**: 訂正は記録 (v0.4 までの `correction`) を持たない。判定の生の出力は台帳の `corrections` にあり、関門は導出のたびに当てる。関門で落ちた理由 (`not_correction`・`new_not_in_utterance`・`quoted`・`old_not_found`・`direction`、忘れた値だった `forgotten`) は、導出の数えた理由に入れる (§5.3)。検証済みの訂正は、新しい値の範囲 (候補の発話の保存した本文の中のバイト位置) と、古い値の、`{old}` の穴の中で一致した範囲 (古い値の無い型では無し。§5.3 の「終えた発言の根拠」に使う) を、導出の中で持つ。
- **候補を見つける時機**: 呼び出しの入力を作るときに、区切りの発話の前のふるいの後の本文に一次のふるい (`triggers`) と型を当て、台帳の `corr` に書く (LLM を使わない)。前のふるいで番号を振らない発話 (短い・挨拶・相槌) にも、コードブロックと引用の行を除いた本文が残れば型を当て、当たれば番号を振って送る (「いや、大阪じゃなくて東京」は短くても訂正になるため)。忘れるの指示の `turns`・`redactions`・`hidden` に入るターンの発話は、候補にしない (伏せ字にしないで忘れた発話の、忘れた値の写しを台帳に戻さないため。§7.5 の「忘れると訂正」)。
- **判定の入力**: 直前の応答は、末尾の側 (候補の発話に近い側) の 800 文字までを入れ、要求の予算 (§5.2.1) に収まらなければさらに半分に切る。本文の中の NFKC で `[`・`]` になる文字は `〔`・`〕` に替える (枠の印を作って枠を閉じられないため。§5.2.1 の「細目」)。関門は、切る前の保存した本文で照合する。古い値の関門の「利用者のそれより前の発話」は、同じセッションの、候補の発話より前の利用者の発話の、前のふるいの後の本文にする (セッションをまたがない)。検証済みになる結果の `old`・`new` の値の鍵と照合の鍵 (§5.6) のどれかが、忘れるの指示の `vks` (§7.5) のどれかと同じなら、`forgotten` で落とす (忘れた値を訂正で戻さないため)。
- **導出への渡し方**: 畳みの前の関門 (1〜3・5) を通った訂正は、新しい値の範囲を位置として、導出の入力の順 (§5.3) に入れる。畳みの中でその位置に来たときに関門 4 を当て、通れば検証済みの訂正として、単位の置き換えの条件 (古い値が今の値の 1 件と一致する、下の「単位への効き方」) を当てる。版の不一致の段で選んだ台帳 (§5.2.1) の `corrections` は使わない。

## 7. 統治 (忘れる・消す・private)

利用者の明示の操作は指示 (`directive`、§7.5) として正本に持ち、導出のたびに当てる (提案書 §7)。忘れる・private が届く置き場所の一覧は §7.9。

### 7.1 操作と結果

| 操作 | 結果 | 版 |
|---|---|---|
| セッションの削除 (`/delete`) | ターン・信号・チャンク・区切りとその台帳・埋め込み (前の世代の索引の分を含む)・想起への操作 (そのセッションの応答への操作と、そのセッションの往復を対象にした操作)・区切りの鍵を消す。単位は全件を導き直す (そのセッションだけを根拠とする単位は消え、ほかにも根拠がある単位は根拠が減る)。導き直すと今の値でなかった値が今の値に戻る組には、その値の `vks` で `end` を足す (§7.4)。後継でなくなって private でなくなる値には「この値だけ」の private を足す (§7.5) | v0.1 (ターン・信号) / v0.2 / v0.5 |
| 単位を忘れる (`/forget <番号>`) | 忘れるの指示 (と要るときは `end`、§7.4) を書く。根拠の発話の、根拠の文の中で値に一致する箇所を伏せ字にする (既定。§7.3)。すべての台帳を掃除し (§7.2)、全件を導き直す (忘れた値の単位は関門 8 で作られない)。伏せ字にしたターンから作った派生物 (チャンク・埋め込み (前の世代の索引の分を含む)) を消して、作り直しを裏の処理に回す。忘れた単位の鍵と掃除で除いた区切りの鍵を索引から除く。忘れた値は、後の呼び出しの候補になっても関門 8 で捨てる (§7.6) | v0.3 (v0.5 で台帳と導出に合わせた) |
| 単位を private にする (`/private <番号>`) | private の指示を書き、全件を導き直す。プロファイルと検索の鍵から外し、想起で添える往復の中の値を伏せる (§7.5)。消しはしない。`/private off <番号>` で解く | v0.3 (同上) |
| 全消去 (`evorag reset`) | データ根を消す。設定は残す。`import-v04` の後の古い根の処分 (`--old`) と同じ実装 (03 §10.2) | v0.1 (v0.5 で古い根の処分を足した) |

- **古い根の処分を先に求める** (v0.5、ADR-0021 の決定 4、[OQ-54](10-decisions.md#oq-54-v05-の新しいデータ根と古いデータ根の扱い) の 5): `import-v04` で取り込んだデータ根で、古い根が残っている間 (`meta` の `import.old_root` が `kept`、03 §3.1.1) は、最初の忘れる (`/forget`) とセッションの削除 (`/delete`) を実行しない。確認の画面で、古い根に値が残ることを示し、「古い根を消してから続ける」と「やめる」だけを選ばせる (古い根を残したまま忘れる・消す選択は出さない)。古い根を消すのは 03 §10.2 と同じ関数で、画面から行える (07 §3)。取り込みの元の古い根には、取り込みの後の忘れる・削除が届かないため。処分の前に、取り込んだときの古い根の要約 (`import.source` の `journal.last_seq` とファイルの要約) と今の古い根を比べ、変わっていれば (取り込みの後に v0.4 で使った) 処分を断って、変わった件数と取り込み直しの案内を示す。確認の画面には、取り込みで除いたターンの件数 (`import.report`) も示す。手順と、途中で止まった処分 (`*.deleting-*`) の続きは 03 §10.2 (確定、2026-11-26)。

- **番号**: `/memory` が最後に表示した単位の一覧の番号 (07 §3)。出典の番号 (05 §5.1) と取り違えないように、`F1`・`F2` のように `F` を付けて示す (履歴の行は `H1`…、忘れた単位の一覧は `X1`…)。単位の ID は打たせない。番号は、その表示のときの一覧に結び付け、表示の後に裏の処理で一覧が変わっても、別の単位を指さない。番号と行の対応は画面が持ち、コアには行の参照を渡す。参照は、単位の ID と、指示と同じ鍵 (entity, 属性, 値の鍵) と、表示したときの状態の種類 (`Live`・`Contested`・`Superseded`) と時制で持つ。指した行が変わっていたら (導出で置き換わった・消えた。同じ単位が、表示したときの状態の種類と時制で今は無い)、「一覧が更新されました」と出して実行せず、同じ読み取りで作った新しい一覧を出す。根拠の増減、`against`・`by` の付け替え、private の印の変化は「変わった」に数えない (private は利用者自身の操作で変わるため。操作の前提が合わないとき (private でない行への `/private off` など) は、別の理由で断る)。
  - 番号を振る行: 辞書の属性の `world` では、今の値と `Contested` の値に加え、今の値が消えた属性 (§7.4) と、値が 1 つも無いが後継まで効く private の指示だけが残る属性にも、行として番号を振る (両方に当たるときは private の指示だけが残る行にする。履歴にはその行からも届く。予定の値だけがある属性には、今の値が消えた行を振らない。`Contested` があって今の値が無い属性には、`Contested` の行と並べて今の値が消えた行も振る) (前者から `/memory history` で履歴に届き、後者を `/private off` で解けるようにするため)。自由記述の属性の `world` の単位と出来事 (`episode`) は、置き換えが無いので、単位ごとに値の行として番号を振る (今の値が消えた行と履歴は作らない)。`/memory history <番号>` は、その行の (entity, 属性) の履歴を出す。`accept` は `Contested` の行にだけ、`/forget` は値の行 (今の値・`Contested` の値・自由記述の属性と出来事の単位) にだけ当てられる。
  - `/memory history` と `/memory forgotten` は、それぞれ自分の一覧の番号を持つ。番号は頭の `F`・`H`・`X` を省いてもよい (省いたときは、その命令が取る一覧の番号とみなす)。一覧をまだ出していないときに番号を打ったら、`/memory` を先に出すよう案内する。
  - 単位の一覧は、データ根の全体のものなので、セッションを開いていなくても出せる。前に見てから変わった行の印は、画面が前に出した一覧と比べて付ける (プロセスの間だけ覚える)。
- **確認の画面** (忘れる): 1 つの画面にし、既定のまま Enter で実行できる。対象の entity・属性・値と、伏せ字にする前と後の本文を 1 行ずつ見本として示す。次の選択は畳んで置く。
  - 出典の発話を伏せ字にするか、発話はそのままで単位だけを消すか。既定は伏せ字にする (確定 (ユーザー回答)、OQ-09)。
  - 選んだ値だけか、同じ (entity, 属性) の置き換えの履歴 (`Superseded` の値。時制を問わない。辞書の属性の `world` だけ) もまとめて忘れるか。既定は選んだ値だけ。`Contested` の値は履歴に含めない (その行を `/forget` で忘れる)。
  - 同じ往復の応答の中で、値の鍵 (§5.6) が一致する範囲も伏せるか (既定は伏せる。探し方は §7.3)。同じ往復の応答は、根拠の発話を `reply_to` に持つすべての応答 (中断・失敗を含む) で、本文の全体で探す。
  - ほかのターンで値の鍵が一致する範囲もまとめて伏せるか (既定は伏せない。探し方は §7.3)。ほかのターンは、すべてのセッションの利用者の発話と応答のうち、上の 2 つに入らないもの。件数を見本と一緒に示す。読めないターン (読めない記録・`v` が新しい記録) は探さずに飛ばし、その数を見本に示す (中止の理由にしない)。
  - 伏せ字にしないときも、後の 2 つの選択は効き、選んだ範囲を `[非表示]` の範囲 (§7.5 の `hidden`) にする (根拠の文に値の一致が見つからないときは、private と同じく、書記素の境界に広げた根拠の文の全体を `[非表示]` の範囲にする)。
  - 根拠のターンの根拠の文に値の跡がまったく無いとき (正規化 v1 でも照合の形 (§5.6) でも値の文字列が無い) は、値と根拠が食い違っているので中止する (F11)。値はあるが書記素の境界で切り出せないとき、または範囲がすでに伏せ字の印を含むとき (後から、影響を受けた単位を忘れる場合) は、そのターンを伏せ字にせず、見本に示す。応答 (echo) の中の読めないターンも、ほかのターンと同じく飛ばして数を示す。
  - 忘れる単位 (見本に示すもの) は、同じ entity の同値類 (§7.6) の単位のうち、値の鍵か照合の鍵 (§5.6) が `vks` にあるものすべてにする (辞書の属性では同じ属性のもの、自由記述の属性の指示では属性を問わない。§7.5 の `forget` の当て方と同じ。導き直すと関門 8 で消えるものと同じ結果にするため)。
- **見本と計画** (確定、2026-11-17): 見本はコアが作る (02 §3 の「忘れるの見本」)。コアは、対象と選択から、伏せ字にするターンと範囲・消える単位・足す `end`・掃除する台帳の要素の数・消す派生の記録の一覧 (計画) を、記録を変えずに作り、次を返す。画面は選択を変えるたびに求め直し、最後に求めたものだけを使う。見本の行は、変わる箇所の前後 24 字 (書記素の単位) を添え、1 行 120 字までに切る。伏せ字にできない (下の「中止」に当たる) ときは警告だけを返し、伏せ字にしない選択で求め直せば件数を示す。ほかのターンの一致はすべてのターンを読むので、裏のスレッドで探し、画面を止めない。
  - 伏せ字にする前と後の本文の見本、ほかのターンの一致の件数、まとめて忘れる履歴の件数、影響するほかの単位 (下) の行、伏せ字にしない出典のターン、飛ばした読めないターンの数、警告 (下の「中止」に当たること)、計画のハッシュ。
  - 計画のハッシュは、実行で変わるものだけを覆う: ターンごとの伏せ字の範囲と伏せ字の前の改訂の番号、消える単位 (まとめる履歴を含む)、足す `end`、影響するほかの単位。消す派生の記録の ID と、選んでいないほかのターンの件数は覆わない (裏の処理で派生の記録が増えても、見本を出し直さないため)。
  - 実行の命令は、見本の計画のハッシュを添える。コアは、書き込みの直前にロック (§7.2 の「ロックの順」) の下で計画を作り直し、ハッシュが違えば (見本の後に会話が増えた・裏の処理で単位が変わったなど) 実行せずに新しい見本を返す (利用者が見ていない範囲を伏せないため)。
- **影響するほかの単位**: 伏せ字にするターンのほかの単位で、値の範囲が伏せ字の範囲に掛かるもの (値の一部が伏せ字に掛かる) は、伏せ字の後の本文では関門 2 に通らないので、導き直すと消える (v0.4 までは span を写し直して事実を残し、取り消すかを利用者に選ばせていた。v0.5 は値を本文から導き直すので、掛かった値は残せない)。見本に、消える行 (entity・属性と、単位の一覧の番号) として示す。 伏せ字にしない忘れるでも、台帳の掃除 (§7.2。語句・部分文字列の鍵が `vks` に当たる要素) で消える単位は、同じく消える行として示す (確定、2026-11-26。事例 FG53)。値の範囲が掛からない単位は、台帳の位置を写し直して残る (§7.2 の「台帳の掃除」)。
- **中止**: 伏せ字にするとき、伏せ字にするターンが読めない (読めない記録・`v` が新しい記録) か、忘れる単位の根拠の改訂の番号が今のターンと合わないときは、操作の全体を中止し、本文も指示も変えない (§7.3 の値の鍵の検査と同じ扱い)。伏せ字は本文を解釈して書き換えるので、03 §4.2 の規則 6 の「本体を解釈せずにできる」に当たらない (削除と、伏せ字にしないで忘れるは、本体を解釈せずにできるので、新しい `v` のターンにも行う)。見本を作るときに同じ検査を記録を変えずに当てて警告に示し、伏せ字にしないで忘れる (単位だけを消す) ことを勧める。
- **受け付けないとき**: どれかのセッションで応答を生成している間は、忘れるを受け付けない (伏せ字にするターンや往復が生成の途中にありうるため。§7.7 の 3)。
- **伏せ字にしないで忘れたとき**: 根拠の発話は DB・ジャーナル・退避にそのまま残る。単位・プロファイル・検索の鍵からは消え (区切りの鍵は掃除する、§7.2)、想起で添える往復と帯に出す往復の中の値 (根拠の文の中で値に一致する箇所と、選んだときは同じ往復の応答とほかのターンで値の鍵が一致する範囲。上の確認の画面。探し方は §7.3) は、private と同じく `[非表示]` にする (§7.5)。**今のセッションの履歴** を chat に送るときも、その範囲を `[非表示]` にする (確定、2026-11-26。private は今のセッションのこれまでのやり取りに残すが、忘れたものは今のセッションの履歴でも伏せる。履歴の本文が変わるので、次の要求は先頭から処理し直す、§5.4)。確認の画面に、発話が残ることと、語彙とベクトルの索引に値の語が残ること (§7.8) を書く。
- 確認の画面には、約束する範囲 (§7.2) と約束しない範囲 (§7.8) を書く (畳んでよい)。private の確認の画面には、消しはしないこと、今のセッションのこれまでのやり取りには残ること (後で開き直したセッションも、そのやり取りは伏せずに送る)、伏せるのはプロファイルと検索の鍵と、単位の根拠の往復の中の値だけで、単位になっていない発言 (問い・仮定、まだ台帳を作っていないもの) や表記の違う書き方 (ひらがなとカタカナ、英数字やハングルの間の空白の有無 (「5 kg」と「5kg」) など、§5.6・§7.8) には効かないことを書く。漢字・かなに接する空白の有無だけが違う書き方 (「7 月 22 日」) には効く。
- **会話の中の依頼**: 利用者が会話の中で「忘れて」「覚えておいて」と頼んでも、モデルには記録を変える手段が無い。システムプロンプト (凍結の核) に、その依頼には `/memory`・`/forget`・`/private` を案内し、忘れた・覚えたと答えないことを書く。

### 7.2 即時に反映する範囲 (約束する範囲)

削除と忘れるの操作をしたら、書き手スレッドが **すぐに** 次から取り除く (確定 (ユーザー回答)、[OQ-09](10-decisions.md#oq-09-忘れるの約束の範囲))。順は、計画を作り直して確かめる (§7.1) → 飛んでいる先読みと、飛んでいる裏の LLM の要求 (B2・埋め込み・リランク) を止め、止まったことを確かめてから、先読みの世代の番号を上げる (確定、2026-11-26) → 下の表の `evorag.redb` とジャーナルの 1 つのトランザクション → コミットの直後に索引から除き、llama-server のスロットのキャッシュの消去を要求する → 退避の写し直し (提案書 §7.2)。

| 場所 | 取り除き方 |
|---|---|
| `evorag.redb` | 1 つのトランザクションで、指示 (忘れるでは `forget` と要るときの `end`、削除では要るときの `end` と後継の private) を書き、ターンの本文を伏せ字にして改訂の番号を上げ、すべての台帳を掃除し (下の「台帳の掃除」)、消す派生の記録 (下の「当て直しの一覧」の 4。削除ではそのセッションの区切り・台帳・チャンク・埋め込みなど) を消し、全件を導き直して単位と導出の指紋を書く。削除では、消した ID を退避の整理と索引の掃除の job (03 §7.3) に書く。忘れるでは、消した ID を索引の掃除の job (`purge_indexes`、§7.7 の 2) に、退避の写し直しを `forget_backups` の job (03 §7.3) に書く。検索の鍵 (§5.5) の索引の作り直しも job にする。同じコミットで `meta` の `compact.pending` を書き (03 §3.1.1)、次の起動時に compact する (03 §8) |

| 索引 | コミットの直後に、消した ID (伏せ字にしたターンのチャンク、忘れた単位と private にした単位の鍵、掃除で除いた区切りの鍵) を今の世代と前の世代のすべての索引から除く。除けなかった分は job に残して再試行し、`doctor` が報告する (§7.7)。読み出しの段階でも DB で確かめて除く。そのセグメントを優先して作り直す (セグメントの `header.json` に持つ ID の最小と最大から、対象を含み得るセグメントだけを選ぶ)。古いセグメントは参照が外れたらすぐ消す。消せないとき (Windows で写像したまま) は、読み手が入れ替わった後にもう一度消し、それでも残れば次の起動時に消す。残っている間は `doctor` が報告する。前のモデルの世代の索引 (05 §2.2) が残っていれば、それも同じく作り直すか消す |
| 退避 | 対象を含む退避を、対象を除いて写し直す (03 §7.3)。写しの中の台帳も、同じ掃除の関数で掃除してから写す。日次・週次と、移行と作り直しの前の退避 (03 §7.2) のすべて |
| `quarantine` | 対象の ID (伏せ字にしたターンと、消した記録と派生の記録) の記録を消す (隔離した原文に伏せる前の本文が残るため) |
| `broken/` | ファイルがあれば、実行の後に消すかを尋ねる (03 §8。中身を読まないので、伏せ字にはできない) |
| 想起の途中 | 候補を集めてから添えるまでの間に操作が入りうるので、添える直前と候補の帯に出す直前に、DB に無い記録 (と出典が DB に無いもの)、private の値、伏せ字の前の改訂の番号から作った派生物を、もう一度ふるい分ける (05 §3.4、[OQ-42](10-decisions.md#oq-42-先に済ませる処理と外へ出る経路電池) の 6)。先に済ませた処理 (05 §4.5) の結果と、問いの埋め込みのキャッシュ (05 §3.1) は捨てる |

| プロファイル | 次のターンで必ず作り直して差し替える (§5.4) |
| llama-server | 先読みと飛んでいる裏の要求を止めた後に、構成を見分けずに、応答 (`chat`) と `memory` の役割のモデルごとに、すべてのスロットについてキャッシュの消去 (`/slots/{id}?action=erase`、06 §4) を要求し、断られたら (既定の構成の 501 など) 無視する。消去の API は `--slot-save-path` 付きの構成でだけ使え、既定の構成では使えない。キャッシュは主記憶に llama-server を再起動するまで残りうるので、§7.8 の約束しない範囲に入れる (OQ-42 の 5、06 §4) |

- **台帳の掃除** (v0.5、提案書 §7.2。本節を正本にする。LLM を呼ばない純粋な関数。生きている DB・退避の写し (03 §7.3)・当て直し・台帳を書く前 (§4)・`doctor --deep` (03 §10.1) で同じ関数を使う。確定、2026-11-26): すべての選択の台帳について、次の要素を除き、除いた数を `scrubbed` に足す。伏せ字にしないときも掃除する。当たりの判定は §7.5 の「当て方の述語」を使う。
  - **対象のターン**: 伏せ字にしたターン、忘れた単位の根拠のターン、`[非表示]` の範囲 (`hidden`) を持つターン。台帳の `sentences` か `inputs` の `refs` にこれらのターンを含む区切りを「対象のターンを含む区切り」とする。
  1. 単位の候補のうち、`v` か `old` の一致 (関門 2 の照合) の範囲が伏せ字の範囲に掛かるもの (伏せ字の後の本文では値が無くなるため)。根拠の文に伏せ字が掛かるだけで、`v` と `old` が掛からない候補は残す (同じ文のほかの記憶まで消さないため)。
  2. 単位の候補のうち、`v`・`old`・`when`・`a`・`e` のどれかの、値の鍵か照合の鍵 (§5.6)、または語句か部分文字列 (書記素の境界で切ったもの) の値の鍵か照合の鍵が `vks` に当たるもの (entity と属性は問わない。台帳の中では、値の写しを残さないことを先にする)。
  3. 訂正の判定 (`corrections`) と候補の表 (`inputs` の `corr`) の要素のうち、候補の発話が対象のターンにあるもの、または `old`・`new` の範囲の文字列の値の鍵か照合の鍵が `vks` に当たるもの (§7.5 の「忘れると訂正」)。判定と表の要素は同じ `id` の組で除く。
  4. `keys` のうち、語句か部分文字列の値の鍵か照合の鍵が `vks` に当たるもの。加えて、対象のターンを含む区切り・`[非表示]` の範囲を持つターンの区切り・この掃除で 1 から 3 の要素を 1 つでも除いた区切りの台帳は、`keys` をすべて除く (鍵は LLM の言い換えなので、忘れた値を言い換えた鍵 (「大阪」に対する「関西の住まい」) は値の鍵では当たらないため。鍵は検索の補助なので、除いても会話は失わず、チャンクの索引で引ける。呼び直すと同じ区切りのほかの単位が揺れるので、呼び直さない)。
  - 要素を 1 つでも除いた台帳は、`inputs` の `input_hash` を null にする (伏せた値を、送ったメッセージのハッシュから総当たりで割り出させないため)。
  - 残った要素と `sentences`・`corr` の位置は、伏せ字の前の改訂の番号のものだけを、位置の写し直しの関数 (§7.3) で伏せ字の後の位置に直し、`sentences` と `refs` の `rev` を伏せ字の後の番号にする (台帳が有効なまま残り、区切りのほかの単位は LLM を呼ばずに残る)。
  - 区切りの鍵の埋め込み (§5.5) は (台帳の ID, 鍵の文字列の値の鍵) で指すので、`keys` の位置がずれても、残った鍵の埋め込みはそのまま使える。除いた鍵の埋め込みは消す (消す鍵は、掃除の前と後の台帳に区切りの鍵の検査を当てた結果の差で求める。§5.5 の「区切りの鍵の作り方の補い」、2026-11-28)。
  - 忘れるのたびに、種類 `proposal` の `quarantine` の記録 (隔離した台帳の原文) をすべて消す (中を読んで掃除できないため。その区切りは台帳が無いものとして呼び直す、03 §8)。
  - 掃除は指示の ID の順に当て、何度当てても同じ結果になる (除いた要素はもう無く、位置は改訂の番号で判定する)。台帳を書く前の掃除は、`forgets_seen` に関わらず、効いているすべての忘れるの指示で行う。
  - `unblock` で印を解いた忘れるの指示は、**根拠のターンの ID** が `unblock` の指示の ID より小さい要素に当て続ける (台帳がいつ作られたかに依らない。印を解いた後に言い直した値は覚えられ、解く前に言っていた値は戻らない)。単位の候補と訂正は根拠 (`s` の文・候補の発話) のターン、`keys` は区切りの最初の往復の発話のターンで比べる。
  - private は台帳を掃除しない (`keys` と単位は導出の時点でふるう、§5.5・§7.5)。
  - **掃除の補い** (2026-11-27。M5.2 で掃除の純粋な関数を書くときに決めた):
    - `scrubbed` は `output` の要素 (`keys`・`units`・`corrections` と、この版の知らない節の要素) の数で数え、`inputs` の `corr` の要素は数えない (事例 FG02)。`output` の要素か `corr` の要素を 1 つでも除いた台帳と、対象のターンを含む区切りの台帳は、`input_hash` を null にする (送ったメッセージに、忘れた値が入っていたため)。
    - 1 は、伏せ字の前の本文が手元にあるか (操作のとき) と、伏せ字の後の本文しか無いか (当て直しで、ターンがすでに伏せ字の後の本文になっているとき) に依らず同じ結果にするため、次の形で判定する: 根拠の文の改訂の番号がその伏せ字の前の番号で、根拠の文が伏せ字の範囲に掛かる候補のうち、伏せ字の後の本文 (前の本文しか無ければ伏せ字を当てて作る) に写した根拠の文 (§7.3) に、`v` か空でない `old` の一致 (正規化 v1 → 照合の形、語の境界を見ない部分一致) が無いもの。後の本文を作れない・写せないときは、根拠の文が伏せ字の範囲に掛かる候補を除く (安全の側)。値が伏せ字に掛かっても、同じ根拠の文のほかの所に同じ値が残る候補は残す (残った値は本文にもあるので、台帳だけに写しが残ることはない)。
    - 3 の範囲の文字列は、候補の改訂の番号の本文で見る。無ければ後の本文に写した範囲で見て、どちらも無ければ除く (確かめられない値の写しを残さない)。掃除には台帳の出典のターン (`sentences`・`refs`・`corr` のターン) の本文をすべて渡し、渡し忘れたターンがあれば誤りにして台帳を変えない (本文の渡し忘れで、要素を黙って除かないため。読めないターンは「本文が無い」として渡す)。
    - 2 の文字列には、型として読めた要素の型の項目 (`v`・`old`・`when`・`a`・`e`) と、知らない項目の名前と値の文字列を含める (文番号・列挙・番号の項目 `s`・`l`・`m`・`tn`・`id`・`verdict` は除く)。読むときの型に合わない要素と、この版の知らない節の要素は、中のすべての文字列 (map の項目の名前と CBOR の tag の中身を含む) で当てる。文字列を集められない要素は、当たったとみなして除く。並びでない節は節ごと除く。台帳の本体と入れ子の型 (`inputs`・`sentences`・`corr`・`refs` の要素) の知らない項目 (03 §4.2 の規則 7 で残すもの) も、名前と値の文字列が当たれば、その項目を除く。`output` の `invalid` の理由の文字列が当たれば、理由を固定の符号 `scrubbed` に替える。知らない節・知らない項目・理由で除いたものは、4 の「1 から 3 の要素を 1 つでも除いた区切り」には数えない。
    - 語句か部分文字列の鍵 (2・4、§5.5) は、正規化の後の長さが 256 文字以下の部分文字列だけで作る (忘れる値の長さの上限の最大 (辞書の属性の `max_chars` の最大 200 文字。自由記述の属性は 60 文字) に、NFKC で伸びる分の余裕 56 文字を足した値)。これより長く伸びる値の一致は約束しない (§7.8)。費用は 書記素の数 × 256 に比例する。
    - **掃除できない台帳**: 忘れるのたびに、型として読めない台帳 (§5.2.1 の「台帳の読み方」) と、`call` が `segment` 以外の台帳は、本体を生のまま走査し、どれかの文字列 (map の項目の名前を含む) の語句か部分文字列の鍵が、どれかの忘れるの指示 (印を解いたものを含む) の `vks` に当たれば、台帳を消す (`quarantine` の台帳と同じ扱い。その区切りは台帳が無いものとして呼び直す。消す実装は M5.4)。
- **まとめて写し直す**: 退避の写し直しは費用が大きい (10 万件で 1 世代 1.2〜1.4 秒、S-01) ので、続けてした操作をまとめ、対象を含み得ない世代を飛ばす。手順は 03 §7.3 を正本にする。写し直しを待つ間も、restore はジャーナルの操作を当て直すので (下)、忘れたものは蘇らない。
- **ジャーナルの書き直し**: 書き直すファイルの選び方・突き合わせ・取っ手の開き直し・失敗のときの再試行は 03 §6 を正本にする。
- **後の版の置き場所**: 学習の事例・辞書 (v0.7)、話題の群と見出し (v0.6・v0.7)、別名の鍵 (v0.7) などへの波及は、§7.9 の一覧に版ごとに足し、その版の判定に置き場所ごとの試験を入れる (08)。
- **ロックの順**: 忘れるは、セッションの削除と同じく、索引を書き換える経路の直列化を取ってから、単位を書く経路のロック (§5.2.1) を取る。逆の順で取る経路を作らない。計画を作り直してから (§7.1 の「見本と計画」)、書き手のコミットと索引から除くのを終えるまで放さない。
- **捨てるキャッシュ**: 忘れるでは、先に済ませた処理 (05 §4.5) の結果と、問いの埋め込みのキャッシュ (05 §3.1) を、どのセッションの分も捨てる (上の表の「想起の途中」)。
- **古い版の経路** (03 §4.2 の規則 12): v0.5 の根は v0.4 以前の版が書き込みで開かない (03 §12.4) ので、古い版が派生の記録を残したままセッションを消す経路は無い。規則 12 の突き合わせは、出典のセッションの無い区切りの台帳を消し、全件を導き直す (03 §4.2)。取り込みの元の古い根には、取り込みの後の忘れる・削除が届かない (処分を求める、§7.1)。
- 削除のときに退避から除く ID には、派生の記録の ID も入れる (03 §7.3)。
- **当て直し** (確定、2026-11-17): restore・repair・ジャーナルの取り込みは、退避の後にした削除・忘れるを、ジャーナルから必ず当て直す。起動時にも、忘れるの指示をすべて当て直す (書き直しの済んでいない分と、操作の途中の強制終了の分を含む)。
  - **当て直しの一覧**: 層ごとに判定する。ターンがもう伏せ字になっていても、2〜4 は毎回確かめる。どれも何度当てても同じ。
    1. ターンの本文: 下の核で伏せ字にする。
    2. 台帳と単位: すべての台帳を掃除し (上の「台帳の掃除」)、指示 (`end` を含む) と掃除した台帳から全件を導き直す (指紋が変わったとき)。
    3. 位置: 台帳の `sentences` と要素の位置のうち、改訂の番号が伏せ字の前の番号と同じものだけを写し直して (§7.3) 改訂の番号を伏せ字の後の番号にする。すでに伏せ字の後の番号のものには触れない。
    4. 消す派生の記録: 伏せ字にしたターンを出典とし、出典の改訂の番号が今と合わない派生の記録 (チャンク・埋め込み)、忘れた単位の鍵とその埋め込み、掃除で除いた区切りの鍵の項目とその埋め込み、伏せ字にしたターンの `quarantine` の記録。
  - **記録を変えたとき**: 当て直し (起動時・取り込み・restore・repair) が DB の記録を変えたら、同じコミットで、消した ID を `purge_indexes` の job に書き、その指示の `forget_backups` の job (03 §7.3) と `compact.pending` (03 §3.1.1) を書く。退避は job からだけ写し直す (起動時に退避を開いて中を確かめない)。
  - **伏せ字の行を先に書く**: 当て直しが生きている DB のターンを伏せ字にするときも、操作のときと同じく、伏せ字にしたターンの封筒の `put` の行を先にジャーナルに書いてからコミットする (03 §6 の順序)。
  - **起動の順** (03 §8): ジャーナルの取り込み → 開くときの削除 (03 §6) → compact → 書き手を作る → 忘れるの当て直し → 照会と命令の受け付け (compact はファイルを置き換えるので書き手の前に行い、当て直しで変えた分は次の起動で compact する)。当て直しを終えるまで、照会 (`/memory`・セッションのターンなど) も命令も受け付けない。sleep-time の前にも残りが無いかを確かめる。書き出しは、残りがあれば断る (03 §11)。
  - **ジャーナルの層の見つけ方**: 済んだかどうかの印を別に持たない。書き込みでデータ根を開くとき、ジャーナルを開く処理が、ターンの `put` の行の改訂の番号と、その行のあるファイルを ID ごとに集める (このプロセスで追記した行も足す)。書き直すファイルは、この集めた結果で選ぶ (ID の時刻では選ばない。古い版で後から足した行もあるため)。
  - ジャーナルの書き直しが入れ替えに失敗したとき (Windows でほかのプロセスが開いている) は、sleep-time に書き手スレッドの依頼として試し直す (03 §6)。残っている行の数は `doctor` と状態の行が示す (§7.8)。ジャーナルの層のための job の種類は足さない (ジャーナルと指示から、いつでも求め直せるため)。
- **`apply_forget` の分け方** (確定、2026-11-17): 忘れるの当て直しは、次の 3 つの層で作る。何度当てても結果が同じになる。
  1. **純粋な核** (`evorag-store` に置く。値の鍵を使わない): (本文, 今の改訂の番号, 1 つのターンの伏せ字の範囲と伏せ字の前と後の改訂の番号と後のハッシュ, 伏せ字の文字列) → 「当てた本文」/「当て済み」/「合わない」/「先の指示が要る」。改訂の番号の無いターンは 0 として読む。
     - 改訂の番号が伏せ字の後の番号と同じで、本文の SHA-256 がハッシュと合う → 当て済み。
     - 改訂の番号が伏せ字の前の番号と同じ → 範囲を伏せ字の文字列に置き換える。置き換えた本文のハッシュが合えば「当てた本文」、合わなければ「合わない」。
     - 改訂の番号が伏せ字の後の番号より大きい → 当て済み (後の忘れるが当たっている)。
     - 改訂の番号が伏せ字の前の番号より小さい → 先の忘れるが当たっていない。層は、同じターンの指示を指示の ID の順に、先のものから当てる。
     - それ以外 (改訂の番号が伏せ字の後の番号と同じで、ハッシュが合わない) → 合わない。
     - 値の鍵の検査 (§7.3) は操作のときだけに行い、当て直しでは行わない (ハッシュで確かめる)。
  2. **DB の層**: 核を、生きている DB と、退避を写した DB (写し直しの途中のもの) の両方に、同じ関数で当てる。同じターンには、生きている DB から読んだそのターンのすべての忘れるの指示を、指示の ID の順に当てる。合わないとき、または先の指示が無い・読めないとき:
     - 生きている DB: ジャーナルに、そのターンの、改訂の番号が伏せ字の後の番号で本文のハッシュが合う `put` の行があれば、それを当てる。無ければ本文を変えずに「合わないターン」とし、想起・候補の帯・裏の LLM の呼び出し (台帳の呼び出しと埋め込みを含む)・応答の要求の履歴と問いの文 (今のセッションのものを含む)・書き出しから除き、画面では本文の代わりに「本文を確かめられない」ことを示し、状態の行に示し、`doctor` が数える (関係の無い本文を失わず、伏せ字の前かもしれない本文も外へ出さないため)。`memory.forget_key` が使えないとき (03 §3.1.1) も、値の鍵の要らない層 (ターンの伏せ字とジャーナル) は当て、鍵の要る部分 (台帳の掃除の値の鍵による部分と導出) だけを飛ばして `doctor` が示す。
     - 退避の写し: そのターンを写しから除く (restore は、ジャーナルから伏せ字の後の行を足すので、伏せ字の本文で戻る)。
     - 上の一覧の 2〜4 は、本文の結果に関わらず当てる。派生の記録が出典の改訂の番号 (`src_rev`。台帳は `sentences` と `refs` の `rev`) を持つことに頼る (03 §3.3)。
  3. **ジャーナルの層**: その ID の、伏せ字の後の改訂の番号以上の `put` の行があるときだけ、それより小さい番号の行を除く (伏せ字の後の行が無ければ、何も除かない。DB の層が戻せなくなるため)。除く行の選び方は 03 §6。

### 7.3 伏せ字

- 伏せ字は、本文の範囲を固定の印 (`ja` は `[伏せ字]`、`en` は `[redacted]`。プロンプトの言語で選ぶ) に置き換える。データ根にプロンプトの言語の記録が無い、または知らない値のときは、伏せ字に合うかの判定 (書き出し・`doctor`・当て直しの合否) では、どちらの印でも合うとみなし、新しく伏せ字にする (当て直しを含む) ときは、設定の `prompt.language` の印を使う。伏せる範囲は、単位の根拠の文 (§5.1 の `anchors`) の中で、値の鍵 (§5.6) が忘れる値と一致する箇所に加え、根拠の発話の中で根拠の文の外にある一致する箇所にする (既定。応答 (echo) と同じく選択で外せる。根拠の外に同じ値があると、伏せ字にしても根拠の本文に値が残るため)。根拠の文の全体は伏せない (周りの文を残すため)。一致する箇所は、正規化 v1 で一致する範囲を先に採り、照合の形 (§5.6) では、それと重ならない一致だけを足して探す (§5.6 の「照合の順」。利用者や応答が漢字・かなの間の空白を変えて書いた写しを残さないため)。同じ往復の応答とほかのターンの範囲 (§7.1) も同じに探す。範囲は保存した本文の UTF-8 のバイト位置で持ち、書記素の境界 (結合文字・異体字セレクタ・ZWJ の並びを分けない) に合わせる。
- **書記素の境界と値の鍵の検査** (確定、2026-11-17): 値の鍵の検査 (次の項) は、値に一致した範囲 (境界に広げる前) で行い、記録して置き換える範囲は、その両端を書記素の境界まで広げたものにする (広げた範囲で値の鍵を取ると、結合文字などが付いて一致しなくなるため)。
- 置き換える前に、範囲の文字列の値の鍵か照合の鍵 (§5.6) のどちらかが、忘れる値の鍵 (指示の `vks` のどれか、§7.5) と一致することを確かめる。1 つでも合わなければ、その忘れるの操作の全体を中止し、本文も指示も変えずに理由を示す (関係の無い本文を失わず、単位だけが消えて発話が残る中途半端な状態も作らないため)。ほかの中止の理由は §7.1 の「中止」。
- ターンは改訂の番号 (任意の項目、03 §3.3) を持ち、伏せ字にするたびに上げる。当て済みかどうかは、改訂の番号と伏せ字の後の本文のハッシュで判定する (伏せ字の前の本文のハッシュは持たない。伏せ字の後の本文に値の候補を入れて照合すれば、値を当てられるため)。
- **範囲・改訂の番号・ハッシュ** (確定、2026-11-17): 1 回の忘れるの操作は、1 つのターンの改訂の番号を、範囲がいくつあっても 1 だけ上げる。範囲は伏せ字の前の本文 (伏せ字の前の改訂の番号) の位置で持ち、始まりの順に並べ、重なる範囲と接する範囲 (前の範囲の終わりが次の範囲の始まりと同じ) は 1 つにまとめる (印が 1 つになる)。ハッシュは、そのターンのすべての範囲を置き換えた後の本文の SHA-256 にする。伏せ字の一覧 (§7.5) は範囲ごとに 1 つの要素を持ち、同じターンの要素はすべて同じ伏せ字の後の改訂の番号とハッシュを持つ。
- **位置の写し直し** (確定、2026-11-17): 伏せ字の前の位置を後の位置に直すのは、1 つの関数で行う。1 つの指示の 1 つのターンの範囲 (まとめた後のもの) について、位置との比べは伏せ字の前の位置で行う。位置 p は、p 以前に終わる範囲 (終わり ≦ p) の (範囲の長さ − 印の長さ) の和だけ前へずらす。範囲の内側 (始まり < p < 終わり) の p は、始まりの位置なら印の始まりへ、終わりの位置なら印の終わりへ寄せる (範囲の始まりちょうどの p は、その範囲ではずらさない)。指示が 2 つ以上あれば、指示の ID の順に、1 つずつ当てる (次の指示の範囲は、前の指示の後の本文の位置で書かれているため)。改訂の番号が、その指示の伏せ字の前の番号でない位置は写さない (§7.2 の「当て直しの一覧」の 3)。
  - 使うところ: 台帳の `sentences` と要素の位置と貼り付けの範囲 (伏せ字と同じトランザクションで写す)、`[非表示]` の範囲 (§7.5 の `hidden`) と、private・採る・戻すの指示の根拠の位置 (どちらも指示は書き換えず、読むときに、その指示より後の忘れるの伏せ字で写す)、当て直しの DB の層 (§7.2)。
  - `[非表示]` の範囲が後の伏せ字の範囲に重なるときは、写した範囲 (印を含む) を伏せる。
- 裏の処理の結果は、入力の改訂の番号が今と合わなければ捨てる (§4)。ターンの付帯の項目 (観測値など) を更新するときは、書き手のトランザクションの中で記録を読み直してから書く (外で読んだ本体を丸ごと書き戻さない)。
- 伏せ字で本文の長さが変わったら、同じトランザクションで、同じターンを指す台帳の位置と貼り付けの範囲を写し直し、その改訂の番号を新しい番号にする (§4 の「改訂の番号が合わなければ捨てる」と台帳の有効性 (§5.2.1) に当たらないようにするため)。
- ターンの `v` は上げない (改訂の番号は任意の項目、03 §3.3)。
- 伏せ字の印について、システムプロンプト (凍結の核) に「利用者が伏せた部分で、推測も言及もしない」と書く。画面では、伏せ字と `[非表示]` を本文と見分けられる表示にする。
- **画面への印の範囲** (確定、2026-11-17): コアは、セッションのターンの照会 (02 §3) に、本文 (保存したまま。変えない) と一緒に印の範囲の並び (範囲と種類) を添える。範囲は今の本文の UTF-8 のバイト位置で、書記素の境界にある。種類は 2 つ: 伏せ字 (本文のその範囲がすでに印の文字列) と `[非表示]` (本文には値が残っていて、画面が表示するときにその範囲を `[非表示]` の印に置き換える。画面の印の文字列は画面の言語の文言で描く)。忘れた後は、開いているセッションの変わったターンを、印を添えた照会の結果としてイベントで送り、画面は本文と印だけを置き換える。そのターンを候補の帯に持つ応答の帯も、同じく送り直す。忘れるの途中 (計画から書き終えるまで) は、発話・作り直し・先に済ませる処理を受け付けない (§7.7 の 3)。範囲は、忘れるの指示の伏せ字の一覧と `hidden` から、上の「位置の写し直し」で求める。開いているセッションのターンに伏せ字か `[非表示]` の範囲ができたら、セッションと対象のターンをイベントで知らせ、画面はそのターンを読み直す (07 §2.1)。

### 7.4 削除と置き換えの連鎖 (`end`)

- 置き換えの連鎖の新しい側が消えたとき (セッションの削除・忘れる) は、古い側の値を今の値に戻さない (確定 (ユーザー回答)、[OQ-49](10-decisions.md#oq-49-置き換えの連鎖の新しい側が消えたとき))。古い値を今の値として添えてしまうため。全件の導出では、消えた値の候補が無くなるので、そのままでは古い値が今の値に戻る。そこで、消えた位置でその値を終える出来事を、指示 `end` として足す (提案書 §7.1。v0.4 までの `Retracted` と繰り上げの規則を、値の文字列を持たずに表す)。
- **`end` の形** (確定、2026-11-26。OQ-49 の改訂): `end` は、entity (正規化した文字列と、生の文字列)、aspect (辞書の属性の名前か、自由記述の属性の `aspect_mac`)、終える位置 (ターンの ID)、**終える値の `vks`** (値の鍵と照合の鍵。値の文字列は持たない) を持つ。
- **`end` を足すとき**: 忘れる・削除の計画 (§7.1) で、対象を除いて導き直した結果と今の結果を、自由記述の属性を含むすべての `world` の (entity, aspect) ごとに比べる。「導き直すと、今 `Live` でない値が `Live` になる」組があれば、その組の、その値の `vks` で `end` を足す。終える位置は、その組で除いた候補の根拠のうち最も新しいターンにする。位置が決まらない (除いた候補の `turns` がすべて消えた) ときは、`end` の指示の ID を位置にする。操作と同じトランザクションで足す。足した後にもう一度導き直して比べ、まだあれば繰り返す (組ごとに、除いた候補の数で止まる)。今の値を過去形・否定で終えていた組で、終えた発言だけが消えたときも、同じ比べで `end` が足される (終えた値を今の値に戻さない)。
- **組の欠けた `end`** (v0.5、03 §6 の「組の行」): ジャーナルの忘れるの組で `forget` の指示の行はあるが `end` の行が欠けた (壊れた) ときは、取り込みは読める行を当て、その組の記録の ID を `meta` の `journal.partial_groups` に残す。導出の前に、その忘れるについて `end` を計画し直して足す (上の「`end` を足すとき」と同じ比べ。M5.4 で入れる)。
- **`end` の当て方** (導出、§5.3): 入力の順の中で、終えた位置のターンの候補の後に当てる。entity は、`end` が持つ生の文字列を今の規則 (正規化 v1 と主語を明示する語、§5.1) で解き直してから比べる (辞書の版を上げたり `subject_self` の語を足したりして組が変わっても、前の値が戻らないため)。その時点で、その (entity, aspect) の `Live` のうち、値の鍵か照合の鍵が `end` の `vks` に当たるものだけを `Superseded` (`by` なし) にする (多値の属性で兄弟の値を巻き込まない。単値の属性の予定 (`planned`) の枠も同じ規則で当てる)。単値の属性でその値が今の値なら、その組は「今の値なし」になる。残った `Contested` の `against` は終えた値を指したままにする (§5.3)。
- `end` の後の候補は、今の値が無ければ、置き換えの条件に依らず `Live` になる。`end` の後に言い直された `Contested` の値も、その言い直しで `Live` になる (§5.3 の「同じ値」。v0.4 までの「消えた値より新しい `Contested` を繰り上げる」の後継)。`end` の前にしか根拠の無い `Contested` は `Contested` のまま残る (利用者が `/memory accept` で採れる)。
- 出来事 (`episode`) は状態を持たないので、`end` を足さない。
- **`import-v04` の `end`** (確定、2026-11-26): 取り込みでは、写した忘れるごとに無条件に `end` を足さない。取り込みの最初の導出の後に、v0.4 で `Superseded` (か `Retracted`) だった値が v0.5 で `Live` になった組に、その値の `vks` で `end` を足す (`origin` は `import`)。v0.4 の状態の表は取り込みのときに新しい根の `meta` の `import.v04_ended` に写しておき、取り込んだターンの区切りの台帳がそろうまで、導出のたびに照らす (03 §12.4)。
- 利用者は `/memory` で、今の値が消えた属性と `Contested` の値を見て、次の操作で直せる (07 §3)。どちらも指示 (§7.5) として残し、導き直しても効く。
  - `/memory accept <番号>`: `Contested` の値を今の値にする。
  - `/memory revert <履歴の番号>`: 履歴の値を今の値に戻す。

### 7.5 指示 (`directive`)

利用者が単位にした明示の操作と、その結果として足す出来事は、単位とは別の正本の記録 (種類 `directive`) として持つ (提案書 §7.1)。ジャーナルには、新しい操作の行ではなく `directive` の `put` の行として書く (03 §6)。単位を導き直しても (台帳の作り直し・規則の版の変更・restore)、指示を当て直せば同じ結果になる (全件の導出、§5.3。v0.4 までの「作り直しで変わりうること」(忘れた値の時刻や順が残らない) は、`end` が終えた位置を持つので起きない)。

| `op` | 持つもの | 当て方 |
|---|---|---|
| `forget` | 忘れた値の値の鍵と照合の鍵の並び (`vks`。履歴もまとめたときはそのすべて。同じ鍵は 1 つにまとめる)、entity とその時点の別名、属性 (辞書の属性なら名前、自由記述なら属性の鍵 (§5.6))、忘れた単位の根拠のターンの並び (`turns`。`/memory forgotten` でセッションの題名を示すため)、伏せ字の一覧 (ターンの ID・伏せ字の前と後の改訂の番号・伏せ字の前の本文でのバイト範囲・伏せ字の後の本文の SHA-256。§7.3)、伏せ字にしないときに想起で `[非表示]` にする範囲 (ターンの ID・そのときの改訂の番号・バイト範囲。読むときに後の伏せ字で写す、§7.3)、履歴もまとめたか、伏せ字にしたか、値の鍵の正規化の版 | `apply_forget` (§7.2) と台帳の掃除。導出では関門 8 (§5.2) で、下の「当て方の述語」で当てる。値そのものは持たない |
| `end` (自動で足す) | entity (正規化した文字列と生の文字列)、属性 (辞書の属性の名前か `aspect_mac`)、終える値の `vks`、終えた位置 (ターンの ID。決まらなければ指示の ID)、きっかけ (忘れるの指示の ID。削除と取り込みでは null) | 導出で、その位置で、その組の `vks` に当たる `Live` だけを終える (§7.4) |
| `private` | 値の鍵と照合の鍵 (`vks`。確定、2026-11-26)、entity、属性、根拠の位置 (ターン・改訂の番号・値の範囲)、効く範囲 (後継まで / この値だけ)、値の鍵の正規化の版 | 導出で、値の鍵か照合の鍵 (`vks`) **か** 根拠の位置のどちらかで当たる単位に private の印を付ける。「後継まで」は辞書の属性だけ (自由記述の属性と出来事は「この値だけ」) |
| `private_off` | 対象の private の指示の ID | 印を外す。`/private off <番号>` は、その行に効いているすべての private の指示 (後継まで効くもの、その値だけのもの、削除で足したもの) を解く。ほかの行の印も外れるときは、確認の画面でその行を示す (履歴の値 (`Superseded`) で外れるものも、件数と行を示す) |
| `accept`・`revert` | 値の鍵、entity、属性、根拠の位置、値の鍵の正規化の版 | 導出の入力の順の中で、指示の ID の時点で、その値を今の値にする。単位は根拠の位置で探し、無ければ値の鍵で、同じ (entity, 属性) の競合の組 (`Contested` か履歴) にあるときだけ当てる。後から置き換えの条件を満たす値が来たら、通常どおり置き換える |
| `unblock` | 対象の忘れるの指示の ID | 根拠のターンの ID が `unblock` の指示の ID より後の候補には、その忘れるの指示を当てない。根拠のターンが前の候補と台帳の要素には当て続ける (台帳がいつ作られたかに依らない。確定、2026-11-26、§7.2) |

- **本体の形** (v1。最上位を平らにし、使わない項目は null か空の並びにする。本節を `directive` の本体の項目の正本にし、03 §3.3 は耐久性・関係・副索引だけを持つ。副索引は `vk` (`vks` の要素ごと)・`ent` (正規化した entity)・`turn`): 共通の項目は `op`・`entity`・`aliases` (entity のその時点の別名の並び。v0.5 は空。v0.7 から entity の別名の辞書、13)・`aspect` (辞書の属性の名前か null)・`aspect_mac` (自由記述の属性の鍵の 16 進か null)・`vks` (値の鍵と照合の鍵の 16 進の並び。区別せずに 1 つの並びに入れる)・`norm`・`at` (根拠の位置 `{turn, rev, start, end}` か null)・`unit` (参考の単位の ID)・`target` (解く相手の指示の ID)・`origin` (誰が足したか。`user` は利用者の操作、`delete` は削除で足した指示、`import` は `import-v04` で足した指示。無い・知らない値は `user` として読む)。`forget` は `turns`・`redactions` (`{turn, rev_before, rev_after, start, end, hash}` の並び。`hash` は 64 桁の小文字の 16 進)・`hidden` (`{turn, rev, start, end}` の並び)・`history`・`redact` を、`private` は `scope` (`successors`・`value_only`。無い・知らない値は `successors` として読む) を、`end` は `turn` (終えた位置)・`cause` (きっかけの指示の ID)・`entity_raw` (entity の生の文字列) を持つ (`end` の `vks` は終える値の鍵)。`import-v04` で足した `private`・`accept`・`revert` の `at` は、v0.4 の事実の出典の範囲にする (下の「取り込んだ指示の位置」)。`redactions` と `hidden` の位置は、それぞれ `rev_before`・`rev` の本文の UTF-8 のバイト位置。`import-v04` で写した指示 (03 §12.4) は `imported` を真にし、v0.4 の再び覚えない印 (`marks`) を持つ (当てるときは使わない、§7.6)。
- **追記だけ**: 指示は書き換えも削除もしない。解くときは、解く指示を新しく足す。
- **当てる時点**: 採る・戻すは、指示の ID の時点で 1 回だけ当てる出来事にする (§5.3 の入力の順。後から条件を満たす値が来れば置き換わるため)。`end` は終えた位置の時点の出来事にする。private・private の解除・忘れる・印を解くは、時点に依らず常に効く制約にする。
- **後継** (private の効く範囲): 同じ (entity, 辞書の属性) の単位のうち、根拠の最も新しいターンの ID が、private の指示の ID より後のもの (指示の後に言われた値)。導き直しても同じになるよう、記録した時刻ではなくターンの ID で比べる。最も新しい根拠で比べるので、台帳が遅れて古い根拠が足されても外れない。指示の前から知っていた値でも、指示の後に言い直されれば private になる (安全の側に倒す)。セッションの削除 (§7.1・規則 12 の突き合わせを含む) で根拠が外れて後継でなくなり、private でなくなる単位には、同じ依頼で、その値だけ (`value_only`) の private の指示を足す (`origin` は `delete`。消したセッションの言い直しで private になっていた値を、削除によってプロファイルに出さないため)。
- **解く指示の相手**: private の解除は private の指示だけを、印を解くは忘れるの指示だけを解く (種類の違う相手を指していれば当てない)。
- **`/private` を当てられる行**: 今の値と `Contested` の値の行 (`Contested` の値も添える文脈に出うるため)、自由記述の属性と出来事の単位の行。
- **忘れた単位の一覧**: entity・属性 (自由記述の属性は鍵しか持たないので「自由記述の属性」とだけ示す)・忘れた日時と、根拠のセッションの題名を示す。根拠のターンが無くなった分は、その数だけを示す。印を解いた指示は一覧から除く (伏せ字にしないで忘れた範囲の `[非表示]` は、印を解いた後も続く)。
- **private の理由の表示**: `/memory` の private の印は、利用者が選んだ値か、後継の規則で private になった値か、削除で足した指示で private の値かを見分けて示す (自分で選んでいない値に印が付く理由を示すため)。
- **戻すの重なり**: 単位の ID は中身から作るので、戻す値の単位は、置き換えられた同じ単位が今の値に戻る (同じ値の開いた単位が 2 件になることは無い)。
- **忘れるの指示と訂正・戻す**: 忘れるの指示は、候補だけでなく、検証済みの訂正の新しい値と、戻す値にも当てる (忘れた値を、訂正や戻すで蘇らせないため)。どれも、値の鍵と照合の鍵の両方で引く (§7.6)。
- **読んだ後に足された忘れる**: 台帳は、入力を読んだときに見えていた最新の忘れるの指示の ID (`forgets_seen`) を持つ (`doctor` の報告と調べものに使う)。台帳を書く前に (§4)、`forgets_seen` に関わらず、効いているすべての忘れるの指示で掃除してから書く (確定、2026-11-26。呼び出しの間に伏せ字にしないで忘れた値を、台帳に残さないため。伏せ字にしたときは、改訂の番号が合わないので書かずに捨てる)。当て直しも、すべての台帳を掃除する (掃除は何度当てても同じ)。
- **忘れると訂正** (確定、2026-11-17 の考え方を台帳に合わせた): 忘れるは、同じトランザクションで、台帳の訂正の判定と候補の表 (`corr`) のうち §7.2 の「台帳の掃除」の 3 に当たるものを除く (伏せ字にしないで忘れるときも除く。訂正の判定は値の文字列を持つため)。除いた判定は作り直さない: 指示の `turns`・`redactions`・`hidden` のターンからは訂正の候補を作らず (§6 の「候補を見つける時機」)、判定の結果が忘れた値なら `forgotten` で落とす (§6)。
- **知らない `op` の読み方**: 新しい版の指示は、当てずに数えて残す (`doctor` が報告する)。新しい版が忘れるの性質を持つ指示を足すときは、`op` を `forget` のまま項目を足す形にする (古い版でも、忘れるとして当たるようにするため)。

- **当て方の述語** (確定、2026-11-26): 忘れるの指示が候補・台帳の要素・単位に当たるかは、1 つの関数で判定し、関門 8 (§5.2)、台帳の掃除 (§7.2)、忘れるの計画 (§7.1)、`doctor --deep` の (3)・(4) (03 §10.1) で同じ関数を使う。当たるのは、相手の値の値の鍵か照合の鍵が `vks` にあり、相手の entity が指示の entity の同値類 (§7.6) にあるとき。辞書の属性の相手には、同じ辞書の属性の指示と、自由記述の属性の指示を当てる (属性も比べる)。自由記述の属性の相手には、属性を見ずにすべての指示を当てる (属性の揺れで当たらなくなるのを防ぐ。止めすぎは `unblock` で解ける)。印を解いた指示は、根拠のターンの ID が `unblock` の指示の ID より前の相手にだけ当てる (上の表)。`doctor --deep` が印を解いた指示まで見るのは、(1) 本文・(2) ジャーナル・(7) 退避だけにする (03 §10.1)。
- **取り込んだ指示の位置** (確定、2026-11-26): `import-v04` で写した `private`・`accept`・`revert` は、v0.4 の事実の出典の範囲を `at` に入れる (出典が 2 つ以上あれば、範囲を持つ出典のうちターンの ID の最も新しいもの。事実が無ければ null で、値の鍵だけで当たる、03 §12.4)。取り込んだ指示に限って、根拠の位置の当たりを「範囲が重なれば当たる」にする (v0.5 の文の分け方と値の範囲は v0.4 の事実の span と一致しないため)。取り込みの最初の導出の後に、どの単位にも当たらなかった取り込みの private を、`doctor` と `/memory` で示す (利用者が private にし直せるように)。
- どの指示にも、操作したときの単位の ID を参考の情報として持たせてよい。当てるときは使わず、鍵 (entity・属性・値の鍵) と根拠の位置で当てる (単位の ID は中身から作るが、辞書の写しや entity の別名で中身が変わりうるため)。
- **private の効く範囲** (確定 (ユーザー回答)、[OQ-47](10-decisions.md#oq-47-private-の効く範囲)): 既定は、指定した値と、同じ (entity, 辞書の属性) にあとで入る値 (後継) の両方にする。後継には、置き換えた値に限らず、多値の属性であとで並べて足した値も含む。機微になりうる値 (食べないもの、家族のことなど) で、新しい値が private でないまま入るのを防ぐため。確認の画面で「この値だけ」も選べる。
- **想起での private**: 往復の原文を添えるとき (OQ-36 の 7)、private の単位の根拠の文の中で値に一致する箇所と、同じ往復の中で値の鍵が一致する範囲 (どちらも §7.3 と同じく、正規化 v1 の一致を先に採り、照合の形 (§5.6) で重ならない一致を足して探す) を、`[非表示]` (`en` は `[hidden]`。プロンプトの言語で選ぶ) に置き換えてから添える (同じ往復の中を値の鍵で探すのは、その単位の根拠のどれかの改訂の番号が今のターンと合うときだけ。根拠の文の中に値の一致が見つからなければ、根拠の文の全体を伏せる。リランクに渡す本文にも当てる)。往復の全体は除かない (ほかの話題を落とさないため)。学習の事例 (v0.7) にも同じ置き換えを当てる。
- **当て方の補い** (確定、2026-11-26。M5.0 の試験の材料 `tests/memory-cases/v0.5/` を書くときに決めた):
  - **自由記述の属性の private**: 忘れるの当て方の述語 (§7.6) と同じく、自由記述の属性の private は属性を見ない。値の鍵か照合の鍵 (`vks`) か根拠の位置で当てる (事例 DR01)。
  - **辞書の写しの後の `end`**: 辞書の版を上げて自由記述の属性が辞書の属性に写っても、`end` は、写す前の候補の自由記述の属性の鍵 (`aspect_mac`) とも比べて当てる (`entity_raw` を今の規則で解き直すのと同じく、組の解き方が変わっても前の値が戻らないため。事例 DR02・FG24)。
  - **private の値の鍵の当たり** (2026-11-27。M5.2): private の値の鍵か照合の鍵 (`vks`) での当たりも、entity の同値類と属性を、忘れるの当て方の述語と同じ形で比べる (辞書の属性の指示と辞書の属性の単位のときだけ属性を比べ、どちらかが自由記述の属性なら属性を見ない)。
  - **指示の entity の解き直し** (2026-11-27。M5.2): どの指示 (忘れる・private・採る・戻す・`end`) の entity と別名も、書いたときの形と、今の規則 (正規化 v1 と主語を明示する語、§5.1) で解き直した形の両方を同値類に入れる (規則の版を上げて `subject_self` に語を足しても、前の指示が新しい候補に当たり続け、当たる相手の集合が縮まないため。§7.6)。相手の entity も今の規則で解いてから比べる。
  - **同じ忘れるを解く `unblock` が 2 つ以上あるとき** (2026-11-27。M5.2): ID の最も小さい `unblock` と比べる (最初に印を解いた時点の後の言い直しは、覚えてよいため)。
  - **解く指示の ID** (2026-11-27。M5.2): 解く相手より ID の小さい `unblock`・`private_off` (時計が戻ったときに書いたもの) は当てずに数える (忘れる自身の根拠まで解けないため)。
  - **項目を欠く指示** (2026-11-27。M5.2): 種類ごとに倒す側を決める。忘れると private は止めすぎる側に倒す: entity の無い指示はどの entity にも当て、属性 (`aspect`・`aspect_mac`) の無い指示は属性を見ずに当てる (private の「後継まで」も、どの辞書の属性の後継にも当てる。忘れるの止めすぎは `unblock` で、private は `/private off` で解ける)。`end`・採る・戻すで entity か属性を欠くものは、当てずに数える (止めすぎではなく、終えすぎ・採りすぎになるため。`doctor` が報告する)。`vks` の読めない要素 (64 桁の小文字の 16 進でないもの) と、`norm` が 1 でない指示も数える (読めた要素では当てる)。
  - **訂正の `forgotten`** (2026-11-27。M5.2): §6 の「判定の入力」の `forgotten` は、関門 8 の当て方の述語ではなく、`old`・`new` の値の鍵か照合の鍵がどれかの忘れるの指示の `vks` にあるかだけで判定する (entity と属性を問わない、広い側)。印を解いた指示は、候補の発話のターンの ID が `unblock` の指示の ID より前のときだけ当てる。

### 7.6 再び覚えない印

忘れた値を、次の呼び出しや導き直しで再び覚えないための仕組み (確定 (ユーザー回答)、[OQ-48](10-decisions.md#oq-48-忘れた事実を再び覚えない印))。v0.5 からは、忘れるの指示の `vks`・entity・属性で当てる (関門 8、§7.5)。

- 伏せ字にした発話からは、値が消えているので再び候補にならない (関門 2)。そのため当て方が要るのは、伏せ字にしないことを選んだときと、同じ値を別のターンで言っていたとき。
- 値の鍵と照合の鍵は、データ根ごとの乱数の鍵 (`meta` の `memory.forget_key`。作る時機と探し方は 03 §3.1.1) による HMAC-SHA256 で作る (§5.6)。値だけのハッシュにしない (短い値は辞書で戻せるため)。辞書の属性では属性も比べ (別の属性の同じ値まで止めないため)、自由記述の属性では属性を見ない (属性の揺れで忘れた値を覚え直さないため、提案書 §7.1)。
- **entity の同値類**: 正規化 v1 か照合の形 (§5.6) で同じ呼び名と、主語を明示する語を `self` とみなしたもの (§5.1) に、指示が持つその時点の別名 (`aliases`) を足したもの。v0.7 で entity の別名の辞書 (13) を足すと広がる。指示の `aliases` は書いたときのまま残るので、辞書を巻き戻しても縮まない (辞書の採用の前後で、指示が当たる単位の集合が縮まないことを確かめてから採る、提案書 §9.5)。
- 忘れるときは、値の鍵に加えて照合の鍵 (§5.6) も `vks` に入れる (2 つが同じなら 1 つ)。当てるとき (関門 8・訂正の新しい値・戻す値・台帳の掃除) は、相手の値の値の鍵と照合の鍵の両方で引き、どちらかが `vks` にあれば当たったとみなす (「7月22日」を忘れた後に「7 月 22 日」から覚え直さないため、またその逆)。
- 照合の鍵は、この規則を足した後 (2026-11-18) の忘れるから `vks` に入る。それより前に作った忘れるの指示は値の鍵だけを持ち、足し直さない (v0.3 のリリースの前の、開発中のデータだけのため。`import-v04` でもそのまま写す)。
- **v0.4 までの印** (`marks`。(主語, 属性, 値の鍵) の HMAC、§5.6): `import-v04` で写した指示に残すが、当てるときは使わない (同じ主語・属性・値の鍵なら、`vks` と entity と属性の当て方でも当たり、こちらの方が広く当たるため)。
- 鍵はデータ根と退避の中にあるので、データ根を手に入れた者は値を推測して照合できる。これは約束しない範囲に書く (§7.8)。鍵を消すことで消す方式は OQ-27 で扱う。
- 関門 8 (§5.2) で当たった候補は、黙って捨てて数える (値を画面にも出さない)。利用者がまた覚えさせたいときは、`/memory forgotten` の一覧 (entity・属性・忘れた日時・根拠のセッションの題名を示し、値は出さない) から `/memory unblock <番号>` で印を解く (07 §3)。

### 7.7 消した記録を読み出しで除く仕組み

消した ID を残す専用の種類 (以前の版の仕様の `tombstone`) は持たない (2026-11-17)。古い版が消したものには残らず、伏せ字 (ターンの ID は残る) と `/private off` (同じ単位の鍵が戻る) には ID で拒む仕組みが効かないため。代わりに、次の 5 つで、消した・忘れた本文が蘇らないようにする。

1. **読み出しは DB で確かめる**: 派生の記録と索引の項目を読み出す経路はすべて、使う直前に、自分と出典が DB にあること、出典の改訂の番号 (`src_rev`・台帳の `sentences` と単位の `anchors` の `rev`) が今のターンと合うこと、単位なら private でないことを、DB で確かめる (許す一覧で判定する。今後足す経路 (学習の事例・カートリッジなど) も同じ)。書き出しは、台帳を private の値を含んだまま書く (利用者が自分のデータを持ち出す経路なので。単位は書き出さない、03 §11)。ほかの確かめ (DB にあること・改訂の番号) は書き出しにも当てる (書き出しはコアのメモリの層を通して確かめ、確かめられない派生の種類は書き出さない、03 §11)。
2. **索引からすぐ除く**: コミットの直後に、利用者に知らせる前に、消した ID を今の世代と前の世代のすべての索引から除く。除く対象の ID は、削除では退避の整理と同じ job (03 §7.3) に、忘れるでは索引だけの job (`purge_indexes`。退避は `forget_backups` の job が受け持つ) に、コミットと同じ依頼で書いて残す。除けなかった分 (強制終了・Windows の写像) は job から再試行し、索引と退避の両方が済むまで job を消さない。起動時の突き合わせで前の世代の索引から除けなかった行は、退避に触れない索引だけの job (`purge_indexes`) に残す (前の世代の行の ID は、生きている記録と同じ ID のことがあるため)。終わるまで `doctor` が報告する。起動時の突き合わせ (DB に無い項目を除く) も、すべての世代の索引に当てる。
3. **書き戻させない**: 書き手は、ジャーナルの削除の行 (開くときに集める) とこのプロセスで消した ID の記録を、`put` で作り直さない (古い封筒を書き直す経路で、消したものが蘇らないため。同じ依頼の中で消してから作るのも許さない)。ジャーナルの取り込みも、削除の行のある ID の `put` を当てない (03 §6、§4.2 の規則 0)。ただし単位 (`unit`) は、中身から ID を決める派生の種類なので、この規則の外にする (確定、2026-11-26。忘れた値の単位は関門 8 で作られないので、同じ ID が戻るのは同じ中身を導き直したときだけ。03 §4.2 の規則 0 の例外)。ターンの本文と改訂の番号は、書き手のトランザクションの中で読み直してから更新する (§7.3)。削除は、そのセッションで応答を生成している間は受け付けない。忘れるは、どれかのセッションで応答を生成している間は受け付けない (§7.1。伏せ字にするターンはどのセッションにもありうるため)。
4. **派生物は出典を確かめてから書く**: 派生の記録 (チャンク・埋め込み・区切り・台帳・単位) を作る手順は、書く前に、書き手のトランザクションか単位を書く経路のロック (§5.2.1) の下で、出典が DB にあり改訂の番号が読んだときと合うことを確かめ、合わなければ書かない。複数のターンを出典とする台帳は、`sentences` と `refs` に出典ごとの改訂の番号を持ち、書く前に効いているすべての忘れるで掃除する (§7.5)。
5. **退避と整理を直列にする**: 退避を作る処理と退避の整理は同じ順序で通す。整理の job を書いた後に作り終えた退避も、整理の対象にする。開けない退避があれば job を残して再試行する (03 §7.3)。

- 忘れるの `directive` (`forget` と `end`) とジャーナルの削除の行が、消した・忘れたものの永続する記録になる (restore・repair・ジャーナルの取り込みは、ここから当て直す、§7.2)。

### 7.8 約束しない範囲 (確認の文言に書く)

- 利用者が書き出したファイル、OS のバックアップ (ファイル履歴、Time Machine)、SSD の物理的な消去、llama-server のログ (`-v` など)、llama-server が主記憶に持つプロンプトのキャッシュ (llama-server を再起動するまで残りうる、OQ-42 の 5) とスロットの保存 (`--slot-save-path`)、`llm.allow_remote` の構成で外の機械に渡った呼び出しの入力 (06 §9)。
- 取り込みの元の古い根 (`import-v04`、03 §12.4): 取り込みの後に忘れた・消したものは、処分するまで古い根とその退避に残る (取り込みの後の最初の忘れる・セッションの削除の前に処分を求める、§7.1)。
- 次の起動時の compact までの間、DB のファイルの空きの領域に残る消した記録。空きが足りず compact できないときは、次の起動時にやり直し、それまで `doctor` と状態の行で知らせる (03 §8)。Windows で消せずに残った索引のセグメント (次の起動時に消す)。
- ジャーナルの書き直しが入れ替えに失敗している間 (Windows でほかのプロセスがファイルを開いている): 伏せ字の前の行がジャーナルに残る。試し直して入れ替わるまで、`doctor` と状態の行で知らせる (§7.2)。
- 消すかを尋ねて残した `broken/` のファイル、ファイルシステムのスナップショット (ZFS・Btrfs・ボリュームシャドウコピーなど)。
- `/bad` に添えた理由の文 (信号の記録、03 §3.3) は、忘れるの対象にしない (値を書いていれば残る。消すにはセッションを消す)。
- 伏せ字の印は固定の長さだが、伏せ字の一覧の範囲の長さ (バイト数) から、忘れた値の長さが分かる。
- セッションの題名: 忘れるは題名を伏せ字にしない (題名は利用者が付けたもので、値の鍵で探す範囲に入れない。題名に値を書いていれば残る。`/memory forgotten` は題名を示す)。題名を変えても、前の題名はジャーナルと退避に残る。消すには、セッションを消す。
- 言い換え: 区切りの鍵と自由記述の属性は LLM が書くので、忘れた値を言い換えたものは値の鍵では当たらない (§7.2 の「台帳の掃除」の 4)。忘れるの見本には、値の鍵で当たるものだけが出る。
- 呼び出しの最中の忘れる: 呼び出しの間に伏せ字にしないで忘れた値は、台帳を書く前に掃除するが (§7.5 の「読んだ後に足された忘れる」)、同じ呼び出しのほかの要素の言い回しには影響しうる。
- 忘れるの指示の `vks` から、値を推測して照合されうること (§7.6)。
- **Windows の貼り付け** (既知の穴、確定、2026-11-26): Windows の端末では貼り付けを見分けられない (§5.2 の前のふるい、S-16) ので、貼った文書の中の言い切りが、利用者の発言として単位になりうる。長い一度の入力からの候補は置き換えの条件を満たさない (`Contested` に留める、§5.3) が、今の値の無い属性では `Live` になりうる。02 §8 にも書く。
- 伏せ字にしないで忘れた値: 本文に値が残るので、そのターンのチャンクは作り直さず、語彙とベクトルの索引には値の語が残る (問いに当たって候補にはなりうるが、添える往復・候補の帯・今のセッションの履歴では `[非表示]` にする、§7.1)。消すには伏せ字にして忘れ直すか、セッションを消す。
- 長い部分文字列: 台帳の掃除と区切りの鍵のふるいは、正規化の後の長さが 256 文字以下の部分文字列の鍵だけで当てる (§7.2 の「掃除の補い」)。それより長く伸びる値 (NFKC で大きく伸びる文字を多く含む値) の一致は約束しない。
- 書き方の違い: 伏せ字・`[非表示]`・忘れるの指示が同じ値とみなすのは、値の鍵の正規化 (全角と半角・大文字と小文字・空白の連なりの長さ) か照合の形 (漢字・かなに接する空白の有無、§5.6) で同じになる書き方だけ。英数字どうしやハングルの間の空白の違い (「5 kg」と「5kg」)、ひらがなとカタカナの違い、言い換えは、同じ値とみなさない (伏せず、覚え直しうる)。
