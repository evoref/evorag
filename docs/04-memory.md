## 1. メモリとカートリッジ

evorag が応答に添える情報は、出どころで 2 つに分ける。

| | メモリ | カートリッジ (v0.5、[14](14-cartridge.md)) |
|---|---|---|
| 中身 | チャットの会話と、そこから作ったチャンク・ノート・事実 | 文書をまとめた、版のある束 |
| 誰のものか | 利用者とのやり取りそのもの | 外から持ち込んだ知識。配られたもの、または利用者が手元の文書から作ったもの |
| 変わり方 | 会話のたびに増え、sleep-time に統合される。訂正で置き換わる | 版ごとに中身は変わらない。更新は新しい版を入れて切り替える |
| 書き手 | 書き手スレッド (依頼は応答の経路と sleep-time から) | 導入と作成のときだけ (チャット中は読むだけ) |
| 応答での扱い | 「あなたについて覚えていること」「以前の会話」として添える | 「カートリッジ」として出典つきで添える |
| 消し方 | セッションの削除、事実を忘れる | カートリッジを無効化・削除する |
| 保存先 | `evorag.redb` | `cartridges/` (中身) と `evorag.redb` (導入の台帳) |

- 2 つは検索の部品 (05) を共有するが、索引も保存先も分ける。
- 利用者についての事実はメモリを優先し、一般の知識はカートリッジを優先する。両方が食い違うときは、両方を出典つきで添え、食い違うことを示す (05 §4.4)。
- **カートリッジからメモリへは何も書き写さない**。カートリッジの内容が利用者の事実として残ることはない。

## 2. 層

| 層 | 中身 | いつ書くか | 入る版 |
|---|---|---|---|
| セッション | 題名、モード、状態 | 作成・改名・削除のとき | v0.1 |
| ターン | 発話・応答の全文と付帯情報 (状態、model_key、生成の設定、添えたものの ID。v0.2 から観測値、05 §3.6) | 発話は送る前、応答は完了・中断・失敗のとき | v0.1 |
| 信号 | 評価・再生成の生の記録 (v0.3 から訂正の候補と検証の結果も) | 発生したとき | v0.1 |
| 想起への操作 | 候補の帯から添えた操作と、「無関係」の印 (05 §5.2) | 利用者が操作したとき | v0.2 |
| チャンク | 検索のためにターンを区切ったもの (05 §2.4)。本文は持たず、ターンの中の範囲を持つ | ターンの確定のとき (語彙の索引)、sleep-time (埋め込み) | v0.2 |
| ノート | 話題ごとの **検索の鍵** (数往復〜1 セッションの話題を表す短い語句)。その話題の往復の一覧を指す | sleep-time | v0.2 |
| 事実 | 利用者や関わる人・物についての事実 | sleep-time (書き込みの入口は 1 つ) | v0.3 |

- v0.1 では、語彙の索引 (05 §2.1) はターンを直接の単位にする。v0.2 からはチャンクと検索の鍵を単位にする。
- **往復**: 利用者の発話と、それへの応答の組。記録は持たず、ターンの `reply_to` から組み立てる。想起で添える単位にする (05 §3.3)。
- **ノートは検索の鍵にし、添えるのは原文にする** (確定、[OQ-36](10-decisions.md#oq-36-想起の規則-候補リランク添え方縮退) の 7): ノートは、問いと元の会話の語彙の違いを補うための索引の項目で、文脈には入れない。鍵で当たったら、鍵が指す往復をリランクして添える。要約が原文と食い違って誤りを持ち込むのを避けるため。
  - 1 つのノートは、1 つの話題の鍵の並びと、その話題の往復の一覧を持つ。索引の項目 (語彙とベクトル) は鍵ごとに作る。鍵で当たったときは、ノートが指す往復のそれぞれに、その鍵の値を付ける (05 §2.4 の「ターンの値」は、その往復のターンに付いた値の最良のもの)。
  - 1 つのノートの鍵は 8 個まで、1 つの鍵は 40 文字までにする。超える出力は切り捨てる。
  - ノートは、型縛りの補助の呼び出し (06 §6) で作る。鍵が出典の往復の本文に (正規化した上で) 含まれる語だけからなる必要はない (言い換えを補うため) が、命令形の文や URL を含む鍵は捨てる (02 §8)。
  - private の事実から鍵を作らない (v0.3)。
- **話題の区切り** (確定、2026-11-12。話題の推定に LLM を使わない。区切り方は派生の記録の作り方なので、`evorag rebuild` で作り直せる): セッションの往復を、古い順に先頭から詰めて区切る。
  - 往復は、利用者の発話と、それへの最新の完了した応答の組にする。完了した応答の無い発話は入れない。
  - 1 つの区切りは 8 往復まで、かつ鍵を作る呼び出しに渡す本文 (往復ごとに発話を 300 文字、応答を 500 文字までに切ったもの) が合わせて 1,600 文字までにする (1 往復は必ず入る)。裏の処理の要求を 2,048 トークンまでにする規則 (§4) に収めるため。
  - 区切りは、往復が 8 つになったか文字数が埋まったとき、またはそのセッションの最後のターンから 10 分過ぎたときに「区切りがついた」とする。
  - 区切りがついた後にセッションが続き、最後の区切りに往復が足されたら、その区切りのノートを作り直す (ノートの往復の一覧が区切りと違えば作り直す。古いノートと、その索引の項目と埋め込みは消す)。
- **鍵の検査** (決定論、`evorag-memory` に置く): 前後の空白を除き、40 文字を超える部分を切り捨てる。空のもの、URL (`://`・`www.`) を含むもの、命令形の文 (「ください」「しろ」「せよ」「無視して」、英語の `ignore`・`you must`・`please` など。一覧は `evorag-memory` に同梱し、プロンプトの言語に関わらず両方を当てる) を含むものを捨てる。重複を除き、9 個目からは捨てる。鍵が 1 つも残らないときは、鍵の無いノートを記録する (同じ区切りで呼び出しを繰り返さないため。索引の項目は作らない)。
- **鍵を作る呼び出し**: 型縛り (06 §6) で `{"keys": [文字列, …]}` を求める。temperature 0・固定の seed・裏の処理のスロット (06 §4) で出し、`llm.chat.aux_request_extra` を足す。点検 (06 §3.3) で型縛りか思考を切るのが通らなかった応答のモデルでは作らない (チャンクと埋め込みだけで動く)。点検がまだのモデルでは、点検を待つ。
- **ノートの版**: ノートは、区切りと鍵の作り方の版 (`rules`) と、作った応答のモデルの model_key を持つ。版が変わったら作り直す。応答のモデルを切り替えても作り直さない (鍵は検索の補助で、`evorag rebuild` で作り直せる)。
- **索引の項目の ID**: 語彙とベクトルの索引の項目は鍵ごとに作り、項目の ID はノートの ID にする (1 つのノートが鍵の数だけ項目を持つ。ノートを消すと、その ID の項目がすべて消える)。鍵の埋め込みの記録 (`embedding`) は、単位 `key` と鍵の位置 (0 から) を持つ。

## 3. 応答の経路での書き込み

1. 利用者が発話を送ると、まず発話のターン (状態「応答待ち」) を確定する (ジャーナル → DB、03 §3.4・§6)。確定に失敗したら、発話を入力欄に戻して知らせ、LLM に送らない。
2. 文脈を組み立てて (05) 生成を始める。
3. 応答は、完了・中断・失敗のいずれかの状態のターンとして書く。中断と失敗の応答も、受け取ったところまでの本文と理由を残す。
4. 応答の経路では、要約も抽出もしない。

- 入力欄の下書き (送る前の文章) は、所有者だけが読める一時ファイルに 5 秒ごとに保存し、次の起動時に戻す。外部のエディタで書いた一時ファイルも同じ置き場所に置き、送った後に消す。

## 4. sleep-time

利用者が操作していない間に進める裏の処理 (v0.2)。

- **起動後の点検** (確定、2026-11-12): モデルの性質の点検 (06 §3.3) とリランカーの較正 (05 §3.7) は、下の sleep-time の手順と分ける。入力が 2 秒途切れ (`idle_seconds` がそれより短ければその長さ)、応答を生成していない間に流し、`memory.sleep_time` と `idle_seconds` には縛らない (「TUI を開いた後に裏で、短い間に」済ませるため)。電池の設定の `stop` と空きの不足では止める。利用者が操作したら、下の「譲る」と同じく切り、次の機会に続ける (較正は済んだ問いの結果を覚えておき、続きから求める)。
- **繰り返しを防ぐ**: 終えたのにまだ要る手順 (結果を保存できなかったなど) と、失敗した較正は、5 分おいてから試し直す (繋がらないサーバや書けない DB に、要求を送り続けないため)。
- **外部のエディタ**: 利用者が外部のエディタで書いている間は、裏の要求を出さない (06 §4 の「入力している間は出さない」)。
- **アイドルの判定** (sleep-time の手順): 次のすべてを満たすときに始める。
  - キー入力が一定の時間 (既定 60 秒、設定 `memory.idle_seconds`) 無い。
  - 応答を生成していない。次のターンの分の先の処理 (05 §4.5) も終わっている。
  - llama-server の chat のスロットに空きがある (06 §4)。
  - 電池の設定 (`memory.on_battery`、07 §4.2) が止めていない。
- **譲る**: 利用者が操作したら (キー入力、発話の送信)、今の手順の LLM の要求 (chat・embed・rerank のどれでも) を 1 秒以内に止める (NFR-105、06 §4)。止めたところまでの結果は、作り直せるものだけを残す。
- **job による再開**: 各手順の進み具合は `job` の記録に残し、次の機会に続ける。強制終了の後も、起動してアイドルになったら続ける。ただし、進み具合を状態から求められる手順は job を書かない (2026-11-12): 埋め込み (手順 1) は「語彙の索引にあってベクトルの索引に無いチャンク」を 32 件ずつ埋め込み、記録と索引への反映を 1 回ごとに落とされない形で行うので、止めても強制終了しても、次の機会に足りない分から続く。ノート (手順 2) も、区切り (§2) と記録したノートを突き合わせて足りない分から作るので job を書かない (1 つのノートは 1 回の呼び出しと 1 回の書き込みで作る)。型が合わずにやり直しても合わなかった区切りは、このプロセスの間は飛ばす (job の代わり)。
- **要る作り直しは状態から求める**: job の記録は裏の処理の結果と同じく失いうる (ジャーナルに書かない、03 §6) ので、job が無いことを「作り直しが要らない」とみなさない。起動時に、軽い検査 (件数と、最後に処理した ID の比較。全件は走査しない、NFR-101) で次を確かめ、足りなければ job を作る。
  - チャンクの無いターン (古い版で足したターンを含む) が無いか。
  - 記録した埋め込みのモデルの索引が、すべてのチャンクと鍵を覆っているか。
  - ノートを作っていない区切りが無いか。
  - 記録したリランカーのしきい値があるか (無ければ較正を裏で流す、05 §3.7)。
- **冪等**: 各手順は **何度やっても結果が同じ** になるように作る。入力 (ターンの ID の範囲) と、手順の版と、使ったモデルの model_key を `job` に記録する。途中で止めてから再開しても、止めずに通したときと同じ結果になる。型縛りの呼び出しは temperature 0・固定の seed・固定のスロットで出す (06 §6)。
- 手順 (版):
  1. 新しいターンのチャンクの埋め込みを作る (v0.2。チャンクへの区切りと語彙の索引への追加は、ターンの確定のときに行う、05 §2.3)。
  2. 区切りのついた話題のノート (検索の鍵) を作る (型縛りの LLM の呼び出し、v0.2)。
  3. 利用者の発話から事実の候補を抽出する (型縛りの LLM の呼び出し、v0.3)。
  4. 訂正の候補を検証する (v0.3)。
  5. 事実を統合する (重複の除去、置き換え、矛盾の記録、v0.3)。
  6. 索引の新しいセグメントを作り、入れ替える (v0.2)。埋め込みのモデルを切り替えたときの作り直し (05 §2.2) もここで進める。
  7. 自動の退避 (03 §7.1、v0.2 から sleep-time で行う)。
  8. カートリッジの埋め込みの不足分を作る (v0.5)。
  9. 自己学習の手順 (13、v0.4)。
- 型縛りの補助の呼び出しを使えないモデル (06 §3.3 の点検で通らない) では、手順 2 を飛ばす (チャンクと埋め込みだけで動く)。
- 裏の処理の LLM の要求は、1 回に送るプロンプトを 2,048 トークン (暫定) までにする。長い入力は分けて送る。
- 裏の処理は、空きの不足 (03 §8)、設定 `memory.sleep_time = false`、電池の設定で止められる。止めても会話の保存と想起 (語彙の索引と、作ってある埋め込み) は動く。

## 5. 事実

### 5.1 事実の形

| 項目 | 内容 |
|---|---|
| `subject` | 誰・何についてか (既定は利用者本人) |
| `attribute` | 属性の名前。属性の一覧 (同梱の TOML、`evorag-memory/attributes.toml`) で、単値か多値か、値の長さの上限を宣言する |
| `value` | 値 (文字列。既定の上限 200 文字。型付きの値は v1.0 より後) |
| `valid_from` / `valid_to` | 現実で成り立っていた期間。分からなければ空 |
| `recorded_at` / `retracted_at` | 記録した時刻と、取り消した時刻 |
| `state` | `Live` / `Superseded { by, at }` / `Retracted { at }` |
| `source` | 出典のターンの ID の一覧と、古い値の位置 (span) |
| `private` | 応答に添えない印 (利用者が指定したもの) |

- 属性の一覧の初期内容は v0.3 の着手前に決める (確定、[OQ-12](10-decisions.md#oq-12-属性の一覧の初期内容))。一覧に無い属性の候補は捨てて数え、`doctor` が報告する (一覧を広げる材料にする)。

### 5.2 抽出と統合

- **抽出の出典は利用者の発話だけ** にする。応答・利用者が貼った引用 (コードブロック、引用の記号で始まる行)・カートリッジからは抽出しない (確定、[OQ-20](10-decisions.md#oq-20-事実を抽出してよい出典))。貼られた文書に埋め込まれた指示が、事実として信頼する枠に入るのを防ぐため (02 §8)。
- 抽出は型縛り (06 §6) で、属性は一覧の内側だけ、値は長さの上限の内だけを受け付ける。
- 抽出した値が出典の発話に (正規化した上で) 含まれない候補は捨てる (決定論の関門)。

### 5.3 置き換え

- **単値の属性**: 新しい値で古い値を `Superseded` にする。
- **多値の属性**: 古い値の位置が特定できたときだけ、その 1 件を置き換える。特定できなければ並べて足し、兄弟の値には触れない。
- **削除しない**: 置き換えた値も残す。「いつ何を言っていたか」に答えられ、誤った置き換えを戻せる。
- **書き込みの入口は 1 つ**: 事実を書く関数は `evorag-memory` の 1 つだけにし、畳みの規則と private の検査を必ず通す。

### 5.4 応答での使い方

- 文脈に添えるのは `Live` で `private` でない事実だけ (05 §4)。
- 事実は「データ」として、属性と値の表の形で文脈に入れる。値に指示に読める文 (命令形の文、他の指示への言及) を含むものは、表に入れずに捨てて数える。
- `private` の事実は、文脈・リプレイ (13) には渡さない。sleep-time の統合 (重複の判定と置き換え) にだけ渡す (同じ PC の llama-server の中で閉じるため、提案、[OQ-21](10-decisions.md#oq-21-private-の事実を裏の処理に渡すか))。

## 6. 訂正

- **候補**: 字句の規則 (「違います」「ではなく」「じゃなくて」など。規則は同梱の TOML) で見つけたものは、候補として `signal` に記録するだけにする (v0.1 から記録する)。
- **検証**: sleep-time に、型縛りの LLM の呼び出しで判定し、決定論の関門を通ったものだけを「検証済みの訂正」にする (v0.3)。
  - 関門: 訂正した語が発話に逐語で含まれる、向き (古い値 → 新しい値) が合っている、引用ではない。
- **型**: 候補と検証済みは別の型にし、事実の置き換えと学習 (13) には検証済みの型しか渡せない。

## 7. 忘れる・消す

### 7.1 操作と結果

| 操作 | 結果 | 版 |
|---|---|---|
| セッションの削除 (`/delete`) | ターン・信号・チャンク・ノート (検索の鍵)・埋め込み (前の世代の索引の分を含む)・想起への操作 (そのセッションの応答への操作と、そのセッションの往復を対象にした操作) を消す。そのセッションだけを出典とする事実も消す。他にも出典がある事実は、出典の一覧から外す。回帰台帳の事例と検索の事例のうち、そのセッションのターンを入力に持つものも消す | v0.1 (ターン・信号) / v0.2 / v0.3 / v0.4 |
| 事実を忘れる (`/forget <ID>`) | 事実を `Retracted` にして値を消す。さらに、出典の発話のうちその事実の部分を伏せ字にし (ターンの本文の該当の範囲を置き換える)、そのターンから派生したチャンク・ノート (検索の鍵)・埋め込み (前の世代の索引の分を含む)・事実の鍵を作り直す。同じ事実を再び抽出しない印を残す (値のハッシュだけを持つ) | v0.3 |
| 事実を private にする (`/private <ID>`) | 応答に添えない (§5.4)。消しはしない | v0.3 |
| 全消去 (`evorag reset`) | データ根を消す。設定は残す | v0.1 |

- 「忘れる」で出典の発話を伏せ字にするか、発話はそのままで事実だけを消すかは、確認の画面で選ばせる。既定は伏せ字にする (確定 (ユーザー回答)、OQ-09)。

### 7.2 即時に反映する範囲 (約束する範囲)

削除と忘れるの操作をしたら、書き手スレッドが **すぐに** 次から取り除く (確定 (ユーザー回答)、[OQ-09](10-decisions.md#oq-09-忘れるの約束の範囲))。

| 場所 | 取り除き方 |
|---|---|
| `evorag.redb` | 同じトランザクションで記録を消し、`tombstone` を書く。次の起動時に compact する |
| ジャーナル | 該当する月のファイルを書き直して入れ替える (03 §6) |
| 索引 | 消した ID を読み出しの段階で除き、そのセグメントを優先して作り直す。古いセグメントは参照が外れたらすぐ消す。前のモデルの世代の索引 (05 §2.2) と、v0.1 の索引 (`lex/`) が残っていれば、それも同じく作り直すか消す |
| 想起の途中 | 候補を集めてから添えるまでの間に操作が入りうるので、添える直前と候補の帯に出す直前にもう一度ふるい分ける (05 §3.4)。先に済ませた処理 (05 §4.5) の結果と、問いの埋め込みのキャッシュ (05 §3.1) は捨てる |
| 退避 | 対象を含む退避を写し直す (03 §7.3) |
| `quarantine` | 対象の ID の記録を消す |
| `broken/` | ファイルがあれば、消すかを尋ねる |
| llama-server | サーバが消去の API を持つ構成 (`--slot-save-path` 付き) のときだけ、スロットのキャッシュの消去を要求する。既定の構成では消去の API が無く、上書きした会話のキャッシュも主記憶に残る (S-13 §3) ので、§7.3 の約束しない範囲に入れる (06 §4) |

- restore と repair は、ジャーナルの操作の行から、退避の後にした削除・忘れるを必ず当て直す。古い退避から戻して、忘れたものが蘇ることはない。
- **派生の記録に届かない経路** (03 §4.2 の規則 12): 古い版 (v0.1.2 など) は、新しい版の種類 (チャンク・ノート・埋め込み・想起への操作) と索引を知らないので、セッションを消しても、それらを消さない。ジャーナルからの取り込みと restore も、消した記録そのものしか消さない。新しい版は、規則 12 の突き合わせで、出典の無くなった派生の記録を消し (退避からも除く)、必要なら索引を作り直す。それまでの間も、出典の無い派生の記録は、想起・`/memory`・書き出しから除かれる。
- 削除のときに退避から除く ID には、派生の記録の ID も入れる (03 §7.3)。

### 7.3 約束しない範囲 (確認の文言に書く)

- 利用者が書き出したファイル、OS のバックアップ (ファイル履歴、Time Machine)、SSD の物理的な消去、llama-server のログ (`-v` など)、llama-server が主記憶に持つ会話のキャッシュ (**llama-server を再起動するまで残りうる**、OQ-42 の 5) とスロットの保存 (`--slot-save-path`)。
- 古い版に戻して消したもの: v0.2 で使ったデータ根を v0.1.2 で開いて消したセッションは、v0.2 の派生物 (チャンク・ノート・埋め込み・`chunk-lex/`・`vec-…/`) と、その派生物を含む退避に、**v0.2 で開き直すまで残る** (v0.1.2 はそれらを知らないため)。v0.2 のリリースノートに書く。

### 7.4 tombstone

- 消した ID は `tombstone` に記録し、索引を作り直すまでは読み出しの段階で除く。`tombstone` は本文を持たない。
