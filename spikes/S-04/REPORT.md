# S-04 日本語の bi-gram の語彙の検索による想起の質 (技術検証)

| 項目 | 内容 |
|---|---|
| 検証 | 08 §3 の S-04 (合否: 想起の事例で、正しい以前の発言が上位 3 件に入る割合が 80% 以上) |
| 関わる仕様 | 05 §2.1・§3・§3.4、09 §5.2、AC-FR-402-1 / -2 |
| 実施 | 2026-11-09 |
| 再現 | `python -I s04.py --detail A` / `--detail K` (標準ライブラリだけ。出力は `results-A.md` / `results-K.md`) |
| 判定 | **仕様どおり (設定 A) は不合格。正規化と単位を 2 点直した設定 K で合格** (仕様を K に直す) |

## 1. 結論

- **仕様どおり (05 §2.1 のまま) では不合格**。recall@3 は全 34 件のうち 24 件 (71%)。言い換えは 13 件中 6 件 (46%) と弱く、ひらがなとカタカナの違い (「ニンニク」と「にんにく」) でも外れる。
- **2 点を直すと合格の水準になる**。直すのは (1) ひらがなとカタカナの統一、(2) 漢字 1 文字も単位に加えること。この設定 (K) では recall@3 が 31/34 (91%)、言い換えが 11/13 になった。しきい値を掛けて実際に添えるものに限っても 29/34 (85%)。
- **しきい値だけでは Abstain を確実にできない**。関係の無い問い 9 件のうち、Abstain になったのは良い設定でも 6 件だった。言い回し (「どのくらいの頻度ですればいい？」) や一般の語 (「毎日」「続ける」「少額」) が、別の話題の発言と重なるため。
- 勧める初期値: 内容の単位だけで取った比が **0.14** 以上で、かつ上位の最大の **0.7 倍** 以上のものを添える。

## 2. データ

- 作った会話だけを使った (`data/sessions.txt`)。22 セッション、308 ターン (利用者 154・応答 154)。各 7 往復。ID は `sNN-tMM` (奇数が利用者)。
- 話題の重なりと紛らわしい候補:
  - 旅行 3 つ (京都 s01・北海道 s02・沖縄 s03) と京都の歴史 (s21)
  - 料理 3 つ (カレー s04・食パン s05・作り置き s06)
  - 植物 2 つ (s07・s08)、冷蔵庫 2 つ (節電 s18・掃除 s22)、電池 2 つ (s09・s10)
  - ほかに引っ越し・確定申告・ランニング・睡眠・TOEIC・子猫・自転車・プレゼント・Python
- 事例: `data/cases.txt`。
  - 関係のある問い 34 件 (易しい easy 9、表記揺れ variant 12、言い換え para 13) と、関係の無い問い 9 件。
  - 調整用 28 件で改善案を比べて K を決め、そのあとで確かめ用 15 件 (H) を足して測った。
  - 正解はその話題の往復 (利用者の発話と応答) で、上位 3 件のどれかが正解なら「入った」と数えた。

- 調整用と確かめ用に分けた recall@3: A は 14/22 (64%) と 10/12 (83%)、K は 19/22 (86%) と 12/12 (100%)。
- 1 問あたりの時間は Python で 0.1〜0.2 ms (308 ターン)。
- K でも外れたのは、共通の文字が無い言い換えの 3 件 (「珈琲」と「コーヒー」、「眠れない」と「寝つけない」、「ふくらまない」と「発酵が進まない」)。これらは v0.2 のベクトルの検索と言い換えの評価の事例として残す。

## 4. しきい値

- **05 §2.1 の比** (全単位、K): 正解は中央 0.23 (0.05〜0.59)、不正解は中央 0.14 (0.07〜0.41)、関係の無い問いの上位 3 件の最大は中央 0.16 (0.10〜0.54)。値が重なり、分けられない。
- **内容の比** (案): 分子・分母とも、元の表記でひらがなだけではない単位で取る。順位付けは全単位のまま。

| t | 05 の比: 正解を添える / Abstain / 添えたもののうち誤り | 内容の比: 正解を添える / Abstain / 誤り |
|---|---|---|
| 0.12 | 30/34 / 3/9 / 48/92 | 29/34 / 6/9 / 37/80 |
| 0.14 | 30/34 / 3/9 / 34/76 | 29/34 / 6/9 / 28/70 |
| 0.16 | 26/34 / 5/9 / 23/58 | 28/34 / 6/9 / 21/59 |
| 0.18 | 24/34 / 7/9 / 16/49 | 26/34 / 7/9 / 17/52 |
| 0.20 | 19/34 / 7/9 / 12/37 | 22/34 / 8/9 / 13/44 |

- 「上位の最大の 0.7 倍未満を捨てる」を足すと (内容の比、t = 0.14)、誤りが 28/70 から 17/52 に減る。正解を添える数と Abstain の数は変わらない。
- 弱点: ひらがなだけの語でしか一致しない正解 (H12) は、内容の比が 0 になって添えられない。関係の無い問いの約 3 分の 1 には、何かが添えられる。

## 5. 限界

- 作り手が手法を知った上で事例を書いた (言い換えでも漢字が共通しやすい)。実際の問いより易しめの可能性がある。
- 308 ターンは小さい。規模による比の分布の変化と待ち時間は測っていない。しきい値は規模が変われば見直す。
- 追い質問と新しさは扱っていない。nDCG は出していない。

## 6. 仕様に直す点

1. 05 §2.1 の正規化に、ひらがなとカタカナの統一 (カタカナをひらがなに。「ー」は残す) を加える。
2. 05 §2.1 の単位に、漢字 1 文字を加える (bi-gram に足すもので、置き換えではない)。
3. しきい値の比は「内容の単位」(元の表記でひらがなだけではない単位) だけで取る。初期値は 0.14。05 §3.4 に「上位の最大の 0.7 倍未満は添えない」を加える。
4. 「記号の除去」は区切りとして扱い、数字の桁区切りの「,」だけを詰める (この事例では差は無かった)。1 文字の区切りはその字を単位にする。
5. 利用者の発話と応答の両方を索引に入れる (利用者の発話だけにする案に利点は無かった)。v0.1 はターンを単位のままにする。
6. 05 §3.4 の多様性は、下位を捨てるのではなく「1 つの枠として一緒に添える」と書く (捨てる実装では recall@3 が 91% から 88% に下がった)。
7. 08 §3・09 §5.2・AC-FR-402-1 の想起の事例を「30 件以上で、易しい・表記揺れ・言い換えをそれぞれ 3 割以上、合否は全体の 80%」に改め、関係の無い問いを 10 件以上置く。`data/` は `tests/retrieval/recall-v0.1.toml` の初版に使える。
8. 誤った想起は残る前提で、出典の画面での確認 (05 §5・FR-110) と信頼しない引用の枠 (05 §4.2) を v0.1 の必須として保つ。
