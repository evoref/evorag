# メモリの回帰ケース (09 §3.5、OQ-29)

事実の抽出・統合・訂正・忘れる・削除の波及について、入力 (作った会話と、固定した LLM の出力) と、期待する結果の組を置く。v0.3 の M3.1〜M3.4 の試験がこれを読む。

- 会話はすべて架空で、実在の人物・個人情報を含まない (11 §9.7)。
- 事例を足すときは、ここの書式に合わせる。形は `crates/evorag-memory/tests/memory_cases.rs` が検査する (属性の名前、参照するターンの ID、状態の名前、理由の名前、値の長さなど)。
- LLM の出力 (抽出の候補、訂正の検証) は、事例の中に固定して書く。LLM を含む抽出そのものは、記録と再生 (09 §3.3) で別に試験する。

## ファイル

| ファイル | 中身 | 仕様 |
|---|---|---|
| `prefilter.toml` | 前のふるい。発話を抽出に送るか | 04 §5.2 |
| `gates.toml` | 抽出の関門 1〜8。候補を受け付けるか、どの理由で捨てるか | 04 §5.1・§5.2 |
| `consolidation.toml` | 統合と、事実への操作 (private・削除・採る・戻す・印を解く・作り直し) の筋書き | 04 §5.3・§5.4・§7.4〜§7.6 |
| `corrections.toml` | 訂正の候補 (字句の規則) と検証の関門 | 04 §6 |
| `forget.toml` | 忘れると伏せ字、想起での伏せ | 04 §7.1〜§7.3・§7.5 |

## 共通の項目

| 項目 | 内容 |
|---|---|
| `id` | 事例の ID。ファイルの中で一意 (`P01`・`G01`・`C01`・`K01`・`F01`) |
| `title` | 何を確かめるか (1 行) |
| `lang` | データ根のプロンプトの言語 (`ja`・`en`)。省くと `ja` |
| `mode` | セッションのモード。省くと `chat` |
| `spec` | 根拠の仕様の節 |

候補 (抽出の LLM の出力、04 §5.2 の出力の型) は、`s`・`a`・`v`・`e`・`m`・`tn`・`old` の項目で書く。`m` を省くと `fact`、`tn` を省くと `current`、`old` を省くと空。`t` (束の中の番号) は、事例が指すターンで代える。

## prefilter.toml

`[[case]]` に `text` (保存した発話の本文) と、`expect` (`send` か `skip`) を書く。`skip` には `reason` を書く。`send` には、前のふるいの後に送る本文を `sent` に書いてよい (省くと `text` と同じ)。

| `reason` | 意味 |
|---|---|
| `mode` | チャットのセッションではない |
| `empty` | コードブロックと引用の行を除くと何も残らない |
| `greeting` | 挨拶・相槌の一覧に一致する (全言語を合わせて当てる) |
| `short` | 内容の単位 (日本語) か語 (英語) が言語ごとのしきい値に足りない |

理由は表の上から順に当て、最初に当たったものを書く。短さのしきい値は、発話の文字種から決めた言語のものを使う。

## gates.toml

`[[case]]` に `text` (発話)、`candidate` (候補)、`expect` を書く。`expect` は `accept` か、捨てる理由。`forgotten` に、前もって置く再び覚えない印 (`{ s, a, v }` の並び) を書ける。`count` は、受け付けても別に数える理由 (関門 1 を正規化の後の照合で通ったときの `evidence_normalized`)。

関門は 1 から 8 の順に当て、最初に外れた関門の理由を `expect` に書く。関門 6 の中は次の順に当てる: `forbidden_category` → `forbidden_char` → `url` → `role_marker` → `mixed_script` → `imperative` → `instruction_ref`。

| `expect` | 関門 | 意味 |
|---|---|---|
| `unknown_attribute` | (§5.1) | 属性が一覧に無い |
| `evidence_missing` | 1 | 根拠が、前のふるいの後の発話に (正規化しても) 含まれない |
| `value_not_in_evidence` | 2 | 値が根拠に含まれない (英数字は語の境界で) |
| `old_not_in_evidence` | 2 | `old` が根拠に含まれない |
| `mood` | 3 | 叙法が `question` か `hypothetical` |
| `quoted` | 4 | 値が根拠の中で引用の括弧の内側にある (属性の例外を除く) |
| `subject_not_allowed` | 5 | 主語が `self` 以外で、属性がそれを許さない。または、呼び名が 32 文字を超える・根拠に含まれない・表で本人を表す語 (「利用者」・user) と同じ。呼び名が関門 6 に外れたときは、関門 6 の理由で捨てる |
| `forbidden_category` | 6 | 一般カテゴリ Cc・Cf・Co・Cn・Cs の文字と、Default_Ignorable の文字 (04 §5.2 の関門 6) |
| `forbidden_char` | 6 | 行・段落の区切り、表の区切り |
| `url` | 6 | URL・スキームの印 |
| `role_marker` | 6 | 役割の詐称・区切りの模倣 |
| `mixed_script` | 6 | 1 つの語に複数の文字体系を混ぜた並び (Script 属性。UTS #39 highly restrictive の組だけを許す) |
| `imperative` | 6 | 命令形の文・依頼の印 (全言語を合わせて当てる) |
| `instruction_ref` | 6 | ほかの指示への言及 |
| `too_long` | 7 | 値が属性の上限を超える |
| `forgotten` | 8 | 再び覚えない印に当たる |

`m = "negated"` の候補は関門を通り、統合 (§5.3 の「否定」) に渡る (`expect = "accept"`)。

## consolidation.toml と forget.toml

`[[case]]` は、順に当てる `[[case.step]]` の並び。各段は次のどれか 1 つ。

| 段 | 項目 | 意味 |
|---|---|---|
| ターン | `turn = { id, session, at, role, text }` | ターンを作る (`role` は `user` か `assistant`。省くと `user`)。`at` は時刻で、ID の順と同じ順にする |
| 候補 | `candidate = { turn, s, a, v, e, m, tn, old }` | 関門を通った候補を統合に渡す |
| 訂正 | `correction = { turn, old, new }` | 検証済みの訂正を統合に渡す |
| 操作 | `op = { kind, ... }` | 下の表 |
| 期待 | `expect = { ... }` | その時点の状態 (下の表) |

続いた候補と訂正の段は、1 回の sleep-time の束として、(ターンの ID、根拠の始まり) の順に並べ直してから当てる (04 §5.3 の入力の順。書いた順に当てるのではない)。操作の段の時点 (指示の ID) は、その段より前に書いた最後のターンの後で、次のターンの前とする (採る・戻すは、この時点で当てる。04 §7.5 の「当てる時点」)。
| 細工 | `tamper = { id, text }` | 記録のターンの本文を、規則を通さずに書き換える (伏せ字の範囲と本文が食い違う状態を作る、04 §7.3 の中止の試験だけに使う) |

| `op.kind` | 項目 | 意味 |
|---|---|---|
| `forget` | `target = { s, a, v }`、`redact` (既定 true)、`history` (既定 false)、`echo` (既定 true)、`others` (既定 false) | 忘れる (04 §7.1)。`echo` は同じ往復の応答の中の一致も伏せる、`others` はほかのターンの一致も伏せる |
| `private` | `target`、`scope` (`successors` 既定 / `value_only`) | private にする (04 §7.5) |
| `private_off` | `target` | private を解く |
| `delete_session` | `session` | セッションを消す (04 §7.1) |
| `accept` | `target` | `Contested` の値を今の値にする (04 §7.4) |
| `revert` | `target` | 履歴の値を今の値に戻す (04 §7.4) |
| `unblock` | `target` | 再び覚えない印を解く (04 §7.6) |
| `rebuild_facts` | なし | 事実を捨て、それまでの候補と訂正を順に当て直し、事実への指示を当て直す (`rebuild --facts`、03 §10) |
| `shuffle` | なし | それまでの候補と訂正を、順を入れ替えて当て直す。結果は同じになる (04 §5.3 の「入力の順」) |

| `expect` の項目 | 内容 |
|---|---|
| `facts` | その時点のすべての事実 (`Retracted` を含む。消えた事実は書かない)。各々 `s`・`a`・`v` (`Retracted` は空)・`state` (`Live` / `Contested` / `Superseded` / `Retracted`)・`sources` (ターンの ID の集合)。任意で `tn` (省くと `current`)、`private` (省くと false)、`against` (`Contested` の相手の値)、`by` (`Superseded` の後の値。後の値の記録が消えたときは `"(deleted)"`、忘れて `Retracted` になったときは `"(retracted)"`) |
| `table` | 事実の表に入る行 (`"<主語>/<属性>/<値>"` を表の順に)。書いたときだけ比べる |
| `turns` | ターンの本文 (`{ id, text }`)。書いたターンだけ比べる |
| `recall` | 想起で添えるときの往復の本文 (`{ turn, text }`)。private と伏せ字にしない忘れるの `[非表示]` を確かめる |
| `blocked` | 再び覚えない印の一覧 (`{ s, a, v }`)。書いたときだけ比べる |
| `aborted` | true なら、直前の操作が中止され、状態が操作の前と変わらない |

## corrections.toml

`[[case]]` に `text` (候補の発話)、`previous` (直前の応答)、`expect_candidate` (字句の規則で候補になるか) を書く。古い値の照合の相手として、`earlier` (それより前の利用者の発話の並び) と `live` (今の Live の値、`{ s, a, v }` の並び) を書ける。候補になる事例には、型から決まる向き `direction = { old, new }` と、固定した検証の LLM の出力 `llm = { target, old, new, e }` と、`expect` (`verified` か理由) を書く。

事例は `crates/evorag-memory/tests/correction_cases.rs` が走らせる。`direction` の `old`・`new` は、当たった型の `{old}`・`{new}` の穴の本文 (記録の `dir_old`・`dir_new`) に含まれることを確かめる (穴は「でした」「に住んでいます」など、型の後ろの語を含みうる、04 §6)。古い値の無い型 (`I meant {new}` など) は `old` を書かない。

| `expect` | 意味 |
|---|---|
| `verified` | 検証済みの訂正になる |
| `new_not_in_utterance` | 新しい値か根拠が発話に含まれない |
| `old_not_found` | 古い値が、直前の応答・それより前の利用者の発話・今の値のどれにも無い |
| `direction` | LLM の出力の向きが、型から決まる向きと逆 |

関門は表の上から順に当て、最初に外れた理由を書く。引用 (コードブロック・引用の行) の中の訂正は、型を前のふるいの後の本文に当てるので候補にならない (`expect_candidate = false`)。候補の型が引用の外に当たり、検証の LLM が引用の中の値を返したときは、新しい値を前のふるいの後の本文で照合するので `new_not_in_utterance` で落ちる (04 §6 の「引用ではない」は、この 2 つに含まれる)。訂正の型は、発話の一部に当たればよい (発話の全体と一致しなくてよい)。

## 04 に決めたこと

事例を書いていて、仕様だけでは期待値を 1 つに決められなかった点は、04 に書いて決めた (2026-11-16)。事例はこのとおりに書いてある。

| 点 | 決めたこと | 04 |
|---|---|---|
| 時制 `past` で今の値を終えるときの `valid_to` | 発話に日付があり読めたときだけ埋める。事例では比べない | §5.3 の時制 |
| 伏せ字と `[非表示]` の範囲 | 根拠の範囲の中の、値に一致する箇所だけ | §7.1・§7.3・§7.5 |
| `planned` | 単値は別の枠に 1 件、多値は兄弟と並べる。予定の値を今の値に移すときは、同じ記録の時制を `current` にして出典を足す | §5.3 の時制 |
| 検証済みの訂正が当てる属性 | 一致する値が 2 つ以上の (主語, 属性) にあれば、事実は変えない | §6 |
| `en` の印の文言 | 伏せ字は `[redacted]`、想起での伏せは `[hidden]` | §7.3・§7.5 |
| 今の値を終えた発言 (過去形・否定) の出典 | 終えた発言のターンを、終えた事実の出典に足す | §5.3 |
| 過去形で終えた事実の時制 | 元のまま。履歴として足した過去の値だけが `past` | §5.3 の時制 |
| 事実を作り直した後の `Retracted` の記録 | 作らない。印だけが残る | §7.5 |
| 今の値が消え、それより古い矛盾の値だけが残ったとき | `Contested` のまま残し、`against` は消えた値の記録を指す | §7.4 |
| 多値の属性の private の「後継」 | 置き換えた値に限らず、あとで並べて足した値も含む | §7.5 |
| 関門・理由の順、訂正の型の当て方 | 上の各ファイルの節の順。訂正の型は発話の一部に当たればよい | §5.2・§6 |
